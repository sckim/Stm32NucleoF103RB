GPIO: 신호가 핀과 CPU 사이를 어떻게 흐르는가

GPIO(General-Purpose Input/Output, 범용 입출력)는 디지털논리 시간에 배운 소자, 즉 D 플립플롭, 2:1 선택기, CMOS(Complementary Metal-Oxide-Semiconductor, 상보형 금속산화막 반도체) 출력단, 슈미트 트리거, 엣지 검출기를 핀 하나마다 묶어 둔 회로이다. 이 개념설명은 STM32F103RB 한 칩을 기준으로, 핀에 들어온 전압이 CPU(Central Processing Unit, 중앙처리장치)가 읽는 비트가 되고 CPU가 쓴 비트가 핀 전압이 되기까지의 경로를 원본 블록도 위에서 따라간다.

1. 문제 정의: GPIO가 없으면 CPU가 무엇을 직접 해야 하는가

CPU가 외부 세계와 주고받는 수단은 버스 쓰기와 버스 읽기뿐이다. 쓰기 한 번에 실리는 주소·데이터·쓰기 신호는 버스 사이클 한 번 동안만 유효하고, 다음 사이클에는 다른 값으로 바뀐다. 그러니 핀에 LED를 달고 1초 동안 켜 두려면 다음 문제를 누군가 풀어야 한다.

핀 하나를 여러 주변장치가 쓰기보드 배선을 바꿔야 한다출력 선택기(GPIO/대체 기능)와 리맵 선택기(AFIO)

마지막 두 줄이 이 그룹의 핵심이다. 입력 데이터 레지스터(IDR, Input Data Register)는 그 순간의 핀 상태를 보여 줄 뿐 지나간 사건을 기억하지 않는다. CPU가 읽는 간격보다 짧은 펄스는 흔적 없이 사라진다. 반면 EXTI는 엣지가 오면 플래그를 세우고 CPU가 지울 때까지 그대로 둔다. 이 플래그를 펜딩(pending, "처리 대기 중") 비트라고 부른다. 즉 IDR은 상태를 보여 주고, EXTI의 펜딩 비트는 사건을 저장한다. 디지털논리로 말하면 IDR은 매 클럭 덮어쓰는 레지스터이고, 펜딩 비트는 한 번 세트되면 지울 때까지 유지되는 SR(Set-Reset) 래치이다. 하부 예제의 폴링(05, 07)과 인터럽트(06, 08)가 바로 이 차이를 비교한다.

2. 일반 개념

여기서 다루는 내용은 어느 MCU(Microcontroller Unit, 마이크로컨트롤러)의 GPIO에나 해당한다. 3장부터는 이 개념이 F103의 어느 블록에 들어 있는지 찾아본다.

메모리 맵 I/O와 주소 디코더

CPU 입장에서 GPIO 레지스터는 특정 주소에 있는 32비트 워드이다. 주소 디코더가 버스 주소를 보고 해당 레지스터의 쓰기 enable이나 읽기 선택 신호를 켠다. "레지스터에 쓴다"는 말은 결국 "디코더가 고른 플립플롭 묶음에 클럭 에지를 한 번 준다"는 뜻이다. 레지스터 주소가 왜 그 값인지는 3장 메모리 맵에서 본다.

출력단: 푸시풀, 오픈드레인, 3상태

풀업·풀다운과 떠 있는 입력

아무것도 연결되지 않은 CMOS 입력은 전압이 정해지지 않아 0과 1 사이를 떠돈다. 약한 저항으로 VDD나 VSS 쪽에 걸어 두면 외부 구동이 없을 때의 기본값이 정해진다. 저항이 클수록 외부 회로가 값을 바꾸기 쉽지만 선을 충전하는 속도는 느려진다(8장).

슈미트 트리거: 문턱이 두 개인 비교기

디지털 입력은 전압을 0과 1 중 하나로 판정해야 한다. 데이터시트는 두 경계를 준다. VIL(Input Low voltage)은 "이 전압 이하이면 0으로 인정"하는 상한이고, VIH(Input High voltage)는 "이 전압 이상이면 1로 인정"하는 하한이다. 두 값 사이는 판정이 보장되지 않는 구간이다. 슈미트 트리거는 지금 출력이 0이면 VIH를 넘어야 1로, 지금 출력이 1이면 VIL 아래로 내려가야 0으로 바꾼다. 출력이 자기 상태에 따라 문턱을 바꾸므로 기억이 있는 회로이며, 두 문턱의 차이를 히스테리시스라고 한다.

동기화기와 엣지 검출기

플립플롭은 클럭 에지 직전·직후의 짧은 구간(셋업·홀드 시간) 동안 입력이 변하지 않아야 정상 동작한다. 외부 신호는 클럭과 무관하게 변하므로 언젠가는 그 구간에 걸린다. 그러면 플립플롭 출력이 0도 1도 아닌 중간 전압에 잠시 머무는데, 이것을 메타안정(metastable) 상태라고 한다. 대부분은 곧 0이나 1로 정착하므로, 플립플롭을 하나 더 두어 한 클럭 동안 정착할 시간을 준다. 이것이 2단 동기화기이다.

접점 튐(바운스)

기계식 스위치는 닫히는 순간 수 ms 동안 붙었다 떨어지기를 되풀이한다. 슈미트 트리거는 문턱 근처의 작은 잡음은 걸러 내지만, 접점이 실제로 떨어져 전압이 레일까지 다시 올라가는 튐은 거르지 못한다. 그 결과 엣지가 여러 번 생기고, 이것이 7장 시나리오의 핵심이다.

3. 내부 구현 블록도

신호를 입력 → 클럭 → 처리 → 플래그/이벤트 → 출력 순서로 따라간다. 먼저 GPIO가 칩의 어디에 붙어 있는지 확인한다.

핀 한 개의 내부

  1. 1
    입력: 핀 → 보호 다이오드 → 풀업/풀다운 스위치보호 다이오드는 핀 전압이 VDD보다 높거나 VSS보다 낮아지지 않도록 묶어 둔다. 두 개의 on/off 스위치가 약한 풀 저항을 연결하거나 끊는다. RPU(풀업 저항)과 RPD(풀다운 저항)은 30~50 kΩ, 전형값 40 kΩ이다(DS5319 Table 36).
  2. 2
    처리: TTL 슈미트 트리거히스테리시스 비교기이다. TTL(Transistor-Transistor Logic)은 문턱 전압이 TTL 논리 규격과 호환된다는 뜻이다. 히스테리시스 Vhys는 표준 핀에서 200 mV, 5 V 허용 핀(FT, Five-volt Tolerant)에서 5 % VDD(최소 100 mV)이다(DS5319 Table 36, p.61). 아날로그 입력은 슈미트 트리거 앞에서 갈라져 ADC(Analog-to-Digital Converter, 아날로그-디지털 변환기)로 간다.
  3. 3
    클럭: Input data register(IDR)가 APB2 클럭마다 샘플링"The Input Data register captures the data present on the I/O pin at every APB2 clock cycle"(RM0008 9.1.1, p.161). 즉 PCLK2(APB2 주변장치 클럭)로 클럭되는 D 플립플롭 16개이다. 슈미트 출력은 대체 기능 입력으로도 갈라져 다른 주변장치와 EXTI로 간다.
  4. 4
    플래그/이벤트: EXTI로 가는 갈래입력 신호는 포트 선택기(AFIO_EXTICRx, External Interrupt Configuration Register)를 지나 EXTI의 엣지 검출기에 이르고, 펜딩 플래그를 세운 뒤 NVIC로 간다. 6장에서 자세히 본다.
  5. 5
    출력: Output data register → 2:1 선택기 → Output control → P-MOS/N-MOSCPU가 쓴 값은 Output data register(ODR, D 플립플롭)에 머문다. Bit set/reset registers(BSRR: Bit Set/Reset Register, BRR: Bit Reset Register)는 이 플립플롭을 비트별로 세트·리셋하는 별도 입구이다. 사다리꼴 2:1 선택기가 ODR과 주변장치의 Alternate Function Output 중 하나를 고르고, Output control이 푸시풀, 오픈드레인, 비활성 중 하나로 트랜지스터를 구동한다.

RM0008은 입력 레지스터가 "APB2 클럭마다 샘플링한다"고만 적고 있다. 그 앞에 동기화 단이 몇 개인지는 밝히지 않는다. 그래서 표에서 이 항목은 등가 모델로 표시했다.

4. 클럭 경로와 시간 계산

입력 쪽 시간: 샘플링 주기와 놓치는 펄스

IDR 샘플링 주기 = 1 / f_PCLK2 (f_PCLK2 최대 72 MHz, DS5319 Table 9, p.38) 72 MHz → 13.9 ns 64 MHz → 15.6 ns 8 MHz(리셋 직후 HSI: 내부 RC 발진기) → 125 ns EXTI가 검출하는 최소 펄스 폭 t_EXTIpw = 10 ns (DS5319 Table 38, p.65)

72 MHz에서도 EXTI의 최소 검출 폭(10 ns)이 APB2 한 주기(13.9 ns)보다 짧다. RM0008 10.2.1도 EXTI가 "pulse width lower than APB2 clock period"인 신호를 검출한다고 적고 있다. 그러니 EXTI의 엣지 검출기는 2장의 동기식 검출기(클럭마다 비교)일 수 없고, 펄스 자체로 플래그를 세우는 비동기 포착 회로여야 한다(6장).

폴링은 더 불리하다. IDR은 매 APB2 클럭마다 갱신되지만 지나간 값을 붙잡아 두지 않는다. CPU가 IDR을 읽는 그 순간에 펄스가 핀에 있어야만 보인다. 펄스가 보일 확률은 대략 펄스 폭 / CPU 읽기 간격이다.

출력 쪽 시간: MODE는 토글 속도가 아니라 슬루율이다

MODE를 50 MHz로 골라도 핀이 50 MHz로 토글하지는 않는다. 토글 주기는 CPU나 다른 버스 마스터가 출력 레지스터에 얼마나 자주 쓰느냐로 정해진다. MODE는 그렇게 정해진 엣지가 얼마나 가파른지만 정한다. 버스 쓰기 한 번이 몇 APB2 사이클에 핀까지 도달하는지는 근거 문서에 나오지 않는다. 이것은 하부 예제 10에서처럼 계측으로 확인한다.

5. 제어 요소의 역할: 블록도의 스위치와 레지스터 비트

RM0008 9.1.7~9.1.10은 같은 회로를 네 가지 구성으로 다시 그린다. 그림마다 Figure 13의 어떤 스위치가 닫히고 열렸는지만 다르다. 그 스위치를 고르는 것이 핀당 4비트 필드이며, 상위 2비트는 CNF[1:0](Configuration: 입출력 방식), 하위 2비트는 MODE[1:0](입력인가 출력인가, 출력이면 속도)이다.

핀이 16개이므로 4비트 × 16 = 64비트가 필요하다. 32비트 레지스터 두 개로 나누어 핀 0~7은 GPIOx_CRL(Port Configuration Register Low), 핀 8~15는 GPIOx_CRH(High)에 넣었다. 핀 y의 필드는 CRL이면 비트 [4y+3 : 4y], CRH이면 비트 [4(y−8)+3 : 4(y−8)]이다. 리셋값 0x4444 4444는 모든 필드가 0100, 즉 CNF = 01, MODE = 00(플로팅 입력)이라는 뜻이다. 전원을 켠 직후 어떤 핀도 출력을 내지 않도록, 외부 회로와 충돌하지 않는 가장 안전한 상태로 시작하는 것이다.

출력 플립플롭에 이르는 세 입구

핀 5 하나만 1로 바꾸고 싶다고 하자. ODR은 16비트가 한 워드에 묶여 있으므로 CPU는 ① ODR을 읽고, ② 비트 5만 OR로 고치고, ③ 다시 쓴다. 이것을 읽고-고치고-쓰기(RMW, Read-Modify-Write)라고 한다. ①과 ③ 사이에 인터럽트가 들어와 그 서비스 루틴이 핀 6을 바꾸고 돌아오면, ③은 ①에서 읽은 옛 값으로 덮어쓰므로 핀 6의 변경이 사라진다. 세 단계가 하나로 묶여 있지 않아서 생기는 문제이다.

BSRR(Bit Set/Reset Register)은 이 문제를 하드웨어로 없앤다. 아래 16비트(BS0~BS15)에 1을 쓴 비트는 1로, 위 16비트(BR0~BR15)에 1을 쓴 비트는 0으로 바뀌고, 0을 쓴 비트는 그대로 둔다. CPU는 쓰기 한 번만 하면 되고 읽을 필요가 없다. 중간에 아무것도 끼어들 수 없는 한 번의 동작을 원자적(atomic) 동작이라고 한다. BRR(Bit Reset Register)은 BSRR의 리셋 절반만 따로 떼어 놓은 레지스터이다.

ODRy⁺ = BSy + ¬BSy·¬BRy·(WE·Dy + ¬WE·ODRy) (⁺ = 다음 클럭의 값, WE = ODR 쓰기 enable) BSRR ← 0x0020 0040 : 비트 6 세트, 비트 5 리셋, 나머지 유지 BSRR ← 0x0020 0020 : 비트 5에 BS와 BR이 함께 → BS 우선 → 1

설정을 얼리는 상태기계: LCKR

왜 필요한가. 프로그램에 버그가 있어 엉뚱한 주소에 값을 쓰거나 폭주하면 CRL/CRH가 덮어써질 수 있다. 그러면 외부 회로가 신호를 넣고 있는 입력 핀이 출력으로 바뀌어 두 출력이 맞붙거나(단락 전류), 모터 구동 신호 같은 출력이 입력으로 바뀌어 떠 버릴 수 있다. 그래서 한 번 정한 핀 구성을 다음 리셋까지 바꿀 수 없게 얼리는 기능이 있다. 그 레지스터가 GPIOx_LCKR(Port Configuration Lock Register)이다.

구성. 비트 0~15의 LCK0~LCK15는 "어느 핀을 잠글지" 표시하는 비트이고, 비트 16의 LCKK(Lock Key)는 잠금이 걸렸는지를 나타내는 키 비트이다(RM0008 9.2.7). LCKy 비트 하나는 해당 핀의 CRL/CRH 4비트(CNF·MODE)를 얼린다.

왜 순서(키)가 필요한가. LCKK에 1을 한 번 쓰는 것만으로 잠긴다면, 위에서 말한 버그성 쓰기 한 번에도 잠금이 걸리거나 엉뚱한 설정이 얼어 버린다. 그래서 하드웨어는 정해진 쓰기·읽기 순서가 정확히 이어질 때만 잠금을 건다. 우연히 이 순서가 맞아떨어질 가능성은 거의 없다. 비밀번호 자물쇠와 같은 원리이고, 디지털논리의 시퀀스 검출기(예: 입력열에서 "101"을 찾는 상태기계)와 같은 구조이다.

단계CPU 동작예: PA5만 잠글 때 LCKR 값상태기계
1LCKK = 1과 잠글 핀의 LCKy = 1을 함께 쓴다0x0001 0020 쓰기대기 → S1
2LCKK = 0, LCKy는 그대로 쓴다0x0000 0020 쓰기S1 → S2

4LCKR을 읽는다. LCKK가 0으로 읽힌다읽기 → 비트 16 = 0S3 → 잠김
5 (선택)다시 읽어 LCKK = 1이면 잠금이 걸린 것이다읽기 → 비트 16 = 1확인

순서 도중에 LCK[15:0] 값이 바뀌거나 순서가 어긋나면 잠금은 걸리지 않는다. 그래서 세 번의 쓰기 모두 아래 16비트를 같은 값(위 예에서는 0x0020)으로 유지한다. 한 번 걸린 잠금은 소프트웨어로 풀 수 없고, 리셋만이 해제 방법이다. 잠기는 것은 CRL/CRH의 구성 비트뿐이다. RM0008은 LCKy가 "the corresponding 4 bits of the control register (CRL, CRH)"를 얼린다고만 적는다. 따라서 잠근 출력 핀이라도 ODR이나 BSRR로 출력 값을 바꾸는 일은 계속할 수 있다.

대체 기능과 리맵 선택기

대체 기능(AF, Alternate Function)은 핀을 GPIO 대신 USART(Universal Synchronous/Asynchronous Receiver-Transmitter, 직렬 통신), SPI(Serial Peripheral Interface), I2C(Inter-Integrated Circuit), 타이머 같은 다른 주변장치가 구동하게 하는 것이다. 칩에는 주변장치 신호가 핀보다 훨씬 많아서 핀 하나가 여러 주변장치의 후보가 된다. 주변장치 출력은 Figure 13의 2:1 선택기(CNF[1] = 1)를 통해 핀에 이른다.

그런데 기본 배정 핀이 이미 다른 용도로 쓰이고 있다면 어떻게 할까. F103은 일부 주변장치 신호를 다른 핀으로 옮길 수 있게 해 두었다. 이것을 리맵(remap)이라고 하고, AFIO_MAPR(AF Remap and debug I/O configuration Register)의 리맵 필드가 고른다(RM0008 9.3, p.175). 예를 들어 I2C1의 SCL(Serial Clock)·SDA(Serial Data)는 I2C1_REMAP = 0이면 PB6·PB7, 1이면 PB8·PB9에 연결된다(RM0008 Table 55, p.181). 디지털논리로 보면 리맵 비트는 "주변장치 신호를 어느 핀의 선택기 입력으로 보낼지" 고르는 다중화기의 select 입력이다.

같은 레지스터의 SWJ_CFG(Serial Wire JTAG Configuration) 필드는 디버그 포트가 차지한 핀을 범용 I/O로 돌려준다(RM0008 9.3.5, p.176). 디버그 포트는 JTAG(Joint Test Action Group, 5핀 디버그 규격)과 SWD(Serial Wire Debug, 2핀 디버그 규격)를 함께 지원한다. 리셋 직후 PA13~PA15와 PB4가 풀업/풀다운 입력인 까닭은 이 핀들이 디버그 포트에 연결되어 있기 때문이다(RM0008 9.1.1). 디버그 핀을 GPIO로 돌려받으면 그 디버그 방식으로는 더 이상 연결할 수 없다는 대가가 있다.

6. 이벤트 생성 기전: 핀의 엣지가 CPU에 닿기까지

① 포트 선택기: 112개 핀을 16개 라인으로

디지털논리로 보면 4비트 select가 달린 16개의 다중화기이다. select 값 0000 = 포트 A, 0001 = 포트 B, 0010 = 포트 C … 순서이다. 4비트 필드가 16개 필요하므로 32비트 레지스터 네 개(AFIO_EXTICR1~4)에 4개씩 들어 있다. EXTICR1이 라인 0~3, EXTICR2가 4~7, EXTICR3이 8~11, EXTICR4가 12~15를 맡는다. 출력이 라인당 하나이므로 같은 번호의 두 핀은 동시에 인터럽트 소스가 될 수 없다. 또 RM0008 9.1.3에 따라 외부 인터럽트로 쓰는 핀은 입력 모드여야 한다.

② EXTI 라인 하나의 내부

"마스크(mask)"라는 이름이 헷갈리기 쉽다. IMR/EMR의 비트가 1이면 통과, 0이면 차단이다(RM0008 10.3.1: "0: … is masked, 1: … is not masked"). 즉 AND 게이트의 다른 쪽 입력이며, 리셋값 0에서는 모든 라인이 막혀 있다. 왜 0을 쓰면 PR이 지워지지 않고 1을 써야 지워질까? 여러 라인의 PR이 한 워드에 들어 있기 때문이다. 지울 비트만 1로 쓰면 0을 쓴 다른 비트는 영향을 받지 않으므로, BSRR과 마찬가지로 다른 라인의 플래그를 건드리지 않고 하나만 지울 수 있다.

③ NVIC: 16개 라인, 7개 벡터

먼저 용어를 정리한다. 인터럽트가 걸리면 CPU는 하던 일을 멈추고 그 인터럽트를 처리하는 함수, 곧 ISR(Interrupt Service Routine, 인터럽트 서비스 루틴)로 뛴다. 어느 ISR로 뛸지는 메모리 앞부분의 벡터 테이블이 정한다. 벡터 테이블은 인터럽트 번호마다 ISR 시작 주소를 하나씩 적어 둔 표이고, 그 칸 하나를 벡터라고 한다. 주변장치의 요청을 받아 "접수됨(펜딩)" 상태로 만들고, 우선순위를 비교해 CPU에 넘기는 하드웨어가 NVIC이다.

EXTI 라인NVIC 위치(IRQ: Interrupt Request 번호)벡터 주소디지털 등가
0, 1, 2, 3, 46, 7, 8, 9, 100x58 ~ 0x68라인마다 전용 요청선
5 ~ 923 (EXTI9_5)0x9C5입력 OR
10 ~ 1540 (EXTI15_10)0xE06입력 OR

근거는 RM0008 Table 63(F103RB 같은 medium-density에 해당, p.204~205)이다. 라인 0~4는 벡터를 하나씩 가지지만, 라인 5~9와 10~15는 각각 벡터 하나(이름 EXTI9_5, EXTI15_10)를 나누어 쓴다. 공유 벡터는 OR 게이트이므로 벡터에 들어온 것만으로는 어느 라인이 불렀는지 알 수 없다. 서비스 루틴은 PR을 읽어 출처를 가린다.

PR 출력은 레벨 신호이다. PM0056 4.3.9(p.126)에 따르면 NVIC는 서비스 루틴에 들어갈 때 펜딩을 지우지만, 복귀할 때 요청선이 아직 High이면 다시 펜딩으로 만든다. 그래서 PR을 지우지 않고 복귀하면 같은 서비스 루틴이 끝없이 다시 실행된다.

④ 인터럽트가 아닌 갈래: 이벤트, 다른 주변장치 트리거, DMA

  • 이벤트 → WFE 깨움: WFE(Wait For Event)는 CPU를 저전력 대기 상태로 재우고 이벤트가 오면 다음 명령부터 이어 가게 하는 명령이다. 인터럽트와 달리 ISR로 뛰지 않는다. EMR 경로는 PR을 세우지 않고 펄스만 만든다. 따라서 깨어난 뒤 지울 플래그가 없다(RM0008 10.2.3, p.208). ES096 2.1.2(p.5)에 따르면 WFE 실행 전에 인터럽트가 먼저 오면 이벤트 레지스터가 세트되지 않아 깨어나지 못한다. 정오표는 그 대책으로 EXTI 라인을 이벤트 모드로 쓰라고 권한다.
  • CPU 이벤트 → 핀: 반대 방향 경로도 있다. AFIO_EVCR(Event Control Register, RM0008 9.4.1, p.183)은 Cortex-M3 코어의 이벤트 출력 신호 EVENTOUT을 PORT[2:0]·PIN[3:0]으로 고른 핀 하나로 내보낸다. 이것도 선택기이다.
  • 다른 주변장치의 트리거: EXTI 라인 11은 ADC(Analog-to-Digital Converter, 아날로그-디지털 변환기) 정규 채널, 라인 15는 주입 채널(정규 변환 도중 끼어들어 먼저 변환하는 채널)의 외부 트리거로 고를 수 있다(RM0008 Table 67·68, p.225~226). 핀 엣지 하나로 CPU 개입 없이 변환을 시작하는 경로이다.
  • DMA(Direct Memory Access, CPU를 거치지 않는 메모리 전송): DMA1 요청 표(RM0008 Table 78, p.282)에는 GPIO와 EXTI가 없다. GPIO는 DMA를 부르지 못한다. 다만 DMA가 다른 주변장치(타이머 등)의 요청을 받아 BSRR에 쓰는 반대 방향은 가능하다. 이것은 07_DMA 그룹에서 다룬다.

9. 이해 확인 문제

Q1. 포트 B 핀 10을 "오픈드레인 범용 출력, 최대 2 MHz"로 쓰려 한다. 어느 레지스터의 몇 번 비트에 어떤 4비트 값을 넣는가? 그때 P-MOS는 언제 켜지는가?

핀 8~15는 CRH이고 필드 위치는 4 × (10 − 8) = 8이므로 GPIOB_CRH의 비트 11:8이다. CNF = 01(범용 오픈드레인), MODE = 10(2 MHz)이므로 0b0110 = 0x6이다. 오픈드레인에서 P-MOS는 절대 켜지지 않는다. ODR = 0이면 N-MOS가 켜지고, 1이면 Hi-Z이다(RM0008 9.1.8).

Q2. GPIOA_ODR = 0x0000 0020일 때 BSRR에 0x0020 0040을 쓰면 ODR은? 0x0020 0020을 쓰면?

첫 번째는 BS6 = 1, BR5 = 1이므로 비트 6은 세트, 비트 5는 리셋되어 ODR = 0x0000 0040이다. 두 번째는 비트 5에 BS와 BR이 함께 1이므로 BS가 우선해(RM0008 9.2.5) ODR = 0x0000 0020이 유지된다.

Q3. f_PCLK2 = 36 MHz이다. 폭 20 ns의 Low 펄스가 핀에 들어온다. CPU가 1 µs마다 IDR을 읽으면 이 펄스를 볼 확률은? EXTI는 잡는가?

APB2 주기는 27.8 ns로 펄스보다 길다. IDR 샘플 자체가 펄스를 놓칠 수 있고, 잡혀도 다음 샘플에서 사라진다. CPU가 읽는 순간에 펄스가 있어야 하므로 확률은 약 20 ns / 1000 ns = 2 %이다. EXTI의 최소 검출 폭은 10 ns이므로(DS5319 Table 38) 엣지 선택만 맞으면 PR이 세트된다.

Q4. 핀에 하강 엣지가 분명히 들어오는데 EXTI_PR이 세워지지 않는다. 블록도의 경로를 따라 원인 후보를 앞에서부터 나열하라.

① 핀이 입력 모드가 아니다(RM0008 9.1.3). ② AFIO 클럭(AFIOEN)이 꺼져 있어 EXTICR 쓰기가 무시되었다(RM0008 9.4). ③ EXTICR의 포트 선택이 다른 포트를 가리킨다(Figure 21). ④ FTSR의 해당 비트가 0이다. ⑤ IMR이 0이다(Figure 20에서 PR 앞에 IMR AND 게이트가 있다). 어떤 경우든 SWIER에 1을 써서 PR이 서는지 확인하면 엣지 검출 앞쪽과 뒤쪽 중 어디가 문제인지 나눌 수 있다.

Q5. PC13과 PA13을 둘 다 하강 엣지 인터럽트로 쓰려 한다. 가능한가?

불가능하다. 둘 다 EXTI 라인 13의 선택기 입력이고 EXTICR4의 EXTI13[3:0]은 포트 하나만 고를 수 있다. 게다가 PA13은 리셋 직후 디버그 포트(JTMS: JTAG Mode Select / SWDIO: Serial Wire Data I/O)에 연결되어 있다(RM0008 9.1.1). 한쪽을 번호가 다른 핀으로 옮겨야 한다.

Q6. 오픈드레인 출력에 ODR = 1을 썼는데 IDR이 1과 0을 불규칙하게 오간다. 외부에는 아무것도 연결하지 않았다. 왜 내부 풀업이 도와주지 않는가?

ODR = 1이면 N-MOS가 꺼지고 P-MOS는 원래 쓰지 않으므로 핀은 Hi-Z로 떠 있다. 출력 구성에서는 약한 풀업/풀다운이 끊긴다(RM0008 9.1.8, Figure 16). 오픈드레인의 1은 외부 풀업이 만들어야 한다.

Q7. MODE = 11, C_L = 50 pF, VDD = 3.3 V이다. Figure 30의 조건 (t_r + t_f) ≤ 2/3 T로 계산한 최대 주파수와 Table 38의 값을 비교하라.

Table 38에서 tr = tf = 8 ns이다. T ≥ 1.5 × 16 = 24 ns이므로 41.7 MHz가 나온다. 표의 fmax는 30 MHz로 더 보수적이다. 표 값은 듀티 조건 등을 포함한 보증치이므로 설계에는 표 값을 쓴다.

Q8. GPIOA_ODR 비트 5의 비트 밴드 별칭 주소를 계산하라.

GPIOA_ODR = 0x4001 080C이므로 주변장치 비트 밴드 영역 기준 바이트 오프셋은 0x1080C이다. 별칭 = 0x4200 0000 + 0x1080C × 32 + 5 × 4 = 0x4200 0000 + 0x21 0180 + 0x14 = 0x4221 0194(PM0056 2.2.5).

Q9. EXTI_PR의 비트 하나를 지우려고 비트 밴드 별칭에 1을 썼더니 다른 라인의 인터럽트가 사라졌다. 왜인가?

PM0056 Table 14에 따르면 별칭 쓰기는 하드웨어가 읽고-고치고-쓰기로 수행한다. 그래서 워드 전체를 읽은 뒤 해당 비트만 바꿔 다시 쓴다. PR은 1을 쓰면 지워지는 비트(rc_w1)이므로, 읽을 때 1이었던 다른 펜딩 비트가 그대로 1로 다시 쓰여 함께 지워진다. PR은 지울 비트만 1인 값을 직접 써야 한다.

Q10. 라인 7과 라인 8을 함께 쓰는데 하나만 처리하고 복귀했다. 무슨 일이 생기는가?

둘 다 EXTI9_5 벡터(OR 게이트)로 들어간다. 처리하지 않은 라인의 PR이 남아 요청선이 High로 유지되므로, 복귀하자마자 NVIC가 다시 펜딩해 같은 벡터로 재진입한다(PM0056 4.3.9). 서비스 루틴은 PR을 읽어 세워진 비트를 모두 처리해야 한다.

10. 하부 예제 연결

비트 밴딩: 주소 디코더로 비트 하나 고르기

5장에서 본 RMW 문제는 ODR에만 있는 것이 아니다. 클럭 허용 비트, 소프트웨어 플래그 등 워드 안의 비트 하나를 바꾸는 모든 곳에서 생긴다. BSRR처럼 전용 레지스터를 두는 대신, Cortex-M3는 주소 공간에서 해결한다. 주변장치 영역과 SRAM(Static RAM, 칩 내부 데이터 메모리) 영역의 모든 비트에 각각 32비트짜리 별도 주소, 곧 별칭을 하나씩 붙였다. 별칭 주소에 쓰면 버스가 해당 비트 하나만 바꾼다. 주소 디코더가 "어느 워드의 몇 번 비트인가"까지 해석하는 셈이다.

정리
  • GPIO 핀 하나는 D 플립플롭(ODR, IDR), 세트/리셋 논리(BSRR), 2:1 선택기, CMOS 출력단, 슈미트 트리거, 풀 스위치의 조합이다.
  • CNF·MODE 4비트는 이 소자들의 스위치를 고른다. MODE는 출력단 on/off와 엣지 기울기를 고를 뿐 토글 속도를 정하지 않는다.
  • IDR은 APB2 클럭마다 상태를 샘플링할 뿐 사건을 기억하지 않는다. EXTI의 PR은 엣지로 세트되어 소프트웨어가 지울 때까지 사건을 기억한다.
  • EXTI 경로는 포트 선택기 → 비동기 엣지 검출 → IMR/EMR 게이트 → PR(SR FF) → NVIC(공유 벡터는 OR) 순서이다. PR을 지우지 않으면 레벨 요청이 남아 재진입한다.
