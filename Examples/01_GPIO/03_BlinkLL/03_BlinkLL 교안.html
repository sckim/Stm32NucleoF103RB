LL 계층의 Blink: 인라인 레지스터 접근, COUNTFLAG 지연, JTAG 해제

LL 드라이버는 HAL의 핸들·상태·콜백을 걷어 내고 레지스터 접근에 이름만 붙인다. 그만큼 코드가 작고 빠르지만, HAL이 대신하던 틱 설정과 클럭 보정을 생성 코드가 직접 호출해야 한다. 이 교안은 LL_GPIO_TogglePin이 컴파일 후 ODR 읽기와 BSRR 쓰기로 펼쳐지는 모습, 인터럽트 없이 COUNTFLAG를 폴링하는 LL_mDelay, AFIO_MAPR로 JTAG을 해제하는 코드를 해석하고 다른 세 계층과 비교한다. 대상 폴더는 03_BlinkLL이다.

1. 문제: HAL보다 얇은 계층은 무엇을 덜어 내는가

LL(Low-Layer) 드라이버는 핸들 구조체, 상태 머신, 타임아웃, 콜백을 두지 않는다. 대부분의 함수가 헤더의 static inline 함수여서 컴파일 후에는 레지스터 접근 몇 개로 펼쳐진다. 그 대신 HAL이 자동으로 해 주던 일(예: SysTick 인터럽트 틱, 클럭 재설정 후 틱 보정)을 생성 코드가 명시적으로 호출해야 한다. 학습 목표는 다음과 같다.

  • LL_GPIO_TogglePin이 컴파일 후 ODR 읽기 1회 + BSRR 쓰기 1회가 됨을 역어셈블로 확인한다.
  • LL_Init1msTick과 LL_mDelay가 SysTick 인터럽트 없이 COUNTFLAG 폴링으로 지연을 만드는 방식을 설명한다.
  • LL_GPIO_AF_Remap_SWJ_NOJTAG()가 AFIO_MAPR.SWJ_CFG를 바꿔 JTAG 핀을 해제하면서 SWD를 유지하는 이유를 이해한다.
  • HSE 바이패스 × PLL8 클럭 설정을 LL 함수 나열로 읽고, HAL·Arduino·레지스터 계층과 비교한다.
이 예제의 동작

LD2(PA5)를 약 1초(1001 ms)마다 토글한다. 점멸 주기는 약 2 s이며 02_BlinkHAL과 같다. 시간 기준은 SysTick 인터럽트가 아니라 SysTick의 COUNTFLAG 비트이다.

2. 핵심 개념: LL은 "이름 붙은 레지스터 접근"이다

그림 1. 네 예제는 같은 하드웨어(PA5의 출력 레지스터)에 도달하지만 출발하는 계층이 다르다. 굵은 주황 경로가 이 교안의 예제이며, 위 계층일수록 그 아래 계층을 모두 거친다.

Flash 크기는 각 폴더의 .pio/build 산출물(firmware.elf)의 .text 크기이며, 빌드 시점·옵션(debug)에 따라 달라진다. 레지스터 접근 열은 빌드 산출물을 역어셈블해 확인한 내용이다.

LL_GPIO_TogglePin(GPIOA, LL_GPIO_PIN_5) ; LL_GPIO_PIN_5 = 0x0000 2020 odr = GPIOA->ODR ; ldr r3, [r1, #12] BSRR = ((odr << 16) & 0x0020 0000) | (~odr & 0x0000 0020) ; str r3, [r1, #16]

위 식은 빌드 산출물(.pio/build/nucleo_f103rb/firmware.elf)의 main 역어셈블에서 확인한 것이다. 함수 호출이 아니라 main 안에 직접 펼쳐져 있다. 결과는 02_BlinkHAL의 HAL_GPIO_TogglePin과 같은 원자적 토글이다.

LL 핀 상수의 비트LL_GPIO_PIN_5 = 0x0000 2020쓰임
비트 31:240x00CRL(0x00)/CRH(0x04) 중 어느 레지스터인지 (오프셋). PA8~15는 0x04
비트 23:80x0020BSRR/BRR/ODR에 쓰는 핀 마스크 (값 >> 8)
비트 7:00x20최하위 1의 위치(5) → CRL 안의 필드 위치 5 × 4 = 20

F1의 핀 설정 레지스터가 CRL/CRH 두 개로 나뉘어 있으므로, LL은 핀 상수 하나에 "어느 레지스터인가"와 "비트 마스크"를 함께 인코딩한다. HAL의 GPIO_PIN_5(= 0x0020)와 값이 다르므로 두 계층의 핀 상수를 섞어 쓰면 안 된다.

그림 2. PA5 출력. LL_GPIO_ResetOutputPin으로 Low에서 시작해 첫 토글로 High가 된다. LL_mDelay(1000)은 COUNTFLAG를 1001번 확인하므로 토글 간격은 1000~1001 ms이다.

JTAG 해제의 의미

리셋 직후 F103은 JTAG(PA13, PA14, PA15, PB3, PB4)과 SWD를 모두 허용한다. SWJ_CFG = 010은 JTAG-DP만 끄고 SW-DP(PA13 = SWDIO, PA14 = SWCLK)는 남긴다. 그 결과 PA15, PB3, PB4를 GPIO로 쓸 수 있고 ST-LINK 업로드·디버깅은 그대로 된다. 이 설정은 AFIO_MAPR을 쓰므로 먼저 AFIOEN을 켜야 한다(코드 첫 줄). SWJ_CFG = 100(둘 다 해제)으로 바꾸면 다음 업로드는 리셋 버튼을 누른 채 연결해야 한다.

4. 직접 만져 보기: LL 호출과 ODR/BSRR 변화

아래 시뮬레이터는 GPIOA의 하위 8비트를 대상으로 LL 함수가 쓰는 레지스터 값을 계산한다. 아래쪽은 "토글 도중 ISR이 같은 포트의 다른 핀(PA6)을 세트하는" 경쟁 상황에서 BSRR 방식과 ODR 읽고-쓰기 방식의 결과를 비교한다.

  1. SetOutputPin, ResetOutputPin, TogglePin을 차례로 눌러 BSRR/BRR에 쓰이는 값과 ODR 변화를 확인한다.
  2. 토글 방식을 LL_GPIO_TogglePin (BSRR)으로 두고 토글 중 ISR이 PA6 세트를 누른다. PA6이 1로 남는지 본다.
  3. 방식을 ODR ^= (1 << 5)로 바꾸어 다시 누른다. ISR이 세운 PA6이 사라지는 것을 확인한다.

시뮬레이터 모델: LL 함수의 레지스터 동작은 빌드 산출물에서 확인한 식을 따른다(SetOutputPin → BSRR, ResetOutputPin → BRR). 경쟁 상황은 "ODR 읽기 직후, 쓰기 직전"에 인터럽트가 들어온다고 가정한다. LL_mDelay는 먼저 STK_CTRL을 읽어 COUNTFLAG를 지우고, N < 0xFFFF FFFF이면 N+1번 COUNTFLAG를 기다린다. 첫 COUNTFLAG까지는 0~1 ms이므로 실제 대기는 N ~ N+1 ms이다.

6. 실행 경로: 초기화부터 핀 출력까지

  1. 1
    Reset_Handler → SystemInit() → main()소프트웨어SystemInit은 빈 함수이다. HSI 8 MHz로 시작한다.
  2. 2
    AFIO·PWR 클럭, NVIC 그룹, NOJTAG소프트웨어HAL 예제의 HAL_Init() + HAL_MspInit()이 하던 일을 main 첫 부분에서 직접 호출한다.
  3. 3
    SystemClock_Config()소프트웨어Flash 대기 → HSE 바이패스 → PLL ×8 → 분주 → SW 전환. 각 단계마다 준비 비트를 폴링한다.
  4. 4
    LL_Init1msTick소프트웨어SysTick을 1 ms 주기 자유 계수기로만 켠다. 인터럽트는 끈다.

    MX_GPIO_Init()소프트웨어포트 클럭 → PA5 Low → EXTI13 → PA2/PA3 → PA5 출력 → EXTI15_10_IRQn 허용.

    while: TogglePin → LL_mDelay(1000)소프트웨어BSRR 쓰기 후 COUNTFLAG를 1001번 기다린다.
  7. 7
    SysTick 카운터 0 도달하드웨어COUNTFLAG = 1. STK_CTRL을 읽으면 0으로 지워진다. 예외는 발생하지 않는다.

외부 부품은 필요 없다. 보드의 LD2만 사용하며 시리얼 출력은 없다.

8. 실험

실험 A. 인라인 확인

디버거의 역어셈블 창에서 LL_GPIO_TogglePin 줄이 함수 호출(bl) 없이 ldr/str 명령으로 펼쳐지는지 확인한다. 02_BlinkHAL의 bl HAL_GPIO_TogglePin과 비교한다.

실험 B. 인터럽트 틱으로 바꾸기

LL_SYSTICK_EnableIT()를 추가하고 SysTick_Handler에 카운터 변수를 증가시켜 본다. TICKINT = 1이 되면 ISR이 호출되는지, LL_mDelay는 그대로 동작하는지 확인한다.

실험 C. PLL 배수 변경

LL_RCC_PLL_MUL_8을 MUL_9(72 MHz)로 바꾸되 LL_Init1msTick(64000000)은 그대로 둔다. 점멸 주기가 얼마나 짧아지는지 계산(64/72)하고 측정한다. 그다음 두 상수도 72000000으로 고친다.

실험 D. B1 인터럽트 사용

USER CODE BEGIN LL_EXTI_LINE_13 안에 플래그 변수를 세우는 코드를 넣고, main에서 플래그가 서면 점멸을 멈추게 한다. ISR과 main이 공유하는 변수에 volatile을 붙인다.

9. 트러블슈팅

증상원인점검/조치
LL 함수가 정의되지 않았다는 링크 오류USE_FULL_LL_DRIVER 미정의로 LL_GPIO_Init 등 .c 구현이 빠짐platformio.ini의 build_flags = -D USE_FULL_LL_DRIVER 확인

10. 확인 문제

문제 1. LL_mDelay(0)은 얼마나 기다리는가?

N < 0xFFFF FFFF이므로 N+1 = 1번 COUNTFLAG를 기다린다. 첫 COUNTFLAG는 호출 시점에 따라 0~1 ms 뒤에 오므로 대기는 0~1 ms이다.

문제 2. ODR = 0x0000 0060(PA6, PA5 = 1)에서 LL_GPIO_TogglePin(GPIOA, LL_GPIO_PIN_5)가 쓰는 BSRR 값은?

((0x60 << 16) & 0x0020 0000) | (~0x60 & 0x20) = 0x0020 0000 | 0 = 0x0020 0000이다. PA5만 리셋되고 PA6은 영향을 받지 않는다.

문제 3. LL_GPIO_AF_Remap_SWJ_NOJTAG() 전에 AFIO 클럭을 켜지 않으면 어떻게 되는가?

AFIO_MAPR 쓰기가 무시되어 JTAG 핀이 해제되지 않는다. 이 예제에서는 PB3/PA15를 쓰지 않으므로 겉보기 동작은 같지만, 그 핀을 GPIO로 쓰는 코드에서는 출력이 나오지 않는다.

문제 4. HSE 바이패스 × 8과 HSI/2 × 16은 모두 64 MHz이다. 차이는 무엇인가?

정확도와 의존성이다. HSE는 ST-LINK의 수정 발진 기반 8 MHz를 쓰므로 정확하지만 MCO 입력이 있어야 한다. HSI는 칩 내부 RC로 외부 의존이 없지만 온도·전압에 따른 오차가 크다(데이터시트의 HSI 정확도 표 참조).
