레지스터 계층의 Blink: RCC·CRL·BSRR과 SysTick을 직접 쓴다

HAL·LL·Arduino가 감추던 일을 모두 걷어 내면, LED 하나를 켜는 데 필요한 것은 클럭 허용 비트 하나, 핀 설정 4비트, 출력 레지스터 한 번의 쓰기, 그리고 1 ms 틱을 만드는 SysTick 세 레지스터이다. 이 교안은 RCC_APB2ENR.IOPAEN, GPIOA_CRL의 MODE5/CNF5, GPIOA_BSRR, STK_LOAD/VAL/CTRL의 값을 RM0008·PM0056으로 계산하고, 같은 Blink를 구현한 세 계층과 비교한다. 대상 폴더는 04_BlinkReg이다.

1. 문제: 프레임워크 없이 LED 하나를 켜려면 무엇을 알아야 하는가

앞의 세 예제에서는 프레임워크·생성 코드가 클럭을 켜고, 핀 모드를 쓰고, 1 ms 틱을 만들었다. 이 예제는 CubeMX도 HAL/LL도 없이 stm32f1xx.h의 레지스터 정의만으로 같은 일을 한다. 필요한 정보는 모두 레퍼런스 매뉴얼(RM0008)과 Cortex-M3 프로그래밍 매뉴얼(PM0056)에 있다. 학습 목표는 다음과 같다.

  • GPIO 사용 3단계(클럭 허용 → 모드 설정 → 출력)를 RCC_APB2ENR.IOPAEN, GPIOA_CRL의 MODE5/CNF5, GPIOA_BSRR로 직접 쓴다.
  • CRL의 read-modify-write(&= ~mask, |= value)와 BSRR의 쓰기 전용 원자적 동작의 차이를 설명한다.
  • SysTick_Config()가 STK_LOAD/STK_VAL/STK_CTRL에 쓰는 값을 클럭에서 계산한다.
  • 클럭을 설정하지 않은 framework = cmsis 프로젝트가 HSI 8 MHz로 동작하는 이유를 확인하고 HAL·LL·Arduino 계층과 비교한다.
이 예제의 동작

GPIOA->BSRR = GPIO_BSRR_BS5 → delay_ms(1000) → GPIOA->BSRR = GPIO_BSRR_BR5 → delay_ms(1000)을 반복한다. 켜짐 1 s + 꺼짐 1 s, 점멸 주기 2 s이다. 시간 기준은 사용자가 직접 작성한 SysTick_Handler가 1 ms마다 증가시키는 msTicks이다.

클럭: 아무것도 설정하지 않았을 때

이 예제에는 SystemClock_Config()가 없다. framework = cmsis가 제공하는 SystemInit()도 PLL을 켜지 않는다. 빌드 산출물(.pio/build/nucleo_f103rb/firmware.elf)에서 SystemInit은 즉시 반환(bx lr)하는 빈 함수이고, SystemCoreClock의 초기값은 0x007A 1200 = 8 000 000이다. 따라서 칩은 리셋 기본값인 HSI 8 MHz로 동작한다.

STK_LOAD = SystemCoreClock / 1000 − 1 = 8 000 000 / 1000 − 1 = 7 999 (0x1F3F) 1 틱 = (LOAD + 1) / HCLK = 8 000 / 8 MHz = 1 ms

CPU 속도는 HAL/LL 예제(64 MHz)의 1/8이지만, SysTick 주기를 같은 SystemCoreClock에서 계산하므로 1 ms는 정확하다. 소스 주석에도 HSI 8 MHz와 LOAD = 8000 − 1이 명시되어 있다. platformio.ini의 보드 정의가 넘기는 F_CPU=72000000L 매크로도 이 코드에서는 쓰이지 않는다.

4. 직접 만져 보기: CRL 편집기, BSRR 계산기, SysTick LOAD 계산

세 도구는 이 예제의 레지스터 연산을 그대로 계산한다. 값은 RM0008/PM0056의 비트 정의를 따른다.

  1. CRL 편집기: 핀 5, MODE = 01, CNF = 00에서 ① &= ~mask, ② |= value를 차례로 눌러 0x4444 4444 → 0x4404 4444 → 0x4414 4444 변화를 확인한다.
  2. IOPAEN 체크를 끄고 다시 적용하면 쓰기가 무시된다. 클럭 허용이 먼저여야 하는 이유이다.
  3. BSRR 계산기: 핀을 고르고 BS/BR을 눌러 쓰는 값과 ODR 결과를 본다. BS+BR 동시는 BS가 우선한다.
  4. SysTick 계산: 클럭을 64 MHz로 바꾸면 LOAD = 63 999가 된다. 주기를 늘려 24비트 한계(16 777 215)를 넘는 지점을 찾는다.

7. 코드 읽기

외부 부품은 필요 없다. 보드의 LD2만 사용하며 시리얼 출력은 없다. 소스는 src/main.c 한 파일이다.

src/main.c — SysTick과 delay_ms
#include "stm32f1xx.h"

// SysTick 기반 밀리초 카운터
volatile uint32_t msTicks = 0;

void SysTick_Handler(void)
{
    msTicks++;
}

void SysTick_Init(void)
{
    // SystemCoreClock = 8000000 (HSI 8MHz). framework = cmsis 의 SystemInit()은 PLL 을 켜지 않으므로
    // 칩은 리셋 기본값 HSI 8MHz 로 동작한다 -> SysTick->LOAD = 8000 - 1
    // 1ms마다 인터럽트 발생하도록 설정
    SysTick_Config(SystemCoreClock / 1000);
}

void delay_ms(uint32_t ms)
{
    uint32_t start = msTicks;
    while ((msTicks - start) < ms)
    {
        __NOP();
    }
}
  1. stm32f1xx.h는 레지스터 구조체와 비트 매크로만 정의한다. HAL/LL 헤더를 include하면 이 프레임워크에서는 찾지 못한다.
  2. msTicks는 ISR이 쓰고 main이 읽으므로 volatile이 필수이다.
  3. (msTicks − start) < ms는 부호 없는 뺄셈이라 msTicks가 0xFFFF FFFF에서 0으로 넘어가도 올바르다.
  4. 주석의 "기본 64MHz"와 달리 이 프로젝트의 SystemCoreClock은 8 000 000이다.
src/main.c — GPIO_LED_Init
void GPIO_LED_Init(void)
{
    // 1. GPIOA 클록 활성화 (APB2 버스)
    RCC->APB2ENR |= RCC_APB2ENR_IOPAEN;

    // 2. PA5를 출력 모드로 설정
    // CRL 레지스터는 PA0~PA7 제어 (각 핀당 4비트: CNF[1:0] + MODE[1:0])
    // PA5는 비트 위치 20~23에 해당
    GPIOA->CRL &= ~(0xF << (5 * 4)); // 기존 설정 초기화
    GPIOA->CRL |= (0x1 << (5 * 4));  // MODE = 01 (출력, 10MHz)
                                     // CNF  = 00 (범용 푸시풀 출력)
}
  1. 클럭 허용 → 모드 설정 순서이다. 순서를 바꾸면 CRL 쓰기가 무시된다.
  2. 0xF << 20 = 0x00F0 0000. 이 4비트만 지우므로 PA0~PA4, PA6, PA7 설정은 유지된다.
  3. =로 한 번에 쓰면 다른 7개 핀의 설정까지 바뀐다.
src/main.c — main
int main(void)
{
    SysTick_Init();
    GPIO_LED_Init();

    while (1)
    {
        // 3. PA5 HIGH (LED 켜기) - BSRR 사용
        GPIOA->BSRR = GPIO_BSRR_BS5;
        delay_ms(1000);

        // 4. PA5 LOW (LED 끄기)
        GPIOA->BSRR = GPIO_BSRR_BR5;
        delay_ms(1000);
    }
}
  1. BSRR는 쓰기 전용이고 0인 비트는 영향이 없으므로 |=가 아니라 =로 쓴다.
  2. 켜짐·꺼짐을 각각 1000 ms 기다리므로 주기는 2 s이다.
  3. 빌드 산출물에서 두 쓰기는 str 한 명령씩(0x20, 0x200000)으로 컴파일된다.
관찰 결과

LD2가 1초 켜지고 1초 꺼진다. 디버거에서 RCC->APB2ENR = 0x0000 0004, GPIOA->CRL = 0x4414 4444, SystemCoreClock = 8000000, SysTick->LOAD = 7999를 확인할 수 있다. BSRR를 읽으면 항상 0이고, 결과는 ODR5에서 본다. Flash 사용량은 약 0.7 KB로 네 예제 중 가장 작다.

8. 실험

실험 A. 클럭 허용 빼기

RCC->APB2ENR |= RCC_APB2ENR_IOPAEN;을 주석 처리하고 빌드·업로드한다. 디버거에서 CRL 두 줄 뒤에도 CRL이 0x4444 4444로 남는지, LED가 켜지지 않는지 확인한다.

실험 B. HAL과 같은 토글로

LL 방식처럼 uint32_t odr = GPIOA->ODR; GPIOA->BSRR = ((odr & GPIO_ODR_ODR5) << 16) | (~odr & GPIO_ODR_ODR5);로 토글하고 delay_ms(1000) 한 번만 두어 HAL/LL 예제와 같은 코드 구조를 만든다.

실험 C. COUNTFLAG 폴링 딜레이

SysTick->CTRL에서 TICKINT를 끄고 SysTick_CTRL_COUNTFLAG_Msk를 폴링하는 delay_ms()를 작성한다. SysTick_Handler에 중단점을 걸어 더 이상 호출되지 않는지 확인하고 03_BlinkLL의 LL_mDelay와 비교한다.

실험 D. volatile 제거

msTicks의 volatile을 지우고 build_type = release로 빌드한다. delay_ms가 끝나지 않으면 역어셈블에서 msTicks를 루프 밖에서 한 번만 읽는지 확인한다.

10. 확인 문제

문제 1. PA7을 50 MHz 오픈드레인 출력으로 만들려면 CRL에 어떤 연산을 해야 하는가?

PA7 필드는 비트 31:28이다. CNF7 = 01, MODE7 = 11 → 0111(0x7). GPIOA->CRL &= ~(0xF << 28); GPIOA->CRL |= (0x7 << 28); 리셋 상태에서 결과는 0x7414 4444(PA5 설정 유지)이다.

문제 2. PA5를 끄면서 동시에 PA6을 켜는 BSRR 값 하나는?

BR5 = 비트 21, BS6 = 비트 6 → 0x0020 0040이다. 한 번의 쓰기로 두 핀이 동시에 바뀐다.

문제 3. HCLK가 72 MHz일 때 1 ms SysTick의 LOAD 값과, 1 s 틱이 불가능한 이유는?

LOAD = 72 000 − 1 = 71 999이다. 1 s 틱은 LOAD = 71 999 999가 필요하지만 STK_LOAD는 24비트(최대 16 777 215)이므로 담을 수 없다. CLKSOURCE = 0(HCLK/8 = 9 MHz)으로 해도 8 999 999로 한계 안에 들어온다.

문제 4. 이 예제가 8 MHz로 동작하는데도 점멸 주기가 정확한 이유는?

SysTick_Config()의 인자를 고정 상수가 아니라 SystemCoreClock(= 8 000 000)에서 계산하므로 LOAD = 7 999가 되어 1 틱 = 1 ms이다. 클럭을 바꾸고 SystemCoreClockUpdate()를 호출하지 않으면 이 관계가 깨진다.
