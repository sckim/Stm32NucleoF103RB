버튼 입력 폴링: HAL_GPIO_ReadPin과 IDR 비트 13

출력은 MCU가 핀을 정하지만 입력은 바깥 세계가 정한다. 버튼이 언제 눌릴지 모르므로 프로그램은 핀 상태를 계속 확인하거나(폴링), 하드웨어가 알려 주기를 기다려야 한다(인터럽트). 이 예제설명은 첫 번째 방법인 폴링을 다룬다. 05_ReadPin은 main 루프에서 HAL_GPIO_ReadPin()으로 B1(PC13)을 읽어 LD2(PA5)를 켜고 끈다. 입력 모드의 CNF13/MODE13, GPIOC_IDR 비트 13, 접점 튐(바운싱), 폴링 주기와 응답 지연의 관계까지 레지스터 수준에서 해석한다.

1. 문제: 버튼 상태를 어떻게 읽는가

GPIO 핀을 입력으로 설정하면 핀 전압은 매 APB2 클럭마다 입력 데이터 레지스터 GPIOx_IDR에 샘플링된다. 소프트웨어는 이 레지스터를 읽기만 하면 된다. 문제는 언제 읽느냐이다. 폴링은 "계속 읽는다"는 가장 단순한 답이다. 학습 목표는 다음과 같다.

  • 입력 모드에서 GPIOx_CRH의 MODE13[1:0] = 00, CNF13[1:0] 조합(아날로그·플로팅·풀업/풀다운)을 구분한다.
  • HAL_GPIO_ReadPin()이 GPIOC_IDR 비트 13을 마스크로 검사하는 함수임을 설명한다.
  • B1이 Active-Low(눌림 = 0)인 이유를 보드 회로의 외부 풀업으로 설명한다.
  • 폴링 주기가 응답 지연과 짧은 입력 누락을 결정하는 원리, 바운싱이 레벨 기반 폴링에서 어떻게 나타나는지 이해한다.
이 예제의 동작

main의 while(1)이 쉬지 않고 PC13을 읽는다. 읽은 값이 GPIO_PIN_SET(안 눌림)이면 LD2를 켜고, GPIO_PIN_RESET(눌림)이면 끈다. 즉 버튼을 누르고 있는 동안 LED가 꺼진다. 인터럽트는 쓰지 않으며 동작 중인 ISR은 HAL 틱용 SysTick_Handler뿐이다. 디바운스 처리는 코드에 없다.

2. 입력 모드와 바운싱

F1 계열은 핀 하나를 4비트(CNFy[1:0] + MODEy[1:0])로 설정한다. 핀 0~7은 GPIOx_CRL, 핀 8~15는 GPIOx_CRH에 있으므로 PC13은 GPIOC_CRH의 비트 [23:20]이다 (시작 비트 = (13−8)×4 = 20). MODE = 00이면 입력이고, 이때 CNF가 입력 종류를 고른다.

기계식 스위치는 접점이 닫히거나 열릴 때 수십 µs~수 ms 동안 여러 번 붙었다 떨어진다. 이것이 채터링(바운싱)이다. 폴링 코드는 샘플 시점의 레벨만 보므로, 샘플이 튀는 구간에 걸리면 LED가 잠깐 깜빡였다가 결국 최종 레벨을 따라간다.

그림 1. 누르는 순간 접점이 튀면 PC13이 여러 번 High/Low를 오간다. 폴링은 점선 시점의 레벨만 보므로, 샘플이 튀는 구간에 걸리면 LD2가 잠깐 다시 켜졌다(190) 꺼진다. 최종 상태는 실제 버튼 상태와 같다.

4. 직접 만져 보기

아래 시뮬레이터는 버튼을 한 번 눌렀다 떼는 동안의 PC13 파형(바운싱 포함)과, 일정 주기로 IDR을 샘플링하는 main 루프를 모델링한다. 각 샘플에서 IDR 비트 13과 BSRR에 쓰는 값, LD2 상태를 보여 준다.

  1. 기본값(루프만, 바운싱 1.0 ms)에서 끝까지 실행을 누르고 LD2 전환 횟수를 본다. 2회보다 많으면 바운싱이 LED에 그대로 보인 것이다.
  2. 샘플 1개 진행과 다음 변화까지로 IDR 값이 0x00002000 ↔ 0x00000000으로 바뀌는 순간의 BSRR 값을 확인한다.
  3. 폴링 주기를 10 ms, 누름 시간을 4 ms로 바꾸고 새 시나리오를 여러 번 만든다. 눌림 감지가 "놓침"이 되는 경우를 찾는다.
  4. 바운싱을 0으로 놓으면 LD2 전환이 정확히 2회(꺼짐·켜짐)가 되는지 확인한다.

시뮬레이터 모델: 0~40 ms 구간에서 t = 5 ms에 누르고 지정 시간 뒤에 뗀다. 바운싱은 지정 구간 안에 50~400 µs 간격의 무작위 에지로 만든다. IDR은 비트 13만 모델링하고 다른 비트는 0으로 둔다. "루프만"의 1 µs는 HAL 함수 호출 두 번이 들어간 루프 시간을 가정한 값이며 실제 값은 실험 A로 측정한다. 첫 샘플 이전의 LD2는 MX_GPIO_Init이 쓴 RESET(OFF) 상태이다.

6. 초기화부터 LED 출력까지의 경로

  1. 1
    HAL_Init()소프트웨어Flash 프리페치, NVIC 우선순위 그룹 4, SysTick 1 ms 틱을 설정하고 HAL_MspInit에서 AFIO·PWR 클럭과 JTAG 해제(SWD 유지)를 수행한다.
  2. 2
    SystemClock_Config()소프트웨어HSI/2 × 16 = 64 MHz. APB2(GPIO 버스)도 64 MHz이다.
  3. 3
    MX_GPIO_Init()소프트웨어GPIOA~D 클럭 허용 → PA5 = RESET → PC13 입력(플로팅) → PA5 푸시풀 출력.
  4. 4
    입력 샘플링하드웨어PC13 레벨이 슈미트 트리거를 거쳐 APB2 클럭마다 GPIOC_IDR 비트 13에 래치된다. CPU와 무관하게 계속 일어난다.
  5. 5
    HAL_GPIO_ReadPin()소프트웨어main 루프가 IDR을 읽어 비트 13을 검사한다. 이 시점의 레벨만 보며, 직전 루프 이후의 변화는 알지 못한다.
  6. 6
    HAL_GPIO_WritePin()소프트웨어결과에 따라 GPIOA_BSRR에 BS5 또는 BR5를 쓴다. 매 루프마다 같은 값을 다시 써도 출력은 변하지 않는다.
  7. 7
    PA5 출력 드라이버하드웨어ODR5가 바뀌면 푸시풀 드라이버가 LD2를 구동한다. 다시 5단계로 돌아간다.

7. 코드 읽기

외부 부품은 필요 없다. B1(파란 버튼)을 누르고 있는 동안 LD2(초록 LED)가 꺼진다. USART2도 초기화되지만 출력은 없다.

Core/Src/main.c — main 루프 (USER CODE BEGIN 3)
  MX_GPIO_Init();
  MX_USART2_UART_Init();

  while (1) {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    if (HAL_GPIO_ReadPin(B1_GPIO_Port, B1_Pin) == GPIO_PIN_SET) {
      HAL_GPIO_WritePin(LD2_GPIO_Port, LD2_Pin, GPIO_PIN_SET);
    } else {
      HAL_GPIO_WritePin(LD2_GPIO_Port, LD2_Pin, GPIO_PIN_RESET);
    }
  }
  /* USER CODE END 3 */
  1. B1_GPIO_Port/B1_Pin은 main.h에서 GPIOC/GPIO_PIN_13(0x2000)으로 정의된다.
  2. SET(안 눌림)이면 LED를 켠다. Active-Low이므로 "누르면 꺼짐"이 된다.
  3. 지연이 없으므로 루프는 가능한 한 빨리 돈다. CPU는 이 확인 작업에 계속 쓰인다.
  4. 디바운스가 없다. 바운싱 동안 LED가 수 ms 깜빡일 수 있으나 눈으로는 거의 보이지 않는다.
Core/Src/main.c — MX_GPIO_Init (CubeMX 생성, 발췌)
  /* GPIO Ports Clock Enable */
  __HAL_RCC_GPIOC_CLK_ENABLE();
  __HAL_RCC_GPIOD_CLK_ENABLE();
  __HAL_RCC_GPIOA_CLK_ENABLE();
  __HAL_RCC_GPIOB_CLK_ENABLE();

  /*Configure GPIO pin Output Level */
  HAL_GPIO_WritePin(LD2_GPIO_Port, LD2_Pin, GPIO_PIN_RESET);

  /*Configure GPIO pin : B1_Pin */
  GPIO_InitStruct.Pin = B1_Pin;
  GPIO_InitStruct.Mode = GPIO_MODE_INPUT;
  GPIO_InitStruct.Pull = GPIO_NOPULL;
  HAL_GPIO_Init(B1_GPIO_Port, &GPIO_InitStruct);

  /*Configure GPIO pin : LD2_Pin */
  GPIO_InitStruct.Pin = LD2_Pin;
  GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;
  GPIO_InitStruct.Pull = GPIO_NOPULL;
  GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
  HAL_GPIO_Init(LD2_GPIO_Port, &GPIO_InitStruct);
  1. 클럭 허용이 먼저이다. 클럭이 꺼진 포트의 레지스터에는 쓰기가 반영되지 않는다.
  2. 출력 레벨(RESET)을 먼저 정하고 출력 모드로 바꾸므로 전환 순간 LED가 깜빡이지 않는다.
  3. GPIO_MODE_INPUT + GPIO_NOPULL → CNF13 = 01, MODE13 = 00. 풀업은 보드의 외부 저항이 담당한다.
  4. 06_ExtInt는 이 자리에서 Mode만 GPIO_MODE_IT_FALLING으로 바뀐다.
Core/Src/main.c — 파일 머리 주석 (하드웨어 대응)
 * 하드웨어 대응 (RM0008)
 *   HAL_GPIO_ReadPin  : GPIOC_IDR 비트 13 읽기 (B1 은 Active-Low: 눌리면 0)
 *   HAL_GPIO_WritePin : GPIOA_BSRR 로 PA5 설정/해제
 *   MX_GPIO_Init      : PC13 입력, PA5 출력 (GPIOC_CRH, GPIOA_CRL)
 *

  1. 주석이 HAL 함수와 레지스터를 직접 연결한다. 07_ReadPinReg에서 이 대응을 코드로 확인한다.
  2. SysTick_Handler(stm32f1xx_it.c)는 HAL_IncTick()만 호출하며 버튼 처리와 무관하다.
관찰 결과

전원 직후 LD2가 켜진다. B1을 누르고 있는 동안 꺼지고, 떼면 다시 켜진다. 버튼을 아주 빠르게 톡 쳐도 반응한다. 루프 주기가 µs 단위로 짧기 때문이다. 루프에 HAL_Delay(200)을 넣으면 짧은 누름은 놓치기 시작한다 (실험 B).

8. 실험

실험 A. 루프 1회 시간 측정

루프 끝에 HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_6)처럼 남는 핀 하나를 토글하는 줄을 임시로 넣고(PA6을 출력으로 추가 설정), AD2나 오실로스코프로 주기를 잰다. 반주기가 폴링 주기이며, 이것이 최악 응답 지연이다.

실험 B. 루프에 지연 넣기

루프 끝에 HAL_Delay(200)을 넣고 버튼을 짧게 톡 쳐 본다. 반응하지 않는 경우가 생기는지, 누른 뒤 LED가 꺼질 때까지 지연이 느껴지는지 확인하고 시뮬레이터(폴링 20 ms)와 비교한다.

실험 C. 바운싱 관찰

AD2 채널 1을 PC13(CN7-23 또는 모르포 헤더)에, 채널 2를 PA5(D13)에 연결하고 PC13 하강 에지로 트리거한다. 누르는 순간의 튐과 LD2 출력의 깜빡임을 함께 본다. 보드의 100 nF 커패시터가 에지를 얼마나 둔하게 만드는지도 관찰한다.

실험 D. 논리 뒤집기

조건을 == GPIO_PIN_RESET으로 바꾸어 "누르면 켜짐"으로 만든다. 또 Pull을 GPIO_PULLDOWN으로 바꾸면 무슨 일이 생기는지 예측한다 (외부 4.7 kΩ 풀업과 내부 약 40 kΩ 풀다운의 분압).

10. 확인 문제

문제 1. PC13을 풀업 입력으로 만들려면 GPIOC_CRH 비트 [23:20]와 ODR에 무엇을 써야 하는가?

CNF13 = 10, MODE13 = 00이므로 필드 값은 0x8이고, ODR13 = 1로 풀업을 선택한다. 07_ReadPinReg가 정확히 이렇게 한다.

문제 2. GPIOC_IDR = 0x0000 0000을 읽었다. HAL_GPIO_ReadPin(GPIOC, GPIO_PIN_13)의 반환값과 LD2 상태는?

비트 13이 0이므로 GPIO_PIN_RESET이고 버튼이 눌린 상태이다. else 분기가 BSRR = 0x0020 0000(BR5)을 써서 LD2가 꺼진다.

문제 3. 루프 안에 50 ms 걸리는 작업이 있다. 30 ms 동안 눌린 입력을 항상 잡을 수 있는가?

아니다. 샘플 간격(약 50 ms)이 누름 시간(30 ms)보다 길어 두 샘플 사이에 누름이 끝날 수 있다. 확실히 잡으려면 샘플 간격이 최소 누름 시간보다 짧아야 하며, 그렇지 않으면 인터럽트를 쓴다.

문제 4. 이 예제에서 바운싱이 LED 최종 상태를 틀리게 만들지 않는 이유는?

폴링 코드가 에지가 아니라 레벨을 보고 LED를 레벨에 맞추기 때문이다. 튐이 끝나면 다음 샘플이 안정된 레벨을 읽어 LED가 바로잡힌다. 반면 06_ExtInt처럼 에지마다 토글하면 튐 횟수만큼 토글되어 최종 상태가 틀어질 수 있다.
