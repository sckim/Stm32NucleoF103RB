버튼 외부 인터럽트: EXTI13 → EXTI15_10_IRQHandler → 콜백

폴링은 CPU가 버튼을 계속 지켜봐야 한다. 외부 인터럽트(EXTI)는 핀의 에지를 하드웨어가 감시하고, 에지가 오면 CPU를 불러낸다. 이 교안은 B1(PC13)을 GPIO_MODE_IT_FALLING으로 설정해 눌릴 때마다 LD2를 토글하는 06_ExtInt 예제를 해석한다. AFIO_EXTICR4의 핀 선택, EXTI_IMR/FTSR/RTSR/PR, NVIC EXTI15_10_IRQn, 진짜 ISR과 HAL 콜백의 구분, 그리고 디바운스가 없을 때 바운싱이 다중 인터럽트로 이어지는 현상을 다룬다.

1. 문제: 폴링은 CPU를 묶어 둔다

05_ReadPin의 루프는 버튼 확인 외에는 아무것도 하지 못한다. 루프에 다른 작업을 넣으면 그만큼 응답이 늦어지고 짧은 누름을 놓친다. EXTI를 쓰면 에지 검출은 하드웨어가 하고, CPU는 에지가 왔을 때만 짧은 처리를 한다. 학습 목표는 다음과 같다.

  • PC13 → AFIO_EXTICR4.EXTI13 → EXTI 선 13 → NVIC EXTI15_10_IRQn(IRQ 40)의 연결을 설명한다.
  • EXTI_IMR(허용), EXTI_FTSR/RTSR(에지 선택), EXTI_PR(펜딩, 1을 써서 클리어)의 역할을 구분한다.
  • 벡터 테이블이 호출하는 진짜 ISR(EXTI15_10_IRQHandler), HAL 분배 함수, 사용자 콜백(HAL_GPIO_EXTI_Callback)의 3단 구조를 이해한다.
  • 디바운스가 없는 에지 토글이 바운싱 때문에 다중 인터럽트를 일으키는 원리를 폴링(05·07)과 비교한다.
이 예제의 동작

main의 while(1)은 비어 있다. B1을 누르는 순간(High→Low 하강 에지) EXTI13이 인터럽트를 걸고, 콜백이 HAL_GPIO_TogglePin으로 LD2를 반전한다. 떼는 순간(상승 에지)은 무시된다. 디바운스 처리는 코드에 없다.

2. EXTI 구조와 바운싱

EXTI는 선(line) 0~15가 GPIO용이며, 선 번호는 핀 번호와 같다. 선 13에는 PA13, PB13, PC13 … 중 하나만 연결할 수 있고, 어느 포트를 쓸지는 AFIO_EXTICR4의 EXTI13[3:0]이 정한다. 선 10~15는 NVIC 벡터 하나(EXTI15_10_IRQn)를 공유한다.

그림 1. 보라 상자는 하드웨어, 파란 상자는 소프트웨어이다. 에지가 PR13을 세우면 NVIC가 벡터 테이블의 ISR로 분기하고, HAL이 PR13을 지운 뒤 사용자 콜백을 부른다.

EXTI_EMRMR131 = 이벤트(WFE 깨우기) 허용. 이 예제는 0
EXTI_RTSRTR131 = 상승 에지 검출
EXTI_FTSRTR131 = 하강 에지 검출

디바운스가 없으므로, 누르는 순간 접점이 튀면 하강 에지가 여러 번 생기고 그때마다 인터럽트가 걸려 LED가 여러 번 토글된다. 토글 횟수가 짝수이면 누르기 전과 같은 상태로 보여 "버튼이 안 먹는다"고 느끼게 된다. 떼는 순간의 튐에도 하강 에지가 섞이므로 뗄 때 토글되는 경우도 있다.

그림 2. 보라 세로선은 FTSR13이 검출한 하강 에지이다. 누를 때 튐으로 2회, 뗄 때 튐으로 1회가 더 생겼다. 폴링(05·07)은 레벨을 따라가므로 이런 누적 오류가 없다.

4. 직접 만져 보기

시뮬레이터는 버튼을 한 번 눌렀다 뗄 때의 PC13 파형(바운싱 포함)에서 각 에지가 EXTI → PR → NVIC → ISR → 콜백을 거치는 과정을 한 단계씩 보여 준다.

  1. 에지 설정 하강(코드), 바운싱 1.0 ms에서 단계 진행을 다섯 번 눌러 첫 에지가 콜백까지 가는 과정을 확인한다. PR13이 1 → 0으로 바뀌는 단계에 주목한다.
  2. 남은 에지 모두를 눌러 인터럽트 횟수와 LD2 최종 상태를 본다. 의도한 누름은 1회이다.
  3. 바운싱을 0으로 하면 인터럽트가 정확히 1회가 되는지 확인한다.
  4. 에지 설정을 양쪽으로 바꾸면 바운싱이 없어도 누름·뗌에서 2회 토글되어 LED가 원래대로 돌아오는 것을 본다.

시뮬레이터 모델: 0~40 ms 구간, t = 5 ms에 누르고 지정 시간 뒤에 뗀다. 바운싱 에지 간격은 50~400 µs이며, ISR 전체 실행 시간(수 µs 이하)이 에지 간격보다 짧다고 보아 처리 중 다음 에지가 겹치는 경우(PR13 합쳐짐, 테일 체이닝)는 다루지 않는다. LD2 초깃값은 MX_GPIO_Init의 RESET(OFF)이다. 보드의 RC 필터가 실제로 줄여 주는 튐은 반영하지 않는다.

6. 인터럽트 경로: 진짜 ISR과 콜백

  1. 1
    PC13 하강 에지하드웨어B1을 누르면 PC13이 High → Low. AFIO_EXTICR4.EXTI13 = 0010이므로 이 신호가 EXTI 선 13으로 간다.
  2. 2
    에지 검출 → EXTI_PR.PR13 = 1하드웨어FTSR13 = 1이라 하강 에지를 검출한다. IMR13 = 1이므로 NVIC에 요청한다.
  3. 3
    NVIC EXTI15_10_IRQn (40)하드웨어펜딩 → 우선순위 판정 → 레지스터 8개 스택킹 → 벡터 테이블 오프셋 0xE0(0x40 + 40×4)의 주소로 분기한다.
  4. 4
    EXTI15_10_IRQHandler소프트웨어Core/Src/stm32f1xx_it.c. 벡터 테이블이 직접 호출하는 진짜 ISR이다. 선 10~15 공용이므로 핀 번호(B1_Pin)를 넘겨 HAL에 맡긴다.
  5. 5
    HAL_GPIO_EXTI_IRQHandler(B1_Pin)소프트웨어HAL 라이브러리. EXTI->PR & 0x2000을 확인하고, 콜백보다 먼저 EXTI->PR = 0x2000으로 클리어한 뒤 콜백을 부른다 (빌드된 firmware.elf 디스어셈블리로 확인).
  6. 6
    HAL_GPIO_EXTI_Callback(0x2000)소프트웨어main.c의 사용자 코드. HAL의 weak 함수를 재정의한 것이다. ISR 문맥에서 실행되므로 HAL_Delay()·printf 같은 긴 처리를 넣지 않는다.
  7. 7
    예외 복귀하드웨어스택에서 레지스터를 복원하고 main의 빈 루프로 돌아간다. 그 사이 PR13이 다시 1이 되었으면(튐) 곧바로 다시 진입한다.

7. 코드 읽기

외부 부품은 필요 없다. B1을 누를 때마다 LD2가 토글된다. 간혹 한 번 눌렀는데 LED가 그대로이거나 뗄 때 바뀌면 바운싱이다.

Core/Src/main.c — MX_GPIO_Init (CubeMX 생성, 발췌)
  /*Configure GPIO pin : B1_Pin */
  GPIO_InitStruct.Pin = B1_Pin;
  GPIO_InitStruct.Mode = GPIO_MODE_IT_FALLING;
  GPIO_InitStruct.Pull = GPIO_NOPULL;
  HAL_GPIO_Init(B1_GPIO_Port, &GPIO_InitStruct);

  /*Configure GPIO pin : LD2_Pin */
  GPIO_InitStruct.Pin = LD2_Pin;
  GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;
  GPIO_InitStruct.Pull = GPIO_NOPULL;
  GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
  HAL_GPIO_Init(LD2_GPIO_Port, &GPIO_InitStruct);

  /* EXTI interrupt init*/
  HAL_NVIC_SetPriority(EXTI15_10_IRQn, 0, 0);
  HAL_NVIC_EnableIRQ(EXTI15_10_IRQn);
  1. 05와 다른 곳은 Mode 한 줄뿐이다. IT_FALLING이 핀은 입력으로 두고 AFIO·EXTI(IMR, FTSR)를 설정한다.
  2. NVIC 설정은 CubeMX의 NVIC 탭(NVIC.EXTI15_10_IRQn=true, 우선순위 0)에서 생성된다.
  3. EXTI를 먼저 설정하고 NVIC를 나중에 허용하므로 설정 도중 인터럽트가 걸리지 않는다.

Core/Src/main.c — 사용자 콜백 (USER CODE BEGIN 4)
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
  // 1. 여러 인터럽트 핀 중 현재 발생한 인터럽트가 버튼 핀(B1_Pin)인지 확인
  if (GPIO_Pin == B1_Pin)
  {
    /* * [생체신호처리/임베디드 핵심 팁]
     * 인터럽트 서비스 루틴(ISR) 내부에서는 HAL_Delay()나 무거운 연산을 절대 사용하면 안 됨.
     * 여기서는 플래그 변수만 토글하거나, 아래와 같이 아주 가벼운 하드웨어 제어만 수행하는 것이 정석임.
     */
    // 버튼이 눌릴 때마다 LD2 LED 상태를 반전
    HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
  }
}
  1. HAL의 __weak 콜백을 재정의한다. 이름·인자가 다르면 HAL의 빈 함수가 불려 아무 일도 일어나지 않는다.
  2. GPIO_Pin은 핀 마스크(0x2000)이지 핀 번호(13)가 아니다.
  3. 토글은 ODR을 읽고 BSRR에 반전값을 쓰는 짧은 작업이라 ISR에 둘 만하다. 디바운스가 없어 튐마다 토글된다.

  2. 여기에 __WFI();를 넣으면 다음 인터럽트(SysTick 1 ms 또는 EXTI)까지 CPU 코어가 잠든다.
관찰 결과

B1을 누를 때마다 LD2가 켜짐 ↔ 꺼짐으로 바뀐다. 떼는 것으로는 바뀌지 않는다. 여러 번 시험하면 가끔 반응이 없거나 뗄 때 바뀌는 경우가 생길 수 있는데, 이것이 디바운스가 없는 에지 인터럽트의 바운싱 현상이다. 보드의 100 nF 커패시터 덕분에 빈도는 낮을 수 있다.

8. 실험

실험 A. 인터럽트 횟수 세기

전역 volatile uint32_t gCnt를 만들고 콜백에서 증가시킨다. 디버거 Live Watch로 보며 버튼을 20번 눌러 gCnt가 20보다 큰지 기록한다. 시뮬레이터의 바운싱 설정과 비교한다.

실험 B. 에지 바꾸기

CubeMX에서 B1 모드를 External Interrupt Mode with Rising/Falling edge trigger detection으로 바꾸면 GPIO_MODE_IT_RISING_FALLING이 된다. 누를 때와 뗄 때 모두 토글되는 것을 확인하고, 콜백에서 HAL_GPIO_ReadPin으로 현재 레벨을 읽어 누름만 처리하도록 고친다.

실험 C. 간단한 디바운스

콜백에서 HAL_GetTick()을 읽어 직전 처리 후 50 ms가 지나지 않았으면 무시한다. 단, 이 예제는 SysTick과 EXTI가 같은 우선순위 0이라 콜백 실행 중에는 틱이 증가하지 않는다는 점을 고려한다 (값 읽기만 하므로 문제는 없다).

실험 D. 지연 응답 비교

AD2 채널 1을 PC13, 채널 2를 PA5에 연결하고 PC13 하강 에지로 트리거한다. 에지에서 PA5 변화까지의 지연을 측정해 05_ReadPin(폴링)과 비교한다. 05의 main 루프에 HAL_Delay(100)을 넣은 경우와도 비교한다.

10. 확인 문제

문제 1. PB13과 PC13을 동시에 EXTI 인터럽트로 쓸 수 있는가?

없다. 둘 다 EXTI 선 13을 쓰며 AFIO_EXTICR4.EXTI13은 포트 하나만 고를 수 있다. 다른 선 번호의 핀(예: PB12)을 써야 한다.

문제 2. PA8을 하강 에지 인터럽트로 쓰려면 어느 NVIC 벡터와 EXTICR 필드를 쓰는가?

선 8은 EXTI9_5_IRQn(IRQ 23) 벡터를 공유하며 핸들러는 EXTI9_5_IRQHandler이다. 포트 선택은 AFIO_EXTICR3.EXTI8[3:0] = 0000(PA)이고, EXTI_IMR.MR8 = 1, EXTI_FTSR.TR8 = 1이다.

문제 3. HAL_GPIO_EXTI_IRQHandler가 콜백보다 먼저 PR을 지우는 이유는?

콜백 실행 중에 새 에지가 오면 PR13이 다시 1이 되어 다음 인터럽트로 이어지게 하기 위해서이다. 콜백 뒤에 지우면 그 사이의 에지가 함께 지워져 사라진다. 대신 바운싱 에지도 빠짐없이 인터럽트가 된다.

문제 4. 하강 에지만 검출하는데 버튼을 뗄 때 LED가 토글되는 경우가 있는 이유는?

떼는 순간 접점이 튀면 PC13이 Low → High → Low → High처럼 움직여 하강 에지가 섞인다. FTSR13은 그 하강 에지를 검출하므로 인터럽트가 걸린다. 레벨을 보는 폴링(05·07)에서는 이 문제가 최종 상태에 남지 않는다.
