레지스터로 버튼 읽기: CRH 입력 설정과 GPIOC->IDR 폴링

05_ReadPin의 HAL_GPIO_ReadPin()은 결국 레지스터 하나를 읽는 일이다. 이 교안은 같은 동작을 HAL 없이 CMSIS 헤더만으로 구현한 07_ReadPinReg를 해석한다. RCC_APB2ENR로 클럭을 열고, GPIOC_CRH의 CNF13/MODE13과 ODR13으로 풀업 입력을 만들고, main 루프에서 GPIOC->IDR & (1<<13)을 검사해 BSRR로 LD2를 제어한다. 컴파일된 루프의 명령 수로 폴링 주기를 추정하고, 바운싱과 폴링 주기의 관계를 시뮬레이터로 확인한다.

1. 문제: HAL_GPIO_ReadPin 밑에는 무엇이 있는가

HAL은 편리하지만 무엇을 하는지 감춘다. 입력 하나를 읽는 데 필요한 것은 클럭 허용, 핀 모드 4비트, IDR 비트 하나뿐이다. 이를 직접 써 보면 HAL 코드와 데이터시트·레퍼런스 매뉴얼을 연결해 읽을 수 있다. 학습 목표는 다음과 같다.

  • PC13이 CRH에 있고 필드 시작 비트가 (13−8)×4 = 20임을 계산한다.
  • reg &= ~mask; reg |= value; 패턴으로 다른 핀 설정을 건드리지 않고 4비트 필드만 바꾼다.
  • 입력 모드에서 ODR 비트가 풀업/풀다운 선택에 쓰인다는 점을 설명한다.
  • IDR 비트 검사 루프의 주기를 디스어셈블리로 추정하고, 폴링 주기·바운싱·응답 지연의 관계를 05·06과 같은 기준으로 비교한다.
이 예제의 동작

버튼이 안 눌리면(PC13 = High) LD2 ON, 눌리면 OFF이다. 05_ReadPin과 같은 논리이다. SysTick_Init()이 1 ms 틱을 켜지만 루프는 지연을 쓰지 않는다. 인터럽트로 버튼을 처리하지 않으며 디바운스 처리도 없다.

4. 직접 만져 보기

시뮬레이터는 버튼을 한 번 눌렀다 떼는 동안의 PC13 파형과 일정 주기의 GPIOC->IDR 샘플링을 모델링한다. 각 샘플에서 IDR & 0x2000 결과와 BSRR에 쓰는 값을 보여 준다.

  1. 기본값(루프만 ≈ 2 µs)에서 끝까지 실행을 눌러 LD2 전환 횟수와 눌림 감지 지연을 본다. 지연은 샘플 간격보다 작다.
  2. 다음 변화까지를 반복해 IDR이 0x00002000 → 0x00000000으로 바뀌는 샘플마다 BSRR이 BS5(0x00000020) ↔ BR5(0x00200000)로 바뀌는 것을 확인한다.
  3. 폴링 주기를 1 ms, 5 ms, 20 ms로 늘리며 바운싱이 LED에 보이는 정도와 감지 지연을 비교한다.
  4. 폴링 20 ms, 누름 3 ms로 놓고 새 시나리오를 여러 번 만들어 "놓침"이 나오는 비율을 본다.

7. 코드 읽기

외부 부품은 필요 없다. 빌드는 PlatformIO(framework = cmsis, build_type = debug)이며 소스는 src/main.c 하나이다. 폴더에는 Proteus 시뮬레이션 파일 STM32F103R.pdsprj도 있다.

src/main.c — GPIO_LED_Init
void GPIO_LED_Init(void) {
  // 1. GPIOA, GPIOC 클록 활성화 (APB2 버스, RCC_APB2ENR의 IOPAEN·IOPCEN 비트)
  RCC->APB2ENR |= (RCC_APB2ENR_IOPAEN|RCC_APB2ENR_IOPCEN);

  // 2. PA5를 출력 모드로 설정
  GPIOA->CRL &= ~(0xFU << (5 * 4)); // 기존 설정 초기화
  GPIOA->CRL |= (0x1U << (5 * 4));  // MODE = 01 (출력, 10MHz)
                                   // CNF  = 00 (범용 푸시풀 출력)

  // 3. PC13(B1 버튼)을 풀업 입력으로 설정
  // CRH 레지스터는 PC8~PC15 제어, PC13은 비트 위치 20~23에 해당
  GPIOC->CRH &= ~(0xFU << ((13-8) * 4)); // 기존 설정 초기화
  GPIOC->CRH |= (0x8U << ((13-8) * 4));  // MODE = 00 (입력 모드)
                                         // CNF  = 10 (풀업/풀다운 입력)
  GPIOC->ODR |= (0x1U << 13);       // 입력 모드에서 ODR13 = 1 → 풀업 선택 (0이면 풀다운)
}
  1. 클럭을 먼저 연다. 순서가 바뀌면 CRL/CRH 쓰기가 무시된다.
  2. &= ~(0xF << n)로 4비트를 0으로 만들고 |=로 새 값을 넣는다. 지우지 않고 OR만 하면 리셋 값 0x4와 섞여 0xC(예약)가 된다.
  3. PC13은 CRH의 다섯 번째 필드이므로 시프트량은 (13−8)×4 = 20이다.
  4. ODR13 = 1이 풀업을 고른다. 입력 모드에서 ODR은 출력이 아니라 풀 방향 선택에 쓰인다.
src/main.c — main 루프
int main(void) {
  SysTick_Init();
  GPIO_LED_Init();

  while (1) {
    // 4. PC13 입력 상태를 폴링하여 PA5(LED) 제어 - IDR 읽기, BSRR 쓰기
    //    B1은 Active-Low: 버튼을 누르지 않으면 HIGH, 누르면 LOW
    if (GPIOC->IDR & (0x1U << 13)) // PC13이 HIGH인지 확인 (버튼 안 눌림)
    {
      GPIOA->BSRR = GPIO_BSRR_BS5; // BSRR BS5: PA5 = HIGH → LED ON
    } else {
      GPIOA->BSRR = GPIO_BSRR_BR5; // BSRR BR5: PA5 = LOW → LED OFF (버튼 눌림)
    }
  }
}
  1. GPIOC는 CMSIS 헤더에서 volatile 멤버를 가진 구조체 포인터이므로 매 반복마다 실제로 IDR을 읽는다.
  2. BSRR은 쓰기 전용 원자적 설정/해제 레지스터이다. ODR |=와 달리 읽기-수정-쓰기가 없다.
  3. 디바운스가 없다. 튐 구간에서 LED가 잠깐 바뀐다.

8. 실험

실험 A. 폴링 주기 측정

PA6을 같은 방식으로 출력(CRL [27:24] = 0x1)으로 만들고 루프 끝에서 GPIOA->ODR ^= (1<<6)로 토글한다. AD2로 주기를 재고 추정값(약 2 µs)과 비교한다. 토글 명령이 늘어난 만큼 주기도 길어지는 것에 유의한다.

실험 B. 풀업 끄기

ODR13 줄을 지우면 풀다운이 된다. 외부 4.7 kΩ 풀업과 내부 약 40 kΩ 풀다운의 분압은 약 3.0 V로 여전히 High이므로 동작이 유지되는지 확인한다. 이어서 CRH 값을 0x4(플로팅)로 바꾸어 05와 같은 설정으로 만든다.

실험 C. 필드 지우기 생략

GPIOC->CRH &= ~... 줄을 주석 처리하고 디버거로 CRH를 읽는다. 0x4 | 0x8 = 0xC(예약)가 되는지 확인한다. 실제 입력 동작이 어떻게 되는지 관찰한다.

실험 D. 바운싱 세기

루프에서 IDR13이 1→0으로 바뀔 때마다 전역 카운터를 증가시키고 디버거 Live Watch로 본다. 한 번 누를 때 카운터가 몇씩 오르는지 기록한다. 2 µs 폴링은 튐을 거의 모두 셀 수 있다.

다른 핀 설정이 망가졌다CRH = 0x8 << 20처럼 대입하여 다른 필드를 0(아날로그)으로 덮었다반드시 &= ~mask; |= value 패턴을 쓴다
외부 버튼(풀업 없음)이 불안정하다ODR13 = 0으로 풀다운이 선택되었다Active-Low 버튼은 ODR = 1(풀업)
누를 때 LED가 잠깐 깜빡인다바운싱. 디바운스 없음msTicks로 20 ms 이상 안정될 때만 반영하는 디바운스를 추가한다
타이밍이 예상보다 느리다클럭이 72 MHz가 아니라 HSI 8 MHz이다SystemCoreClock 값 확인, 필요하면 08_Clock_System/04_Clock_Config_Reg_c처럼 PLL 설정

10. 확인 문제

문제 1. PB10을 풀업 입력으로 만들려면 어느 레지스터의 몇 번 비트에 무엇을 써야 하는가?

GPIOB_CRH [11:8]((10−8)×4 = 8)에 0x8을 쓰고 GPIOB_ODR bit 10 = 1로 한다. 그 전에 RCC_APB2ENR.IOPBEN(bit 3)을 켠다.

문제 2. GPIOC->IDR = 0x0000 6000을 읽었다. 이 예제의 if 결과와 BSRR 값은?

0x6000 & 0x2000 = 0x2000 ≠ 0이므로 PC13 = High(안 눌림)이다. BSRR = 0x0000 0020(BS5)이 쓰여 LD2가 켜진다. bit 14의 값은 결과에 영향을 주지 않는다.

문제 3. 같은 동작인데 05는 CRH 필드가 0x4, 07은 0x8이다. 둘 다 버튼이 동작하는 이유는?

보드에 외부 풀업이 있어 플로팅 입력(0x4)으로도 안 눌림 = High가 보장된다. 07의 풀업 입력(0x8 + ODR13 = 1)은 내부 풀업을 추가로 켠 것이다.

문제 4. 루프 주기 약 2 µs인 이 예제와 06_ExtInt 중 바운싱으로 LED 최종 상태가 틀어질 수 있는 쪽은?

06_ExtInt이다. 이 예제는 레벨을 LED에 그대로 옮기므로 튐이 끝나면 최종 상태가 맞는다. 06은 하강 에지마다 토글하므로 튐으로 하강 에지가 짝수 번 생기면 LED가 원래 상태로 돌아간다.
