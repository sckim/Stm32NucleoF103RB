외부 인터럽트 두 개: 서로 다른 EXTI 벡터, 하나의 콜백

버튼이 하나일 때는 인터럽트가 오면 그 버튼이라고 단정할 수 있다. 버튼이 둘이고 EXTI 라인 번호대가 다르면 NVIC 벡터도 달라지고, HAL은 두 ISR을 결국 같은 콜백 하나로 모은다. 이 교안은 B1(PC13, 하강 에지)과 외부 버튼 B2(PA6, 상승 에지)를 각각 EXTI15_10, EXTI9_5 벡터에 걸고 HAL_GPIO_EXTI_Callback에서 GPIO_Pin으로 구분하는 08_ExternalInt 예제를 AFIO·EXTI·NVIC 레지스터 수준까지 해석한다.

1. 문제: 인터럽트가 왔을 때 어느 버튼인가

STM32F103의 EXTI는 16개 GPIO 라인(EXTI0~15)을 갖지만 NVIC 벡터는 7개뿐이다. EXTI5~9와 EXTI10~15는 각각 벡터 하나를 공유하므로, 벡터만으로는 어느 핀에서 인터럽트가 왔는지 알 수 없는 경우가 생긴다. 이 예제는 그 구조를 두 버튼으로 보여 준다. 학습 목표는 다음과 같다.

  • EXTI 라인 번호가 핀 번호와 같고, 라인 → 벡터 대응(0~4 개별, 5~9 공유, 10~15 공유)이 고정되어 있음을 설명한다.
  • AFIO_EXTICRx가 같은 번호 핀(PA6, PB6, PC6 …) 중 하나만 라인에 연결한다는 제약을 이해한다.
  • ISR 2개가 HAL_GPIO_EXTI_IRQHandler()를 거쳐 콜백 1개로 모이고, EXTI_PR 비트로 라인을 판별하는 과정을 추적한다.
  • 회로 극성(Active-Low/Active-High)에 맞춰 에지(FTSR/RTSR)와 풀업/풀다운을 고른다.
이 예제의 동작

B1(PC13)을 누르면(하강 에지) EXTI15_10_IRQHandler가, B2(PA6)를 누르면(상승 에지) EXTI9_5_IRQHandler가 실행된다. 두 ISR 모두 같은 HAL_GPIO_EXTI_Callback(GPIO_Pin)을 호출하고, 콜백은 GPIO_Pin이 B1_Pin인지 B2_Pin인지 비교한 뒤 LD2(PA5)를 토글한다. main 루프는 비어 있다.

2. EXTI 라인과 NVIC 벡터의 공유 구조

EXTI 라인 번호는 포트와 무관하게 핀 번호로 정해진다. PC13은 EXTI13, PA6은 EXTI6이다. 라인에서 NVIC 벡터로 가는 대응은 다음과 같이 고정되어 있다 (RM0008 10.1.2 벡터 테이블).

EXTI0 ~ EXTI4각각 개별 벡터6 ~ 10EXTI0_IRQHandler … EXTI4_IRQHandler벡터 자체로 확정

라인마다 입력 포트를 고르는 것은 AFIO의 외부 인터럽트 설정 레지스터이다. 레지스터 하나가 4개 라인을 맡고, 라인당 4비트 필드에 포트 번호를 쓴다.

그림 1. 두 버튼의 경로. 핀 → AFIO가 고른 EXTI 라인 → 에지 검출로 EXTI_PR 비트 설정 → EXTI_IMR가 허용하면 해당 벡터로 요청 → 두 ISR이 같은 콜백으로 모인다. 주황 = B2, 파랑 = B1.

핵심

벡터 이름은 "어느 그룹"까지만 알려 준다. 그룹 안에서 어느 라인인지는 EXTI_PR의 비트가 알려 주며, HAL은 그 비트를 확인한 핀 마스크를 콜백의 GPIO_Pin 인자로 넘긴다. 이 예제는 두 버튼이 서로 다른 그룹이라 벡터로도 구분되지만, 콜백 안에서는 GPIO_Pin으로만 구분할 수 있다.

4. 직접 만져 보기

아래 시뮬레이터는 두 버튼의 핀 전압 변화가 EXTI 에지 검출 → EXTI_PR → NVIC 펜딩 → ISR → HAL 핸들러 → 콜백 분기로 이어지는 과정을 한 단계씩 보여 준다.

  1. B2 누름을 누르면 PA6이 High가 되어 PR 비트 6이 서고 EXTI9_5가 펜딩된다. 다음 단계를 반복해 ISR → PR 클리어 → 콜백 분기 → LD2 토글까지 따라간다.
  2. B1 누름으로 같은 과정을 EXTI15_10 쪽에서 확인한다. B1 놓기는 상승 에지이므로 아무 일도 일어나지 않는다.
  3. 동시 누름을 누르면 두 벡터가 함께 펜딩된다. 우선순위가 같을 때 어느 쪽이 먼저 처리되는지 본다.
  4. EXTI9_5 NVIC 허용을 끄고 B2를 눌러 본다. PR6은 서지만 ISR이 실행되지 않는다. 다시 켜면 남아 있던 펜딩이 즉시 처리된다.
  5. B2 에지를 양 에지로 바꾸면 누를 때와 놓을 때 모두 토글된다.

6. 인터럽트 경로: B2를 눌렀을 때

  1. 1
    PA6 Low → High하드웨어스위치가 3.3 V를 연결한다. AFIO_EXTICR2가 PA6을 EXTI6에 연결해 두었다.
  2. 2
    EXTI6 상승 에지 검출 → PR6 = 1하드웨어RTSR.TR6 = 1이므로 에지가 인정되고, IMR.MR6 = 1이므로 NVIC로 요청이 나간다.
  3. 3
    NVIC EXTI9_5_IRQn(23) 펜딩 → 진입하드웨어우선순위를 판정하고 레지스터 8개를 스택에 저장한 뒤 벡터 테이블의 핸들러 주소로 분기한다.
  4. 4
    EXTI9_5_IRQHandler()소프트웨어stm32f1xx_it.c의 진짜 ISR. CubeMX가 이 그룹에서 설정된 핀(B2 하나)에 대해서만 HAL_GPIO_EXTI_IRQHandler(B2_Pin)을 호출하도록 생성했다.
  5. 5
    HAL_GPIO_EXTI_IRQHandler(0x0040)소프트웨어EXTI_PR & 0x0040이 0이 아니면 EXTI_PR = 0x0040으로 비트를 지우고 콜백을 부른다. 비트가 0이면 아무것도 하지 않는다.
  6. 6
    HAL_GPIO_EXTI_Callback(GPIO_PIN_6)소프트웨어main.c의 사용자 코드. GPIO_Pin == B2_Pin 분기에서 LD2를 토글한다. ISR 문맥이므로 짧게 끝낸다.
  7. 7
    복귀(언스태킹) 또는 테일 체이닝하드웨어다른 벡터가 펜딩되어 있으면 스택 복원 없이 바로 다음 ISR로 넘어간다.

B1은 같은 흐름에서 라인이 13, 에지가 하강, 벡터가 EXTI15_10_IRQn(40), 핀 마스크가 0x2000으로 바뀔 뿐이다.

예를 들어 PB7(EXTI7)을 추가하면 EXTI9_5_IRQHandler 안에 HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_7) 호출이 하나 더 생성된다. 각 호출이 자기 PR 비트만 확인하므로, 한 번의 ISR 진입에서 펜딩된 라인 모두가 순서대로 처리된다. 이 호출을 빠뜨리면 PR7이 지워지지 않아 ISR이 끝없이 다시 진입한다.

7. 코드 읽기

보드의 B1과 PA6(D12)에 연결한 외부 버튼 B2를 사용한다. 출력은 LD2뿐이며 UART 출력은 없다.

main.c — MX_GPIO_Init() 중 입력 핀과 NVIC (CubeMX 생성)
/*Configure GPIO pin : B1_Pin */
GPIO_InitStruct.Pin = B1_Pin;
GPIO_InitStruct.Mode = GPIO_MODE_IT_FALLING;
GPIO_InitStruct.Pull = GPIO_NOPULL;
HAL_GPIO_Init(B1_GPIO_Port, &GPIO_InitStruct);

/*Configure GPIO pin : B2_Pin */
GPIO_InitStruct.Pin = B2_Pin;
GPIO_InitStruct.Mode = GPIO_MODE_IT_RISING;
GPIO_InitStruct.Pull = GPIO_NOPULL;
HAL_GPIO_Init(B2_GPIO_Port, &GPIO_InitStruct);

/* EXTI interrupt init*/
HAL_NVIC_SetPriority(EXTI9_5_IRQn, 0, 0);
HAL_NVIC_EnableIRQ(EXTI9_5_IRQn);

HAL_NVIC_SetPriority(EXTI15_10_IRQn, 0, 0);
HAL_NVIC_EnableIRQ(EXTI15_10_IRQn);
  1. main.h에서 B1_Pin = GPIO_PIN_13(GPIOC), B2_Pin = GPIO_PIN_6(GPIOA)이다.
  2. 모드 하나(IT_FALLING/IT_RISING)가 GPIO 입력 설정, AFIO_EXTICR, EXTI_IMR, FTSR/RTSR을 한꺼번에 설정한다.
  3. 벡터가 둘이므로 NVIC 설정도 두 번이다. 하나를 빠뜨리면 그 버튼만 반응하지 않는다.

{

  1. 함수 이름은 시작 파일(startup_stm32f103rbtx.s)의 벡터 테이블 이름과 정확히 같아야 한다. 다르면 약한 심볼 Default_Handler(무한 루프)가 실행된다.
  2. 각 ISR은 자기 그룹에서 설정된 핀만 넘긴다. HAL 핸들러가 그 핀의 PR 비트를 확인하고 지운다.
  3. USER CODE 주석 줄은 생략했다.
main.c — 공용 콜백 (USER CODE 4, ISR 문맥)
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
  // 1. 여러 인터럽트 핀 중 현재 발생한 인터럽트가 버튼 핀(B1_Pin)인지 확인
  if (GPIO_Pin == B1_Pin)
  {
    // 버튼이 눌릴 때마다 LD2 LED 상태를 반전
    HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
  }
  if (GPIO_Pin == B2_Pin)
  {
    // 버튼이 눌릴 때마다 LD2 LED 상태를 반전
    HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
  }
}
  1. HAL의 약한(weak) 콜백을 재정의한 것이다. 두 ISR이 모두 이 함수를 부른다.
  2. GPIO_Pin은 핀 번호가 아니라 마스크이다: B1 = 0x2000, B2 = 0x0040.
  3. 두 분기 모두 같은 동작이라 LED만 보고는 어느 버튼인지 구분할 수 없다. 실험 C에서 분기를 다르게 바꾼다.
  4. 원본의 ISR 주의 주석(블록 주석)은 생략했다.
관찰 결과

B1을 누르는 순간(놓는 순간이 아님) LD2가 반전된다. B2도 누르는 순간 반전된다. 바운스가 있는 스위치에서는 한 번 눌렀는데 LED가 두 번 반전되어 변화가 없어 보일 수 있다. MX_USART2_UART_Init()은 CubeMX 기본 생성 코드로 남아 있을 뿐 송신은 하지 않으므로 시리얼 모니터에는 아무것도 나오지 않는다.

8. 실험

실험 A. NVIC 허용 하나 빼기

HAL_NVIC_EnableIRQ(EXTI9_5_IRQn);을 주석 처리하고 빌드한다. B1은 동작하고 B2는 반응하지 않는다. 디버거에서 B2를 누른 뒤 EXTI->PR을 보면 비트 6이 1로 남아 있다. EXTI는 에지를 기록했지만 NVIC가 받아들이지 않은 것이다. 시뮬레이터의 NVIC 체크와 비교한다.

실험 B. 에지 바꾸기

B2의 모드를 GPIO_MODE_IT_RISING_FALLING으로 바꾼다. 누를 때와 놓을 때 모두 토글되므로 "누르고 있는 동안만 켜짐"처럼 보인다. 반대로 IT_FALLING으로 바꾸면 놓는 순간에 토글된다. 회로 극성과 에지의 관계를 정리한다.

실험 C. 어느 버튼인지 보이게 하기

콜백의 B2 분기를 다른 동작(예: 외부 LED 토글, 또는 전역 카운터 volatile uint32_t gB2Count 증가)으로 바꾼다. 디버거의 Live Watch로 버튼별 카운트를 확인하고, 분기마다 브레이크포인트를 걸어 콜 스택에서 EXTI9_5_IRQHandler와 EXTI15_10_IRQHandler 중 어느 쪽에서 호출되었는지 확인한다.

실험 D. 바운스 측정

콘덴서 없이 Analog Discovery 2의 DIO 채널을 PA6에, 다른 채널을 PA5(LD2)에 연결하고 PA6 상승 에지로 트리거한다. 한 번 누를 때 수십 µs~수 ms 동안 여러 번 에지가 생기는지, 그때마다 PA5가 반전되는지 본다. 이어서 콜백에서 HAL_GetTick()으로 마지막 처리 시각을 저장하고 50 ms 이내의 재진입을 무시하는 소프트웨어 디바운스를 넣어 비교한다.

9. 트러블슈팅

증상원인점검/조치
B2만 전혀 반응하지 않는다EXTI9_5_IRQn NVIC 미허용, D12 배선 오류, 스위치 전원 미연결디버거로 EXTI->PR 비트 6과 GPIOA->IDR 비트 6 확인. PR6 = 1이면 NVIC 문제, IDR이 안 바뀌면 배선 문제

10. 확인 문제

문제 1. 세 번째 버튼을 PB6에 EXTI로 추가할 수 있는가? 안 된다면 어떤 핀을 고르고 무엇을 바꿔야 하는가?

안 된다. EXTI6은 AFIO_EXTICR2.EXTI6 필드 하나로 PA6과 PB6 중 하나만 연결할 수 있다. 번호가 다른 핀, 예를 들어 PB7(EXTI7)을 쓰면 EXTICR2.EXTI7 = 0001이 되고 같은 EXTI9_5 벡터를 공유한다. EXTI9_5_IRQHandler에 HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_7) 호출을 추가하고(CubeMX가 자동 생성), 콜백에 GPIO_PIN_7 분기를 넣는다.

문제 2. 두 버튼이 정확히 같은 순간에 눌렸다. 어느 ISR이 먼저 실행되고, 다른 하나는 어떻게 되는가?

두 벡터 모두 선점·서브 우선순위가 (0, 0)으로 같으므로 IRQ 번호가 작은 EXTI9_5(23)가 먼저 실행된다. 같은 우선순위는 서로 선점하지 못하므로 EXTI15_10(40)은 펜딩 상태로 기다렸다가 첫 ISR이 끝나면 테일 체이닝으로 곧바로 실행된다. 두 이벤트 모두 처리되며, LD2는 두 번 반전되어 원래 상태로 돌아온다.

문제 3. HAL_GPIO_EXTI_IRQHandler()가 PR 비트를 지우지 않으면 어떤 일이 생기는가?

EXTI_PR 비트가 1로 남아 NVIC로의 요청이 유지되므로 ISR이 끝나자마자 다시 진입한다. main 루프는 실행되지 못한다. PR은 rc_w1 비트라 해당 위치에 1을 써야 지워진다.

문제 4. B2 회로를 "스위치가 GND로, 10 kΩ 풀업이 3.3 V로"로 바꾸면 코드에서 무엇을 바꿔야 누르는 순간에 반응하는가?

누르면 High → Low가 되므로 B2 모드를 GPIO_MODE_IT_FALLING으로 바꾼다. 그러면 EXTI_FTSR.TR6 = 1, RTSR.TR6 = 0이 된다. 외부 풀업 대신 GPIO_PULLUP을 써도 된다. B1과 같은 Active-Low 구성이 된다.
