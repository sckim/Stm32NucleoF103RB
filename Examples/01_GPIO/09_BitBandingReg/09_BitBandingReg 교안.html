비트 밴딩: 비트 하나를 한 번의 쓰기로 바꾼다

reg |= (1 << n)은 한 줄이지만 CPU에게는 읽기 → OR → 쓰기의 세 단계이다. 그 사이에 인터럽트가 같은 워드를 바꾸면 그 변경은 사라진다. Cortex-M3는 주변장치와 SRAM의 각 비트를 별칭(alias) 영역의 워드 하나에 대응시켜, 별칭 워드 한 번의 쓰기로 비트 하나만 바꾸게 한다. 이 교안은 RCC 클럭 허용, LD2 토글, B1 읽기, SRAM 플래그 공유를 모두 비트 밴드로 처리하는 09_BitBandingReg 예제의 별칭 주소를 직접 계산해 검증한다.

1. 문제: 읽기-수정-쓰기 사이에 끼어드는 인터럽트

ARM은 load/store 구조이므로 메모리의 비트를 직접 바꾸는 명령이 없다. flags |= 1은 LDR(읽기) → ORR(수정) → STR(쓰기)로 번역된다. LDR과 STR 사이에 ISR이 같은 워드의 다른 비트를 세우면, main은 ISR 이전의 값으로 워드 전체를 덮어써 ISR의 갱신을 지운다. 학습 목표는 다음과 같다.

  • 비트 밴드 영역과 별칭 영역의 대응, 공식 alias = alias_base + byte_offset × 32 + bit × 4를 설명한다.
  • 예제가 쓰는 별칭 주소(RCC_APB2ENR, GPIOA_ODR, GPIOC_IDR)를 손으로 계산하고 디버거로 검증한다.
  • 일반 RMW와 별칭 쓰기의 원자성 차이, 그리고 BSRR과의 차이를 구분한다.
  • 비트 밴드를 쓰면 안 되는 경우(w1c 플래그 레지스터, M0/M7 코어)를 안다.
이 예제의 동작

HAL 없이 HSI 8 MHz로 동작한다. 비트 밴드로 RCC_APB2ENR의 IOPAEN·IOPCEN을 켜고, SysTick을 1 ms로 시작한다. main 루프는 B1(PC13)을 IDR 별칭으로 읽어 눌렸으면 100 ms, 아니면 500 ms마다 LD2(PA5)를 ODR 별칭으로 토글한다. SRAM 워드 flags의 bit0은 main, bit1은 SysTick_Handler가 각자 별칭으로 세우고 지운다.

2. 비트 밴드 영역과 별칭 영역

Cortex-M3의 메모리 맵에는 비트 밴드 영역 두 곳이 정해져 있다(PM0056 2.2.5). 각 영역의 비트 하나가 별칭 영역의 32비트 워드 하나에 대응하므로 별칭 영역은 원래 영역의 32배 크기이다.

영역비트 밴드 영역 (원래 주소)별칭 영역대상
SRAM0x2000 0000 ~ 0x200F FFFF (1 MB)0x2200 0000 ~ 0x23FF FFFF (32 MB)전역 변수, 플래그 (F103RB SRAM은 20 KB: 0x2000 0000 ~ 0x2000 4FFF)
주변장치0x4000 0000 ~ 0x400F FFFF (1 MB)0x4200 0000 ~ 0x43FF FFFF (32 MB)APB1·APB2·AHB 주변장치 레지스터 (RCC, GPIO, TIM, USART …)
alias = alias_base + (byte_offset × 32) + (bit × 4) byte_offset = 대상 주소 − band_base (band_base = 0x2000 0000 또는 0x4000 0000)

그림 1. GPIOA_ODR의 비트 5(LD2)는 별칭 워드 0x4221 0194에 대응한다. 인접한 비트는 4바이트 간격의 이웃 워드로 이어진다. 별칭 워드에 1을 쓰면 버스가 ODR 워드를 읽고 비트 5만 바꿔 다시 쓰는 과정을 하나의 잠긴(locked) 전송으로 수행한다.

비트 밴드 쓰기 *alias = 1STR (1개)쓰기 1 → 버스 내부에서 잠긴 RMW그렇다. CPU 입장에서 끼어들 틈이 없다

3. 예제가 쓰는 별칭 주소와 하드웨어 설정

레지스터 주소는 RM0008 메모리 맵의 베이스(RCC 0x4002 1000, GPIOA 0x4001 0800, GPIOC 0x4001 1000)와 오프셋(APB2ENR 0x18, IDR 0x08, ODR 0x0C)으로 구한다. 예제 매크로 BB_PERIPH는 (addr − 0x40000000) << 5로 ×32를, bit << 2로 ×4를 계산한다.

4. 직접 만져 보기

  1. 프리셋에서 GPIOA_ODR.ODR5를 고르고 0x4221 0194가 나오는지 확인한다. IOPAEN, IDR13도 표와 비교한다.
  2. 주소에 비트 밴드 영역 밖의 값(예: 08000000)을 넣어 오류 메시지를 본다.

6. 초기화부터 핀 출력까지의 경로

  1. 1
    별칭 쓰기 *(0x42420308) = 1소프트웨어CPU는 STR 하나를 실행한다.
  2. 2
    코어 버스 인터페이스가 잠긴 RMW로 변환하드웨어0x4002 1018을 읽어 비트 2만 1로 바꾸고 다시 쓴다. 이 동안 다른 마스터나 예외가 그 워드를 바꿀 수 없다.
  3. 3
    GPIO 모드 설정, SysTick 시작소프트웨어CRL/CRH는 일반 RMW로 쓴다. 인터럽트가 시작되기 전이므로 경합이 없다.
  4. 4
    1 ms마다 SysTick 예외하드웨어STK_VAL이 0이 되면 COUNTFLAG가 서고 예외 15번으로 진입한다.
  5. 5
    SysTick_Handler: g_ms++, flags bit1 별칭 ← 1소프트웨어main이 bit0을 만지는 중이어도 bit1만 바뀐다. 콜백 개념은 없다.
  6. 6
    main: IDR13 별칭 읽기 → 간격 결정소프트웨어0x4222 0134를 읽으면 0 또는 1이 바로 나온다. 마스크·시프트가 필요 없다.
  7. 7
    main: ODR5 별칭 반전소프트웨어g_ms − t_led ≥ interval이면 0x4221 0194를 읽고 반전해 쓴다. PA5 핀 출력이 바뀐다.
  8. 8
    main: flags bit0 ← 1, bit1 확인 후 ← 0소프트웨어ISR이 세운 1 ms 이벤트를 소비하고 ticks_seen을 센다.

7. 코드 읽기

외부 부품은 필요 없다. 소스는 Core/Src/main.c 하나이며 HAL 함수를 호출하지 않는다.

main.c — 비트 밴드 매크로와 공유 변수
/* 비트 밴딩 별칭 주소 계산 매크로.  addr: 대상 변수/레지스터 주소,  bit: 0~31 */
#define BITBAND_ALIAS(base_alias, base_band, addr, bit) \
    (*(volatile uint32_t *)((base_alias) + (((uint32_t)(addr) - (base_band)) << 5) + ((bit) << 2)))
#define BB_PERIPH(addr, bit) BITBAND_ALIAS(0x42000000UL, 0x40000000UL, addr, bit)
#define BB_SRAM(addr, bit)   BITBAND_ALIAS(0x22000000UL, 0x20000000UL, addr, bit)

/* SRAM 공유 워드: bit0 = main 이 세움, bit1 = ISR 이 세움 (각자 자기 비트만 비트 밴딩으로 접근) */
static volatile uint32_t flags;
static volatile uint32_t g_ms;
  1. << 5는 ×32, << 2는 ×4이다. 공식과 같다.
  2. 결과를 volatile uint32_t *로 역참조하므로 매크로 자체가 좌변·우변으로 쓰인다.
  3. addr가 상수 주소이면 컴파일러가 별칭 주소를 컴파일 시간에 계산한다.
  4. flags는 ISR과 공유하므로 volatile이다.
main.c — SysTick ISR
void SysTick_Handler(void)
{
    g_ms++;
    BB_SRAM(&flags, 1) = 1;                   /* bit1 만 원자적으로 세움 (main 이 bit0 를 만지는 중이어도 안전) */
}
  1. 벡터 테이블의 약한 심볼 SysTick_Handler를 재정의한 진짜 ISR이다.
  2. g_ms++는 ISR만 쓰고 main은 읽기만 하므로 경합이 없다.
main.c — 초기화
/* (1) 클럭 활성화: 일반 방식은 RCC->APB2ENR |= (1<<2)|(1<<4),  비트 밴딩은 비트마다 한 번의 원자적 쓰기 */
BB_PERIPH(&RCC->APB2ENR, 2) = 1;          /* IOPAEN */
BB_PERIPH(&RCC->APB2ENR, 4) = 1;          /* IOPCEN */

GPIOA->CRL = (GPIOA->CRL & ~(0xFu << 20)) | (0x2u << 20);     /* PA5 출력 2MHz */
GPIOC->CRH = (GPIOC->CRH & ~(0xFu << 20)) | (0x8u << 20);     /* PC13 입력(풀업 선택) */
GPIOC->BSRR = (1u << 13);

SysTick->LOAD = SystemCoreClock / 1000u - 1u;
SysTick->VAL = 0;
SysTick->CTRL = SysTick_CTRL_CLKSOURCE_Msk | SysTick_CTRL_TICKINT_Msk | SysTick_CTRL_ENABLE_Msk;
  1. 클럭 허용은 비트마다 쓰기 1회이다. 일반 방식이라면 한 번의 RMW로 두 비트를 함께 켤 수 있다. 비트 밴드는 비트가 많을수록 접근 횟수가 늘어난다.
  2. CRL·CRH는 4비트 필드이므로 비트 밴드보다 일반 RMW가 자연스럽다.
  3. SystemCoreClock은 클럭 설정이 없으므로 8 MHz(HSI)이고 LOAD = 7999이다.
main.c — main 루프
while (1)
{
    /* (2) B1: IDR 비트 13 을 별칭으로 읽는다 (0 = 눌림).  결과는 항상 0 또는 1 */
    uint32_t interval = (BB_PERIPH(&GPIOC->IDR, 13) == 0) ? 100u : 500u;

    if ((uint32_t)(g_ms - t_led) >= interval)
    {
        t_led = g_ms;
        BB_PERIPH(&GPIOA->ODR, 5) ^= 1u;                       /* 별칭 워드 읽고 반전해 쓰기: ODR5 하나만 바뀜 */
    }

    /* (3) main 이 bit0 를 세우고, ISR 이 세운 bit1 을 확인한 뒤 자기 손으로 비운다 (둘 다 단일 원자 접근) */
    BB_SRAM(&flags, 0) = 1;
    if (BB_SRAM(&flags, 1))
    {
        BB_SRAM(&flags, 1) = 0;               /* ISR 이 세운 1ms 이벤트를 소비 */
        ticks_seen++;
    }
}
  1. (uint32_t)(g_ms - t_led)는 g_ms가 232에서 넘쳐도 올바른 경과 시간을 준다.
  2. ^= 1u는 별칭 읽기 + 별칭 쓰기 두 번의 접근이다. ODR의 다른 비트는 안전하지만, 그 사이에 ISR이 같은 비트 5를 바꾸면 그 변경은 덮인다. 이 예제에서는 ISR이 PA5를 건드리지 않으므로 문제가 없다.
  3. bit1 확인과 클리어도 별개의 두 접근이다. 그 사이에 ISR이 다시 bit1을 세우면 이벤트 두 개가 하나로 합쳐진다(플래그는 "있다/없다"만 전달한다). 워드의 다른 비트가 지워지는 문제와는 다른 성질이다.
관찰 결과

LD2가 500 ms마다 반전(1 Hz 점멸)한다. B1을 누르고 있으면 100 ms마다 반전(5 Hz 점멸)한다. 디버거 메모리 창에서 0x4221 0194를 보면 LD2가 켜졌을 때 0x0000 0001, 꺼졌을 때 0x0000 0000이다. UART 출력은 없다.

8. 실험

실험 A. 디버거로 별칭 주소 검증

실행을 멈추고 메모리 창에서 0x4242 0300부터 32워드를 본다. 0x4242 0308과 0x4242 0310만 1이고 나머지는 0이면 RCC_APB2ENR = 0x0000 0014와 일치한다. 이어서 0x4221 0194에 1을 직접 써 넣으면 LD2가 켜진다. &flags를 Watch 창에서 확인하고 별칭 주소를 계산해 같은 방법으로 bit0·bit1을 확인한다.

실험 B. 디스어셈블리 비교

GPIOA->ODR |= (1u << 5);와 BB_PERIPH(&GPIOA->ODR, 5) = 1;을 나란히 넣고 디스어셈블리 창에서 비교한다. 앞의 것은 LDR/ORR/STR, 뒤의 것은 주소 적재 뒤 STR 하나인지 확인한다. 같은 일을 GPIOA->BSRR = (1u << 5);로 했을 때와도 비교한다.

실험 C. 경합을 실제로 만들기

main 루프의 (3)을 flags |= 1u; flags &= ~1u; 반복으로 바꾸고, ISR은 flags |= 2u;, main의 bit1 소비는 그대로 둔다. ticks_seen을 전역 volatile로 옮긴 뒤 수 초 실행하고 g_ms와 비교한다. 일반 RMW에서는 main의 쓰기가 ISR의 bit1을 덮어 이벤트가 사라질 수 있다. 비트 밴드 버전으로 되돌려 차이를 비교한다. (손실은 확률적으로 생기므로 결과가 0일 수도 있다. 그 이유를 시뮬레이터로 설명해 본다.)

실험 D. BSRR로 다시 쓰기

LD2 토글을 BSRR로 바꾼다(켜기: BSRR = 1u << 5, 끄기: BSRR = 1u << 21). 현재 상태를 알아야 하므로 ODR을 한 번 읽어야 한다는 점, 그리고 이 코드가 Cortex-M0 기반 STM32에서도 그대로 동작한다는 점을 정리한다.

9. 트러블슈팅

증상원인점검/조치
LD2가 켜지지 않는다별칭 계산 오류로 다른 비트를 켰다 (×32 대신 ×8, 비트에 ×4 누락 등)디버거에서 RCC->APB2ENR = 0x14, GPIOA->CRL = 0x4424 4444 확인. 계산기로 주소 재확인
B1을 누르지 않아도 계속 빠르게 깜빡인다IOPCEN 별칭 주소가 틀려 GPIOC 클럭이 꺼져 있다. 클럭이 꺼진 주변장치 레지스터는 대개 0으로 읽혀 "눌림"으로 판정된다RCC->APB2ENR 비트 4와 GPIOC->IDR 확인
별칭 접근에서 HardFault비트 밴드 영역 밖의 주소(플래시 0x0800 xxxx, 코어 0xE000 xxxx 등)로 별칭을 계산해 존재하지 않는 주소에 접근대상 주소가 0x2000 0000~0x200F FFFF 또는 0x4000 0000~0x400F FFFF인지 확인
다른 보드로 옮겼더니 오류 없이 아무것도 안 된다Cortex-M0/M0+/M7/M33에는 비트 밴드가 없다 (F0, G0, L0, F7, H7, L5, U5 등)GPIO는 BSRR, 변수는 __disable_irq() 임계 구역이나 LDREX/STREX(C11 atomic)로 대체
비트 밴드로 플래그 하나를 지웠는데 다른 플래그도 사라졌다EXTI_PR처럼 1을 써서 지우는(rc_w1) 레지스터에 별칭 쓰기를 하면 버스의 RMW가 읽은 1들을 그대로 다시 써서 다른 펜딩 비트까지 지운다rc_w1 레지스터는 비트 밴드 대신 해당 비트만 1인 값을 직접 쓴다 (EXTI->PR = 1u << n)
최적화 빌드에서 플래그 변화를 못 본다공유 변수에 volatile 누락flags, g_ms를 volatile로 선언 (이 예제는 선언되어 있음)

10. 확인 문제

문제 1. TIM2_CR1.CEN(TIM2 베이스 0x4000 0000, CR1 오프셋 0, 비트 0)의 별칭 주소는?

byte_offset = 0, bit = 0이므로 별칭 = 0x4200 0000이다. 주변장치 별칭 영역의 첫 워드이다.

문제 2. GPIOB_ODR(0x4001 0C0C)의 비트 12 별칭 주소를 계산하라.

byte_offset = 0x1 0C0C, ×32 = 0x21 8180, 비트 12 × 4 = 0x30. 별칭 = 0x4200 0000 + 0x21 8180 + 0x30 = 0x4221 81B0이다.

문제 3. 별칭 주소 0x2200 0404는 어느 주소의 몇 번 비트인가?

0x404 = 1028. 1028 / 32 = 32 나머지 4이므로 byte_offset = 32 = 0x20, 나머지 4 / 4 = 비트 1이다. 0x2000 0020 워드의 비트 1이다.

문제 4. LD2 토글에 BB_PERIPH(&GPIOA->ODR, 5) ^= 1u를 쓴다. 이 문장 전체가 원자적인가? ODR의 다른 비트는 안전한가?

문장 전체는 원자적이지 않다. 별칭 읽기와 별칭 쓰기가 각각 한 번씩 일어나므로 그 사이에 ISR이 비트 5를 바꾸면 그 변경은 덮인다. 그러나 쓰기 단계가 비트 5만 바꾸므로 ODR의 다른 비트(다른 핀)는 항상 안전하다. 일반 GPIOA->ODR ^= 1u << 5는 다른 비트까지 위험하다는 점이 다르다.
