# 09_BitBandingReg

> 계층: **레지스터(CMSIS)**

Cortex-M3의 **비트 밴딩(bit-banding)** 으로 레지스터/SRAM의 비트 하나를 원자적으로 읽고 쓴다.

## 핵심 학습 내용

- **비트 밴딩 원리**: 주변장치(0x40000000~) 또는 SRAM(0x20000000~) 영역의 각 비트가 별칭(alias) 영역(0x42000000~ / 0x22000000~)의 32비트 워드 하나에 1:1로 대응한다. 별칭 워드에 0/1을 쓰면 하드웨어가 해당 비트만 원자적으로 바꾼다.
  `alias = alias_base + (byte_offset × 32) + (bit_number × 4)`
- **왜 유용한가**: `reg |= (1<<n)`은 읽기→OR→쓰기 3단계라 그 사이 ISR이 같은 변수를 바꾸면 갱신이 사라진다. 별칭 쓰기는 한 번이므로 인터럽트를 막지 않고도 안전하다. (GPIO는 `BSRR`이 같은 목적을 이미 제공. 비트 밴딩은 `RCC->APB2ENR`, 타이머 `CR1.CEN`, SRAM 플래그 등에 유용)
- **Cortex-M3/M4 전용 기능**: M0/M0+ 에는 없다. (자세한 내용은 아래 "이식성 주의")

## 이식성 주의

비트 밴딩은 STM32 주변장치가 아니라 **Cortex-M 코어의 선택 기능**이라서 코어에 따라 있을 수도, 없을 수도 있다.

| 코어 | 비트 밴딩 | 대표 STM32 |
|---|---|---|
| Cortex-M3 | 있음 | F1 (이 보드), F2, L1 |
| Cortex-M4 | 있음 (구현 선택 사항) | F3, F4, L4 |
| Cortex-M0 / M0+ | 없음 | F0, G0, L0 |
| Cortex-M7 | 없음 | F7, H7 |
| Cortex-M23 / M33 | 없음 | L5, U5, H5 |

- **이 예제의 코드는 F1(M3) 전용**이다. 다른 시리즈로 옮기면 별칭 영역(`0x42000000` / `0x22000000`)에 쓰더라도 비트가 바뀌지 않고, 빌드는 통과하므로 **오류 없이 조용히 동작하지 않는다.**
- 같은 목적(한 비트를 다른 비트나 인터럽트와 충돌 없이 바꾸기)을 이식 가능하게 하려면 다음 방법을 쓴다.
  - **GPIO 출력**: `BSRR`(M 코어와 무관, 모든 STM32). HAL의 `HAL_GPIO_WritePin()`도 내부적으로 `BSRR`을 쓰므로 이미 원자적이다.
  - **SRAM 플래그**: C11 `<stdatomic.h>`의 `atomic_fetch_or()` 등, 또는 `LDREX`/`STREX`(M3 이상), 짧은 구간의 인터럽트 차단(`__disable_irq()`).
  - **주변장치 비트**: 그 레지스터가 set/clear 전용 레지스터를 제공하는지 확인하고, 없으면 임계 구역으로 보호한다.
- **HAL을 쓰는 프로젝트에서는 대개 고민할 필요가 없다.** HAL이 위의 `BSRR` 같은 안전한 방법을 이미 사용한다. 비트 밴딩은 HAL과 함께 써도 되지만, 그 경우에도 위 표의 이식성 한계를 알고 써야 한다.
- 이 예제는 **Cortex-M3의 동작 원리를 배우는 목적**으로 보고, 실무 코드로 옮길 때는 위 대체 방법을 쓴다.

## 동작

1. `RCC->APB2ENR`의 `IOPAEN`(bit2), `IOPCEN`(bit4)을 비트 밴딩으로 켠다.
2. LD2(PA5)를 `GPIOA->ODR` bit5 별칭으로 토글, B1(PC13)은 `GPIOC->IDR` bit13 별칭으로 읽는다.
3. SRAM 플래그 워드의 bit0은 main, bit1은 SysTick ISR이 각자 비트 밴딩으로 세우고 지운다 → 경합 없음을 보인다.
4. B1을 누르고 있으면 LED가 빠르게, 아니면 느리게 깜빡인다.

## ISR

`SysTick_Handler`. 콜백 개념은 없다.
