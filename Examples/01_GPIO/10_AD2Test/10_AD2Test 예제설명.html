헤더 핀 14개 순차 점등과 UART 프레임: AD2로 배선 검증하기

보드의 Arduino 헤더 라벨(D2, D3 …)은 MCU 핀 순서와 무관하게 포트 A, B, C에 흩어져 있다. 라벨을 믿고 배선했다가 핀이 어긋나면 펌웨어를 아무리 고쳐도 동작하지 않는다. 이 예제설명은 D2~D13, A4, A5 열네 핀을 1초씩 차례로 High로 만들고 한 바퀴마다 USART2로 Hello, AD2를 보내는 10_AD2Test 예제를 해석하고, Analog Discovery 2 로직 분석기로 펄스 순서와 UART 프레임을 관찰하는 방법을 다룬다.

1. 문제: 라벨과 실제 핀2. 순차 펄스와 UART 프레임3. 핀 매핑·AD2 배선4. 직접 만져 보기5. 레지스터 대응6. 실행 경로7. 코드 읽기8. 실험9. 트러블슈팅10. 확인 문제

1. 문제: 헤더 라벨과 MCU 핀은 다르다

D2는 PA10, D3는 PB3, D9는 PC7이다. 일부 핀(PB3, PB4)은 리셋 직후 JTAG 디버그 기능이 점유하고 있어 GPIO로 쓰려면 별도 설정이 필요하다. 이 예제는 한 번에 한 핀만 High로 만들기 때문에, 로직 분석기 채널에 펄스가 나타나는 순서만 보면 배선과 매핑이 맞는지 바로 알 수 있다. 학습 목표는 다음과 같다.

  • Arduino 헤더 라벨 ↔ MCU 포트·비트 ↔ HAL 핀 마스크 대응 표를 소스에서 만든다.
  • 핀 표(GpioPin 배열)와 반복문으로 서로 다른 포트의 핀을 같은 코드로 다룬다.
  • HAL_Delay()와 SysTick의 관계, 실제 대기 시간이 1 ms 더 길어질 수 있는 이유를 설명한다.
  • 115200 8N1 UART 프레임을 비트 단위로 그리고, AD2의 UART 디코더로 해석한다.
이 예제의 동작

main 루프는 arduino_pins[]의 14개 핀을 순서대로 SET → HAL_Delay(1000) → RESET 한다. 14개를 모두 돌면 HAL_UART_Transmit()으로 "Hello, AD2\r\n"(12바이트)을 PA2(USART2_TX)로 블로킹 송신하고 처음부터 반복한다. 한 바퀴는 약 14초이다. D13은 LD2와 같은 PA5이므로 13번째 슬롯에서는 보드 LED도 켜진다.

2. 순차 펄스와 UART 프레임

그림 1. 한 바퀴의 타이밍. 핀마다 약 1초 폭의 High 펄스가 한 번씩, 겹치지 않고 차례로 나온다. 마지막에 PA2(TX)에서 약 1.04 ms 동안 UART 프레임 12개가 나간다 (시간축 비율과 무관하게 크게 표시). 파랑 = D2~D12, 주황 = D13(LD2), 청록 = A4·A5, 보라 = TX.

항목값근거
핀당 High 시간1000 ~ 1001 msHAL_Delay(1000)는 경계 오차를 막기 위해 1틱을 더해 기다린다(시작 시점이 틱 중간이면 1000 ms보다 조금 길다)
핀 사이 간격µs 단위RESET 직후 다음 핀 SET. 두 핀이 동시에 High인 구간은 없다
UART 송신 시간12 B × 10 bit / 115200 ≈ 1.04 ms8N1 = 시작 1 + 데이터 8 + 정지 1 = 10비트
한 바퀴약 14.0 s (14.00 ~ 14.02 s + 1.04 ms)14 × HAL_Delay + 송신 시간

UART는 유휴 상태가 High(1)이고, 시작 비트 0으로 프레임을 알린 뒤 데이터를 LSB부터 보내고 정지 비트 1로 끝낸다. 115200 bps에서 비트 하나는 1/115200 = 8.68 µs이다.

그림 2. 첫 글자 'H'(0x48 = 0100 1000b)의 프레임. LSB부터 보내므로 데이터 비트 순서는 0, 0, 0, 1, 0, 0, 1, 0이다. 로직 분석기에서 보이는 파형 그대로이다.

3. 핀 매핑과 AD2 배선

14개 핀의 설정 필드 값은 모두 0x1(MODE = 01: 최대 10 MHz 출력, CNF = 00: 범용 푸시풀)이다. 제외한 핀은 D0/D1(PA3/PA2, USART2와 겹침)과 D14/D15(PB9/PB8, I2C)이다.

주의: UART 프로브 위치

PA2는 Arduino 헤더의 D1 자리에 해당하지만, Nucleo-64 기본 납땜 브리지 설정(SB13·SB14 ON, SB62·SB63 OFF)에서는 PA2/PA3가 ST-LINK 가상 COM 쪽에만 연결되고 Arduino D0/D1 커넥터에는 연결되지 않는다(UM1724의 USART 통신 절). AD2로 TX를 볼 때는 D1 대신 모포 커넥터 CN10-35(PA2)에 DIO 14를 연결한다(UM1724 표 27). 보드의 브리지 설정을 바꾼 경우에는 D1에서도 관찰할 수 있다.

7. 코드 읽기

보드만 있으면 LD2로 13번째 슬롯을 볼 수 있고, 나머지 핀과 TX는 AD2 같은 로직 분석기로 관찰한다.

main.c — 핀 표 (USER CODE PTD / PV)
typedef struct
{
  GPIO_TypeDef *port;
  uint16_t pin; // HAL 핀 마스크 (GPIO_PIN_x = 1 << n)
} GpioPin;

// NUCLEO-F103RB의 D2~D13과 A4/A5 아날로그 헤더 핀을 순서대로 출력한다.
// PA3/PA2는 USART2 RX/TX로 쓰므로 순차 GPIO 출력에서 제외한다 (Arduino D0/D1 자리).
// 단, 보드 기본 설정(SB62/SB63 OFF)에서 PA2/PA3는 D1/D0 핀과 끊겨 있고 ST-LINK 가상 COM에만 연결된다.
// D14/D15(PB9/PB8, I2C)는 사용하지 않는다.
static const GpioPin arduino_pins[] = {
    {D2_GPIO_Port, D2_Pin}, // D2
    {D3_GPIO_Port, D3_Pin}, // D3
    /* … D4 ~ D12 … */
    {LD2_GPIO_Port, LD2_Pin}, // LD2
    {A4_GPIO_Port, A4_Pin}, // A4
    {A5_GPIO_Port, A5_Pin}, // A5
};
#define GPIO_PIN_COUNT (sizeof(arduino_pins) / sizeof(arduino_pins[0]))
  1. 포트(구조체 포인터)와 마스크를 한 쌍으로 묶어, 포트가 달라도 같은 반복문으로 다룬다.
  2. D2_Pin, D2_GPIO_Port는 CubeMX 라벨에서 생성된 main.h의 정의이다. 라벨 이름만 바꾸면 코드는 그대로 둘 수 있다.
  3. const 배열이므로 플래시에 놓인다. GPIO_PIN_COUNT는 컴파일 시간에 14가 된다.
main.c — main 루프 (USER CODE 3)
while (1)
{
  for (uint32_t i = 0; i < GPIO_PIN_COUNT; i++)
  {
    // 현재 핀을 1000ms 켠 뒤 끄고 다음 핀으로 이동한다. (GPIOx_BSRR)
    HAL_GPIO_WritePin(arduino_pins[i].port, arduino_pins[i].pin, GPIO_PIN_SET);
    HAL_Delay(1000); // SysTick ISR(HAL_IncTick)이 증가시키는 uwTick 기반
    HAL_GPIO_WritePin(arduino_pins[i].port, arduino_pins[i].pin, GPIO_PIN_RESET);
  }
  // 순차 출력이 끝날 때마다 PA2(USART2_TX -> ST-LINK 가상 COM, 모포 CN10-35)로 메시지 전송 (폴링: TXE/TC는 HAL이 처리)
  const char msg[] = "Hello, AD2\r\n";
  HAL_UART_Transmit(&huart2, (uint8_t *)msg, strlen(msg), HAL_MAX_DELAY);
}
  1. SET과 RESET은 모두 BSRR 쓰기 1회이다. 다른 핀은 영향을 받지 않는다.
  2. HAL_Delay 동안 CPU는 폴링하며 다른 일을 하지 않는다.
  3. strlen(msg) = 12. 끝의 널 문자는 보내지 않는다.
  4. PA2는 보드 기본 설정에서 D1 커넥터와 연결되지 않으므로, 주석에 측정 위치(모포 CN10-35)를 적어 두었다(3절 주의 참고).
main.c — MX_GPIO_Init() 일부 (CubeMX 생성)
/*Configure GPIO pin Output Level */
HAL_GPIO_WritePin(D2_GPIO_Port, D2_Pin, GPIO_PIN_RESET);
/* … 나머지 13개 핀도 RESET … */

/*Configure GPIO pin : D2_Pin */
GPIO_InitStruct.Pin = D2_Pin;
GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;
GPIO_InitStruct.Pull = GPIO_NOPULL;
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_MEDIUM;
HAL_GPIO_Init(D2_GPIO_Port, &GPIO_InitStruct);
  1. 출력 레벨을 먼저 정한 뒤 모드를 바꾸는 순서가 중요하다.
  2. GPIO_SPEED_FREQ_MEDIUM은 MODE = 01(10 MHz)이다. 1초 펄스에는 속도가 의미가 없지만 에지가 덜 가파라져 링잉이 줄어든다.
stm32f1xx_hal_msp.c — HAL_MspInit()
void HAL_MspInit(void)
{
  __HAL_RCC_AFIO_CLK_ENABLE();
  __HAL_RCC_PWR_CLK_ENABLE();

  /* System interrupt init*/

  /** NOJTAG: JTAG-DP Disabled and SW-DP Enabled
  */
  __HAL_AFIO_REMAP_SWJ_NOJTAG();
}
  1. CubeMX에서 SYS → Debug를 Serial Wire로 두면 생성된다.
  2. 이 줄이 없으면 PB3(D3)과 PB4(D5)는 JTAG 기능에 묶여 펄스가 나오지 않는다.

시리얼 모니터(115200)에는 약 14초마다 한 줄이 찍힌다. AD2 Logic 창에서는 DIO 0 → DIO 13 순서로 1초 펄스가 하나씩 지나가고, DIO 13의 펄스가 끝난 직후 DIO 14에서 약 1 ms 길이의 UART 버스트가 보인다.

8. 실험

실험 A. AD2로 순서와 UART 동시 관찰

3절 표대로 DIO 0~13을 헤더 핀에, DIO 14를 PA2에, GND를 보드 GND에 연결한다. WaveForms의 Logic 도구에서 채널 15개를 추가하고 이름을 헤더 라벨로 붙인다. 펄스 순서를 볼 때는 시간축을 2 s/div 정도로 길게 잡고, DIO 0의 상승 에지로 트리거한다. UART를 볼 때는 Add → UART로 DIO 14를 RX 신호로 지정하고 115200 bps, 8 데이터 비트, 패리티 없음, 정지 1비트로 설정한 뒤 DIO 14 하강 에지(시작 비트)로 트리거하고 샘플링을 1 MHz 이상(비트당 100샘플 이상)으로 올린다. 디코더 표시를 ASCII로 바꿔 Hello, AD2가 읽히는지 확인한다.

실험 B. 1 ms 펄스

HAL_Delay(1000)을 HAL_Delay(1)로 바꾼다. AD2 커서로 각 펄스 폭이 1 ms와 2 ms 사이에서 흔들리는 것을 측정하고, 한 바퀴 시간을 계산값(14 × 1~2 ms + 1.04 ms)과 비교한다. 이제 한 화면에서 순서 펄스와 UART를 함께 볼 수 있다.

실험 C. JTAG 핀 해방 확인

CubeMX에서 SYS Debug를 JTAG(5 pins)로 바꿔 재생성하면 __HAL_AFIO_REMAP_SWJ_NOJTAG()가 사라진다. DIO 1(D3/PB3)과 DIO 3(D5/PB4)에 펄스가 나오지 않는지 확인하고, 디버거에서 AFIO->MAPR의 SWJ_CFG 값을 비교한다. 확인 후 Serial Wire로 되돌린다.

실험 D. 배선 오류 찾기

DIO 4와 DIO 5의 집게를 일부러 서로 바꿔 꽂는다. 펄스가 나타나는 순서만으로 어느 채널이 바뀌었는지 찾아낸다. 이어서 Logic 창에서 채널 하나를 비워 두고, 펄스가 빈 슬롯으로 보이는 것도 확인한다. (출력끼리 직접 단락시키는 실험은 하지 않는다. 한쪽 High, 한쪽 Low인 순간 두 드라이버가 충돌한다.)

10. 확인 문제

문제 1. HAL_Delay(1)로 바꾸면 한 바퀴 시간의 범위는?

HAL_Delay(1)은 1 ~ 2 ms를 기다린다. 따라서 14 × (1~2 ms) + 1.04 ms = 약 15.0 ~ 29.0 ms이다. 지연이 짧아지면 HAL_Delay의 +1틱 보정이 상대적으로 크게 보인다.

문제 2. 문자 'A'(0x41)를 115200 8N1로 보낼 때 PA2의 비트열(시작~정지)과 프레임 시간은?

0x41 = 0100 0001b, LSB부터 1, 0, 0, 0, 0, 0, 1, 0이다. 선로에는 0(시작), 1, 0, 0, 0, 0, 0, 1, 0, 1(정지) 순으로 나간다. 프레임 시간은 10 × 8.68 µs = 86.8 µs이다.

문제 3. MX_GPIO_Init()이 HAL_GPIO_Init()보다 HAL_GPIO_WritePin(RESET)을 먼저 부르는 이유는?

핀이 출력으로 바뀌는 순간 ODR 값이 그대로 출력되기 때문이다. 먼저 BSRR의 BRy로 ODR을 0으로 만들어 두면 모드 전환 순간에 High 글리치가 생기지 않는다. 로직 분석기로 배선을 검증할 때 초기 글리치는 잘못된 펄스로 오해될 수 있다.

문제 4. D2를 켜는 HAL_GPIO_WritePin(GPIOA, GPIO_PIN_10, GPIO_PIN_SET)과 끄는 호출은 각각 어떤 값을 어느 레지스터에 쓰는가?

켜기: GPIOA_BSRR = 0x0000 0400 (BS10). 끄기: GPIOA_BSRR = 0x0400 0000 (BR10 = 비트 26). 둘 다 쓰기 1회이며 GPIOA의 다른 핀(PA5 LD2, PA2 TX 등)에는 영향이 없다.
