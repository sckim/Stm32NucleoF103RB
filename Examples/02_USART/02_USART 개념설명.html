USART: 바이트 하나가 한 가닥 선 위의 비트열이 되기까지

USART(Universal Synchronous/Asynchronous Receiver-Transmitter, 범용 동기/비동기 송수신기)는 디지털논리에서 배운 시프트 레지스터, 카운터(분주기), 다수결 회로, 시퀀스 검출기, XOR 패리티 트리를 묶어 "클럭 선 없이 바이트를 주고받는" 일을 하드웨어로 처리하는 주변장치이다. 이 개념설명은 STM32F103RB를 기준으로, CPU가 데이터 레지스터에 쓴 바이트가 TX 핀의 비트열이 되고 RX 핀으로 들어온 비트열이 다시 바이트가 되기까지의 경로를 원본 블록도 위에서 따라간다.

1. 문제 정의: USART가 없으면 CPU가 무엇을 직접 해야 하는가

두 장치 사이에 선을 두 가닥(송신 TX, 수신 RX)만 두고 바이트를 주고받으려 한다. 클럭 선이 없으므로 받는 쪽은 "비트가 언제 시작해서 언제 끝나는지"를 스스로 알아내야 한다. USART가 없다면 CPU가 GPIO 핀 하나로 이 일을 모두 한다. 이런 방식을 비트뱅잉(bit-banging)이라고 한다.

64 MHz CPU에서 115200 bps 한 비트는 약 556 클럭이다. 비트뱅잉은 이 556 클럭마다 CPU를 정확히 불러 세워야 하므로 송수신 내내 다른 일을 하기 어렵다. USART를 쓰면 CPU는 바이트 하나당 한 번, 즉 약 5 560 클럭(10비트)마다 데이터 레지스터를 읽거나 쓰기만 하면 된다. DMA를 붙이면 그마저 하지 않는다(6장). 이것이 이 그룹 예제들이 폴링 → 인터럽트 → 링 버퍼 → DMA로 발전해 가는 이유이다.

2. 일반 개념

비동기 직렬 통신과 프레임

"비동기"는 송신기와 수신기가 클럭 선을 공유하지 않는다는 뜻이다. 대신 양쪽이 같은 속도(보레이트)를 미리 약속하고, 송신기는 바이트마다 앞뒤에 표지를 붙인다. 이 묶음을 프레임이라고 한다.

  • 유휴(idle): 보낼 것이 없을 때 선은 High(1)이다.
  • 시작 비트: 1비트 동안 Low(0). High → Low 하강 엣지가 "지금부터 프레임"이라는 신호이며, 수신기는 이 엣지로 매번 박자를 다시 맞춘다.
  • 데이터 비트: LSB(Least Significant Bit, 최하위 비트)부터 보낸다. 전압 부호화는 NRZ(Non-Return-to-Zero: 비트 구간 내내 1 = High, 0 = Low 유지)이다.
  • 패리티 비트(선택): 1의 개수를 짝수(또는 홀수)로 맞추는 비트. 모든 데이터 비트의 XOR이다.
  • 정지 비트: 1 또는 2비트 동안 High. 다음 시작 비트의 하강 엣지가 생기도록 선을 High로 되돌린다.

"8N1"은 데이터 8비트(8), 패리티 없음(None), 정지 비트 1개를 뜻한다. 이때 바이트 하나가 1 + 8 + 1 = 10비트를 차지한다. 그래서 115200 bps의 실제 바이트 전송률은 11 520 바이트/초이다. 아래에서 문자와 형식을 바꿔 가며 선 위의 파형을 확인할 수 있다.

수신기의 문제: 박자를 모르고 비트 한가운데를 찾기

수신기는 시작 비트의 하강 엣지를 기준으로 시계를 맞춘다. 그 뒤로는 자기 클럭으로 비트 중앙을 짐작해 읽는다. 양쪽 클럭이 조금씩 다르면 비트를 거듭할수록 읽는 위치가 중앙에서 밀려난다. 프레임 끝의 정지 비트까지 밀림이 반 비트를 넘지 않아야 올바르게 읽힌다. 프레임마다 시작 비트에서 다시 맞추므로 오차는 프레임 안에서만 쌓인다. 이것이 UART가 클럭 선 없이 동작하는 이유이며, 동시에 양쪽 클럭의 허용 오차가 몇 % 수준으로 제한되는 이유이다(4장).

비트를 한 번만 읽으면 잡음 펄스 하나에 값이 뒤집힌다. 그래서 수신기는 한 비트 시간을 여러 조각(보통 16)으로 나누어 빠르게 샘플링한다. 이것을 오버샘플링이라고 한다. 비트 중앙 근처의 샘플 세 개로 다수결을 내리고, 세 값이 일치하지 않으면 "잡음이 있었다"고 표시한다. 다수결은 디지털논리의 2-of-3 회로 maj(a,b,c) = ab + bc + ca이고, 불일치 검출은 ¬(a=b=c)이다.

이중 버퍼와 시프트 레지스터

송신 쪽에는 CPU가 쓰는 버퍼 레지스터와 실제로 비트를 밀어 내는 시프트 레지스터가 따로 있다. 시프트 레지스터가 바이트 1을 내보내는 동안 CPU는 버퍼에 바이트 2를 미리 넣어 둘 수 있다. 그래서 프레임 사이에 빈틈이 생기지 않는다. 수신 쪽도 같다. 시프트 레지스터가 다음 바이트를 모으는 동안 이전 바이트는 버퍼에서 CPU를 기다린다. 버퍼가 한 칸뿐이므로 CPU는 다음 바이트가 다 모이기 전에 버퍼를 비워야 한다. 늦으면 덮어쓰기(오버런)가 일어난다.

흐름 제어와 이중성

받는 쪽이 바쁠 때 보내는 쪽을 멈추게 하는 것이 흐름 제어이다. RTS(Request To Send)와 CTS(Clear To Send) 두 선을 추가해 "지금 받을 수 있다"를 하드웨어로 알린다. 선 구성에 따라 송수신이 동시에 되는 전이중(full duplex, 선 2개)과, 한 선을 번갈아 쓰는 반이중(half duplex, 선 1개)이 있다. 반이중에서는 누가 말할 차례인지 정하는 약속(프로토콜)이 필요하다.

3. 내부 구현 블록도

신호를 입력 → 클럭 → 처리 → 플래그/이벤트 → 출력 순서로 따라간다. 수신 경로를 먼저 본다.

  1. 1
    입력: RX 핀 → (IrDA 블록 통과) → 수신기RX 핀은 GPIO에서 플로팅 입력 또는 풀업 입력으로 둔다(RM0008 Table 24, p.167). IrDA(Infrared Data Association, 적외선 통신) 블록은 해당 모드가 아닐 때 그냥 통과시킨다.
  2. 2
    클럭: fPCLKx → ÷USARTDIV → 샘플 클럭(비트당 16회) → ÷16 → 비트 클럭그림 아래쪽의 /USARTDIV와 /16 상자이다. 수신기는 비트당 16번 샘플링한다(4장).
  3. 3
    처리: 시작 비트 검출 → 비트별 다수결 → Receive Shift registerRECEIVER CONTROL이 샘플을 보고 시작 비트를 확정하고, 각 비트의 8·9·10번째 샘플로 다수결해 시프트 레지스터에 밀어 넣는다(RM0008 27.3.3).
  4. 4
    플래그/이벤트: 시프트 레지스터 → RDR 복사, RXNE·오류 플래그 세트정지 비트까지 받으면 바이트가 RDR로 넘어가고 SR의 RXNE가 1이 된다. 같은 순간에 오류가 있으면 NE·FE·PE·ORE도 세트된다. 허용된 플래그는 인터럽트나 DMA 요청이 된다(6장).
  5. 5
    출력(송신 경로): DR 쓰기 → TDR → Transmit Shift register → TX 핀TDR이 비면 TXE = 1이다. 시프트 레지스터가 비어 있으면 TDR 값이 즉시 시프트 레지스터로 넘어간다. TX 핀은 GPIO에서 대체 기능(AF, Alternate Function) 푸시풀 출력으로 둔다(Table 24, p.166).

4. 클럭 경로와 시간 계산

보레이트 = f_CK / (16 × USARTDIV) (RM0008 27.3.4, p.798) USARTDIV = DIV_Mantissa + DIV_Fraction / 16 (BRR[15:4] = Mantissa, BRR[3:0] = Fraction) f_CK = PCLK2 (USART1) 또는 PCLK1 (USART2, USART3)

BRR은 소수점 아래 4비트를 가진 12.4 고정소수점 수이다. 소수부를 16분의 1 단위로 반올림하므로 원하는 보레이트와 실제 보레이트 사이에 양자화 오차가 생긴다. RM0008의 예: USARTDIV = 25.62이면 소수부 16 × 0.62 = 9.92 → 10 = 0xA이고, BRR = 0x19A, 실제 USARTDIV = 25.625이다. 소수부가 반올림으로 16이 되면 정수부로 올림한다(RM0008 27.3.4의 예 3, BRR = 0x330).

USART가 핀을 쓰려면 GPIO 쪽 스위치도 맞아야 한다. TX는 대체 기능 푸시풀 출력(CNF = 10)이고, RX는 플로팅 또는 풀업 입력이다(RM0008 Table 24). 단선 반이중에서는 TX 한 핀으로 주고받는다. 이때 TX가 "보내지 않을 때 놓아 주는" 상태가 되어야 하므로 플로팅 입력이나 오픈드레인 출력(High)으로 두라고 RM0008 27.3.10이 명시한다. 그리고 클럭 게이트도 열어야 한다. USART1은 RCC_APB2ENR, USART2/3은 RCC_APB1ENR의 허용 비트를 켜야 한다.

플래그는 어떻게 지워지는가

SR의 플래그는 지우는 방법이 플래그마다 다르다. "SR을 읽은 뒤 DR을 읽는다" 같은 두 단계 순서로 지워지는 것이 많다. 왜 순서일까? SR을 읽었다는 것은 소프트웨어가 오류를 봤다는 뜻이고, DR을 읽었다는 것은 그 바이트를 처리했다는 뜻이다. 두 일이 모두 일어났을 때만 플래그를 내리면, 소프트웨어가 보지도 않은 오류가 저절로 사라지는 일이 없다. 디지털논리로 보면 "SR 읽기 → DR 읽기"를 검출하는 2상태 시퀀스 검출기이다. 01_GPIO의 LCKR 키 순서와 같은 발상이다.

6. 이벤트 생성 기전: 플래그 → 인터럽트 → DMA → 다른 장치

① 열 가지 사건, 하나의 인터럽트

RM0008 27.4는 "The USART interrupt events are connected to the same interrupt vector"라고 적는다. USART마다 벡터는 하나이다. USART1은 IRQ 37(벡터 주소 0xD4), USART2는 38(0xD8), USART3은 39(0xDC)이다(RM0008 Table 63, p.205). 그래서 ISR(Interrupt Service Routine)은 SR을 읽어 어떤 사건인지 가려야 한다. 01_GPIO에서 본 공유 벡터와 같은 구조가 주변장치 안에 들어 있는 셈이다.

송신 쪽 허용 비트는 특히 조심해야 한다. TXE는 "TDR이 비었다"는 상태이므로, 보낼 것이 없어도 계속 1이다. TXEIE를 켜 둔 채 보낼 데이터가 떨어지면 인터럽트가 끝없이 반복된다. 그래서 송신 인터럽트 방식에서는 마지막 바이트를 넣은 뒤 TXEIE를 끈다.

② DMA 요청: CPU 대신 버스 마스터가 DR을 읽고 쓴다

③ IDLE: "패킷이 끝났다"는 사건

DMA로 받으면 CPU는 바이트가 들어오는 줄도 모른다. 그런데 길이가 정해지지 않은 메시지는 언제 끝났는지 알아야 처리할 수 있다. IDLE 플래그는 수신 선이 한 프레임 이상 1로 머물 때, 즉 송신기가 잠시 멈췄을 때 선다(RM0008 27.3.1·27.6.1). IDLE은 RXNE가 다시 선 뒤에야 또 세트된다. 그래서 바이트가 오지 않는 긴 침묵 동안 반복해서 울리지 않고, 메시지 하나에 한 번 울린다. "DMA로 계속 받고, IDLE 인터럽트 한 번으로 메시지를 잘라 낸다"는 방식이 여기서 나온다.

정오표 ES096 2.9.2(p.21): 송신측 클럭이 수신측보다 빠르면 유휴 프레임 뒤에 오는 시작 비트가 너무 일찍 떨어져 IDLE이 서지 않을 수 있다. 회피책은 없다. 따라서 IDLE만 믿지 말고 길이나 끝 문자 같은 프로토콜 정보로 보완해야 한다.

9. 이해 확인 문제

Q1. f_CK = 36 MHz에서 9600 bps를 내려면 BRR에 무엇을 쓰는가? 실제 보레이트와 오차는?

USARTDIV = 36 000 000 / (16 × 9600) = 234.375이다. 정수부 234 = 0xEA, 소수부 0.375 × 16 = 6이므로 BRR = 0xEA6이다. 나누어떨어지므로 실제 보레이트는 정확히 9600이고 오차는 0 %이다(RM0008 Table 192와 같다).

Q2. 115200 bps 8N1에서 수신 인터럽트 서비스 루틴은 바이트마다 대략 얼마 안에 DR을 읽어야 하는가? 64 MHz CPU로는 몇 클럭인가?

프레임 10비트 × 8.68 µs = 86.8 µs이다. RXNE가 선 뒤 다음 바이트가 RDR로 넘어올 때까지가 마감이므로 약 86.8 µs, 64 MHz로는 약 5 560 클럭이다. 그보다 늦으면 ORE가 선다.

Q3. 한 데이터 비트의 8·9·10번째 샘플이 0, 1, 1이었다. 받은 비트와 NE는?

다수결로 1이고, 세 값이 같지 않으므로 NE = 1이다(RM0008 Table 191: 011 → 1, NE 1). 바이트는 RDR로 넘어가고 RXNE와 NE가 같이 선다. 단일 바이트 수신에서는 NE 단독 인터럽트가 없으므로 RXNE 처리 중에 SR을 보고 판단해야 한다.

Q4. 'A'(0x41)를 8E1(M = 1, PCE = 1, PS = 0)로 보낸다. 패리티 비트는? 선 위의 11비트를 순서대로 써라.

0x41 = 0100 0001에는 1이 두 개이므로 짝수 패리티 비트는 0이다(XOR = 0). 선 위 순서: 시작 0, 데이터 1 0 0 0 0 0 1 0, 패리티 0, 정지 1. 위 프레임 그리기에서 8E1을 골라 확인할 수 있다.

Q5. 마지막 바이트를 DR에 쓰고 TXE = 1을 확인한 직후 USART를 껐더니 상대가 마지막 글자를 받지 못했다. 왜인가?

TXE = 1은 TDR이 비었다는 뜻일 뿐이다. 마지막 바이트는 아직 시프트 레지스터에서 선으로 나가는 중이다. 마지막 프레임이 선을 다 떠난 것은 TC = 1이 알려 준다(Figure 282). 끄기 전에 TC를 기다려야 한다.

Q6. 송신기 클럭은 +2.0 %, 수신기 클럭은 −1.5 % 어긋나 있고 BRR 소수부는 0이 아니다(M = 0). 통신이 보장되는가?

상대 오차는 약 3.5 %이다. 소수부 ≠ 0일 때 허용치는 3.33 %(Table 194, 잡음을 오류로 볼 때)이므로 이미 넘는다. 양자화 오차와 선로 비대칭까지 더하면 더 나쁘다. 보장되지 않는다. 소수부가 0이 되는 클럭·보레이트 조합이면 허용치가 3.75 %로 올라가지만 여전히 여유가 거의 없다.

Q7. 송신 인터럽트(TXEIE = 1)로 문자열을 보낸다. 다 보낸 뒤 CPU가 ISR에서 빠져나오지 못한다. 원인과 해결은?

TXE는 TDR이 비어 있는 동안 계속 1인 상태 플래그이다. 보낼 것이 없어도 TXE·TXEIE AND 게이트가 계속 참이라 인터럽트가 끝없이 다시 걸린다. 마지막 바이트를 넣은 뒤 TXEIE를 0으로 내려야 한다. 마무리 시점이 필요하면 TCIE로 TC 인터럽트를 받는다.

Q8. ORE가 선 것을 보고 DR만 읽었더니 ORE가 지워지지 않았다. 왜인가?

ORE는 SR 읽기 → DR 읽기 순서로만 지워진다(RM0008 27.6.1). SR 읽기 단계를 건너뛰면 시퀀스 검출기가 완성되지 않는다.

Q9. 115200 bps 8N1에서 IDLE이 서려면 선이 최소 얼마 동안 조용해야 하는가? IDLE이 연달아 두 번 서지 않는 이유는?

유휴 프레임은 한 프레임 길이의 1이므로 약 10비트 = 86.8 µs이다. IDLE은 RXNE가 다시 선 뒤에야 다시 세트된다(RM0008 27.6.1 주석). 그래서 메시지 하나가 끝날 때 한 번만 선다.

Q10. 같은 115200 bps인데 USART1과 USART2의 BRR 값이 다르다(SYSCLK 64 MHz, APB1 ÷2, APB2 ÷1). 각각 얼마인가?

USART1은 PCLK2 = 64 MHz이므로 USARTDIV ≈ 34.72 → BRR = 0x22C이다. USART2는 PCLK1 = 32 MHz이므로 ≈ 17.36 → BRR = 0x116이다. 입력 클럭이 두 배이므로 분주값도 두 배이다.

정리
  • USART는 분주기(보레이트) + 시프트 레지스터(PISO/SIPO) + 한 칸 버퍼(TDR/RDR) + 플래그 + 인터럽트 OR 트리이다.
  • 보레이트 = f_CK / (16 × USARTDIV). USART1은 PCLK2, USART2/3은 PCLK1을 쓰므로 같은 보레이트라도 BRR이 다르다. 양쪽 클럭 오차의 합은 3 % 남짓 안에 들어야 한다.
  • 수신기는 비트당 16회 샘플링하고, 시작 비트는 시퀀스 검출로, 각 비트는 3표 다수결로 판정한다. 불일치는 NE이다.
  • TXE는 "TDR 빔", TC는 "선까지 다 나감", RXNE는 "RDR에 새 바이트"이다. RDR은 한 칸이라 프레임 하나 시간 안에 비워야 한다(아니면 ORE).
  • 사건 10가지가 벡터 하나로 모이고, RXNE/TXE는 DMA 요청이 될 수 있으며, IDLE은 메시지 경계를 알려 준다.
