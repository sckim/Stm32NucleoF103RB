DMA 원형 수신과 IDLE 라인: 길이를 모르는 패킷 받기

바이트마다 인터럽트를 받으면 115200 bps에서 초당 최대 11 520번 CPU가 불려 나오고, 패킷이 언제 끝났는지도 따로 판단해야 한다. 이 예제는 DMA1 채널 6이 USART2 수신 바이트를 원형 버퍼에 CPU 개입 없이 쓰게 하고, 라인이 1프레임 이상 조용해지는 IDLE 순간에 한 번만 콜백을 받아 새로 들어온 구간을 패킷으로 잘라 낸다. 폴더는 04_USART_DMA_IdleLine_c이다.

1. 문제: 패킷의 끝을 누가 알려 주는가

02_USART_Interrupt와 03_USART_RingBuffer는 1바이트마다 RXNE 인터럽트를 받았다. 길이가 정해지지 않은 패킷(명령 한 줄, 센서 응답)을 받으려면 바이트를 모으는 일과 끝을 판정하는 일이 모두 CPU 몫이 된다. DMA는 바이트를 옮기는 일을, USART의 IDLE 검출은 끝을 판정하는 일을 하드웨어로 넘긴다. 학습 목표는 다음과 같다.

  • DMA1 채널 6의 원형 모드 설정(CCR의 CIRC·MINC·TCIE·HTIE)과 USART_CR3.DMAR의 역할을 설명한다.
  • SR.IDLE가 언제 서고 어떤 순서(SR 읽기 → DR 읽기)로 지워지는지 설명한다.
  • 콜백 인자 Size = 128 − CNDTR과 old_pos로 새 데이터 구간과 랩어라운드를 계산한다.
  • IDLE 이벤트와 TC(버퍼 끝) 이벤트가 같은 콜백으로 들어올 때 패킷이 어떻게 나뉘는지 추적한다.
이 예제의 동작

PC 터미널(115200 8N1)에서 문자열을 한 번에 보내면 DMA가 dma_buf[128]에 차례로 쓴다. 마지막 바이트 뒤 1프레임 동안 무신호이면 IDLE 인터럽트가 걸리고, HAL_UARTEx_RxEventCallback이 old_pos~Size 구간을 pkt에 복사한 뒤 pkt_ready를 세운다. main은 [RX n bytes, events=e, drop=d] 내용을 돌려보낸다.

이 예제는 검토 전(컴파일만 확인) 상태이다.

2. 세 가지 수신 이벤트: IDLE, TC, HT

HAL_UARTEx_ReceiveToIdle_DMA()로 수신을 시작하면 세 하드웨어 이벤트가 모두 같은 사용자 콜백 HAL_UARTEx_RxEventCallback(huart, Size)으로 모인다. Size는 "받은 바이트 수"가 아니라 버퍼 안에서 다음에 쓸 위치이다.

이벤트하드웨어 원인HAL이 넘기는 Size이 예제
IDLEUSART_SR.IDLE = 1 (마지막 수신 후 1프레임 무신호), CR1.IDLEIE = 1128 − CNDTR (단, CNDTR이 0 < CNDTR < 128일 때만 호출)사용 — 패킷 끝
TCDMA CNDTR이 0이 됨 → DMA_ISR.TCIF6, CCR.TCIE = 1128 (버퍼 크기)사용 — 버퍼 끝 도달
HTCNDTR이 절반(64) 남음 → HTIF6, CCR.HTIE = 164 (버퍼 크기 / 2)끔 — __HAL_DMA_DISABLE_IT(…, DMA_IT_HT)

그림 1. 프레임(시작 비트 + 8데이터 + 정지 비트 = 10비트)이 연달아 오는 동안 IDLE은 서지 않는다. 마지막 정지 비트 뒤 라인이 1프레임 시간(115200 bps에서 10 / 115200 ≈ 86.8 µs) 동안 High로 유지되면 SR.IDLE이 선다. 파형의 비트 패턴은 모식이다.

Size = RxXferSize − CNDTR = 128 − CNDTR 새 데이터 = dma_buf[old_pos … Size−1] (Size > old_pos) len = Size − old_pos, 처리 후 old_pos = (Size ≥ 128) ? 0 : Size

그림 2. TC 인터럽트가 켜져 있으므로 버퍼 끝을 넘는 패킷은 두 이벤트로 나뉜다. TC 콜백이 old_pos를 0으로 되돌리기 때문에 콜백의 랩어라운드 분기(Size < old_pos)는 TC 이벤트를 놓친 경우에만 실행된다.

IDLE 클리어 순서

F1의 SR.IDLE은 쓰기로 지워지지 않는다. SR을 읽은 다음 DR을 읽는 소프트웨어 시퀀스가 플래그를 지운다. 한 번 지운 뒤에는 새 바이트가 들어와 RXNE가 다시 설 때까지 IDLE이 또 서지 않으므로, 패킷 하나에 IDLE 이벤트는 한 번만 생긴다.

6. 인터럽트 경로

  1. 1
    바이트 수신 → RXNE하드웨어PA3로 들어온 프레임이 DR로 옮겨지고 SR.RXNE = 1. CR3.DMAR = 1이므로 인터럽트 대신 DMA 요청이 나간다.
  2. 2
    DMA1 채널 6 전송하드웨어USART2->DR을 읽어 dma_buf[128 − CNDTR]에 쓰고 CNDTR을 1 줄인다. DR 읽기로 RXNE가 지워진다. CPU는 관여하지 않는다.
  3. 3
    1프레임 무신호 → SR.IDLE = 1하드웨어CR1.IDLEIE = 1이므로 USART2_IRQn이 요청된다.
  4. 4
    USART2_IRQHandler → HAL_UART_IRQHandler소프트웨어stm32f1xx_it.c의 진짜 ISR. HAL이 IDLE을 지우고 CNDTR을 읽는다.
  5. 5
    HAL_UARTEx_RxEventCallback(huart, 128 − CNDTR)소프트웨어main.c의 사용자 코드(ISR 문맥). 새 구간을 pkt에 복사하고 pkt_ready = 1.
  6. 6
    (버퍼 끝) CNDTR = 0 → TCIF6하드웨어원형 모드이므로 CNDTR이 128로 재장전되고 쓰기 위치는 0으로 돌아간다. DMA1_Channel6_IRQHandler → HAL_DMA_IRQHandler → 같은 콜백(Size = 128).
  7. 7
    main 루프소프트웨어pkt_ready를 보면 머리말·패킷·CRLF를 블로킹 송신하고, 다 보낸 뒤에야 pkt_ready = 0으로 내린다.

  1. Instance가 DMA1 채널 6이다. USART2_RX 요청이 이 채널에 고정 배정되어 있으므로 다른 채널을 고르면 동작하지 않는다.

main.c — 수신 시작과 main 루프
/* DMA 수신 + IDLE 이벤트 시작. 반 버퍼(HT) 이벤트는 끄고 IDLE/TC 만 받는다 */
if (HAL_UARTEx_ReceiveToIdle_DMA(&huart2, dma_buf, DMA_BUF_SIZE) != HAL_OK) Error_Handler();
__HAL_DMA_DISABLE_IT(&hdma_usart2_rx, DMA_IT_HT);          /* DMA1_Channel6->CCR.HTIE = 0 */

while (1)
{
  if (pkt_ready)
  {
    uint16_t len = pkt_len;
    int n = snprintf(head, sizeof head, "[RX %u bytes, events=%lu, drop=%lu] ",
                     (unsigned)len, (unsigned long)event_count, (unsigned long)pkt_dropped);
    HAL_UART_Transmit(&huart2, (uint8_t *)head, (uint16_t)n, 100);
    HAL_UART_Transmit(&huart2, pkt, len, 200);
    HAL_UART_Transmit(&huart2, (uint8_t *)"\r\n", 2, 100);
    pkt_ready = 0;

}
  1. 수신은 한 번만 시작한다. 원형 모드라 이후 재무장이 필요 없다.
  2. pkt_ready를 송신이 끝난 뒤에 내린다. 그동안 콜백은 pkt를 덮어쓰지 않고 새 패킷을 버린다(pkt_dropped). 데이터 경쟁은 막지만, 출력 중에 들어온 패킷은 잃는다.
  3. 머리말만 약 30바이트이므로 출력에 2.6 ms 이상 걸린다(1바이트 86.8 µs). 이 시간은 다음 패킷이 도착하기에 충분히 길다.
main.c — HAL_UARTEx_RxEventCallback (ISR 문맥)
void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t Size)
{
  if (huart->Instance != USART2) return;
  event_count++;

  /* Size = dma_buf 안에서 "다음에 쓸 위치". 원형 버퍼이므로 old_pos -> Size 구간이 새 데이터 */
  uint16_t len = 0;
  if (Size != old_pos)
  {
    if (pkt_ready)
    {
      pkt_dropped++;   /* main 이 아직 이전 패킷을 안 가져감 */
    }
    else
    {
      if (Size > old_pos)
      {
        len = Size - old_pos;
        memcpy(pkt, &dma_buf[old_pos], len);
      }
      else             /* 버퍼 끝을 넘어 래핑된 경우 */
      {
        uint16_t first = DMA_BUF_SIZE - old_pos;
        memcpy(pkt, &dma_buf[old_pos], first);
        memcpy(pkt + first, dma_buf, Size);
        len = first + Size;
      }
      pkt_len = len;
      pkt_ready = 1;
    }
  }
  old_pos = (Size >= DMA_BUF_SIZE) ? 0 : Size;
}
  1. 콜백은 IDLE(Size = 128 − CNDTR)과 TC(Size = 128) 양쪽에서 불린다.
  2. Size != old_pos는 새 데이터가 있을 때만 처리하게 한다.
  3. TC 콜백에서 old_pos가 0으로 돌아가므로, TC 이벤트를 놓치지 않는 한 else(랩어라운드) 분기는 실행되지 않는다. 버퍼 끝을 넘는 패킷은 그림 2처럼 두 조각이 된다.
  4. 버린 경우에도 old_pos는 갱신한다. 버려진 바이트는 다시 처리되지 않는다.
기대 출력 (터미널에서 "hello"를 한 번에 전송)
[USART2 DMA + IDLE] 문자열을 보내 보세요
[RX 5 bytes, events=1, drop=0] hello

배너의 한글은 UTF-8로 저장되어 있으므로 터미널 인코딩이 UTF-8이어야 한다. 키보드로 한 글자씩 타이핑하면 글자 사이 간격이 86.8 µs보다 훨씬 길어 글자마다 IDLE 이벤트가 생긴다. "한 줄을 모아 보내기" 또는 붙여넣기로 보내야 패킷 하나가 된다.

8. 실험

실험 A. 타이핑과 붙여넣기 비교

터미널에서 "abc"를 한 글자씩 입력한 경우와 붙여넣기한 경우의 events 증가량을 비교한다. 바이트당 인터럽트였던 02 예제의 인터럽트 횟수와도 비교한다.

실험 B. 버퍼 끝 넘기기

30바이트 문자열을 다섯 번 연속 보낸다(150바이트 > 128). 다섯 번째 패킷이 버퍼 끝을 넘을 때 출력 길이와 drop 값이 어떻게 변하는지 기록하고 그림 2와 대조한다. 시뮬레이터(N = 32)로 먼저 예측한다.

실험 C. HT 이벤트 되살리기

__HAL_DMA_DISABLE_IT 줄을 주석 처리하고 100바이트를 한 번에 보낸다. 64바이트 위치에서 HT 콜백이 끼어들어 패킷이 둘로 나뉘는지 확인한다.

실험 D. 버퍼보다 긴 패킷

200바이트를 한 번에 보낸다. DMA는 멈추지 않고 버퍼 앞부분을 덮어쓰므로, TC·IDLE 이벤트가 각각 무엇을 복사하는지 예측한 뒤 출력과 비교한다. DMA_BUF_SIZE는 예상 최대 패킷보다 커야 한다는 결론을 얻는다.

10. 확인 문제

문제 1. old_pos = 20일 때 IDLE 인터럽트 시점의 CNDTR이 100이었다. Size와 패킷 길이는?

Size = 128 − 100 = 28, len = 28 − 20 = 8바이트이다. 콜백 뒤 old_pos = 28이 된다.

문제 2. 보레이트를 9600 bps로 낮추면 IDLE이 서기까지 걸리는 무신호 시간은?

10비트 / 9600 bps ≈ 1.04 ms이다. 송신 측이 바이트 사이에 1 ms 이상 쉬면 한 패킷이 여러 이벤트로 나뉜다.

문제 3. 콜백의 else(랩어라운드) 분기가 이 예제에서 거의 실행되지 않는 이유는?

TC 인터럽트가 켜져 있어 쓰기 위치가 버퍼 끝에 닿는 순간 Size = 128로 콜백이 불리고 old_pos가 0이 된다. 이후 IDLE의 Size는 항상 old_pos보다 크다. TC를 끄고 IDLE만 쓰면 이 분기가 필요해진다.

문제 4. 패킷이 CNDTR = 0이 되는 순간 정확히 끝났다. IDLE 인터럽트에서 콜백이 또 불리는가?

불리지 않는다. 재장전 후 CNDTR = 128이고, HAL은 0 < CNDTR < 128일 때만 IDLE 콜백을 부른다. 데이터는 이미 TC 콜백에서 처리되었다.
