UART 명령줄 인터페이스: 줄 편집과 명령 테이블

보드를 디버깅하거나 설정을 바꿀 때마다 코드를 고쳐 다시 굽는 것은 비효율적이다. 터미널에서 led on, peek 0x40010800처럼 명령을 입력해 보드와 대화하면 된다. 이 예제는 인터럽트 링 버퍼로 바이트를 받고, main에서 줄 편집(에코·백스페이스·CR/LF)으로 한 줄을 조립한 뒤, 공백으로 토큰을 나눠 함수 포인터 명령 테이블에서 핸들러를 찾아 호출한다. 폴더는 05_UART_CLI_c이다.

1. 문제: 바이트 흐름을 명령으로 바꾼다

UART로 들어오는 것은 글자 하나하나이다. 사람이 입력하는 명령은 "Enter로 끝나는 한 줄"이고, 그 안에서 명령어와 인자가 공백으로 나뉜다. 바이트 흐름 → 줄 → 토큰 → 함수 호출로 단계를 나누면 각 단계를 따로 이해하고 고칠 수 있다. 학습 목표는 다음과 같다.

  • ISR(생산자)과 main(소비자) 사이의 링 버퍼를 03 예제와 연결해 설명한다.
  • 에코, 백스페이스("\b \b"), CR/LF 처리로 줄 편집기를 구현하는 원리를 설명한다.
  • strtok로 argc/argv를 만들고, 구조체 배열 + 함수 포인터 테이블로 명령을 찾는다.
  • 명령을 추가하는 절차와 peek처럼 위험한 명령의 주의점을 정리한다.
이 예제의 동작

부팅하면 [UART CLI] type 'help'와 프롬프트 > 를 출력한다. 사용자가 입력한 글자는 즉시 에코되고, Enter(CR 또는 LF)를 받으면 줄을 해석해 명령을 실행한 뒤 새 프롬프트를 띄운다. 지원 명령은 help, led, uptime, echo, peek, reset이다.

이 예제는 검토 전(컴파일만 확인) 상태이다.

2. 3단계 구조: 수신 → 줄 조립 → 파싱

그림 1. 단계 사이의 경계가 곧 문맥의 경계이다. ISR은 1바이트를 링 버퍼에 넣고 끝나며, 줄 편집·파싱·명령 실행은 모두 main 루프에서 일어난다.

6. 실행 경로: 키 하나가 명령이 되기까지

  1. 1
    PC 키 입력 → ST-LINK VCP → PA3하드웨어한 글자 = 1프레임(86.8 µs). SR.RXNE = 1, RXNEIE = 1이면 USART2_IRQn 요청.
  2. 2
    USART2_IRQHandler → HAL_UART_IRQHandler소프트웨어DR을 rx_byte로 읽고 HAL_UART_RxCpltCallback 호출.
  3. 3
    콜백: 링 버퍼 push + 재무장ISR 문맥next = (rb_head + 1) & 63, next != rb_tail이면 저장 후 rb_head = next. 가득 차면 버린다. 마지막에 HAL_UART_Receive_IT 재호출.
  4. 4
    main: pop과 줄 편집소프트웨어rb_head != rb_tail이면 1바이트를 꺼내 CR/LF, BS/DEL, 출력 가능 문자로 분기한다.
  5. 5
    Enter → execute(line)소프트웨어strtok(line, " \t")로 최대 6개 토큰. argc = 0(빈 줄)이면 아무것도 하지 않는다.
  6. 6
    테이블 검색과 호출소프트웨어cmd_table[i].name과 argv[0]을 strcmp로 비교, 일치하면 cmd_table[i].fn(argc, argv). 없으면 unknown 메시지.
  7. 7
    결과 출력과 프롬프트소프트웨어핸들러가 out()으로 블로킹 송신 → main이 len = 0, "> " 출력.

7. 코드 읽기

외부 부품은 필요 없다. 터미널은 115200 8N1, 로컬 에코 끔, 문자 인코딩 UTF-8(도움말의 한글)로 둔다.

main.c — 명령 테이블과 help
typedef void (*cmd_fn)(int argc, char **argv);

static const struct { const char *name; cmd_fn fn; const char *help; } cmd_table[] = {
    { "help",   cmd_help,   "명령 목록" },
    { "led",    cmd_led,    "led on|off|toggle" },
    { "uptime", cmd_uptime, "부팅 후 경과 시간" },
    { "echo",   cmd_echo,   "echo <text>" },
    { "peek",   cmd_peek,   "peek <hex_addr>  (32비트 읽기)" },
    { "reset",  cmd_reset,  "소프트웨어 리셋" },
};
#define N_CMDS (sizeof cmd_table / sizeof cmd_table[0])

static void cmd_help(int argc, char **argv)
{
    (void)argc; (void)argv;
    for (unsigned i = 0; i < N_CMDS; i++) { out("  "); out(cmd_table[i].name); out(" - "); out(cmd_table[i].help); out("\r\n"); }
}
  1. 모든 핸들러가 같은 서명 void f(int, char **)을 가지므로 함수 포인터 하나로 부를 수 있다.
  2. 테이블은 static const라 플래시에 놓인다. 명령 추가 = 핸들러 작성 + 테이블 한 줄.
  3. N_CMDS는 컴파일 시 계산되어 테이블 길이를 따로 관리할 필요가 없다.
  4. help는 테이블을 그대로 순회하므로 명령을 추가하면 도움말도 자동으로 늘어난다.
main.c — execute(): 토큰화와 디스패치
static void execute(char *line)
{
    char *argv[MAX_ARGS];
    int argc = 0;
    for (char *t = strtok(line, " \t"); t && argc < (int)MAX_ARGS; t = strtok(NULL, " \t")) argv[argc++] = t;
    if (argc == 0) return;
    for (unsigned i = 0; i < N_CMDS; i++)
    {
        if (!strcmp(argv[0], cmd_table[i].name)) { cmd_table[i].fn(argc, argv); return; }
    }
    out("unknown command (type 'help')\r\n");
}
  1. strtok은 구분자 연속을 하나로 취급하므로 led on도 토큰 2개가 된다.
  2. argv의 포인터는 line 내부를 가리킨다. 복사가 없으므로 메모리를 아끼지만, line을 덮어쓰기 전에 처리를 끝내야 한다.
  3. strcmp는 대소문자를 구분한다. LED on은 unknown이다.
main.c — main 루프의 줄 편집
while (1)
{
  if (rb_head == rb_tail) continue;                 /* 수신 데이터 없음 */
  uint8_t c = rb_buf[rb_tail];
  rb_tail = (rb_tail + 1U) & RB_MASK;
  if (c == '\r' || c == '\n')                       /* 줄 완성 */
  {
    out("\r\n");
    line[len] = '\0';
    execute(line);
    len = 0;
    out("> ");
  }
  else if (c == 0x08 || c == 0x7F)                  /* 백스페이스: 화면에서 한 글자 지우기 "\b \b" */
  {
    if (len > 0) { len--; out("\b \b"); }
  }
  else if (c >= 0x20 && c < 0x7F && len < LINE_MAX - 1U)   /* 출력 가능한 문자만 */
  {
    line[len++] = (char)c;
    HAL_UART_Transmit(&huart2, &c, 1, 10);          /* 에코 */
  }
}
  1. CR과 LF를 모두 줄 끝으로 본다. 터미널이 CR+LF를 보내면 빈 줄이 하나 더 처리되어 프롬프트가 두 번 찍힌다.
  2. "\b \b": 커서를 왼쪽으로 옮기고, 공백으로 글자를 덮은 뒤, 다시 왼쪽으로 온다. 터미널 화면과 line이 같은 상태를 유지한다.
  3. 에코는 저장한 글자에만 한다. 무시된 글자는 화면에도 나타나지 않으므로 사용자는 줄이 꽉 찼음을 알 수 있다.
main.c — HAL_UART_RxCpltCallback (ISR 문맥)
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
  if (huart->Instance != USART2) return;
  uint32_t next = (rb_head + 1U) & RB_MASK;
  if (next != rb_tail) { rb_buf[rb_head] = rx_byte; rb_head = next; }
  HAL_UART_Receive_IT(&huart2, &rx_byte, 1);
}
  1. 03 예제와 같은 lock-free 링 버퍼이다. 데이터를 먼저 쓰고 rb_head를 나중에 갱신한다.
  2. HAL_UART_ErrorCallback도 같은 재무장을 하여 오버런 뒤에도 수신이 멈추지 않는다.

8. 실험

실험 A. CR, LF, CR+LF

터미널의 송신 줄바꿈 설정을 CR, LF, CR+LF로 바꿔 가며 help를 입력한다. CR+LF에서 프롬프트가 두 번 찍히는 이유를 코드로 설명하고, 직전 문자가 CR일 때 LF를 무시하도록 고치는 방법을 생각한다.

실험 B. 화살표 키

명령 중간에 ← 키를 누르고 Enter를 친다. 터미널은 ESC [ D 3바이트를 보내며, ESC는 무시되지만 [와 D는 출력 가능 문자라 줄에 들어간다. 명령이 unknown이 되는 것을 확인한다.

실험 C. 명령 추가

ver 명령을 추가한다. 핸들러 cmd_ver를 작성하고 cmd_table에 한 줄을 넣은 뒤 help 출력에 자동으로 나타나는지 확인한다. 테이블 위에 프로토타입이 필요한 이유(cmd_help의 선언 방식)도 살펴본다.

실험 D. 인자 한도와 줄 길이

echo 1 2 3 4 5 6 7 8을 입력하면 argv[0] = echo를 포함해 6개만 받으므로 1 2 3 4 5만 출력된다. 또 64글자 이상을 붙여넣어 63글자 이후가 무시되는지 확인한다.

10. 확인 문제

문제 1. led   on(공백 3칸)과 Tab으로 구분한 led→on은 각각 어떻게 처리되는가?

공백 3칸은 strtok이 하나의 구분으로 처리해 led on과 같다. Tab(0x09)은 출력 가능 문자가 아니어서 줄 편집 단계에서 버려지므로 line은 "ledon"이 되고 unknown이다. strtok의 "\t" 구분자는 이 경로로는 쓰일 일이 없다.

문제 2. 백스페이스 처리에서 "\b" 하나만 보내면 화면에 어떤 문제가 생기는가?

커서만 왼쪽으로 가고 글자는 화면에 남는다. line에서는 지워졌는데 화면에는 보여 사용자가 혼동한다. 공백으로 덮고 다시 왼쪽으로 가야 화면과 버퍼가 일치한다.

문제 3. peek zz를 입력하면 무엇이 출력되는가?

strtoul("zz", NULL, 16)은 변환할 숫자가 없어 0을 돌려준다. 0은 4바이트 정렬이므로 주소 0x00000000을 읽는다. 플래시 부팅이면 이 영역은 플래시의 별칭이라 초기 MSP 0x20005000이 나온다. 입력 검증(endptr 확인)이 없다는 점을 보여 준다.

문제 4. 명령 처리를 ISR(콜백) 안에서 하지 않고 main에서 하는 이유는?

핸들러는 블로킹 송신(out()), HAL_Delay(reset) 등 오래 걸리는 일을 한다. ISR에서 하면 그동안 다음 바이트 수신이 막히고, 같은 우선순위 이하 인터럽트도 지연된다. ISR은 1바이트 저장만 하고 나머지는 main이 맡는다.
