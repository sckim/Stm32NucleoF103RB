USART 단선 반이중: 한 가닥 선으로 묻고 답하기

스마트 서보, 일부 센서 버스, RS-485는 송신선과 수신선을 따로 두지 않고 한 선을 번갈아 쓴다. 선이 하나이므로 "지금 누가 말하는가"를 하드웨어(오픈드레인 + 풀업)와 프로토콜(질문 → 응답)로 정해야 한다. 이 예제는 USART1을 단선 모드(CR3.HDSEL = 1, PA9)로 두고, 같은 보드의 USART3(PB10/PB11)를 가짜 슬레이브로 한 선에 묶어 PING/PONG을 주고받는다. 수신은 상대가 보내기 전에 인터럽트로 무장한다. 폴더는 06_USART_HalfDuplex_c이다.

1. 문제: 선 하나를 둘이 나눠 쓴다

전이중 UART에서 TX끼리 직접 연결하면, 한쪽이 High를 내고 다른 쪽이 Low를 낼 때 두 푸시풀 출력이 단락된다. 한 선을 공유하려면 각 노드는 선을 Low로 끌어내리거나 놓아 주기만 해야 하고, 놓인 선은 풀업 저항이 High로 만든다. 또 수신 데이터 레지스터가 1바이트뿐이므로 상대가 말하기 전에 들을 준비를 해 두어야 한다. 학습 목표는 다음과 같다.

  • USART_CR3.HDSEL이 TX 핀 하나로 송수신하게 만드는 원리와 HAL 초기화 함수를 설명한다.
  • 오픈드레인 + 풀업 버스가 와이어드-AND로 동작하는 이유와 F1의 내부 풀업 한계를 설명한다.
  • HAL_HalfDuplex_EnableTransmitter/Receiver가 바꾸는 CR1.TE/RE와 TC 대기의 의미를 설명한다.
  • 수신을 상대 송신 전에 인터럽트(HAL_UART_Receive_IT, RXNEIE)로 무장해야 하는 이유를 DR 1바이트와 SR.ORE로 설명하고, 자기 에코를 처리한다.
이 예제의 동작

1초마다 다음 순서로 한 주기를 돈다. ① 슬레이브(USART3) 수신을 인터럽트로 무장 → ② 마스터(USART1, 57600 bps)가 송신 모드로 PING 송신, 슬레이브 수신 완료 대기 → ③ 마스터를 수신 모드로 바꾸고 응답 수신 무장 → ④ 슬레이브가 자기 에코 수신을 무장한 뒤 PONG 송신, 에코와 마스터 수신 완료 대기. 결과(슬레이브·마스터가 받은 문자열, ok/fail 횟수)를 USART2 가상 COM(115200 bps)으로 출력한다. 송신은 폴링, 수신은 인터럽트이다.

이 예제는 검토 전(컴파일만 확인) 상태이다.

4. 직접 만져 보기: 버스 구동과 수신 무장 순서

위쪽은 와이어드-AND 버스, 아래쪽은 main 루프 한 바퀴를 단계별로 실행하는 시뮬레이터이다. 아래쪽은 현재 코드(수신을 송신 전에 인터럽트로 무장)와 비교용 이전 코드(블로킹 송신이 끝난 뒤 블로킹 수신 시작) 두 모델을 고를 수 있다.

  1. 마스터·슬레이브 출력 버튼을 눌러 버스 레벨이 와이어드-AND와 맞는지 확인한다. 마스터를 수신 모드(TE = 0)로 두면 마스터의 Low가 버스에 나가지 않는다.
  2. 둘 다 Low를 내 보며 "충돌"이 어떻게 표시되는지 본다.
  3. 현재 코드 모델로 다음 단계를 끝까지 눌러 PING·PONG의 각 바이트가 ISR에서 바로 버퍼로 옮겨지는 것을 본다. 결과 줄이 ok로 끝나는지 확인한다.
  4. 모델을 이전 코드로 바꿔 같은 과정을 반복한다. USART3의 DR, RXNE, ORE가 어떻게 변하는지 비교한다.

시뮬레이터 모델: 수신기는 RM0008의 동작을 따른다. RXNE = 1인 상태에서 다음 바이트가 끝나면 ORE = 1이 되고 DR의 앞 바이트는 남지만 새 바이트는 잃는다. 수신이 인터럽트로 무장되어 있으면 ISR이 바이트마다 DR을 곧바로 읽는 것으로 본다(57600 bps의 1프레임 173.6 µs 안에 ISR이 끝난다고 가정). 블로킹 HAL_UART_Transmit은 끝날 때까지 main을 붙잡지만 ISR은 그 사이에도 실행된다. "이전 코드"는 폴더의 예전 버전을 분석한 모델이다. 비트 단위 타이밍과 풀업 상승 시간은 다루지 않는다.

6. 실행 경로: main 루프 한 바퀴

  1. 1
    HAL_UART_Receive_IT(&huart3, slave_rx, 4)소프트웨어슬레이브 수신을 먼저 무장한다. USART3 RXNEIE = 1.
  2. 2
    EnableTransmitter(&huart1) → HAL_UART_Transmit(&huart1, "PING")소프트웨어USART1 TE = 1, RE = 0. PA9가 4프레임(약 0.69 ms)을 내는 동안 main은 TC까지 블로킹된다.
  3. 3
    PB11 수신 → SR.RXNE → USART3_IRQn하드웨어바이트마다 NVIC가 블로킹 중인 main을 선점한다.
  4. 4
    USART3_IRQHandler → HAL_UART_IRQHandlerISRDR을 읽어 slave_rx에 저장. 4바이트째에서 RXNEIE = 0, RxState = READY.
  5. 5
    st_slave = WaitRx(&huart3, 20)소프트웨어이미 READY이므로 곧바로 HAL_OK. "PING"이면 응답 단계로 간다.
  6. 6
    EnableReceiver(&huart1) → Receive_IT(&huart1, rsp, 4) → Receive_IT(&huart3, echo, 4)소프트웨어마스터는 TE = 0, RE = 1, RXNEIE = 1. 슬레이브는 자기 에코를 받을 준비를 한다. 두 수신 모두 PONG보다 먼저 무장된다.
  7. 7
    HAL_UART_Transmit(&huart3, "PONG") → 두 수신기 동시 수신버스PB10이 낸 신호를 PA9(USART1)와 PB11(USART3)이 함께 듣는다. USART1_IRQHandler와 USART3_IRQHandler가 바이트마다 각각 실행된다(같은 우선순위라 서로 선점하지 않고 차례로 처리).
  8. 8
    WaitRx(&huart3), st_master = WaitRx(&huart1) → 판정·로그소프트웨어rsp == "PONG"이면 ok++. USART2로 한 줄 출력 후 HAL_Delay(1000).

stm32f1xx_it.c — 진짜 ISR
void USART1_IRQHandler(void)
{
  /* [ISR] 마스터(단선) 수신. HAL_UART_IRQHandler 가 SR.RXNE 면 DR 을 읽어 버퍼에 저장하고,
   * 지정 바이트 수가 차면 CR1.RXNEIE=0, RxState=READY 로 돌린다. 오류(ORE/FE/NE)면 수신을 중단한다. */
  HAL_UART_IRQHandler(&huart1);
}

void USART3_IRQHandler(void)
{
  /* [ISR] 가짜 슬레이브 수신 (PING 수신, 자기 PONG 에코 수신). 동작은 USART1_IRQHandler 와 같다. */
  HAL_UART_IRQHandler(&huart3);
}
  1. 핸들러 이름은 시작 파일의 벡터 테이블 이름과 정확히 같아야 한다.
  2. 이 예제는 HAL_UART_RxCpltCallback을 구현하지 않는다. 완료는 RxState로 확인한다.
main.c — WaitRx (USER CODE 0)
static HAL_StatusTypeDef WaitRx(UART_HandleTypeDef *huart, uint32_t timeout_ms)
{
  uint32_t t0 = HAL_GetTick();
  while (huart->RxState != HAL_UART_STATE_READY)
  {
    if ((HAL_GetTick() - t0) > timeout_ms)
    {
      HAL_UART_AbortReceive(huart);
      return HAL_TIMEOUT;
    }
  }
  return (huart->ErrorCode == HAL_UART_ERROR_NONE) ? HAL_OK : HAL_ERROR;
}
  1. ISR이 4바이트를 다 받으면 RxState가 READY가 된다. 오류로 중단되어도 READY가 되므로 ErrorCode로 구분한다.
  2. 시간 초과면 수신을 취소해 다음 주기에 Receive_IT가 BUSY로 거부되지 않게 한다.
  3. 뺄셈 비교 (now − t0) > timeout은 틱 카운터가 넘어가도 올바르게 동작한다.
main.c — main 루프 (USER CODE 3)
/* 1) 슬레이브 수신을 먼저 무장한다: USART3->CR1.RXNEIE=1 (바이트마다 ISR 이 DR 을 읽어 slave_rx 에 저장)
 *    마스터가 송신을 시작한 뒤에 받기 시작하면 DR(1바이트) 에 첫 바이트만 남고 나머지는 ORE 로 사라진다. */
HAL_UART_Receive_IT(&huart3, slave_rx, 4);

/* 2) 마스터: 송신 모드로 바꾸고 "PING" 전송 (마지막 바이트 TC 까지 대기) */
HAL_HalfDuplex_EnableTransmitter(&huart1);                 /* USART1->CR1.TE=1, RE=0 */
HAL_UART_Transmit(&huart1, req, 4, 50);
st_slave = WaitRx(&huart3, 20);                            /* 4바이트 = 약 0.7ms (57600bps) */

if (st_slave == HAL_OK && memcmp(slave_rx, "PING", 4) == 0)
{
  /* 3) 마스터: 수신 모드로 바꾸고 응답 수신을 먼저 무장한다 (USART1->CR1.TE=0, RE=1, RXNEIE=1) */
  HAL_HalfDuplex_EnableReceiver(&huart1);
  HAL_UART_Receive_IT(&huart1, rsp, 4);

  /* 4) 슬레이브: 자기 송신이 PB11 로 되돌아오므로(같은 선) 에코 4바이트를 받을 수신도 먼저 무장한 뒤 "PONG" 응답 */
  uint8_t pong[4] = { 'P', 'O', 'N', 'G' };
  uint8_t echo[4];
  HAL_UART_Receive_IT(&huart3, echo, 4);
  HAL_UART_Transmit(&huart3, pong, 4, 50);
  WaitRx(&huart3, 20);                                     /* 자기 응답의 에코 제거 */
  st_master = WaitRx(&huart1, 20);                         /* 마스터가 응답 수신 */
}

if (st_master == HAL_OK && memcmp(rsp, "PONG", 4) == 0) ok++; else fail++;
  1. 모든 수신이 상대 송신보다 먼저 무장된다. 송신은 블로킹이어도 ISR이 바이트마다 DR을 비우므로 오버런이 생기지 않는다.
  2. 방향 전환은 송신이 TC까지 끝난 뒤에 한다. HAL_UART_Transmit이 TC를 기다리므로 순서만 지키면 된다.
  3. 마스터는 PING 송신 중 RE = 0이라 자기 송신을 듣지 않는다. USART3는 전이중 그대로라 PONG을 자기 RX로 다시 듣는다. 그 4바이트를 echo로 받아 버린다.
  4. 결과 출력(snprintf → USART2)과 HAL_Delay(1000)는 이전과 같다.
기대 출력 (USART2, 정상 배선)
#0  slave got "PING"  master got "PONG"  ok=1 fail=0
#1  slave got "PING"  master got "PONG"  ok=2 fail=0
이전 버전의 문제와 수정

이전 버전은 수신을 송신이 끝난 뒤에 블로킹 HAL_UART_Receive(&huart3, slave_rx, 4, 50)로 시작했다. USART 수신 데이터 레지스터는 1바이트뿐이라, PING이 버스를 지나는 동안 아무도 USART3->DR을 읽지 않으면 첫 바이트 'P'만 DR에 남고(RXNE = 1) 둘째 바이트가 끝나는 순간 SR.ORE = 1이 되며 'I', 'N', 'G'는 사라진다. 이후 수신 함수는 'P' 하나를 읽고 나머지를 기다리다 시간 초과되어, 출력은 매번 slave got "P" master got "", fail 증가였다(소스 분석 결과). 현재 코드는 각 수신을 상대 송신 전에 HAL_UART_Receive_IT로 무장하고, 완료를 WaitRx로 확인하는 구조로 고쳤다. 시뮬레이터의 "이전 코드" 모델로 두 구조를 비교할 수 있다.

8. 실험

실험 A. 그대로 실행

배선 후 실행해 로그가 ok만 증가하는지 확인한다. AD2로 버스를 보면서 PING과 PONG 사이의 간격(방향 전환 + 수신 무장 시간)을 측정한다.

실험 B. 무장 순서 바꾸기 (실패 재현)

1)의 HAL_UART_Receive_IT(&huart3, slave_rx, 4) 줄을 HAL_UART_Transmit(&huart1, …) 아래로 옮긴다. 송신 중에 아무도 DR을 읽지 않으므로 이전 버전처럼 'P'만 남고, 무장 직후 ORE 오류 인터럽트가 걸려 WaitRx가 HAL_ERROR를 돌려줄 것으로 예측된다. slave got 문자열과 fail 증가를 확인한다.

실험 C. 에코 수신을 지우기

4)의 HAL_UART_Receive_IT(&huart3, echo, 4)와 그 WaitRx를 지운다. 이번 주기는 성공하지만 USART3의 DR에 PONG의 'P'와 ORE가 남는다. 다음 주기의 슬레이브 수신이 어떻게 되는지 예측하고 확인한다.

실험 D. 풀업 저항과 에지

외부 4.7 kΩ이 있을 때와 없을 때(PB11 내부 풀업만) 상승 에지 시간을 비교한다. 57600 bps의 1비트는 17.4 µs이다.

10. 확인 문제

문제 1. 두 노드의 TX를 푸시풀로 두고 한 선에 묶으면 어떤 일이 생기는가?

한쪽이 High(3.3 V로 구동), 다른 쪽이 Low(GND로 구동)일 때 두 출력 트랜지스터를 통해 전원과 GND가 단락된다. 큰 전류로 핀이 손상될 수 있고 버스 레벨도 정해지지 않는다. 오픈드레인은 High를 구동하지 않으므로 이런 충돌이 단락으로 이어지지 않는다.

문제 2. 송신 후 TXE만 확인하고 바로 수신 방향으로 바꾸면 무엇이 문제인가?

TXE는 DR이 비었다는 뜻일 뿐, 마지막 바이트는 아직 시프트 레지스터에서 나가는 중이다. 이때 TE를 끄면 마지막 프레임이 잘린다. TC(전송 완료)는 정지 비트까지 나간 뒤 서므로 TC를 기다려야 한다.

문제 3. 이전 버전에서 slave_rx에 'P' 한 글자만 들어간 이유와, 현재 코드가 이를 피하는 방법은?

수신 DR은 한 칸이다. 블로킹 송신이 끝날 때까지 DR을 읽는 코드가 실행되지 않아 첫 바이트만 남고 둘째 바이트에서 ORE가 서며 나머지는 사라졌다. 현재 코드는 송신 전에 HAL_UART_Receive_IT로 RXNEIE를 켜 두어, main이 송신에 묶여 있어도 ISR이 바이트마다 DR을 읽는다.

문제 4. HAL_UART_RxCpltCallback이 없는데 main은 수신 완료를 어떻게 아는가? 시간 초과 때 HAL_UART_AbortReceive를 부르는 이유는?

HAL은 지정 바이트 수를 다 받으면(또는 오류로 중단하면) RxState를 READY로 돌린다. WaitRx는 이 상태를 폴링하고 ErrorCode로 성공·오류를 구분한다. 시간 초과 때 취소하지 않으면 RxState가 BUSY_RX로 남아 다음 주기의 Receive_IT가 HAL_BUSY로 거부된다.
