두 포트로 printf: USART2와 USART1의 BRR 차이, D8 파형 관찰

터미널에 글자가 보인다고 해서 선 위의 비트를 본 것은 아니다. 그런데 Nucleo의 USART2(PA2)는 ST-LINK 쪽에만 연결되어 있어 Arduino 헤더에서 측정할 수 없다. 이 교안은 같은 문자를 헤더 D8(PA9)에 연결된 USART1로도 내보내, Analog Discovery 2(AD2)로 실제 UART 파형을 관찰하는 08_USART_printf_Dual 예제를 다룬다. 두 USART가 서로 다른 버스(APB1 32 MHz, APB2 64 MHz)에 있어 BRR 값이 달라지는 이유와, 두 포트를 차례로 블로킹 송신할 때의 시간 비용도 계산한다.

1. 문제: 측정할 수 있는 핀으로 같은 글자를 보낸다

01 예제의 출력은 PA2 → ST-LINK → USB로 가므로 PC 터미널에서는 보이지만 프로브를 댈 헤더 핀이 없다. 이 예제는 __io_putchar 하나에서 같은 문자를 USART2와 USART1에 차례로 보낸다. 출력 채널을 늘리는 가장 단순한 방법이며, 실습의 목적은 D8 핀의 파형을 직접 보는 것이다. 학습 목표는 다음과 같다.

  • USART1(APB2)과 USART2(APB1)의 입력 클럭 차이로 같은 115200 bps에서도 USART_BRR 값이 다름을 계산으로 보인다.
  • Nucleo 보드의 솔더 브리지 기본 설정 때문에 PA2를 D1에서 측정할 수 없는 이유를 설명한다.
  • AD2 Logic의 UART 디코더와 트리거를 설정하고, 비트 폭 8.68 µs와 프레임 86.8 µs를 측정한다.
  • 두 포트를 바이트마다 TC까지 기다리며 순차 송신할 때 문자당 시간이 약 2배(≈174 µs)가 되는 이유를 설명한다.
이 예제의 동작

부팅 1초 후부터 1초마다 "Hello World!"와 "Hello, everyone! index = N"을 USART2(PC 터미널)와 USART1(PA9 = D8)로 동시에 출력한다. 각 문자는 USART2로 먼저, 이어서 USART1로 나간다. 인터럽트와 콜백은 쓰지 않는다.

2. 핵심 개념: 버스가 다르면 BRR이 다르다

보레이트는 baud = f_PCLK / (16 × USARTDIV)로 정해진다. USART1은 APB2, USART2·USART3는 APB1에 붙어 있다. 이 예제의 클럭 구성(SYSCLK 64 MHz, APB1 ÷2, APB2 ÷1)에서는 USART1의 입력 클럭이 정확히 두 배이므로 같은 보레이트를 내려면 USARTDIV도 두 배가 되어야 한다.

BRR 레지스터 값 278과 556은 정확히 2배이고, 두 포트의 실제 보레이트와 오차는 같다. 코드에서는 이 값을 직접 쓰지 않는다. HAL_UART_Init() 안의 UART_SetConfig()가 huart->Instance == USART1이면 HAL_RCC_GetPCLK2Freq(), 아니면 HAL_RCC_GetPCLK1Freq()를 읽어 계산한다. 레지스터를 직접 다룰 때 USART1에 USART2의 BRR(0x0116)을 넣으면 보레이트가 두 배(230 216 bps)가 된다.

그림 1. __io_putchar는 USART2 송신이 정지 비트까지 끝난(TC = 1) 뒤에야 USART1에 같은 문자를 쓴다. 따라서 두 핀의 프레임은 겹치지 않고 번갈아 나타나며, 각 핀만 보면 프레임 사이에 약 86.8 µs의 유휴(High)가 생긴다. 함수 호출에 드는 수 µs는 생략했다.

4. 직접 만져 보기

아래 시뮬레이터는 두 포트의 BRR을 HAL과 같은 방식으로 계산하고, 문자열을 보낼 때 PA2와 PA9에 프레임이 어떤 순서로 나타나는지 그린다.

  1. 115200 bps에서 USART2와 USART1의 BRR이 0x0116과 0x022C이고 실제 보레이트가 같은지 확인한다.
  2. 보레이트를 921600으로 올려 본다. 두 포트의 오차가 서로 달라지는가? 정수 반올림이 어디서 생기는지 계산 줄을 읽는다.
  3. 문자열 A\n(예제 주석의 비트 관찰용 출력)으로 송신을 누르고, 바이트가 41 0D 0A로 3개가 되는 것과 두 핀의 프레임이 번갈아 나타나는 것을 본다.
  4. 송신 방식을 "비교: TC를 기다리지 않는 경우"로 바꾸어 총 시간을 비교한다. 이 방식은 예제 코드가 아니라 인터럽트·DMA 송신의 효과를 가정한 것이다.

시뮬레이터 모델: BRR은 HAL의 UART_BRR_SAMPLING16()과 같은 정수 연산이다. 타이밍은 프레임 시간(10비트 / 실제 baud)만으로 그렸고, 함수 호출·플래그 폴링에 드는 수 µs의 간격은 넣지 않았다. "TC를 기다리지 않는 경우"는 DR·시프트 레지스터 이중 버퍼로 두 포트가 각자 연속 송신한다고 가정한 비교용 모델이며 이 예제의 동작이 아니다.

6. 실행 경로: 문자 하나가 두 핀으로 나가기까지

  1. 1
    printf() → _write()소프트웨어01 예제와 같다. syscalls.c의 _write가 문자마다 __io_putchar를 호출한다.
  2. 2
    __io_putchar(ch): '\n'이면 '\r'을 두 포트에 먼저소프트웨어CR을 USART2, USART1 순서로 보낸 뒤 본 문자로 넘어간다.
  3. 3
    HAL_UART_Transmit(&huart2, &ch, 1, 0xFFFF)소프트웨어TXE 확인 → USART2_DR ← ch → TC = 1까지 대기(약 86.8 µs).
  4. 4
    PA2에 10비트 프레임하드웨어ST-LINK가 받아 USB로 PC 터미널에 전달한다.
  5. 5
    HAL_UART_Transmit(&huart1, &ch, 1, 0xFFFF)소프트웨어같은 문자를 USART1_DR에 쓰고 TC까지 대기(약 86.8 µs).
  6. 6
    PA9 = D8에 10비트 프레임하드웨어AD2가 하강 에지(시작 비트)로 트리거하고 디코더가 바이트를 해석한다.
시간 비용

문자 하나에 두 번의 블로킹 송신이 이어지므로 문자당 약 2 × 86.8 = 173.6 µs가 걸린다. 한 번의 반복에서 보내는 42바이트(index 0~9 기준)는 약 7.3 ms(42 × 173.6 µs) 동안 CPU를 붙잡는다. 이 시간 동안 동작하는 ISR은 SysTick_Handler뿐이다(B1 EXTI 핸들러는 생성되어 있으나 사용자 콜백이 없다).

  if (ch == '\n') {
    HAL_UART_Transmit(&huart2, (uint8_t *)"\r", 1, 0xFFFF); /* USART2_DR <- '\r' */
    HAL_UART_Transmit(&huart1, (uint8_t *)"\r", 1, 0xFFFF); /* USART1_DR <- '\r' */

}

8. 실험 (AD2)

실험 A. Logic UART 디코더로 문자열 확인

WaveForms Logic에서 + → UART를 추가하고 DIO 0, 115200 bps, 8 bit, Parity None, Polarity Standard로 설정한다. Trigger는 DIO 0 Fall, Mode는 Normal로 둔다(Auto면 대부분 High 직선만 보인다). Base를 10 ms 이상으로 두어 송신 묶음 전체를 잡고, 디코더 줄의 글자를 PC 터미널 출력과 비교한다. 묶음의 길이를 커서로 재어 7.2 ms 계산값과 비교한다.

실험 B. 비트 폭과 프레임 길이 측정

main 루프를 주석의 printf("A\n"); 한 줄로 바꾼다. 첫 프레임에서 시작 비트의 하강 에지부터 D0가 끝나는 상승 에지까지를 커서로 재면 2비트이므로 약 17.4 µs, 1비트는 약 8.69 µs이다. 시작 비트 하강 에지부터 정지 비트 끝까지는 86.9 µs 근처이다. 측정값과 이상값(8.68 µs)의 차이가 BRR 오차(−0.08 %)만으로 설명되는지, HSI 오차가 더 큰지 생각해 본다.

실험 C. 프레임 사이 유휴 시간

실험 B에서 첫 프레임(0x41)의 정지 비트 끝과 둘째 프레임(0x0D)의 시작 비트 사이 간격을 잰다. 약 86.8 µs에 함수 호출 시간 몇 µs가 더해진 값이 나오면 그림 1의 순차 송신 모델이 맞다. 훅에서 USART2 송신 두 줄을 주석 처리하면 이 간격이 어떻게 변하는지 확인한다.

실험 D. Scope로 아날로그 파형 보기

Scope CH1(1+)을 D8, 1−를 GND에 연결한다. Trigger CH1 Falling, Level 약 1.6 V, Mode Normal, Range 1 V/div, 시간축 20 µs/div로 비트 단위 파형을 본다. 상승·하강 에지의 모양과 High 레벨(약 3.3 V)을 확인하고, msp.c의 PA9 속도를 GPIO_SPEED_FREQ_LOW로 바꾸어 에지 변화를 비교한다.

10. 확인 문제

문제 1. APB1을 ÷1(64 MHz)로 바꾸면 USART2_BRR 값은 얼마가 되는가? (주의: 실제로는 APB1 최대 36 MHz 제약이 있다.)

입력 클럭이 USART1과 같아지므로 BRR = 0x022C이다. 다만 STM32F103의 APB1 최대 주파수는 36 MHz이므로 SYSCLK 64 MHz에서는 APB1 ÷1 설정을 쓸 수 없다. 그래서 이 예제는 APB1을 ÷2로 둔다.

문제 2. 같은 115200 bps인데 왜 두 포트의 실제 보레이트가 완전히 같은가?

입력 클럭이 정확히 2배이고 HAL 정수 연산 결과 BRR도 정확히 2배(278 → 556)이므로 비율 f/BRR이 같다. 클럭 비가 정수배가 아니거나 반올림이 다르게 일어나면 두 포트의 오차가 달라질 수 있다.

문제 3. printf("A\n")을 실행하면 D8에 나타나는 송신 묶음의 길이는 최소 얼마인가?

바이트는 41 0D 0A 3개이다. D8 기준으로 첫 프레임 시작부터 마지막 프레임 끝까지는 프레임 3개와 사이의 유휴 2개(USART2 송신 시간)이므로 5 × 86.8 ≈ 434 µs이다. CPU가 묶이는 시간은 USART2 쪽까지 포함해 6 × 86.8 ≈ 521 µs이다.

문제 4. 두 포트에 동시에 프레임이 나가게 하려면 코드를 어떻게 바꿀 수 있는가?

TC를 바이트마다 기다리지 않게 해야 한다. 예를 들어 두 포트 모두 HAL_UART_Transmit_IT나 HAL_UART_Transmit_DMA로 버퍼를 넘기면 두 USART가 각자 연속 송신하므로 프레임이 겹쳐 나가고 총 시간이 약 절반이 된다. 대신 송신이 끝날 때까지 버퍼 내용을 유지해야 하고, 이전 송신이 끝났는지 확인하는 처리가 필요하다.
