printf를 UART로: 리다이렉션 경로, 10비트 프레임, 보레이트 레지스터

MCU에는 화면이 없으므로 프로그램 내부 상태를 확인하는 가장 쉬운 창구는 시리얼 출력이다. 그런데 C 표준 라이브러리의 printf는 UART를 모른다. 이 예제설명은 printf → newlib _write → __io_putchar → HAL_UART_Transmit로 이어지는 경로를 따라가고, 그 끝에서 USART2가 한 바이트를 10비트 프레임으로 내보내는 과정과 USART_BRR 값을 실제 클럭으로 계산한다. 대상 예제는 01_USART_printf이다.

1. 문제: printf의 글자는 어디로 가는가

PC에서 printf는 운영체제가 표준 출력(파일 디스크립터 1)을 터미널로 연결해 준다. 운영체제가 없는 MCU에서는 newlib이 마지막 단계를 _write()라는 시스템 호출 함수로 남겨 두고, 그 구현을 사용자에게 맡긴다. 이 함수를 UART 송신으로 채우면 printf가 그대로 시리얼 출력이 된다. 학습 목표는 다음과 같다.

  • printf → _write → __io_putchar → HAL_UART_Transmit 호출 사슬과 각 함수의 위치(파일)를 설명한다.
  • UART 8N1 프레임(시작 비트 1 + 데이터 8비트 LSB 먼저 + 정지 비트 1)을 그리고, 115200 bps에서 비트·바이트 시간을 계산한다.
  • USARTDIV = f_PCLK / (16 × baud)로 USART_BRR의 DIV_Mantissa/DIV_Fraction을 구하고 실제 보레이트 오차를 계산한다.
  • HAL_UART_Transmit가 TXE·TC 플래그를 폴링하는 블로킹 송신임을 이해하고, 그 시간 비용을 추정한다.
이 예제의 동작

부팅 후 1초를 기다린 뒤, 1초마다 "Hello World!"와 "Hello, everyone! index = N" 두 줄을 USART2(PA2, ST-LINK 가상 COM 포트)로 출력한다. __io_putchar가 '\n' 앞에 '\r'을 덧붙여 보내므로 터미널에서 줄 바꿈이 맞게 보인다. 인터럽트와 콜백은 쓰지 않는다.

2. 핵심 개념: 비동기 직렬 프레임과 보레이트

UART는 클럭 선 없이 데이터 선 하나로 비트를 보낸다. 송신기와 수신기가 미리 같은 속도(보레이트)를 약속하고, 수신기는 시작 비트의 하강 에지에 맞춰 이후 비트를 일정한 간격으로 샘플링한다. 선이 쉬고 있을 때는 High(유휴, idle)이다.

구성 요소비트 수레벨/내용역할
유휴(idle)–High전송이 없는 상태. 송신기가 선을 High로 유지한다.
시작 비트(Start)1Low하강 에지로 수신기에 프레임 시작을 알린다.
데이터(D0~D7)8LSB 먼저USART_DR에 쓴 바이트. USART_CR1.M = 0이면 8비트이다.
패리티0없음CR1.PCE = 0 (8N1의 N).
정지 비트(Stop)1HighCR2.STOP[1:0] = 00. 다음 프레임의 시작 에지를 만들 수 있게 선을 High로 되돌린다.

그림 1. 문자 'A'(0x41 = 0100 0001₂)의 8N1 프레임. LSB(D0)부터 보내므로 선 위에는 1 0 0 0 0 0 1 0 순서로 나타난다. 115200 bps에서 1비트는 1/115200 ≈ 8.68 µs이다.

보레이트 발생기

STM32F1의 USART는 버스 클럭(PCLK)을 USARTDIV로 나누어 비트 시간의 1/16 간격(16배 오버샘플링) 클럭을 만든다. USARTDIV는 12비트 정수부(DIV_Mantissa)와 4비트 소수부(DIV_Fraction, 1/16 단위)로 USART_BRR에 저장된다.

baud = f_PCLK / (16 × USARTDIV) USARTDIV = DIV_Mantissa + DIV_Fraction / 16 USART2 (APB1, f_PCLK1 = 32 MHz): USARTDIV = 32 000 000 / (16 × 115200) = 17.3611… DIV_Mantissa = 17 = 0x11, DIV_Fraction = round(0.3611 × 16) = round(5.78) = 6 USART2_BRR = (17 << 4) | 6 = 0x0116 (= 278) 실제 baud = 32 000 000 / 278 = 115 107.9 bps → 오차 −0.08 %

HAL은 부동소수점 없이 같은 값을 얻도록 UART_BRR_SAMPLING16() 매크로로 정수 연산한다. DIV×100 = PCLK×25 / (4×baud) = 1736, 정수부 1736/100 = 17, 소수부 ((1736 − 1700)×16 + 50)/100 = 6이다. 소수부 반올림 결과가 16이 되면 정수부로 자리올림된다.

오차 −0.08 %는 비트 시간이 8.6806 µs에서 8.6875 µs로 늘어나는 정도이며, 10비트 프레임 끝(정지 비트)에서도 누적 어긋남은 약 0.07 µs로 비트 폭의 1 %에 못 미친다. 수신기는 16배 오버샘플링으로 각 비트의 가운데(8·9·10번째 샘플)를 읽으므로 이 정도 오차는 문제가 되지 않는다. 다만 HSI(내부 RC 발진기) 자체의 주파수 오차가 여기에 더해진다는 점은 기억해 둔다.

4. 직접 만져 보기

아래 시뮬레이터는 문자열이 __io_putchar를 거쳐 바이트 열이 되는 과정과, 각 바이트가 PA2에 10비트 프레임으로 나가는 모습을 보여 준다. 보레이트와 PCLK를 바꾸면 HAL과 같은 정수 연산으로 BRR과 오차를 다시 계산한다.

  1. 기본 문자열 A\n으로 printf 호출을 누른다. 바이트 열이 41 0D 0A로 3바이트가 되는 이유('\n' 앞에 '\r' 추가)를 확인한다.
  2. 다음 바이트 송신을 눌러 프레임 파형을 하나씩 본다. 0x41의 데이터 비트가 1 0 0 0 0 0 1 0 순서로 나타나는지 그림 1과 비교한다.
  3. 문자열을 Hello, everyone! index = 0\n으로 바꾸어 바이트 수와 총 송신 시간을 확인한다. 끝을 \r\n으로 바꾸면 훅이 붙이는 CR까지 '\r'이 두 번 나가 1바이트가 늘어나는 것을 본다.
  4. 보레이트를 9600, 230400, 921600으로 바꾸어 BRR과 오차가 어떻게 변하는지 본다. PCLK를 64 MHz로 바꾸면 BRR이 정확히 두 배가 되는지 확인한다.

6. 실행 경로: printf에서 PA2 핀까지

그림 2. printf 한 번은 문자마다 __io_putchar를 부르고, 각 호출은 1바이트를 USART2에 넘긴 뒤 프레임 송신이 끝날 때까지 기다린다.

  1. 1
    printf("Hello World!\n")소프트웨어newlib이 서식을 처리해 문자열을 stdout 버퍼에 모으고, 버퍼를 비울 때 _write(1, ptr, len)을 호출한다.
  2. 2
    _write() — syscalls.c소프트웨어len개 문자에 대해 차례로 __io_putchar(*ptr++)를 부른다. weak 함수이므로 사용자가 다시 정의할 수도 있다.
  3. 3
    __io_putchar(ch) — main.c소프트웨어ch == '\n'이면 먼저 "\r"을 1바이트 보낸 뒤 ch를 보낸다.
  4. 4
    HAL_UART_Transmit(&huart2, …, 1, 0xFFFF)소프트웨어SR.TXE = 1을 기다려 DR에 쓰고, SR.TC = 1이 될 때까지 기다린다. 이 동안 CPU는 다른 일을 하지 못한다.
  5. 5
    DR → 시프트 레지스터 → PA2하드웨어USART가 시작 비트, D0~D7, 정지 비트를 BRR이 정한 간격(8.68 µs)으로 내보낸다. 끝나면 TC = 1이다.
  6. 6
    ST-LINK → USB → PC하드웨어ST-LINK의 MCU가 UART를 받아 USB 가상 COM 포트(CDC)로 PC에 전달한다.
인터럽트 관점

이 경로에는 ISR이 없다. 동작 중인 ISR은 HAL_Delay()의 시간 기준이 되는 SysTick_Handler(1 ms마다 HAL_IncTick())뿐이다. CubeMX가 생성한 B1(PC13) EXTI 설정과 EXTI15_10_IRQHandler는 있지만, 사용자 콜백이 없어 버튼을 눌러도 아무 일도 일어나지 않는다.

7. 코드 읽기

외부 배선은 필요 없다. USB 케이블로 Nucleo를 연결하고 시리얼 터미널을 ST-LINK COM 포트, 115200 8N1로 연다(platformio.ini의 monitor_port = COM9는 각자 환경에 맞게 고친다).

main.c — printf 출력 훅 (USER CODE 0)
#ifdef __GNUC__
#define PUTCHAR_PROTOTYPE int __io_putchar(int ch)
#else
#define PUTCHAR_PROTOTYPE int fputc(int ch, FILE *f)
#endif

PUTCHAR_PROTOTYPE {
  if (ch == '\n')
    HAL_UART_Transmit(&huart2, (uint8_t *)"\r", 1, 0xFFFF);

  HAL_UART_Transmit(&huart2, (uint8_t *)&ch, 1, 0xFFFF);

  return ch;
}
  1. GCC(newlib)는 __io_putchar, Keil 등 다른 툴체인은 fputc를 출력 훅으로 쓰므로 매크로로 이름을 고른다.
  2. '\n'을 만나면 '\r'을 먼저 보낸다. 터미널은 CR(0x0D)로 커서를 줄 처음으로, LF(0x0A)로 다음 줄로 옮긴다.
  3. &ch는 int의 주소이다. Cortex-M3는 리틀 엔디언이므로 첫 바이트가 하위 8비트, 즉 문자 자체이다.
syscalls.c — newlib 시스템 호출 (생성 코드)
extern int __io_putchar(int ch) __attribute__((weak));

__attribute__((weak)) int _write(int file, char *ptr, int len)
{
  (void)file;
  int DataIdx;

  for (DataIdx = 0; DataIdx < len; DataIdx++)
  {
    __io_putchar(*ptr++);
  }
  return len;
}
  1. file(stdout = 1, stderr = 2)을 구분하지 않고 모두 UART로 보낸다.
  2. __io_putchar는 weak 선언이다. main.c에서 정의하지 않으면 링크는 되지만 출력이 사라진다.
main.c — USART2 초기화 (CubeMX 생성)
huart2.Instance = USART2;
huart2.Init.BaudRate = 115200;
huart2.Init.WordLength = UART_WORDLENGTH_8B;
huart2.Init.StopBits = UART_STOPBITS_1;
huart2.Init.Parity = UART_PARITY_NONE;
huart2.Init.Mode = UART_MODE_TX_RX;
huart2.Init.HwFlowCtl = UART_HWCONTROL_NONE;
huart2.Init.OverSampling = UART_OVERSAMPLING_16;
if (HAL_UART_Init(&huart2) != HAL_OK)
{
  Error_Handler();
}
  1. 8N1, 115200 bps가 그대로 5절 표의 레지스터 값이 된다.
  2. BRR 계산은 HAL_UART_Init가 PCLK1(32 MHz)을 읽어 수행하므로 코드에 0x0116이 직접 나타나지 않는다.
main.c — main 루프 (USER CODE WHILE / 3)
uint8_t index = 0;
/* … HAL_Init, SystemClock_Config, MX_GPIO_Init, MX_USART2_UART_Init … */
HAL_Delay(1000);
while (1) {
  printf("Hello World!\n");
  /* 줄 끝은 '\n' 하나만 쓴다. 훅이 '\r'을 붙여 0D 0A가 된다 */
  printf("Hello, everyone! index = %d\n", index++);
  // printf("%s", sMsg);
  HAL_Delay(1000);
}
  1. 두 줄 모두 줄 끝에 "\n"만 쓴다. 훅이 CR을 붙이므로 실제로는 0D 0A가 나간다.
  2. 줄 끝을 "\r\n"으로 쓰면 훅이 CR을 하나 더 붙여 0D 0D 0A가 된다. 터미널 화면은 같아 보여 눈에 띄지 않지만 바이트가 하나 늘어난다. 이 예제의 이전 버전이 이 상태였으며, 줄 끝을 \n 하나로 통일해 고쳤다.
  3. index는 uint8_t이므로 255 다음에 0으로 돌아간다.
  4. HAL_Delay(1000)은 송신 시간(약 3.6 ms)과 별개이므로 실제 주기는 1초보다 조금 길다.

한 번의 반복에서 보내는 바이트는 14 + 28 = 42바이트(index 0~9 기준)이며, 115200 bps에서 최소 42 × 86.8 µs ≈ 3.65 ms가 걸린다. 이 시간 동안 CPU는 TXE·TC 플래그만 확인한다.

8. 실험

실험 A. 보레이트 불일치

터미널을 9600 bps로 열고 출력을 본다. 깨진 문자가 나오는 이유를 비트 시간(8.68 µs 대 104 µs)으로 설명한다. 이어서 코드의 BaudRate를 9600으로 바꾸고 터미널도 맞추어 다시 확인한다. 시뮬레이터로 9600의 BRR(0x0D05 = 208 + 5/16)과 오차를 미리 계산해 둔다.

실험 B. CR을 빼면

__io_putchar의 if (ch == '\n') 두 줄을 주석 처리하고, 첫째 줄 출력이 어떻게 보이는지 관찰한다. 터미널 프로그램의 "LF를 CRLF로 처리" 옵션을 켜고 끄며 비교한다.

실험 C. 송신 시간 측정

uint32_t t0 = HAL_GetTick();로 두 printf 앞뒤 시간을 재어 출력한다. 1 ms 해상도이므로 3~4 ms가 나오는지 확인하고, 바이트 수 × 86.8 µs 계산값과 비교한다. 문자열을 10배로 늘리면 어떻게 되는가?

실험 D. 클럭을 바꾸면

APB1CLKDivider를 RCC_HCLK_DIV4로 바꾸어 PCLK1을 16 MHz로 만든다. HAL_UART_Init가 BRR을 다시 계산하므로 출력이 정상인지 확인하고, 새 BRR 값을 계산으로 예측한다(16 MHz/(16 × 115200) = 8.68 → 0x008B).

10. 확인 문제

문제 1. 문자 'H'(0x48)를 보낼 때 선 위에 나타나는 10비트를 시간 순서로 적어라.

0x48 = 0100 1000₂. LSB부터 보내므로 Start(0), 0 0 0 1 0 0 1 0, Stop(1)이다. 전체는 0 0001 0010 1 순서가 된다.

문제 2. USART2를 57600 bps로 쓰면 BRR 값과 실제 오차는?

USARTDIV = 32 000 000/(16 × 57600) = 34.722. HAL 연산: 3472 → 정수부 34, 소수부 ((72 × 16) + 50)/100 = 12. BRR = (34 << 4) | 12 = 0x022C. 실제 baud = 32 MHz/556 = 57 553.96 bps, 오차 −0.08 %이다.

문제 3. printf("Hello, everyone! index = %d\n", 7)은 UART로 몇 바이트를 보내며 최소 몇 µs가 걸리는가?

문자열 25자 + 숫자 1자 + (훅이 붙인 \r) + \n = 28바이트이다. 28 × 86.8 µs ≈ 2.43 ms이다. 줄 끝을 \r\n으로 쓰면 CR이 하나 더 붙어 29바이트(약 2.52 ms)가 된다.

문제 4. HAL_UART_Transmit가 마지막에 TXE가 아니라 TC를 기다리는 것은 어떤 상황에서 중요한가?

TXE는 DR이 비었다는 뜻일 뿐 시프트 레지스터는 아직 비트를 내보내는 중이다. 송신 직후 USART를 끄거나(UE = 0), 저전력 모드로 들어가거나, 반이중 통신에서 방향을 바꿀 때는 마지막 정지 비트까지 나간 뒤(TC = 1)여야 프레임이 잘리지 않는다.
