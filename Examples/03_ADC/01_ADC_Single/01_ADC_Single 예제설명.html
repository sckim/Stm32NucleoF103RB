ADC 단일 채널: 전압을 12비트 숫자로 바꾸는 과정

마이크로컨트롤러는 전압을 직접 다룰 수 없고 숫자만 다룬다. ADC는 핀의 전압을 잠깐 붙잡아(샘플&홀드) 12번의 비교로 0~4095 사이의 코드로 바꾼다. 이 예제설명은 ADC1을 교정한 뒤 연속 변환으로 돌려 두고, 200 ms마다 결과를 폴링해 원시 값과 mV를 UART로 출력하는 01_ADC_Single 예제를 블록 구조, 레지스터, 변환 시간, 양자화 오차까지 해석한다.

1. 문제: 아날로그 전압을 숫자로 읽는다

가변저항, 센서, 배터리 전압처럼 연속적인 값을 프로그램에서 쓰려면 먼저 숫자로 바꿔야 한다. ADC의 결과는 전압 그 자체가 아니라 기준 전압(VDDA)에 대한 비율이며, 그 비율을 몇 단계로 나누는지가 분해능이다. 학습 목표는 다음과 같다.

  • 샘플&홀드 → 12비트 SAR → ADC_DR로 이어지는 ADC 블록 구조를 설명한다.
  • 교정(ADC_CR2.RSTCAL/CAL), 채널 선택(SQR3.SQ1), 샘플 시간(SMPR1/2), 연속 변환(CR2.CONT)을 레지스터로 짚는다.
  • 변환 시간 (샘플 시간 + 12.5) / ADCCLK를 계산하고, 샘플 시간이 신호원 임피던스와 어떻게 얽히는지 안다.
  • 코드 → mV 환산식과 양자화 오차(1 LSB = 3.3 V / 4096 ≈ 0.806 mV)를 구분한다.
이 예제의 동작

시작 시 한 번 HAL_ADCEx_Calibration_Start()로 교정하고 HAL_ADC_Start()로 연속 변환을 켠다. 이후 무한 루프에서 HAL_ADC_PollForConversion() → HAL_ADC_GetValue()로 최신 결과를 읽고 ADC PA0 = <raw> (<mV> mV)를 출력한 뒤 200 ms 쉰다. 인터럽트·DMA는 쓰지 않는다.

흔한 실수 — CubeMX에서 채널을 잘못 고른다

CubeMX의 ADC1 설정 화면에서 Temperature Sensor Channel을 켜면 랭크 1 채널이 ADC_CHANNEL_TEMPSENSOR(CH16)로 바뀌고, 새로 추가한 채널의 샘플 시간은 기본값 1.5 사이클이 되기 쉽다. 이 경우 핀 설정(PA0 아날로그)과 printf 문구는 그대로여서 겉보기에는 PA0를 읽는 것 같지만, 실제로는 PA0와 무관한 값이 나온다. 다시 생성한 뒤에는 MX_ADC1_Init()의 sConfig.Channel과 SamplingTime을 반드시 확인한다(9절, 실험 A).

2. ADC 블록 구조: 샘플&홀드와 축차 비교

STM32F103의 ADC는 축차 비교형(SAR, Successive Approximation Register) 변환기이다. 아날로그 멀티플렉서가 18개 입력(외부 CH0~15, 내부 CH16 온도 센서, CH17 Vrefint) 중 하나를 고르고, 샘플&홀드 커패시터가 그 전압을 붙잡은 뒤, SAR 논리가 내부 DAC 전압과 12번 비교해 비트를 위에서부터 하나씩 확정한다.

그림 1. ADC1 단일 채널 경로. 파랑은 이 예제가 읽는 외부 채널(PA0), 보라는 같은 MUX에 연결된 내부 채널(CH16, 02 예제)이다. 결과 레지스터 DR은 하나뿐이며, 연속 변환에서는 새 결과가 이전 값을 덮어쓴다.

샘플 시간과 신호원 임피던스

샘플 시간 동안 C_ADC는 신호원 저항 R_AIN과 R_ADC를 거쳐 충전된다. 12비트에서 오차를 ¼ LSB 아래로 두려면 RC 시정수의 ln(214) ≈ 9.7배 이상이 필요하다. 데이터시트 Equation 1은 이를 R_AIN 상한으로 쓴다.

R_AIN < t_S / (f_ADC × C_ADC × ln(2^14)) − R_ADC (C_ADC = 8 pF, R_ADC = 1 kΩ)

ADCCLK 8 MHz에서 1.5 사이클(0.19 µs)이면 R_AIN이 약 1.4 kΩ 이하여야 하고, 239.5 사이클(29.9 µs)이면 식으로는 수백 kΩ까지 허용된다. 다만 데이터시트 Table 47은 R_AIN 최대 50 kΩ을 따로 규정하므로 그 이상은 쓰지 않는다. 10 kΩ 가변저항의 가운데 단자는 최악일 때 약 2.5 kΩ이므로 239.5 사이클에서 여유가 크다.

양자화: 1 LSB의 크기

그림 2. 단순화한 ADC 전달 특성(바닥 함수 모델). 폭 1 LSB 안의 모든 전압이 같은 코드가 되므로 양자화 오차는 피할 수 없다. 실제 칩에는 오프셋·이득·비선형 오차가 더해진다(데이터시트 Table 50, 총 오차 TUE 대표 ±2 LSB, 최대 ±5 LSB).

1 LSB = VDDA / 4096 = 3300 mV / 4096 ≈ 0.806 mV 코드의 환산: mV = raw × 3300 / 4095 (정수 나눗셈, 4095 → 3300 mV가 되도록 4095로 나눈다)

소스는 4095로 나누어 최댓값 코드가 정확히 3300 mV가 되게 했다. 4096으로 나누는 식과의 차이는 최대 약 0.8 mV로 1 LSB보다 작다. 정수 나눗셈은 소수점 아래를 버리므로 출력 mV는 최대 1 mV만큼 더 작게 나온다.

4. 직접 만져 보기

아래 시뮬레이터는 PA0 전압을 12비트 코드로 바꾸고, 예제와 같은 정수식으로 mV를 계산한다. 샘플 시간과 ADC 분주비를 바꾸면 변환 시간과 허용 신호원 저항이 함께 바뀐다.

  1. 입력 전압을 1650 mV에 두고 코드가 2048 근처인지, 출력 mV와 실제 전압의 차이가 1 LSB(0.806 mV) 안팎인지 확인한다.
  2. 입력을 1 mV씩 움직여 코드가 바뀌지 않는 구간(같은 코드를 내는 입력 범위)을 찾는다.
  3. 실제 VDDA를 3200 mV로 낮춘다. 입력은 그대로인데 출력 mV가 약 3% 커지는 이유를 생각한다.
  4. 샘플 시간을 1.5와 239.5로 바꿔 변환 시간과 R_AIN 상한을 비교한다. 분주비를 ÷4로 바꾸면 14 MHz 상한 경고가 뜬다.
  5. 채널을 CH16으로 바꿔 ‘채널을 잘못 고른’ 흔한 실수를 재현한다. 입력 슬라이더를 움직여도 출력이 따라오지 않는다.

6. 초기화부터 결과 출력까지의 경로

이 예제에는 ADC 인터럽트가 없다. 동작하는 ISR은 HAL_Delay()용 SysTick_Handler뿐이다(CubeMX가 만든 B1의 EXTI15_10_IRQHandler도 있으나 콜백을 쓰지 않는다).

  1. 1
    MX_ADC1_Init()소프트웨어HAL_ADC_Init()이 MSP에서 ADC1 클럭과 PA0 아날로그 모드를 켜고 CR1·CR2·SQR1을 쓴다. HAL_ADC_ConfigChannel()이 SQR3·SMPRx를 쓴다.
  2. 2
    교정하드웨어ADON=1로 2 ADC 클럭 이상 켠 뒤 RSTCAL → CAL. 데이터시트 t_CAL은 83 ADC 클럭으로, 8 MHz에서 약 10.4 µs이다. 결과 보정 코드는 이후 모든 변환에 적용된다.
  3. 3
    HAL_ADC_Start()소프트웨어EOC를 지우고 SWSTART | EXTTRIG를 세운다. 한 번만 호출한다.
  4. 4
    샘플 → SAR → DR, EOC = 1하드웨어CONT=1이므로 T_conv(31.5 µs)마다 DR이 새 값으로 바뀐다. CPU가 읽지 않아도 계속 덮어쓴다.
  5. 5
    HAL_ADC_PollForConversion(&hadc1, 100)소프트웨어EOC가 1이 될 때까지 기다린 뒤 STRT·EOC를 지운다. 연속 변환 중이므로 대개 다음 변환 한 번(최대 T_conv)만 기다린다.
  6. 6
    HAL_ADC_GetValue() → printf소프트웨어DR의 최신 값을 읽어 mV로 환산하고 USART2로 블로킹 송신한다.
  7. 7
    HAL_Delay(200)소프트웨어그동안 ADC는 약 6,350회(31.5 µs 기준) 변환하지만 마지막 값만 DR에 남는다. 5로 돌아간다.
연속 변환을 끄면

ContinuousConvMode = DISABLE로 바꾸고 코드는 그대로 두면, 첫 변환 뒤 ADC가 멈춘다. 두 번째 PollForConversion은 EOC를 100 ms 동안 기다리다 HAL_TIMEOUT을 돌려주고, 예제는 Error_Handler()로 들어가 멈춘다. 단일 변환 모드에서는 루프마다 HAL_ADC_Start()를 다시 불러야 한다.

계층은 HAL이다. 사용자 코드는 USER CODE 영역의 교정·시작·루프뿐이고, ADC 설정은 CubeMX가 생성한 MX_ADC1_Init()에 있다.

8. 실험

배선: 10 kΩ 가변저항의 양 끝을 3V3과 GND에, 가운데 단자를 A0(PA0)에 연결한다. 터미널은 115200 8N1이다.

실험 A. 채널을 잘못 고르면

프로젝트를 복사한 뒤 CubeMX에서 Temperature Sensor Channel을 켜고 Rank 1 채널을 이것으로, 샘플 시간을 1.5 Cycles로 바꿔 다시 생성한다. 출력이 가변저항과 무관해지는 것을 확인하고, 디버거로 ADC1->SQR3(SQ1 = 16)와 CR2.TSVREFE를 읽어 원인을 찾는다. 원래 설정(Channel 0, 239.5 Cycles)으로 되돌려 복구한다.

실험 B. 샘플 시간과 신호원 저항

A0와 가변저항 사이에 100 kΩ 저항을 직렬로 넣는다. 샘플 시간을 239.5와 1.5 사이클로 바꿔 가며 같은 전압에서 값이 어떻게 달라지는지 본다. 시뮬레이터의 R_AIN 상한과 비교한다. (100 kΩ은 데이터시트의 R_AIN 최대 50 kΩ을 넘으므로 ‘규격 밖’ 관찰 실험이다.)

실험 C. VDDA 가정 확인

멀티미터로 보드의 3V3(=VDDA)을 잰다. 3.30 V가 아니라면 같은 입력에서 출력 mV가 얼마나 틀어지는지 계산하고, 3300 대신 실측값을 넣었을 때와 비교한다. VDDA를 칩 내부에서 역산하는 방법은 06_ADC_Vrefint_VDDA_c에서 다룬다.

실험 D. 단일 변환 모드로 바꾼다

ContinuousConvMode를 DISABLE로 바꾸고 실행해 첫 줄만 출력되고 멈추는지(폴링 타임아웃 → Error_Handler) 확인한다. 이어서 루프 안에서 매번 HAL_ADC_Start()를 부르도록 고쳐 정상 동작을 회복시킨다.

9. 트러블슈팅

증상원인점검/조치
가변저항을 돌려도 값이 거의 변하지 않는다랭크 1 채널이 CH0가 아니다(예: CubeMX에서 온도 센서 채널을 선택)sConfig.Channel과 .ioc의 Rank 1 채널을 확인한다. ADC1->SQR3를 디버거로 읽어 SQ1 = 0인지 본다.
아무것도 연결하지 않았는데 값이 마구 흔들린다PA0 플로팅정상이다. 측정하려면 신호원을 연결하거나 GND에 묶어 0 근처인지 확인한다.
첫 줄만 출력되고 멈춘다CONT=0인데 Start를 한 번만 불러 폴링이 타임아웃ContinuousConvMode = ENABLE 또는 루프마다 HAL_ADC_Start()

10. 확인 문제

문제 1. ADCCLK 8 MHz, 샘플 시간 239.5 사이클일 때 변환 1회의 시간과 최대 변환 속도는?

(239.5 + 12.5) / 8 MHz = 252 / 8 MHz = 31.5 µs이다. 연속 변환이면 초당 약 1 / 31.5 µs ≈ 31.7 k회이다.

문제 2. raw = 1241일 때 예제가 출력하는 mV는? 1 LSB 크기와 함께 답하라.

1241 × 3300 / 4095 = 4,095,300 / 4095 = 1000.07 → 1000 mV이다. 1 LSB = 3300 / 4096 ≈ 0.806 mV이므로 실제 입력은 대략 1000.1 ± 0.8 mV 범위에 있다(ADC 자체 오차 제외).

문제 3. 이 예제의 SQR3, SMPR2 값은? CubeMX에서 실수로 CH16·1.5 사이클을 고르면?

이 예제: SQR3 = 0x0000 0000(SQ1 = 0), SMPR2 = 0x0000 0007(SMP0 = 111). 실수한 경우: SQR3 = 0x0000 0010(SQ1 = 16), SMPR2 = 0이고 샘플 시간은 SMPR1.SMP16 = 000(1.5 사이클)에 있다.

문제 4. 이 예제에서 HAL_ADC_PollForConversion()은 EOC를 실제로 폴링하는가? 03_ADC_Multi와 무엇이 다른가?

폴링한다. CR1.SCAN = 0이고 SQR1.L = 0이면 HAL은 SR.EOC를 기다린다. 03_ADC_Multi는 SCAN=1, L=3이라 EOC가 시퀀스 끝에서만 서므로 HAL이 EOC 대신 최대 변환 시간만큼 빈 루프로 기다린다.
