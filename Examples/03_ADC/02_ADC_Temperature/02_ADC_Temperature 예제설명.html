내부 온도 센서: 핀 없는 채널을 읽고 섭씨로 바꾼다

ADC1에는 외부 핀 말고도 칩 안쪽에 연결된 입력이 있다. 채널 16은 다이(die) 온도에 따라 출력 전압이 바뀌는 온도 센서이다. 배선 없이 읽을 수 있지만, 출력 임피던스가 커서 샘플링을 오래 해야 하고 칩마다 오프셋이 커서 절대 온도계로는 믿기 어렵다. 이 예제설명은 TSVREFE로 센서를 켜고 239.5 사이클 샘플링으로 읽은 값을 정수 연산으로 0.1 °C 단위까지 환산하는 02_ADC_Temperature 예제를 데이터시트 수치와 함께 해석한다.

1. 문제: 칩의 온도를 칩 스스로 잰다

01_ADC_Single이 외부 핀 PA0(CH0)을 읽었다면, 이 예제는 핀이 없는 내부 채널 CH16을 읽는다. 변환 순서(교정 → 시작 → 폴링 → 읽기)는 같고, 달라지는 것은 센서 전원 비트, 샘플 시간, 그리고 전압을 온도로 바꾸는 식이다. 학습 목표는 다음과 같다.

  • ADC_CR2.TSVREFE가 온도 센서와 Vrefint를 함께 켜는 비트임을 알고, HAL이 이를 언제 켜는지 확인한다.
  • 온도 센서에 긴 샘플 시간(RM0008 권장 17.1 µs)이 필요한 이유를 샘플&홀드 충전으로 설명하고, ADCCLK 8 MHz에서 239.5 사이클만 이 조건을 만족함을 계산한다.
  • T = (V25 − Vsense) / Avg_Slope + 25를 정수 연산(0.1 °C 단위)으로 구현한 코드를 읽는다.
  • V25·Avg_Slope의 min/typ/max 편차, VDDA 가정, 칩 자체 발열이 결과를 얼마나 흔드는지 수치로 판단한다.
이 예제의 동작

교정 후 연속 변환을 시작하고, 1초마다 HAL_ADC_PollForConversion() → HAL_ADC_GetValue()로 CH16 값을 읽는다. Vsense[mV] = raw × 3300 / 4095, t10 = (1430 − mV) × 100 / 43 + 250을 계산해 ADC TempSensor raw=… (… mV) -> xx.x C를 출력한다. 외부 배선은 필요 없다.

2. 센서 특성과 환산식

센서 출력 Vsense는 온도가 오르면 내려간다. 데이터시트는 25 °C에서의 출력 V25와 평균 기울기 Avg_Slope를 준다. 아래 값은 STM32F103xB 데이터시트(DS5319 Rev 19) Table 51에서 직접 확인한 것이다.

TS_temp의 17.1 µs는 표의 max 칸에 있고 각주는 “가장 짧은 샘플 시간은 응용에서 반복 시험으로 정할 수 있다”고 적는다. 즉 17.1 µs를 확보하면 설계상 충분하다는 값이다. RM0008 11.10절도 “온도 센서의 권장 샘플 시간은 17.1 µs”라고 쓴다.

그림 1. Vsense–온도 직선(기울기 4.3 mV/°C). 주황은 V25 = 1.52 V(max), 보라는 1.43 V(typ), 파랑은 1.34 V(min)인 칩이다. 같은 온도에서 칩마다 출력이 최대 180 mV 다르며, 이는 typ 식으로 환산하면 약 ±21 °C의 오프셋이 된다. 그래프는 1.19 V 아래를 잘라 표시했다.

T[°C] = (V25 − Vsense) / Avg_Slope + 25 (RM0008 11.10) 소스: Vsense_mV = raw × 3300 / 4095 t10 = (1430 − Vsense_mV) × 100 / 43 + 250 (0.1 °C 단위 정수, C의 나눗셈은 0쪽으로 버림)

(1430 − mV) / 4.3 [°C]에 10을 곱하면 (1430 − mV) × 10 / 4.3 = (1430 − mV) × 100 / 43 [0.1 °C]이다. printf("%f")는 newlib-nano 기본 설정에서 동작하지 않으므로, 정수부 t10/10과 소수부 t10%10을 따로 찍는다. 1 LSB(0.806 mV)는 0.19 °C에 해당하므로 0.1 °C 표시 자릿수는 분해능보다 촘촘하다.

절대 온도계가 아니다

RM0008은 “이 직선의 오프셋은 공정 편차로 칩마다 다르며(칩 간 최대 45 °C), 내부 온도 센서는 절대 온도보다 온도 변화를 감지하는 용도에 적합하다. 정확한 온도가 필요하면 외부 센서를 쓴다”고 적는다. 측정 대상도 주변 공기가 아니라 접합(다이) 온도 TJ이다.

왜 샘플 시간이 길어야 하는가

샘플 구간에 ADC 내부 커패시터(C_ADC ≤ 8 pF)가 입력 전압까지 충전된다. 온도 센서 출력은 외부 버퍼가 없는 내부 회로라 구동 능력이 약하므로(출력 임피던스 수치는 데이터시트에 없다) 충전에 시간이 걸린다. 데이터시트는 이를 ‘17.1 µs 이상 샘플링’이라는 조건으로만 준다.

ADCCLK 8 MHz에서 17.1 µs를 넘는 선택지는 239.5 사이클뿐이다. ADCCLK가 최대 14 MHz라면 239.5 사이클이 정확히 17.1 µs가 되며(데이터시트 Table 48), 이것이 17.1이라는 숫자가 나온 배경이다.

칩 자체 발열

센서는 다이 온도를 재므로 코드가 돌아가는 동안 칩이 내는 열이 그대로 더해진다. 데이터시트의 HSI·64 MHz 동작 전류(Table 17, 주변장치 꺼짐 23.9 mA ~ 모두 켬 31.4 mA, typ)와 LQFP64 열저항 ΘJA = 45 °C/W(JEDEC 정지 공기 조건)로 어림하면 3.3 V × 약 25~31 mA ≈ 0.08~0.10 W, 상승분은 약 4 °C이다. 실제 보드는 구리 면적, ST-LINK 쪽 발열, 케이스 유무에 따라 달라지므로 이 값은 크기 감각을 위한 추정이다.

4. 직접 만져 보기

아래 시뮬레이터는 ‘이 칩의 실제 V25·Avg_Slope’로 Vsense를 만들고, 예제와 똑같은 정수 연산(1430, 43)으로 온도를 계산한다. 두 값이 다를 때 표시 온도가 얼마나 틀어지는지 본다.

  1. 모든 값을 typ에 두고 다이 온도를 바꾸며 표시 온도가 따라가는지(오차 ±0.3 °C 안팎) 확인한다.
  2. ‘이 칩의 V25’를 1.34 V, 1.52 V로 바꾼다. 같은 다이 온도에서 표시값이 약 ±21 °C 달라진다.
  3. 실제 VDDA를 3250 mV로 낮춘다. 소스는 3300 mV를 가정하므로 Vsense가 약 1.5% 크게 계산되고 온도는 약 5 °C 낮게 나온다.
  4. ‘raw 직접 입력’에 코드 하나를 넣고 아래 3×3 표에서 V25·Slope 조합별 온도 범위를 본다.
  5. 샘플 시간을 1.5 사이클로 바꾸면 17.1 µs 조건 경고가 뜨고 값이 흔들린다(01 예제의 현재 소스 상태와 같다).

6. 실행 경로

ADC 인터럽트·콜백은 없다. 동작하는 ISR은 HAL_Delay()용 SysTick_Handler뿐이다.

  1. 1
    MX_ADC1_Init()소프트웨어HAL_ADC_Init()으로 CR1·CR2·SQR1을 쓰고, HAL_ADC_ConfigChannel()이 SQR3.SQ1 = 16, SMPR1.SMP16 = 111을 쓴다.
  2. 2
    TSVREFE = 1 → 센서 기동하드웨어센서가 파워다운에서 깨어나 Vsense가 안정될 때까지 4~10 µs 걸린다. HAL은 같은 함수 안에서 10 µs 대기한다.
  3. 3
    교정과 시작소프트웨어HAL_ADCEx_Calibration_Start() → HAL_ADC_Start(). 이후 CONT=1로 31.5 µs마다 변환이 반복된다.
  4. 4
    29.9 µs 샘플 + 12.5 사이클 변환 → DR, EOC하드웨어1초 대기 동안 약 31,700회 변환되고 DR에는 마지막 값만 남는다.
  5. 5
    Poll → GetValue소프트웨어EOC를 기다렸다 지우고 DR을 읽는다.
  6. 6
    정수 환산 → printf → HAL_Delay(1000)소프트웨어Vsense mV, t10을 계산해 부호·정수부·소수부로 나눠 출력한다.
RM0008이 권하는 순서와의 비교

RM0008 11.10은 “센서와 ADC 모두 기동 시간이 있으므로 ADON과 TSVREFE를 동시에 세워 지연을 줄이라”고 한다. HAL은 채널 설정 때 TSVREFE를 먼저 켜고 10 µs를 기다린 다음, 교정·시작 단계에서 ADON을 켠다. 지연이 조금 늘 뿐 결과에는 영향이 없다.

if ((sConfig->Channel == ADC_CHANNEL_TEMPSENSOR) ||

  1. CH16·CH17을 고르면 HAL이 TSVREFE를 자동으로 켠다. 사용자 코드에는 이 비트가 나오지 않는다.
  2. 대기 루프 횟수 = 10 × 64 = 640회. 한 바퀴가 여러 사이클이므로 실제 대기는 10 µs보다 길다.

Core/Src/main.c — USER CODE BEGIN WHILE (환산과 출력)
while (1)
{
  // ADC1_SR.EOC 플래그 대기 후 ADC1_DR에서 내부 온도 센서(ADC1_IN16) 변환값(12bit, 0~4095) 읽기
  HAL_ADC_PollForConversion(&hadc1, 100);
  adc1 = HAL_ADC_GetValue(&hadc1);

  // Vsense[mV] = raw * 3300 / 4095  (VDDA = 3.3V 가정)
  int32_t vsense_mv = (int32_t)(adc1 * 3300UL / 4095);
  // T = (V25 - Vsense) / Avg_Slope + 25 를 0.1°C 단위 정수로 계산 (V25 = 1430mV, Avg_Slope = 4.3mV/°C)
  //   (1430 - mV) / 4.3 [°C] * 10 = (1430 - mV) * 100 / 43 [0.1°C]
  int32_t t10 = ((1430 - vsense_mv) * 100) / 43 + 250;
  int32_t t10_abs = (t10 < 0) ? -t10 : t10;
  printf("ADC TempSensor raw=%u (%ld mV) -> %s%ld.%ld C\n",
         (unsigned)adc1, (long)vsense_mv, (t10 < 0) ? "-" : "",
         (long)(t10_abs / 10), (long)(t10_abs % 10));
  /* USER CODE END WHILE */

  /* USER CODE BEGIN 3 */
  HAL_Delay(1000);
}
  1. 폴링 반환값을 검사하지 않는다. 타임아웃이 나도 직전 DR 값을 그대로 쓰고 넘어간다(01 예제는 검사 후 Error_Handler).
  2. 곱셈을 먼저 하고 나눈다. 3300UL로 부호 없는 32비트 연산이 되어 넘침이 없다.
  3. Vsense가 1430 mV보다 크면(25 °C 미만) 분자가 음수가 되며, C의 정수 나눗셈은 0쪽으로 버린다.
  4. t10이 음수일 때 -0.5 같은 값도 부호를 따로 찍어 올바르게 표시한다. t10/10만 쓰면 −0.5가 “0.5”로 보이는 문제가 생긴다.
  5. %f 없이 정수부·소수부를 찍어 newlib-nano 기본 설정에서도 동작한다.
기대 출력 (예시 — raw 값은 칩과 온도에 따라 다르다)
ADC TempSensor raw=1735 (1398 mV) -> 32.4 C
ADC TempSensor raw=1700 (1369 mV) -> 39.1 C     ← 칩을 손가락으로 데운 뒤

1735 × 3300 / 4095 = 1398.2 → 1398 mV, (1430 − 1398) × 100 / 43 = 74.4 → 74, t10 = 324 → 32.4 °C이다. 1초마다 한 줄씩 나오며, 값은 ±1 LSB(±0.2 °C) 정도 흔들린다. 표시 온도가 실내 온도보다 높은 것은 오프셋 편차와 자체 발열 때문이며 이상이 아니다.

8. 실험

실험 A. 손가락과 냉각 스프레이

칩(보드 가운데의 STM32F103RB) 위를 손가락으로 덮고 30초간 출력을 기록한다. 몇 °C 오르는지, 손을 뗀 뒤 원래 값으로 돌아오는 데 얼마나 걸리는지 본다. 절대값보다 변화량이 이 센서의 쓸모임을 확인한다.

실험 B. 샘플 시간을 줄인다

CubeMX에서 샘플 시간을 1.5 사이클로 바꾸고 다시 생성한다. 출력이 어떻게 달라지는지(평균 위치, 흔들림) 239.5 사이클과 비교한다. 01_ADC_Single의 현재 소스가 바로 이 설정이다.

실험 C. 한 점 오프셋 보정

보드를 실온에서 10분 이상 켜 둔 뒤, 신뢰할 수 있는 온도계로 칩 표면 온도를 잰다. 차이 (기준 − 표시) × 10을 상수로 두고 t10에 더하는 코드를 직접 추가해 본다. 이 보정은 오프셋만 맞추고 기울기 오차(4.0~4.6 mV/°C)는 남는다는 점을 시뮬레이터로 확인한다.

실험 D. 클럭을 낮춰 발열을 비교한다

SYSCLK를 64 MHz에서 8 MHz(HSI 직접)로 바꾸고 ADCPRE를 맞춘 뒤, 같은 환경에서 몇 분 후의 안정된 표시 온도를 비교한다. 동작 전류가 줄면(Table 17: 64 MHz 약 24~31 mA → 8 MHz 약 4~5 mA) 다이 온도가 얼마나 내려가는지 본다.

10. 확인 문제

문제 1. ADCCLK 8 MHz에서 온도 센서 샘플 시간으로 71.5 사이클을 쓰면 안 되는 이유는?

71.5 / 8 MHz = 8.94 µs로 권장 17.1 µs에 못 미친다. 8 MHz에서 조건을 만족하는 값은 239.5 사이클(29.9 µs)뿐이다.

문제 2. raw = 1800이면 예제가 출력하는 온도는? 중간 값까지 정수 연산으로 구하라.

1800 × 3300 / 4095 = 1450.5 → 1450 mV. (1430 − 1450) × 100 / 43 = −2000 / 43 = −46.5 → −46(0쪽으로 버림). t10 = −46 + 250 = 204 → “20.4 C”이다.

문제 3. 어떤 칩의 실제 V25가 1.52 V(max)라면, 소스의 1430 mV 식은 몇 °C쯤 틀리게 표시하는가? 방향은?

같은 온도에서 Vsense가 90 mV 높으므로 (1520 − 1430) / 4.3 ≈ 20.9 °C 낮게 표시한다. 반대로 V25가 1.34 V인 칩은 약 20.9 °C 높게 표시한다. RM0008이 말하는 칩 간 최대 45 °C 오프셋과 같은 크기이다.

문제 4. 출력 온도를 ‘방 온도’로 쓸 수 없는 이유를 두 가지 들라.

첫째, 센서는 공기가 아니라 다이 온도를 재며 칩 자체 발열(이 예제 조건에서 수 °C 추정)이 더해진다. 둘째, V25 칩 편차가 ±90 mV(약 ±21 °C)로 커서 보정 없이는 절대값을 믿을 수 없다. 여기에 VDDA 가정 오차와 직선성 오차(±1~2 °C)가 더해진다.
