ADC: 핀의 전압 하나가 12비트 숫자가 되기까지

ADC(Analog-to-Digital Converter, 아날로그-디지털 변환기)는 디지털논리에서 배운 멀티플렉서, 카운터, 상태기계, 크기 비교기에 아날로그 소자 셋(스위치, 커패시터, 비교기)을 더해 "연속적인 전압"을 "정수"로 바꾸는 주변장치이다. 이 개념설명은 STM32F103RB를 기준으로, 핀에 걸린 전압이 아날로그 멀티플렉서를 지나 커패시터에 붙잡히고, 축차 비교로 12비트 코드가 되어 데이터 레지스터에 놓이기까지의 경로를 원본 블록도 위에서 따라간다. 그다음 그 결과가 플래그, 인터럽트, DMA 요청으로 바뀌어 칩 안의 다른 장치로 퍼져 나가는 길을 본다.

1. 문제 정의: ADC가 없으면 CPU가 무엇을 직접 해야 하는가

가변저항이나 센서가 내는 전압을 숫자로 읽고 싶다. 디지털 입력 핀은 전압을 문턱 하나와 비교해 0 또는 1만 알려 준다(01_GPIO의 슈미트 트리거). 12비트 분해능, 즉 4096단계로 읽으려면 "기준전압을 4096칸으로 나눈 눈금 중 어디에 있는가"를 알아내야 한다. ADC가 없다면 CPU가 외부 비교기 하나와 GPIO로 만든 DAC(Digital-to-Analog Converter, 디지털-아날로그 변환기)를 써서 이 일을 직접 한다.

F103의 ADC는 이 전부를 하드웨어로 한다. 변환 하나는 샘플링 시간 + 12.5 ADC 클럭이며, ADC 클럭 14 MHz와 최소 샘플링 1.5 클럭이면 14 클럭 = 1 µs이다(RM0008 11.6, p.225). 그동안 CPU는 아무것도 하지 않아도 된다. 이 그룹 예제들이 폴링 → 타이머 트리거 + DMA → 하드웨어 비교(워치독) → 기준전압 보정으로 발전해 가는 것은, 위 표의 오른쪽 열을 하나씩 더 많이 하드웨어에 맡기는 과정이다.

2. 일반 개념

샘플링과 양자화

ADC는 두 가지 "자르기"를 한다. 샘플링은 시간을 자른다. 연속 신호에서 특정 순간의 값만 골라낸다. 양자화는 크기를 자른다. 골라낸 전압을 2N개의 칸 중 하나로 반올림(정확히는 버림)한다. N비트 ADC에서 한 칸의 폭을 1 LSB라고 한다.

1 LSB = V_REF+ / 2^N (DS5319 Figure 37의 정의, N = 12이면 4096칸) 코드 k ⇔ k·LSB ≤ V_IN < (k+1)·LSB (이상적인 변환 곡선) V_REF+ = 3.3 V 이면 1 LSB = 0.806 mV, 최대 코드 4095 = 3.299 V

코드를 전압으로 되돌릴 때 VREF+/4096을 곱하는 것이 정의에 맞다. 하부 예제들처럼 /4095를 쓰면 전체 범위에서 차이가 1 LSB보다 작으므로 실용상 문제는 없다. 양자화 때문에 생기는 오차는 최대 1 LSB(버림 기준)이며, 이보다 정밀하게 읽을 수는 없다.

샘플-홀드: 왜 붙잡아야 하는가

변환에는 시간이 걸린다. 그 사이 입력이 1 LSB(0.8 mV)만 움직여도 결과가 틀어진다. 그래서 변환 전에 스위치를 닫아 작은 커패시터를 입력 전압까지 충전하고(샘플), 스위치를 열어 그 전압을 붙잡은 채(홀드) 변환한다. 디지털논리의 D 래치와 같은 발상이다. 클럭이 High인 동안 입력을 따라가고(투명), Low가 되면 마지막 값을 붙잡는다. 다른 점은 저장하는 것이 비트가 아니라 전하라는 것이다.

RC 회로의 커패시터 전압은 목표값과의 차이가 시정수 τ = (RAIN + RADC) × CADC마다 1/e로 줄어든다. 남은 차이가 1/4 LSB, 즉 전체의 2−(N+2)보다 작아지려면 샘플링 시간 TS가 τ × ln(2N+2)보다 길어야 한다. 이 식을 RAIN에 대해 풀면 데이터시트의 식 1이 된다.

R_AIN < T_S / ( f_ADC × C_ADC × ln(2^(N+2)) ) − R_ADC (DS5319 Equation 1, p.75, N = 12) T_S는 ADC 클럭 수(1.5, 7.5, … 239.5), ln(2^14) ≈ 9.70

결론은 간단하다. 신호원 저항이 클수록 샘플링을 길게 해야 한다. 샘플링을 길게 하면 변환 하나가 길어지므로 초당 샘플 수가 줄어든다. 이 맞교환은 4장 계산기와 8장에서 다시 본다.

축차 비교(SAR): 12번의 이진 탐색

홀드된 전압을 숫자로 바꾸는 방법 중 F103이 쓰는 것은 축차 비교(successive approximation)이다(RM0008 11.1, p.215). 숫자 맞히기 놀이와 같다. "절반보다 큰가?"를 묻고, 답에 따라 범위를 반으로 줄이는 일을 12번 하면 4096칸 중 하나가 정해진다.

  1. SAR 레지스터를 1000 0000 0000(가운데 값)으로 놓는다.
  2. DAC가 이 코드를 전압 VDAC로 바꾼다. 비교기가 홀드 전압과 비교한다.
  3. Vhold ≥ VDAC이면 그 비트를 1로 남기고, 아니면 0으로 되돌린다.
  4. 다음 아래 비트를 1로 놓고 2~3을 반복한다. 비트 0까지 끝나면 SAR 레지스터 값이 결과이다.

문서 안의 엇갈림: EOC는 언제 서는가

6. 이벤트 생성 기전: 플래그 → 인터럽트 → DMA → 다른 장치

① 들어오는 사건: 다른 주변장치가 변환을 시작시킨다

정규 그룹의 트리거 선택기에는 TIM1_CC1, TIM1_CC2, TIM1_CC3, TIM2_CC2, TIM3_TRGO, TIM4_CC4, EXTI 11번 선, SWSTART의 여덟 입력이 있다(RM0008 Table 67, p.225). 주입 그룹은 TIM1_TRGO, TIM1_CC4, TIM2_TRGO, TIM2_CC1, TIM3_CC4, TIM4_TRGO, EXTI 15번 선, JSWSTART이다(Table 68, p.226). 타이머의 TRGO에 무엇을 실을지는 타이머 쪽 MMS가 정한다. MMS = 010이면 갱신(update) 이벤트가 TRGO가 된다(RM0008 15.4.2, p.406). 타이머 주기가 곧 샘플링 주기가 되므로, 샘플 간격이 소프트웨어 실행 시간과 무관해진다. 외부 트리거는 상승 엣지에서만 변환을 시작한다(11.7).

정오표 ES096 2.6.2(p.14): TRGO는 펄스로 전달되므로, 받는 주변장치(여기서는 ADC)의 클럭을 켜기 전에 타이머가 TRGO를 내면 트리거가 실패할 수 있다. 트리거를 받는 동안 받는 쪽 클럭 분주(ADCPRE)를 바꿔도 실패할 수 있다. ADC 클럭을 먼저 켜고, 타이머는 마지막에 출발시키는 순서가 필요하다. 문서는 "documentation issue"로 분류하고 이 순서를 지키면 회피책이 필요 없다고 적는다.

② 인터럽트: 세 사건, 하나의 벡터, 두 개의 ADC

EOC·JEOC·AWD 셋이 각자의 허용 비트와 AND된 뒤 OR되어 ADC 인터럽트 선 하나가 된다(Figure 22 위쪽, Table 71). 게다가 RM0008 11.11은 "ADC1 and ADC2 interrupts are mapped onto the same interrupt vector"라고 적는다(p.236). 벡터 테이블에서는 위치 18, 이름 ADC1_2, 주소 0x0000_0088이다(RM0008 Table 63, p.205). Cortex-M3에서 IRQ n의 벡터는 0x40 + 4n이므로 0x40 + 4 × 18 = 0x88로 맞는다(PM0056 Table 16, p.34). 따라서 ISR(Interrupt Service Routine)은 두 ADC의 SR을 모두 읽어 어느 ADC의 어느 사건인지 가려야 한다.

STRT·JSTRT는 SR에 서지만 인터럽트로 이어지지 않는다(11.11). AWD 인터럽트는 "상태"를 알리는 성격이라 7장 ③처럼 창 밖에 머무는 동안 반복될 수 있다.

③ DMA 요청: 결과를 CPU 없이 메모리로

"Only the end of conversion of a regular channel generates a DMA request"(RM0008 11.8, p.227). CR2.DMA = 1이면 정규 변환이 끝날 때마다 요청선이 서고, DMA1 채널 1이 ADC_DR을 읽어 메모리에 쓴다(Table 78, p.282). DMA1 채널 1에는 TIM2_CH3, TIM4_CH1 요청도 OR로 묶여 있어 동시에 하나만 켜야 한다(13.3.7, p.281).

DMA를 원형(circular) 모드로 두면 전송 개수가 0이 될 때 자동으로 처음 값과 처음 주소로 돌아간다. 절반을 옮기면 HTIF(Half Transfer), 전부 옮기면 TCIF(Transfer Complete)가 서고, 허용하면 각각 인터럽트가 된다(RM0008 13.3.3, p.278). DMA1 채널 1의 벡터는 위치 11, 0x0000_006C이다(Table 63, p.204). 이렇게 하면 CPU는 변환마다가 아니라 "버퍼 절반마다" 한 번 깨어난다. HT 시점에 앞 절반을 처리하는 동안 DMA는 뒤 절반을 채우므로, 처리 중인 데이터가 덮어써지지 않는다(이중 버퍼링). DMA 내부 구조는 07_DMA 그룹에서 다룬다.

④ 나가는 사건

Figure 22에서 ADC가 바깥으로 내보내는 선은 인터럽트 선과 DMA 요청선뿐이다. 워치독 사건(AWD)을 타이머 등 다른 주변장치의 입력으로 직접 연결하는 경로는 이 문서들에 나오지 않는다. 이중 모드에서는 ADC1이 ADC2에 시작 신호를 넘긴다(11.9, Figure 29).

9. 이해 확인 문제

Q1. PCLK2 = 72 MHz이다. 쓸 수 있는 가장 빠른 ADCCLK와 최단 변환 시간은?

÷4는 18 MHz로 14 MHz를 넘으므로 ÷6 = 12 MHz가 최대이다. 최단 변환은 (1.5 + 12.5) / 12 MHz = 1.17 µs이다. RM0008 11.2의 "1.17 µs at 72 MHz"와 같다.

Q2. ADCCLK 10.67 MHz, 두 채널을 각각 55.5 클럭으로 스캔한다. 1 kHz 트리거라면 1 ms 중 ADC가 일하는 비율은?

채널당 68 클럭 = 6.375 µs, 두 채널 12.75 µs, 트리거 지연 약 0.2 µs를 더해 약 12.95 µs이다. 1000 µs 중 약 1.3 %이다. 나머지 시간에 다른 채널을 더 넣거나 샘플링을 늘릴 여유가 충분하다.

Q3. 신호원 저항이 30 kΩ인 센서를 ADCCLK 14 MHz로 읽는다. 고를 수 있는 가장 짧은 SMP와 변환 시간은?

Table 48에서 28.5 클럭은 25.2 kΩ까지라 부족하고, 41.5 클럭이 37.2 kΩ까지이므로 41.5를 고른다. 변환 시간은 (41.5 + 12.5) / 14 MHz = 3.86 µs이다. 4장 계산기에서 확인할 수 있다.

Q4. ADCCLK 12 MHz에서 온도 센서를 읽는다. 샘플링 17.1 µs를 만족하는 SMP는?

17.1 µs × 12 MHz = 205.2 클럭이 필요하다. 71.5는 모자라므로 239.5를 고른다. 이때 샘플링은 20.0 µs, 변환 전체는 252 / 12 MHz = 21.0 µs이다.

Q5. VDDA = 3.3 V일 때 1 LSB는? 입력 1.000 V의 이상적인 코드는?

1 LSB = 3.3 / 4096 = 0.806 mV이다. 1.000 / 0.806 mV = 1241.2이므로 코드는 1241이다(k·LSB ≤ VIN < (k+1)·LSB). 2장의 축차 비교 따라가기 기본값이 이 경우이다. 실제 칩은 Table 50의 오차(전형 ±2 LSB)만큼 흔들린다.

Q6. VREFINT 채널의 코드가 1490이다. VDDA는? VREFINT 편차를 고려하면 범위는?

전형값 1.20 V로 VDDA = 1.20 × 4096 / 1490 = 3.30 V이다. VREFINT가 1.16 V이면 3.19 V, 1.24 V이면 3.41 V이다. 칩별 교정값이 없으므로 약 ±3.3 %의 불확실성이 남는다.

Q7. 네 채널을 SCAN = 1, DMA 없이 돌리고 EOC 인터럽트에서 DR을 읽었더니 늘 마지막 채널 값만 보인다. 왜이며, 해결책 두 가지는?

정규 결과 레지스터는 하나이고, 스캔 중 EOC 인터럽트는 마지막 채널 끝에서만 생긴다(CR1.SCAN 주석). 앞 채널 결과는 이미 덮어써졌고, 오버런 플래그도 없어 알 수 없다. 해결책은 ① DMA로 변환마다 메모리에 옮기기(RM0008이 요구하는 방식), ② 불연속 모드 n = 1로 트리거 한 번에 한 채널만 변환하고 그때마다 읽기이다.

Q8. LTR = 1000, HTR = 3000, VDDA = 3.3 V. 입력이 3.0 V에 머문다. 무슨 일이 일어나는가?

코드는 3.0 / 3.3 × 4096 ≈ 3723으로 HTR보다 크다. 연속 변환이면 변환마다 AWD가 다시 선다. AWDIE를 켜 둔 채 플래그만 지우면 변환마다 인터럽트가 걸려(239.5 클럭, 10.67 MHz라면 초당 약 4만 번) CPU가 다른 일을 못 한다. 첫 인터럽트에서 AWDIE를 끄고 복귀를 확인한 뒤 다시 켜야 한다(7장 ③).

Q9. VSENSE = 1.38 V이다. 전형값으로 계산한 온도는? V25 편차만 고려하면 범위는?

(1.43 − 1.38) / 0.0043 + 25 = 36.6 °C이다. V25가 1.34 V이면 15.7 °C, 1.52 V이면 57.6 °C로 약 ±21 °C이다. 그래서 RM0008은 온도 "변화" 감지에 쓰고, 정확한 온도는 외부 센서를 쓰라고 한다.

Q10. ALIGN = 1(왼쪽 정렬)에서 정규 채널 결과 0xABC는 DR에 어떻게 보이는가? 워치독 HTR에는 어떤 값을 써야 하는가?

D11이 비트 15에 오므로 DR = 0xABC0이다(Figure 28). 워치독은 정렬 전 12비트 값과 비교하므로 HTR에는 정렬과 무관하게 0xABC 같은 12비트 값을 쓴다(11.3.7).

Q11. CR2에 CONT = 1과 ADON = 1을 한 번에 썼더니(ADON은 이미 1이었다) 변환이 시작되지 않았다. 왜인가?

ADON 외의 비트를 같은 쓰기에서 함께 바꾸면 변환이 시작되지 않는다(RM0008 p.243 주석). 잘못된 설정 변경이 곧바로 변환을 일으키지 않게 하려는 장치이다. CONT를 먼저 쓰고, ADON만 따로 다시 써야 한다.

    예: PCLK2 64 MHz ÷ 6 = 10.67 MHz, 샘플링 55.5사이클 → (55.5 + 12.5) / 10.67 MHz ≈ 6.4 µs
    신호원의 저항이 크면 커패시터가 천천히 차므로 샘플링 시간을 늘려야 정확해지고, 그만큼 변환이 느려진다.
  4. 여러 채널과 시작 방법을 고를 수 있다. 한 번만 변환할 수도 있고(단일), 계속 반복할 수도 있고(연속, CONT), 채널 여러 개를 순서대로 변환할 수도 있다(스캔, SCAN). 시작은 소프트웨어 명령으로 하거나 타이머 신호로 한다. 타이머로 시작하면 샘플 간격이 하드웨어로 정해져 일정하다. 결과 레지스터가 하나뿐이라 여러 채널의 결과를 놓치지 않으려면 DMA로 옮긴다.
  5. 결과는 "전원 전압에 대한 비율"이다. 이 칩에서는 기준전압이 전원(VDDA)에 묶여 있다. 전원이 3.3 V에서 3.2 V로 내려가면 같은 입력이어도 코드가 약 3 % 커진다. 칩 안의 고정 전압 VREFINT(약 1.2 V)를 읽으면 VDDA를 거꾸로 계산해 보정할 수 있다. 다만 VREFINT 값도 칩마다 조금씩 다르다(1.16~1.24 V).
한 걸음 더 — 필요할 때 해당 장에서 찾아본다
  • 아날로그 워치독(5장, 7장): 변환값이 정해 둔 범위를 벗어나면 인터럽트를 낸다. 범위를 벗어나 있는 동안은 변환할 때마다 반복해서 걸린다.
  • 인터럽트 연결(6장): 변환 완료, 주입 변환 완료, 워치독이 ADC1과 ADC2가 공유하는 벡터 18 하나로 모인다.
  • 시작 시점 선택(5장, 6장): 외부 트리거를 고르는 EXTSEL·EXTTRIG, 연결할 수 있는 타이머 신호의 종류.
  • 온도 센서와 VREFINT 읽기(7장): 내부 채널은 샘플링 시간을 17.1 µs 정도로 길게 잡아야 한다.
  • 값의 정렬(5장): 12비트 결과를 16비트 레지스터의 오른쪽 또는 왼쪽에 붙여 놓는 방식을 고른다.
