ADC 다채널 읽기: 스캔 모드와 불연속 모드

ADC 한 개로 여러 아날로그 입력을 읽으려면 채널을 차례로 바꿔 가며 변환해야 한다. 그런데 결과 레지스터(DR)는 하나뿐이다. 이 교안은 그 제약에서 출발해 변환 시퀀스(랭크), 스캔 모드, 불연속 모드를 차례로 익히고, DMA 없이 폴링만으로 4채널(A0, A1, A2, Vrefint)을 순서대로 읽는 03_ADC_Multi 예제를 레지스터 수준까지 해석한다.

1. 문제: 채널은 여럿, DR은 하나

STM32F103의 ADC1은 변환기(SAR) 하나를 아날로그 멀티플렉서로 여러 입력에 나눠 쓴다. 외부 핀 채널 0~15에 내부 온도 센서(CH16)와 내부 기준전압 Vrefint(CH17)까지 18개 입력이 있지만, 한 번에 변환하는 채널은 하나이다. 레귤러 그룹의 결과가 들어가는 데이터 레지스터 ADC1_DR도 하나뿐이다.

여러 채널을 연달아 변환하면 앞 채널의 결과는 CPU가 읽기 전에 다음 결과로 덮어써진다. F103의 ADC에는 덮어쓰기를 알려 주는 오버런(OVR) 플래그도 없다. 따라서 다채널 측정의 핵심 질문은 하나이다.

핵심 질문

각 채널의 결과가 DR에 들어온 뒤, 다음 결과가 덮어쓰기 전에 누가 그것을 꺼내 가는가?

2. 변환 시퀀스: 랭크(rank)와 샘플 시간

레귤러 그룹은 최대 16개의 변환을 순서표로 갖는다. 순서표의 칸을 랭크라 하고, 각 랭크에 어떤 채널을 넣을지는 SQR1~SQR3, 전체 변환 개수는 SQR1.L(= 개수 − 1)로 정한다. 샘플 시간은 랭크가 아니라 채널마다 SMPR1(CH10~17), SMPR2(CH0~9)에 둔다.

랭크레지스터 필드채널핀샘플 시간 (SMPRx 코드)변환 시간
1SQR3.SQ1 = 0CH0PA0 (A0)55.5 cyc (101) · SMPR268 cyc = 6.4 µs
2SQR3.SQ2 = 1CH1PA1 (A1)55.5 cyc (101) · SMPR268 cyc = 6.4 µs
3SQR3.SQ3 = 4CH4PA4 (A2)55.5 cyc (101) · SMPR268 cyc = 6.4 µs
4SQR3.SQ4 = 17CH17내부 Vrefint239.5 cyc (111) · SMPR1252 cyc = 23.6 µs
SQR1.L = 3 → 변환 4개. 시퀀스 전체 3×68 + 252 = 456 ADC 클럭 ≈ 42.8 µs.
변환 시간 계산

T_conv = (샘플 시간 + 12.5) / ADCCLK — 12.5 사이클은 12비트 축차 비교에 드는 고정 시간이다.

ADCCLK = PCLK2 64 MHz / 6 (RCC_CFGR.ADCPRE) = 10.67 MHz. F103의 ADCCLK 상한은 14 MHz이다.

예: (55.5 + 12.5) / 10.67 MHz = 68 / 10.67 MHz ≈ 6.4 µs

샘플 시간을 채널마다 다르게 주는 이유. 샘플 시간 동안 ADC 내부의 샘플링 커패시터가 입력 전압까지 충전된다. 신호원 임피던스가 클수록 오래 걸린다. 가변저항 같은 외부 신호에는 55.5 사이클이면 충분하지만, Vrefint는 데이터시트가 샘플 시간 17.1 µs 이상을 권장한다. 239.5 사이클은 239.5 / 10.67 MHz ≈ 22.4 µs로 이 조건을 만족한다.

3. 세 가지 변환 모드 비교

같은 순서표(랭크 1~4)를 두고 CR1.SCAN, CR1.DISCEN 비트에 따라 트리거 한 번에 변환되는 범위가 달라진다. 아래 막대는 트리거 한 번에 일어나는 일이다.

SQ1SQ2SQ3SQ4

랭크 1 하나만 변환한다. 다른 채널을 읽으려면 매번 SQ1을 다시 설정해야 한다.

② 스캔SCAN=1, DISCEN=0

4개를 쉬지 않고 연달아 변환한다. DR이 세 번 덮어써져 CPU는 마지막 값만 본다. EOC는 시퀀스 끝에서 선다. DMA가 필요하다.

③ 스캔 + 불연속 (이 예제)SCAN=1, DISCEN=1, DISCNUM=000
SQ1→ 대기

트리거마다 시퀀스의 다음 1채널만 변환하고 멈춘다. 그 사이 CPU가 DR을 읽는다. 마지막 랭크 다음 트리거는 랭크 1로 돌아간다.

불연속 모드의 DISCNUM은 트리거 한 번에 변환할 개수(n = DISCNUM + 1, 최대 8)이다. 이 예제는 n = 1로 두어 ‘트리거 1번 = 1채널’을 만든다. 레퍼런스 매뉴얼(RM0008 11.3.10)의 예처럼 n = 3이면 랭크 8개를 3, 3, 2개씩 나누어 변환하고, EOC는 시퀀스의 마지막 묶음이 끝났을 때만 선다. 이 사실이 5절의 HAL 동작으로 이어진다.

하드웨어는 ‘지금 몇 번째 랭크인지’ 알려 주지 않는다

불연속 모드의 다음 랭크 위치는 ADC 내부에만 있고 읽을 수 있는 레지스터가 없다. 소프트웨어는 트리거 횟수를 정확히 4의 배수로 유지해서 순서를 맞춘다. 한 번이라도 빼먹거나 더하면 그 뒤의 값이 모두 한 칸씩 밀린다(8절 실험 A).

5. HAL 함수 흐름과 F1의 제약

예제의 adc_scan_once()는 아래 세 줄을 채널 수만큼 반복한다. 각 단계에서 하드웨어와 소프트웨어가 하는 일을 나누어 보면 다음과 같다.

  1. 1
    HAL_ADC_Start(&hadc1)CPUADON이 이미 1이면 다시 켜지 않는다. SR.EOC를 지우고 CR2.SWSTART | CR2.EXTTRIG를 세운다.
  2. 2
    다음 랭크 1채널 변환ADC불연속 모드이므로 시퀀스의 다음 랭크 하나만 샘플링·변환하고 결과를 DR에 쓴 뒤 멈춘다. 랭크 1~3에서는 EOC가 서지 않고, 랭크 4(시퀀스 끝)에서만 선다.
  3. 3
    HAL_ADC_PollForConversion(&hadc1, 10)CPU스캔 모드(SCAN=1)이고 SQR1.L ≥ 1이면 EOC를 기다리지 않고 최대 변환 시간만큼 빈 루프로 대기한 뒤 EOC, STRT를 지운다.
  4. 4
    HAL_ADC_GetValue(&hadc1)CPUDR을 읽는다. 다음 HAL_ADC_Start 전에 읽어야 한다.
왜 EOC를 기다리지 않는가 — stm32f1xx_hal_adc.c의 주석

“On STM32F1 devices, limitation in case of sequencer enabled (several ranks selected): polling cannot be done on each conversion inside the sequence. In this case, polling is replaced by wait for maximum conversion time.”

3절에서 본 대로 EOC는 시퀀스 끝에서만 선다. 랭크 1~3 뒤에 EOC를 기다리면 영원히 오지 않으므로, HAL은 대신 모든 채널 중 가장 긴 샘플 시간(이 예제는 239.5 → 252 ADC 클럭)에 해당하는 CPU 사이클 수를 계산해 그만큼 센다(ADC_CONVCYCLES_MAX_RANGE). 64 MHz / 10.67 MHz = 6이므로 6 × 252 = 1512회 루프이며, 루프 한 바퀴가 여러 CPU 사이클이므로 실제 대기는 변환 시간보다 넉넉히 길다.

HAL_ADC_Stop()을 루프 중간에 부르지 않는다

HAL_ADC_Stop()은 CR2.ADON = 0으로 ADC를 끈다. 예제는 ADC를 켠 상태로 두어 다음 HAL_ADC_Start()가 시퀀스의 다음 랭크에서 이어지게 한다. 네 번의 Start가 정확히 한 시퀀스를 이루도록 시작·정지 횟수를 바꾸지 않는 것이 이 방식의 전제이다.

이 예제에 ISR이 있는가? 없다. ADC 인터럽트(ADC1_2_IRQn)를 쓰지 않으며 HAL ADC 콜백(HAL_ADC_ConvCpltCallback)도 정의하지 않는다. 동작 중인 ISR은 HAL 틱용 SysTick_Handler뿐이다.

6. Vrefint로 VDDA를 역산한다

ADC 결과는 전압 그 자체가 아니라 VDDA에 대한 비율이다. raw = V_in / VDDA × 4095. VDDA가 3.3 V라고 가정하고 mV로 바꾸면 VDDA가 3.2 V로 떨어졌을 때 모든 값이 약 3% 틀어진다.

Vrefint(CH17)는 VDDA와 무관하게 약 1.20 V인 내부 기준전압이다. 이 값을 같은 ADC로 재면 거꾸로 VDDA를 구할 수 있다.

두 식

VDDA[mV] = 1200 × 4095 / raw_vref

V_ch[mV] = raw_ch × VDDA[mV] / 4095

예: raw_vref = 1489 → VDDA = 1200 × 4095 / 1489 = 3300 mV (정수 나눗셈)

  • Vrefint를 쓰려면 ADC1_CR2.TSVREFE = 1이어야 한다. HAL_ADC_ConfigChannel()이 CH16/CH17을 설정할 때 이 비트가 꺼져 있으면 켠다. 안정화 시간(ADC_TEMPSENSOR_DELAY_US = 10 µs)을 기다리는 것은 온도 센서(CH16)를 설정할 때뿐이고, 이 예제처럼 Vrefint(CH17)만 쓰면 비트만 켜고 기다리지 않는다. Vrefint 채널의 샘플링 시간 239.5 사이클(ADC 클럭 10.67 MHz에서 약 22.5 µs)은 데이터시트의 Vrefint 샘플링 시간 최댓값 17.1 µs보다 길다.
  • Vrefint의 개체 편차는 1.16~1.24 V이다. F103에는 공장 교정값이 저장되어 있지 않으므로 1200 mV를 쓰면 최대 약 ±3%의 오차가 남는다. 시뮬레이터에서 ‘이 칩의 실제 Vrefint’를 바꿔 출력 VDDA가 얼마나 틀어지는지 확인한다.
  • VDDA가 바뀌어도 raw_ch / raw_vref 비율은 그대로이므로, 이 방식으로 환산한 mV는 VDDA 변동에 강하다. 원리는 06_ADC_Vrefint_VDDA_c에서 더 자세히 다룬다.

Core/Src/main.c — USER CODE BEGIN 0: adc_scan_once()
static void adc_scan_once(uint16_t out[N_CH])
{
  for (uint32_t r = 0; r < N_CH; r++)
  {
    HAL_ADC_Start(&hadc1);
    if (HAL_ADC_PollForConversion(&hadc1, 10) != HAL_OK)
      Error_Handler();
    out[r] = (uint16_t)HAL_ADC_GetValue(&hadc1);
  }
  /* HAL_ADC_Stop() 은 호출하지 않는다 */
}
  1. N_CH = 4 = SQR1.L + 1이어야 한다. 다르면 순서가 밀린다.
  2. CR2.SWSTART = 1 → 다음 랭크 1채널 변환
  3. 스캔 모드이므로 EOC 대신 최대 변환 시간 대기
  4. DR 읽기. r번째 읽기 = 랭크 r+1의 결과
  5. ADON을 유지해야 다음 호출이 랭크 1에서 이어진다.

HAL_ADCEx_Calibration_Start(&hadc1);

while (1) {

8. 실험

배선: PA0(A0), PA1(A1), PA4(A2)에 가변저항의 가운데 단자를 연결하고, 양 끝을 3V3과 GND에 연결한다. 연결하지 않은 핀은 떠 있어(플로팅) 값이 흔들린다. 터미널은 115200 8N1이다.

기본 동작 확인

A0=2048(1650mV) A1=   0(   0mV) A2=4095(3300mV) | Vref=1489 -> VDDA=3300mV

가변저항을 돌리며 해당 채널 값만 바뀌는지 확인한다. 다른 채널까지 함께 움직이면 배선이나 랭크 순서를 의심한다.

실험 A. 읽는 횟수를 하나 줄인다

adc_scan_once()의 반복 횟수를 3으로 바꾼다(예: 루프 조건을 r < N_CH - 1로). 시퀀스는 여전히 4칸이므로 매 호출마다 시작 랭크가 한 칸씩 밀린다. 출력에서 각 값이 어느 채널을 가리키는지 추적하고, 시뮬레이터의 ‘읽는 횟수 3’과 비교한다.

실험 B. 불연속 모드를 끈다

CubeMX에서 Discontinuous Conversion Mode를 Disabled로 바꾸거나, USER CODE BEGIN ADC1_Init 2에서 CLEAR_BIT(hadc1.Instance->CR1, ADC_CR1_DISCEN);을 추가한다. 트리거 한 번에 4채널이 연달아 변환되면 어떤 값이 출력되는지 예측한 뒤 확인한다. 시뮬레이터 모드 ②는 ‘네 칸 모두 Vrefint’로 예측하지만, 실제 결과는 HAL 대기 시간과 시퀀스 길이의 관계에 따라 달라질 수 있다.

실험 C. Vrefint 샘플 시간을 줄인다

랭크 4의 샘플 시간을 ADC_SAMPLETIME_239CYCLES_5에서 ADC_SAMPLETIME_7CYCLES_5로 바꾼다. 샘플링 커패시터가 덜 충전되면 Vref 값과 계산된 VDDA가 어떻게 달라지는지 관찰한다.

실험 D. 한 번의 스캔에 걸리는 시간을 잰다

adc_scan_once() 앞뒤에서 DWT 사이클 카운터(08_Clock_System/10_DWT_Profiling_Reg_c)를 읽어 실제 소요 시간을 잰다. 하드웨어 변환 시간(약 42.8 µs)과 비교해 HAL의 소프트웨어 대기가 얼마나 차지하는지 확인한다. 이 차이가 DMA 방식(04_ADC_DMA_TimTrigger)을 쓰는 이유 중 하나이다.

9. 트러블슈팅

증상원인조치
네 값이 모두 비슷하고 Vref 값과 같다불연속 모드가 꺼져 시퀀스가 한 번에 끝나고 DR에 마지막 랭크만 남았다DiscontinuousConvMode = ENABLE, NbrOfDiscConversion = 1을 확인한다.
값이 채널 사이에서 한 칸씩 밀려 보인다트리거 횟수와 랭크 수(SQR1.L + 1)가 맞지 않는다N_CH와 NbrOfConversion을 같게 하고, 루프 중간에 HAL_ADC_Start를 더 부르지 않는다.
VDDA가 4000 mV 이상 또는 터무니없는 값Vrefint 샘플 시간이 너무 짧거나 TSVREFE가 꺼져 있다239.5 사이클을 쓰고, CH17을 HAL_ADC_ConfigChannel로 설정했는지 확인한다.
연결하지 않은 채널 값이 계속 흔들린다플로팅 입력정상이다. 측정하려면 가변저항이나 분압 회로를 연결한다.
모든 값에 일정한 오프셋이 있다교정을 하지 않았다HAL_ADCEx_Calibration_Start()를 첫 변환 전에 호출한다.
모든 채널의 mV가 같은 비율로 조금씩 틀리다Vrefint 개체 편차(1.16~1.24 V)정밀한 전압계로 VDDA를 재서 VREFINT_MV를 보정한다.

10. 확인 문제

먼저 스스로 답을 정해 본 뒤 펼쳐 확인한다.

문제 1. 스캔 모드만 켜고(DISCEN = 0) DMA 없이 HAL_ADC_GetValue()를 4번 부르면 왜 4채널 값을 얻지 못하는가?

트리거 한 번에 4채널이 연달아 변환되며 결과는 모두 하나뿐인 DR에 차례로 쓰인다. CPU가 읽을 때는 이미 뒤 채널 값으로 덮어써져 있다. F1 ADC에는 오버런 플래그도 없어 덮어쓰기를 알 수 없다.

문제 2. 이 예제에서 SQR1.L, SQR3.SQ1~SQ4, CR1.DISCNUM의 값은?

SQR1.L = 3(변환 4개), SQ1 = 0, SQ2 = 1, SQ3 = 4, SQ4 = 17, DISCNUM = 000(트리거당 1채널).

문제 3. 스캔 모드에서 HAL_ADC_PollForConversion()은 왜 EOC를 기다리지 않는가? 그 대신 무엇을 하는가?

F1에서 시퀀스가 여러 랭크이면 EOC는 시퀀스 끝에서만 서므로, 랭크 1~3 뒤에는 EOC가 오지 않는다. HAL은 대신 모든 채널 중 가장 긴 샘플 시간에 해당하는 최대 변환 시간(이 예제는 252 ADC 클럭)을 CPU 루프 횟수로 바꿔 그만큼 기다린다.

문제 4. ADCCLK = 10.67 MHz일 때 샘플 시간 55.5 사이클 채널 하나의 변환 시간은? Vrefint(239.5)는?

(55.5 + 12.5) / 10.67 MHz = 68 / 10.67 MHz ≈ 6.4 µs. Vrefint는 (239.5 + 12.5) / 10.67 MHz = 252 / 10.67 MHz ≈ 23.6 µs이다. 이 중 샘플 시간은 239.5 / 10.67 MHz ≈ 22.4 µs로 권장값 17.1 µs 이상이다.

문제 5. Vref 평균이 1520으로 나왔다. 예제가 출력하는 VDDA는? A0 평균이 2000이면 A0 전압은?

VDDA = 1200 × 4095 / 1520 = 4914000 / 1520 = 3232 mV (정수 나눗셈).

A0 = 2000 × 3232 / 4095 = 6464000 / 4095 = 1578 mV.

문제 6. adc_scan_once()의 반복 횟수를 3으로 줄이면 두 번째 호출의 out[0]에는 어느 채널 값이 들어가는가?

첫 호출이 랭크 1~3을 읽고 끝났으므로 두 번째 호출의 첫 트리거는 랭크 4를 변환한다. out[0]에 Vrefint(CH17) 값이 들어간다. 이후 호출마다 한 칸씩 더 밀린다.

문제 7. 이 예제에서 동작하는 ISR과 HAL 콜백을 모두 말하라.

ISR은 HAL 틱을 세는 SysTick_Handler뿐이다. ADC 인터럽트를 켜지 않으므로 ADC1_2_IRQHandler도, HAL_ADC_ConvCpltCallback 같은 콜백도 없다. 변환 완료 확인은 main 문맥의 폴링(소프트웨어 대기)으로 한다.
