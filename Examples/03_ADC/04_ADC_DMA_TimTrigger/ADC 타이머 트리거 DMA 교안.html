타이머 트리거와 DMA로 정확한 주기 샘플링

03_ADC_Multi는 여러 채널을 읽었지만 샘플 간격을 소프트웨어 대기가 정했고, CPU가 매 변환을 기다렸다. 이 교안은 그 두 일을 하드웨어에 넘긴다. 타이머(TIM3)가 정확히 1ms마다 변환을 시작하고, DMA가 결과를 원형 버퍼에 쌓는다. CPU는 버퍼가 반쯤 찼을 때와 다 찼을 때만 깨어나 평균을 낸다. 04_ADC_DMA_TimTrigger 예제를 레지스터 수준까지 해석한다.

1. 03에서 무엇이 바뀌는가

03_ADC_Multi의 한 바퀴는 ‘CPU가 시작 → CPU가 기다림 → CPU가 읽음’이었다. 모든 단계에 CPU가 붙어 있었으므로 샘플 사이 간격은 HAL 대기 루프, UART 송신, HAL_Delay에 따라 흔들렸다. 04는 이 사슬에서 CPU를 빼낸다.

“각 채널의 결과가 DR에 들어온 뒤, 다음 결과가 덮어쓰기 전에 누가 꺼내 가는가?” — 03에서는 CPU였고, 04에서는 DMA이다. DMA는 EOC 플래그와 상관없이 변환이 하나 끝날 때마다(DR이 갱신될 때마다) ADC의 요청을 받아 움직이므로, 시퀀스 중간 값도 놓치지 않는다.

2. 타이머 트리거: 언제 변환할지를 하드웨어가 정한다

TIM3을 1kHz로 맞추기

APB1 = 32 MHz이고 APB1 분주비가 1이 아니므로 TIM3의 클럭은 ×2 = 64 MHz이다. 06_Timers_RTC/01_TIM_TimeBase와 같은 설정을 쓴다.

f_update = 64 MHz / ((PSC + 1) × (ARR + 1)) = 64 MHz / (64 × 1000) = 1 kHz

PSC = 63, ARR = 999. 업데이트 이벤트가 정확히 1 ms마다 생긴다.

트리거 체인

  1. 1
    TIM3 업데이트 이벤트 → TRGOHWTIM3_CR2.MMS = 010(Update): 카운터가 ARR에서 0으로 넘어갈 때마다 TRGO에 펄스를 낸다. CubeMX의 MasterOutputTrigger = TIM_TRGO_UPDATE.
  2. 2
    TRGO → ADC1 외부 트리거HWADC1_CR2.EXTSEL = 100(TIM3_TRGO), EXTTRIG = 1. 03의 EXTSEL = 111(SWSTART) 대신 타이머 신호로 시작한다.
  3. 3
    시퀀스 1회 변환HWCR1.SCAN = 1, DISCEN = 0, CR2.CONT = 0: 트리거 한 번에 랭크 1(CH0), 랭크 2(CH1)를 연달아 변환하고 다음 트리거까지 쉰다.

TIM3 인터럽트는 쓰지 않는다. HAL_TIM_Base_Start()는 TIM3_CR1.CEN만 켜며, TRGO 신호는 인터럽트 없이 하드웨어 배선으로 ADC에 전달된다.

시간축으로 보기

두 채널은 같은 트리거에서 약 6.4 µs 차이로 변환된다. 그래서 매 주기 두 채널의 ‘스냅샷’을 얻는다. 채널당 샘플링 주파수는 1 kHz이고, 나이퀴스트 주파수는 그 절반인 500 Hz이다.

불연속 모드를 켜면?

DMA는 불연속 모드에서도 정상 동작한다. 다만 DISCEN = 1, n = 1이면 트리거마다 1채널만 변환되어 CH0, CH1이 번갈아 가며 1 ms 간격으로 측정된다. 채널당 샘플링은 500 Hz로 떨어지고 두 채널의 측정 시점이 1 ms 벌어진다. 이 예제는 스냅샷을 원하므로 불연속 모드를 끈다. 시뮬레이터에서 두 모드를 비교할 수 있다.

3. DMA 원형 버퍼

DMA(Direct Memory Access)는 CPU 대신 주변장치와 메모리 사이에서 데이터를 옮기는 하드웨어이다. F103의 ADC1 요청은 DMA1 채널1에 고정 연결되어 있다.

레지스터·비트값의미
DMA1_CPAR1&ADC1->DR읽어 올 곳 (주변장치 주소, 고정)
DMA1_CMAR1adc_buf쓸 곳 (메모리 시작 주소)
DMA1_CNDTR1128남은 전송 수. 한 번 옮길 때마다 1씩 줄고, 원형 모드면 0에서 128로 다시 채워진다
CCR.DIR = 0주변장치 → 메모리DMA_PERIPH_TO_MEMORY
CCR.PINC = 0, MINC = 1주변장치 주소 고정, 메모리 주소 증가DR 한 곳에서 읽어 배열에 차례로 쓴다
CCR.PSIZE = MSIZE = 0116비트(반워드)12비트 결과를 uint16_t에 담는다
CCR.CIRC = 1원형 모드끝에 닿으면 처음으로 돌아가 멈추지 않는다
CCR.PL = 01Medium다른 DMA 채널과의 우선순위
CCR.HTIE, TCIE, TEIE = 1반 완료, 전체 완료, 오류 인터럽트HAL_ADC_Start_DMA()가 켠다

버퍼 배치: 채널이 교대로 쌓인다

스캔 순서대로 CH0, CH1이 번갈아 저장된다(인터리브). BUF_LEN = N_CH × N_SCAN × 2 = 2 × 32 × 2 = 128이다.

[0] CH0[1] CH1[2] CH0[3] CH1[4] CH0[5] CH1…[63] CH1 [64] CH0[65] CH1[66] CH0[67] CH1[68] CH0[69] CH1…[127] CH1
인덱스 공식

스캔 번호 i, 채널 번호 c의 값: p[i × N_CH + c] (p는 절반 버퍼의 시작)

앞 절반 adc_buf[0..63] = 스캔 32번, 뒤 절반 adc_buf[64..127] = 스캔 32번. 한 절반을 채우는 데 32 ms, 한 바퀴는 64 ms이다.

순서가 맞으려면 버퍼 길이가 채널 수의 배수여야 하고, DMA와 ADC가 랭크 1에서 함께 시작해야 한다. 하드웨어는 ‘지금 몇 번째 랭크인지’ 알려 주지 않으므로(03 교안 3절), 한 번 어긋나면 이후 값의 채널 이름표가 모두 틀린다.

4. 직접 만져 보기

아래 시뮬레이터는 1 ms 단위로 TRGO를 발생시켜 adc_buf[128]이 채워지는 모습을 보여 준다. 칸의 막대 높이가 변환 값이고, 청록 테두리가 DMA가 다음에 쓸 위치(CNDTR)이다.

  1. 재생을 눌러 앞 절반이 차면 HT, 뒤 절반이 차면 TC가 생기고, 그때마다 CPU가 방금 찬 절반을 처리하는 것을 본다.
  2. 1초 진행을 눌러 UART 출력의 half, full 횟수가 15 또는 16인지 확인한다.
  3. 콜백 처리 시간을 40 ms로 바꾸고 재생한다. 처리가 끝나기 전에 DMA가 그 절반을 다시 덮어쓰는 칸이 빨갛게 표시된다.
  4. A0에 사인파를 넣고 주파수를 바꿔 본다. 600 Hz는 1 kHz 샘플링의 나이퀴스트(500 Hz)를 넘어 400 Hz처럼 보인다.

5. 반 버퍼 처리: 한쪽을 읽는 동안 다른 쪽이 찬다

원형 DMA는 멈추지 않는다. CPU가 버퍼를 읽는 순간에도 DMA는 계속 쓴다. 그래서 버퍼를 두 절반으로 나누고 역할을 교대한다. 이것을 핑퐁(더블) 버퍼링이라 한다.

이벤트시점DMA가 쓰는 곳CPU가 처리하는 곳
HT (Half Transfer)CNDTR: 128 → 64뒤 절반 [64..127]앞 절반 [0..63]
TC (Transfer Complete)CNDTR: 1 → 0 → 128앞 절반 [0..63]뒤 절반 [64..127]
처리 시간 예산

한 절반이 다시 덮어써지기 시작할 때까지 32 ms(스캔 32번 × 1 ms)가 남는다. 콜백은 이 안에 그 절반을 다 읽어야 한다.

이 예제의 process_half()는 덧셈 64번과 나눗셈 2번뿐이라 수 µs면 끝난다. 여유가 매우 크다. 샘플링을 10 kHz로 올리면 예산은 3.2 ms로 줄어든다.

콜백 횟수 계산. 버퍼 한 바퀴(128칸)는 1 kHz에서 64 ms이다. HT와 TC는 한 바퀴에 한 번씩이므로 각각 1000 / 64 ≈ 15.6회/초, 둘을 합쳐 31.25회/초이다. 1초 창에 들어오는 횟수는 15 또는 16이 번갈아 나온다.

6. ISR과 콜백

03_ADC_Multi에는 ADC 관련 ISR이 없었다. 04에서는 DMA 인터럽트 하나가 생긴다. 진짜 ISR과 HAL 콜백의 역할을 구분해 둔다.

  1. 1
    DMA1이 HTIF1 또는 TCIF1을 세운다HWDMA1_ISR의 플래그가 서고, CCR.HTIE/TCIE = 1이므로 NVIC에 DMA1_Channel1_IRQn(우선순위 1)을 요청한다.
  2. 2
    DMA1_Channel1_IRQHandler() — 진짜 ISRISRstm32f1xx_it.c. 벡터 테이블에서 바로 불리는 함수이며 HAL_DMA_IRQHandler(&hdma_adc1)만 호출한다.
  3. 3
    HAL_DMA_IRQHandler()ISR 문맥DMA1_ISR을 읽어 HT인지 TC인지 판단하고 DMA1_IFCR로 플래그를 지운다. 원형 모드이므로 인터럽트는 끄지 않는다. 이어서 ADC_DMAHalfConvCplt 또는 ADC_DMAConvCplt를 부른다.
  4. 4
    HAL_ADC_ConvHalfCpltCallback() / HAL_ADC_ConvCpltCallback() — HAL 콜백main.c사용자가 정의한 함수이다. ISR이 아니지만 ISR 문맥에서 실행되므로 짧게 끝내야 한다. 여기서 process_half()로 평균을 내고 이벤트 수를 센다.
콜백과 main이 공유하는 변수

avg_ch[], half_events, full_events는 콜백(ISR 문맥)이 쓰고 main이 읽으므로 volatile이다. 32비트 정렬 변수 하나를 읽는 것은 Cortex-M3에서 원자적이다.

다만 main이 avg_ch[0]을 읽은 직후 콜백이 끼어들면 avg_ch[1]은 다음 절반의 값일 수 있다. 두 값이 같은 절반에서 왔다는 보장이 필요하면 읽는 동안 __disable_irq()/__enable_irq()로 감싸 복사한다. 이 예제처럼 천천히 변하는 값을 1초마다 보여 줄 때는 영향이 거의 없다.

Core/Src/main.c — USER CODE BEGIN 0 / 4 (콜백)
static void process_half(const uint16_t *p)
{
  uint32_t sum[N_CH] = {0};
  for (i = 0; i < N_SCAN; i++)
    for (c = 0; c < N_CH; c++)
      sum[c] += p[i * N_CH + c];
  for (c = 0; c < N_CH; c++)
    avg_ch[c] = sum[c] / N_SCAN;
}
void HAL_ADC_ConvHalfCpltCallback(ADC_HandleTypeDef *hadc)
{ if (hadc->Instance == ADC1) { process_half(&adc_buf[0]); half_events++; } }
void HAL_ADC_ConvCpltCallback(ADC_HandleTypeDef *hadc)
{ if (hadc->Instance == ADC1) { process_half(&adc_buf[BUF_LEN/2]); full_events++; } }
  1. 절반 버퍼(스캔 32번)의 채널별 평균. 인터리브 공식 p[i × N_CH + c]
  2. HT: 앞 절반 [0..63]을 처리 (DMA는 뒤 절반에 쓰는 중)
  3. TC: 뒤 절반 [64..127]을 처리 (DMA는 앞 절반으로 돌아감)
  4. hadc->Instance 검사: ADC가 여럿일 때 같은 콜백을 공유하므로 넣는 습관
Core/Src/main.c — USER CODE BEGIN 3 (main 루프)

  2. 이벤트 카운터의 차이 = 지난 1초 동안의 콜백 횟수 (기대값 15 또는 16)
  3. UART 송신이 블로킹이어도 샘플링은 하드웨어가 계속하므로 영향이 없다. 03과 가장 크게 달라진 점이다.

8. 실험

배선: PA0(A0), PA1(A1)에 가변저항(양 끝 3V3, GND) 또는 0~3.3 V 신호를 연결한다. 터미널은 115200 8N1이다.

실험 A. 기본 출력 확인

CH0=2048 CH1= 993  (half 16/s, full 15/s)
CH0=2049 CH1= 993  (half 15/s, full 16/s)

half와 full이 15, 16을 오가는지 확인한다. 0이면 트리거 체인(9절)부터 점검한다.

실험 B. 콜백 시점을 핀으로 본다

두 콜백 안에 HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);을 넣고 PA5(D13)를 AD2 오실로스코프로 본다. 32 ms마다 토글되므로 주기 64 ms(약 15.6 Hz)의 구형파가 나와야 한다. 03처럼 소프트웨어가 시점을 정할 때와 달리 주기가 흔들리지 않는다.

실험 C. 샘플링 주파수를 바꾼다

htim3.Init.Period를 999에서 99로 바꾼다(CubeMX에서 ARR 변경). 10 kHz가 되므로 half/full이 각각 약 156회/초로 늘어나야 한다. 처리 예산은 3.2 ms로 줄어든다.

실험 D. 콜백을 일부러 느리게 한다

process_half() 끝에 빈 루프를 넣어 처리 시간이 32 ms를 넘게 한다(실험 B의 핀 토글이나 DWT로 실제 시간을 확인한다). 콜백이 끝나기 전에 같은 절반이 다시 덮어써지고, 다음 인터럽트도 늦게 처리된다. 시뮬레이터의 ‘40 ms’ 설정과 비교한다.

실험 E. 불연속 모드를 켠다

DiscontinuousConvMode = ENABLE, NbrOfDiscConversion = 1로 바꾼다. 트리거마다 1채널만 변환되므로 버퍼가 두 배로 천천히 차서 half/full이 각각 약 7.8회/초가 된다. 버퍼 배치(CH0, CH1 교대)는 그대로이다.

실험 F. 03처럼 4채널 + VDDA 보정으로 확장한다

PA4(CH4)를 랭크 3, Vrefint(CH17, 239.5 사이클)를 랭크 4로 추가하고 NbrOfConversion = 4, N_CH = 4로 바꾼다. 출력 문자열에 CH4와 VDDA(= 1200 × 4095 / avg_ch[3])를 더한다. 시퀀스가 길어져도 1 ms 안에 충분히 끝나는지 계산해 본다(3 × 68 + 252 = 456 ADC 클럭 ≈ 42.8 µs).

9. 트러블슈팅

증상원인조치
half/full이 0이고 값도 0트리거가 오지 않는다: TIM3 미시작, MMS가 TRGO 업데이트가 아님, EXTSEL이 다른 소스HAL_TIM_Base_Start 호출, MasterOutputTrigger = TIM_TRGO_UPDATE, ExternalTrigConv = ..._T3_TRGO 확인
값은 변하지만 half/full이 0DMA 인터럽트가 NVIC에서 꺼져 있다MX_DMA_Init()의 HAL_NVIC_EnableIRQ(DMA1_Channel1_IRQn) 확인
DMA가 전혀 동작하지 않는다MX_DMA_Init()이 MX_ADC1_Init()보다 뒤에 호출됐다 (CubeMX 생성 순서 문제로 알려진 사례)DMA 초기화를 ADC 초기화보다 먼저 호출한다. 이 예제는 올바른 순서이다.
CH0, CH1 값이 뒤바뀌거나 섞인다버퍼 길이가 채널 수의 배수가 아니거나, DMA를 시퀀스 중간에 다시 시작했다BUF_LEN을 N_CH의 배수로 두고, 재시작할 때는 ADC와 DMA를 함께 멈췄다가 다시 시작한다.
평균값이 가끔 튄다콜백 처리가 32 ms 예산을 넘어 DMA가 처리 중인 절반을 덮어썼다콜백에서는 계산만 하고 출력 같은 느린 작업은 main으로 옮긴다.
HardFault 또는 엉뚱한 변수가 바뀐다adc_buf를 지역 변수로 선언했다전역 또는 static으로 선언한다.

10. 확인 문제

먼저 스스로 답을 정해 본 뒤 펼쳐 확인한다.

문제 1. TIM3 클럭 64 MHz에서 PSC = 63, ARR = 999이면 TRGO 주파수는? ARR만 499로 바꾸면?

64 MHz / (64 × 1000) = 1 kHz. ARR = 499이면 64 MHz / (64 × 500) = 2 kHz이다.

문제 2. BUF_LEN = 128, 2채널, 1 kHz일 때 HT와 TC는 각각 몇 ms마다 생기는가? 초당 몇 번인가?

트리거 한 번에 2칸이 차므로 128칸은 64 ms에 한 바퀴 돈다. HT는 t = 32, 96, 160 … ms, TC는 t = 64, 128, 192 … ms이다. 각각 64 ms 간격이므로 1000 / 64 ≈ 15.6회/초, 1초 창에서는 15 또는 16이다.

문제 3. adc_buf[37]에는 어느 채널의, 몇 번째 스캔 값이 들어 있는가? 어느 절반에 속하는가?

37 = 18 × 2 + 1이므로 스캔 번호 18(0부터 셈, 즉 19번째 스캔)의 CH1 값이다. 인덱스 0~63이므로 앞 절반에 속하고 HT 콜백에서 처리된다.

문제 4. 왜 HAL_ADC_Start_DMA()를 HAL_TIM_Base_Start()보다 먼저 호출하는가?

타이머가 먼저 돌면 ADC와 DMA가 준비되기 전에 TRGO가 나올 수 있다. 그 트리거는 버려지거나, DMA가 아직 설정되지 않은 상태에서 변환이 일어나 순서가 어긋날 수 있다. 받는 쪽(ADC, DMA)을 먼저 준비하고 마지막에 트리거원(타이머)을 켜는 것이 원칙이다.

문제 5. HT 콜백이 40 ms 걸리면 어떤 일이 생기는가?

HT 이후 DMA는 뒤 절반을 32 ms 동안 채우고 TC를 낸 뒤 다시 앞 절반에 쓰기 시작한다. 콜백이 아직 앞 절반을 읽는 중이므로 마지막 약 8 ms 동안 읽는 데이터가 새 값으로 바뀐다. 또 TC 인터럽트는 같은 IRQ라서 HT 콜백이 끝날 때까지 대기(pending)했다가 늦게 처리된다.

문제 6. 이 설정에서 불연속 모드(n = 1)를 켜면 채널당 샘플링 주파수와 HT 간격은 어떻게 되는가?

트리거마다 1채널만 변환하므로 채널당 500 Hz가 된다. 버퍼는 1 ms에 1칸씩 차므로 128칸에 128 ms가 걸리고, HT/TC는 각각 128 ms 간격(약 7.8회/초)이 된다.

문제 7. 1 kHz로 샘플링하는 CH0에 600 Hz 사인파를 넣으면 샘플은 몇 Hz처럼 보이는가? 이유는?

나이퀴스트 주파수 500 Hz를 넘으므로 에일리어싱이 생겨 |600 − 1000| = 400 Hz처럼 보인다. 샘플만으로는 600 Hz와 400 Hz를 구별할 수 없다. 그래서 ADC 앞에 차단 주파수가 샘플링 주파수의 절반보다 낮은 저역통과 필터(안티에일리어싱 필터)를 둔다.

문제 8. 이 예제의 진짜 ISR과 HAL 콜백을 각각 말하라. 콜백 안에서 HAL_UART_Transmit을 부르면 안 되는 이유는?

진짜 ISR은 DMA1_Channel1_IRQHandler(와 HAL 틱용 SysTick_Handler)이다. HAL 콜백은 HAL_ADC_ConvHalfCpltCallback, HAL_ADC_ConvCpltCallback이다.

콜백은 ISR 문맥에서 실행되므로 블로킹 송신(수 ms)을 하면 32 ms 처리 예산을 잡아먹고, 같은 우선순위 이하의 다른 인터럽트도 그동안 막힌다. 콜백은 결과를 변수에 남기고 출력은 main에서 한다.
