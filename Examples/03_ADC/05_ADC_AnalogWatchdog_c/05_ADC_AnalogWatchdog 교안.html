아날로그 워치독: 전압 창 이탈을 하드웨어가 감시한다

과전압·저전압 보호처럼 ‘값이 범위를 벗어났는가’만 알면 되는 일에 CPU가 변환값을 계속 읽어 비교하는 것은 낭비이고, 200 ms 주기로 확인하면 짧은 이탈을 놓친다. STM32F1의 ADC에는 변환이 끝날 때마다 결과를 상한(ADC_HTR)·하한(ADC_LTR)과 비교하는 아날로그 워치독(AWD)이 들어 있다. 이 교안은 PA0를 연속 변환하며 DMA로 최신값을 받고, 창을 벗어나면 AWD 인터럽트로 LD2를 켜는 05_ADC_AnalogWatchdog_c 예제를 레지스터 수준까지 해석한다. 특히 창 밖에 머무는 동안 인터럽트가 변환마다 반복되는 문제와 이 예제의 ‘해제 후 재무장’ 처리를 자세히 본다.

1. 문제: ‘범위를 벗어났는가’를 CPU 없이 안다

04_ADC_DMA_TimTrigger까지는 CPU가 변환값을 받아 평균을 내고 판단했다. 범위 감시만 필요하다면 비교 자체를 ADC 하드웨어에 맡길 수 있다. CPU는 이탈이 일어났을 때만 깨어난다. 학습 목표는 다음과 같다.

  • ADC_HTR/ADC_LTR 창과 SR.AWD 플래그의 조건(초과·미만, 같으면 창 안)을 설명한다.
  • CR1.AWDEN/AWDSGL/AWDCH[4:0]/AWDIE로 감시 대상 채널과 인터럽트를 설정한다.
  • 창 밖에 머무는 동안 AWD가 변환마다 다시 발생해 인터럽트가 초당 수만 회 반복되는 이유를 계산으로 보인다.
  • 콜백에서 AWDIE를 끄고 main이 복귀를 확인한 뒤 플래그를 지우고 다시 켜는 무장/해제 패턴과 그 한계(히스테리시스 없음)를 이해한다.
이 예제의 동작

PA0(A0)를 239.5 사이클 샘플 시간으로 연속 변환하고, DMA1 채널1이 결과를 1워드 원형 전송으로 adc_val에 계속 덮어쓴다. 변환값이 1000~3000(약 0.81~2.42 V @ 3.3 V) 창을 벗어나면 HAL_ADC_LevelOutOfWindowCallback이 LD2를 켜고 awd_flag를 세우며 AWD 인터럽트를 끈다. main은 200 ms마다 adc_val을 보고, 창 안으로 돌아왔으면 LD2를 끄고 SR.AWD를 지운 뒤 인터럽트를 다시 켠다. 같은 주기로 현재 값과 상태를 USART2(115200 8N1)로 출력한다.

이 예제는 검토 전(컴파일만 확인) 상태이다.

2. 핵심 개념: 창 비교와 인터럽트 폭주

AWD는 변환이 끝날 때마다 결과 코드를 두 임계값과 비교한다. RM0008 11.3.7의 정의는 “변환값이 하한보다 작거나 상한보다 크면 AWD 상태 비트가 선다”이다. 임계값은 정렬(CR2.ALIGN)과 무관하게 12비트 원값과 비교한다.

변환 결과 (code)판정SR.AWD이 예제 (HTR = 3000, LTR = 1000)
code > HTR창 위로 이탈1로 세움3001 이상 (약 2418 mV 초과)
LTR ≤ code ≤ HTR창 안변화 없음 (자동으로 지워지지 않음)1000~3000 — 경계값 자체는 창 안
code < LTR창 아래로 이탈1로 세움999 이하 (약 806 mV 미만)

여기서 중요한 성질 두 가지가 문제를 만든다. 첫째, SR.AWD는 ‘창을 넘는 순간’이 아니라 창 밖 결과가 나올 때마다 선다. 둘째, 이 플래그는 하드웨어가 지우지 않고 소프트웨어가 지운다. 연속 변환에서는 변환 한 번이 (239.5 + 12.5) / 10.67 MHz = 23.6 µs이므로, 입력이 창 밖에 머물면 1초에 약 42,300번 플래그가 선다. AWDIE를 켜 둔 채 콜백에서 플래그만 지우면(HAL이 그렇게 한다) 인터럽트도 같은 횟수만큼 반복된다.

그림 1. A0 입력(파랑)이 HTR을 넘는 구간(음영) 동안 변환(점)마다 SR.AWD가 선다. AWDIE를 유지하면 인터럽트도 매번 생기고(가운데 줄), 이 예제는 첫 인터럽트에서 AWDIE를 끄고 main이 창 안 복귀를 확인한 뒤 다시 켠다(아래 줄). 시간축은 비례가 아니다. 실제로는 변환 간격이 23.6 µs, main 확인 간격이 약 200 ms이다.

DMA는 쓰지만 DMA 인터럽트는 쓰지 않는다

HAL_ADC_Start_DMA()는 내부에서 HAL_DMA_Start_IT()를 불러 DMA 채널의 TC·HT·TE 인터럽트 허용 비트를 켠다. 그러나 이 예제의 MX_DMA_Init()은 DMA1 클럭만 켜고 DMA1_Channel1_IRQn을 NVIC에서 허용하지 않으며, stm32f1xx_it.c에도 DMA1_Channel1_IRQHandler가 없다. 그래서 1워드 원형 전송이 변환마다(23.6 µs마다) 완료돼도 CPU는 끼어들지 않는다. 플래그는 DMA1_ISR에 쌓일 뿐이다.

주의. CubeMX의 기본값 NVIC.ForceEnableDMAVector=true이면 Generate할 때 DMA 채널 인터럽트가 NVIC에서 강제로 허용되고 핸들러가 생성된다. 그러면 1워드 전송마다, 즉 변환마다 DMA 인터럽트가 걸려 2절의 폭주와 같은 부하가 생긴다. 이 예제의 .ioc는 이를 false로 꺼 두어 다시 생성해도 지금 코드처럼 DMA 인터럽트가 꺼진 상태로 나온다(9절).

4. 직접 만져 보기

아래 시뮬레이터는 변환 23.625 µs 간격으로 AWD 비교를 수행하고, 콜백과 200 ms main 루프가 AWDIE를 끄고 켜는 과정을 그대로 따라간다.

  1. 기본 상태에서 ▶ 재생을 누른다. 사인 입력이 HTR을 넘을 때마다 인터럽트가 1회만 생기고, 복귀 후 main이 재무장(청록 표시)하는 것을 본다.
  2. 처리 방식을 AWDIE 유지로 바꾸고 다시 재생한다. 인터럽트 횟수와 ‘최근 1초 인터럽트’가 수만 단위로 뛴다.
  3. 이 예제 방식으로 돌아가 직류 성분을 HTR 근처(약 2400 mV), 진폭 0, 잡음 ±20 LSB로 둔다. 경계 근처에서 재무장과 재발이 200 ms마다 반복되는 것을 본다. 히스테리시스 재무장과 비교한다.
  4. 입력을 창 안에 두고 글리치 주입을 누른다. 변환 한 번짜리 스파이크도 AWD는 잡지만, 200 ms마다 읽는 ADC= 값에는 거의 나타나지 않는다.
  5. HTR/LTR 슬라이더로 창을 바꿔 본다. LTR > HTR이면 모든 값이 창 밖이 된다.

시뮬레이터 모델: VDDA = 3.3 V, 변환값 = round(V / 3300 × 4095) + 균일 잡음(±설정 LSB)이며 0~4095로 제한한다. 변환은 t = 23.625 µs × n에 끝나고, DMA가 즉시 adc_val을 갱신한다. 인터럽트 지연과 ISR 실행 시간은 0으로 보며, 콜백 직후 HAL이 SR.AWD를 지운다. main 한 바퀴는 HAL_Delay(200) + 출력 문자열 송신 시간(바이트당 86.8 µs)이고, HAL_Delay의 +1 ms 여유는 무시한다. ‘AWDIE 유지’는 콜백의 __HAL_ADC_DISABLE_IT 줄을 지운 경우, ‘히스테리시스’는 main의 재무장 조건을 LTR+100 ≤ v ≤ HTR−100으로 좁힌 경우이며 소스에는 없다. 글리치는 다음 변환 1회에만 +1500 LSB를 더한다. HTR/LTR 슬라이더는 .ioc의 임계값과 main의 AWD_HIGH/AWD_LOW를 함께 바꾼 것으로 본다.

6. 인터럽트 경로: 진짜 ISR과 콜백, 그리고 main의 재무장

  1. 1
    변환 완료 → DR 갱신 → DMA가 adc_val로 복사하드웨어23.6 µs마다 반복된다. DMA1 채널1 인터럽트는 NVIC에서 꺼져 있어 CPU와 무관하게 진행된다.
  2. 2
    AWD 비교: code > HTR 또는 code < LTR → SR.AWD = 1하드웨어AWDSGL = 1, AWDCH = 0이므로 CH0 결과만 비교한다.
  3. 3
    CR1.AWDIE = 1이면 NVIC ADC1_2_IRQn 요청하드웨어우선순위 1. SysTick(우선순위 0)은 이 ISR을 선점할 수 있다.
  4. 4
    ADC1_2_IRQHandler() — 진짜 ISRstm32f1xx_it.c벡터 테이블이 직접 호출한다. HAL_ADC_IRQHandler(&hadc1)만 부른다.
  5. 5
    HAL_ADC_IRQHandler()HAL, ISR 문맥CR1에 AWDIE가 있고 SR.AWD가 서 있으면 상태에 HAL_ADC_STATE_AWD1을 표시하고 콜백을 부른 다음 SR.AWD를 지운다. EOC 인터럽트는 꺼져 있어 그 분기는 건너뛴다.
  6. 6
    HAL_ADC_LevelOutOfWindowCallback()main.c, ISR 문맥awd_flag = 1, awd_events++, LD2 점등, AWDIE = 0(해제). 이후 창 밖 변환이 계속돼도 SR.AWD만 서고 인터럽트는 없다.
  7. 7
    main 루프 (200 ms마다): 복귀 확인 → 재무장main 문맥adc_val이 1000~3000이고 awd_flag가 서 있으면 플래그와 LD2를 끄고, 해제 동안 쌓인 SR.AWD를 지운 뒤 AWDIE = 1. 그다음 상태를 출력한다.
재무장 직전에 SR.AWD를 지우는 이유

해제 동안에도 AWD 비교는 계속되므로 창 밖 변환이 하나라도 있었다면 SR.AWD가 서 있다. 이 상태에서 AWDIE만 켜면 입력이 창 안인데도 즉시 인터럽트가 걸려 거짓 경보가 된다. 그래서 지우고 켠다. 대가도 있다. main이 adc_val을 읽은 뒤 플래그를 지우기까지의 짧은 사이에 생긴 순간 이탈은 지워져 놓친다. 이탈이 계속되면 다음 변환이 다시 플래그를 세우므로 지속 이탈은 놓치지 않는다.

8. 실험

배선: PA0(A0)에 가변저항 와이퍼, 양 끝을 3V3과 GND에 연결한다. 터미널은 115200 8N1이다.

실험 A. 경계값 찾기

가변저항을 천천히 돌려 OUT-OF-WINDOW로 바뀌는 순간의 ADC= 값을 기록한다. 위쪽은 3001 이상, 아래쪽은 999 이하에서 바뀌어야 한다. 200 ms 출력 간격 때문에 정확히 3001이 찍히지 않을 수 있다는 점도 확인한다.

실험 B. 인터럽트 폭주를 재현한다

콜백의 __HAL_ADC_DISABLE_IT(hadc, ADC_IT_AWD);를 주석 처리하고 입력을 창 밖에 둔다. 출력의 events가 루프 한 바퀴(약 205 ms)마다 약 8,700씩(42,300 × 0.205) 늘어나는지 본다. ISR 실행 시간만큼 main 루프가 느려지는지도 줄 간격으로 확인한다. 시뮬레이터의 ‘AWDIE 유지’와 비교한다.

실험 C. 경계 근처 떨림과 히스테리시스

입력을 HTR 바로 근처(약 2.42 V)에 맞추고 가변저항 와이퍼를 손으로 살짝 건드린다. 재무장과 재발이 반복되며 events가 조금씩 늘고 LD2가 깜빡인다. main의 재무장 조건을 v >= AWD_LOW + 100 && v <= AWD_HIGH - 100으로 좁혀 차이를 비교한다(코드 수정은 실험용 사본에서 한다).

실험 D. 짧은 이탈 잡기

AD2 파형 발생기로 PA0에 1.65 V 직류 + 수 ms 폭의 3.0 V 펄스를 1초에 한 번 넣는다(0~3.3 V 범위를 지킨다). AWD는 펄스마다 events를 1씩 올리지만 200 ms마다 읽는 ADC= 값에는 펄스가 거의 보이지 않는다. 펄스 폭을 줄여 가며 몇 µs부터 놓치기 시작하는지 찾아 변환 주기 23.6 µs와 비교한다.

10. 확인 문제

문제 1. VDDA = 3.3 V일 때 HTR = 3000, LTR = 1000 창은 몇 V에서 몇 V까지인가? 변환값이 정확히 3000이면 SR.AWD가 서는가?

1000 × 3.3 / 4095 ≈ 0.806 V, 3000 × 3.3 / 4095 ≈ 2.418 V이다. AWD는 ‘HTR보다 크거나 LTR보다 작을 때’ 서므로 3000은 창 안이며 플래그가 서지 않는다. main의 v <= AWD_HIGH도 같은 정의를 쓴다.

문제 2. 콜백에서 AWDIE를 끄지 않고 입력을 3.0 V에 고정하면 1초에 인터럽트가 몇 번 걸리는가?

변환 한 번이 (239.5 + 12.5) / 10.67 MHz ≈ 23.6 µs이고 매 결과가 창 밖이므로 1 / 23.625 µs ≈ 42,300회이다. HAL이 콜백 뒤에 SR.AWD를 지워도 다음 변환이 다시 세운다.

문제 3. main이 재무장할 때 __HAL_ADC_ENABLE_IT보다 먼저 __HAL_ADC_CLEAR_FLAG를 부르는 이유는?

AWDIE를 꺼도 AWDEN = 1이라 비교는 계속되고, 해제 동안의 창 밖 변환이 SR.AWD를 세워 두었다. 지우지 않고 켜면 입력이 이미 창 안인데도 즉시 인터럽트가 걸려 events가 늘고 LD2가 다시 켜진다(거짓 경보).

문제 4. 입력이 창 안에 있을 때 50 µs 폭의 스파이크가 HTR을 넘었다. AWD는 이를 잡는가? 같은 일을 main의 200 ms 폴링으로 하면?

변환이 23.6 µs마다 끝나므로 50 µs 동안 적어도 한 번(대개 두 번)은 스파이크 구간에서 샘플링된다. 무장 상태라면 AWD가 잡아 events가 1 늘고 LD2가 켜진다. LD2는 다음 main 확인(최대 약 205 ms 뒤)에서 꺼진다. main이 200 ms마다 한 표본만 보면 그 표본이 50 µs 구간에 걸릴 확률은 약 50 µs / 205 ms ≈ 0.02%로 사실상 놓친다.
