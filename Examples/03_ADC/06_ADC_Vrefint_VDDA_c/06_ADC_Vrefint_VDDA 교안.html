Vrefint로 VDDA를 역산하고 ADC 값을 보정한다

ADC가 내놓는 12비트 코드는 전압이 아니라 VDDA에 대한 비율이다. mV = code × 3300 / 4095는 VDDA가 정확히 3.3 V일 때만 맞고, 전원이 흔들리면 모든 채널이 같은 비율로 틀어진다. 이 교안은 내부 기준전압 Vrefint(CH17)를 같은 ADC로 재서 실제 VDDA를 계산하고 외부 채널 값을 보정하는 06_ADC_Vrefint_VDDA_c 예제를 해석한다. 03_ADC_Multi 교안 6절의 두 식에서 한 걸음 더 들어가, 데이터시트의 Vrefint 편차가 보정 결과에 남기는 오차, 보정이 오히려 손해인 조건, 1점 교정과 해상도 개선까지 다룬다.

1. 문제: 기준이 흔들리면 모든 측정이 흔들린다

LQFP64 패키지의 F103은 VREF+가 내부에서 VDDA에 연결되어 있다(데이터시트 Table 47 주 3). 즉 ADC의 기준전압은 곧 아날로그 전원이다. USB 전원, 배터리, 부하 변동으로 VDDA가 바뀌면 같은 입력 전압에서도 코드가 달라진다. 학습 목표는 다음과 같다.

  • 코드가 Vin / VDDA × 4095라는 비율임을 이용해 Vrefint 측정값으로 VDDA를 역산한다.
  • 데이터시트 Table 12의 Vrefint min/typ/max(1.16/1.20/1.24 V)로부터 보정 후 남는 오차 범위(+3.4%~−3.2%)를 계산한다.
  • 보정 없음(3.3 V 가정)과 보정 있음의 오차를 비교해 보정이 이득인 VDDA 범위를 판단한다.
  • 내부 채널 사용 조건(CR2.TSVREFE, 샘플 시간 TS_vrefint)과 정수 연산의 해상도 한계를 설명한다.
이 예제의 동작

1초마다 adc_read_avg()로 Vrefint(CH17)를 16회 변환해 평균을 내고, 이어서 PA0(CH0)도 16회 평균한다. VDDA = 1200 × 4095 / raw_vref를 계산하고, A0를 ‘3.3 V 가정 mV’와 ‘실측 VDDA 기준 mV’로 함께 USART2(115200 8N1)에 출력한다. 인터럽트와 DMA는 쓰지 않는다(폴링).

이 예제는 검토 전(컴파일만 확인) 상태이다.

2. 핵심 개념: 비율 측정과 남는 오차

같은 ADC로 두 전압을 재면 둘 다 같은 VDDA로 나뉜다.

raw_vref = Vrefint × 4095 / VDDA raw_a0 = Vin × 4095 / VDDA VDDA = Vrefint × 4095 / raw_vref (예제: VREFINT_MV = 1200 고정) Vin = raw_a0 × VDDA / 4095 = Vrefint × raw_a0 / raw_vref

마지막 식이 핵심이다. 보정된 Vin에는 VDDA가 사라지고 Vrefint와 두 코드의 비율만 남는다. 따라서 보정 결과의 정확도는 VDDA가 아니라 Vrefint를 얼마나 정확히 아느냐가 정한다. 예제는 Vrefint를 전형값 1200 mV로 두므로, 이 칩의 실제 Vrefint가 다르면 그 비율만큼 모든 결과가 틀어진다.

방식계산값 / 실제값VDDA = 3.0 V3.3 V3.6 V
3.3 V 가정 (a0_naive)3.3 V / VDDA+10.0%0%−8.3%
Vrefint 보정, 실제 Vrefint = 1.16 V1.20 / 1.16+3.4%+3.4%+3.4%
Vrefint 보정, 실제 Vrefint = 1.20 V1.20 / 1.200%0%0%
Vrefint 보정, 실제 Vrefint = 1.24 V1.20 / 1.24−3.2%−3.2%−3.2%

그림 1. 3.3 V 가정 환산의 오차(주황)는 VDDA에 따라 +10%~−8.3%로 변하지만, Vrefint 보정 후 오차는 VDDA와 무관하게 Vrefint 개체 편차가 정하는 띠(보라, +3.4%~−3.2%) 안에 머문다. VDDA가 3.3 V 근처(약 3.19~3.41 V)이면 최악의 경우 보정하지 않는 편이 더 정확할 수 있다.

F1에는 공장 교정값이 없다

F0·F3·F4·L4 등 후속 STM32는 생산 시 측정한 Vrefint 코드(VREFINT_CAL)를 시스템 메모리에 저장해 두지만, F103 데이터시트 DS5319와 RM0008에는 그런 값이 없다(이 저장소의 Docs/ 문서에서 확인). 그래서 예제는 전형값 1200 mV를 상수로 쓰고, 개체 편차는 그대로 오차로 남는다. 줄이려면 사용자가 직접 1점 교정을 해야 한다(실험 B).

4. 직접 만져 보기

아래 시뮬레이터는 예제의 정수 연산(uint32_t 곱셈·나눗셈, 16회 평균의 버림)을 그대로 따라 한다. ‘실제 VDDA’와 ‘이 칩의 실제 Vrefint’는 펌웨어가 모르는 값이다.

  1. 실제 VDDA를 3.0 V로 내린다. 보정 없음(assume3.3V)은 약 +10% 틀리고, 보정 값은 거의 맞는 것을 본다.
  2. VDDA를 3.3 V로 두고 실제 Vrefint를 1.24 V로 바꾼다. 이번에는 보정 값이 약 −3.2% 틀리고 보정 없음이 정확하다.
  3. 1점 교정을 켠다. 실제 VDDA를 멀티미터로 잰 값으로 이 칩의 Vrefint를 구해 상수로 쓰면, 두 슬라이더를 어떻게 움직여도 보정 오차가 수 mV로 줄어든다.
  4. 평균 대신 합 사용을 켜고 잡음을 ±2 LSB로 둔다. VDDA 계산의 계단(약 2.2 mV)이 더 촘촘해진다.
  5. 1초 루프를 여러 번 눌러 UART 출력이 잡음 때문에 몇 mV씩 흔들리는 폭을 본다.

시뮬레이터 모델: 각 변환 코드 = round(V / VDDA × 4095) + 균일 정수 잡음이며 0~4095로 제한한다. ADC 자체의 오프셋·이득·비선형 오차(데이터시트 Table 49, 50)와 입력 임피던스 영향은 넣지 않았다. 16회 합을 N_AVG로 나눈 몫이 raw이고, 이후 계산은 예제와 같은 uint32_t 정수 나눗셈이다. ‘1점 교정값’은 VDDA = 3.300 V일 때 한 번, 오차 없는 멀티미터로 쟀다고 보고 VREFINT_MV = raw_vref × VDDA_meas / 4095로 구한 값이며, 소스에는 없는 확장이다. ‘16회 합 사용’은 VDDA = 1200 × 4095 × 16 / sum(실험 C)이다. 오차 곡선은 잡음 없이 계산한다.

6. 실행 경로: 1초 루프 한 바퀴

인터럽트가 없으므로 모든 일은 main 문맥에서 차례로 일어난다. 동작하는 ISR은 HAL 틱용 SysTick_Handler뿐이다.

  1. 1
    adc_read_avg(ADC_CHANNEL_VREFINT): 채널 설정mainSQ1 = 17, SMP17 = 111. 첫 호출에서 TSVREFE = 1.
  2. 2
    연속 변환 16회하드웨어첫 HAL_ADC_Start로 ADC가 켜지면 CONT = 1이라 23.6 µs마다 결과가 나온다.
  3. 3
    EOC 폴링 → DR 읽기 × 16 → HAL_ADC_Stopmain합을 16으로 나눈 몫(버림)이 raw_vref이다.
  4. 4
    adc_read_avg(ADC_CHANNEL_0)main같은 절차로 PA0를 16회 평균해 raw_a0.
  5. 5
    정수 계산mainvdda_mv = 1200 × 4095 / raw_vref, a0_naive = raw_a0 × 3300 / 4095, a0_corr = raw_a0 × vdda_mv / 4095.
  6. 6
    UART 송신 후 HAL_Delay(1000)main한 줄 약 85바이트 × 86.8 µs ≈ 7.4 ms. 루프 주기는 1초보다 조금 길다.
연속 모드와 루프 안의 Start

ContinuousConvMode = ENABLE이므로 첫 HAL_ADC_Start 뒤 ADC는 스스로 변환을 이어 간다. 16개 값은 연속된 변환 결과를 EOC마다 하나씩 읽은 것이다. 루프 안에서 매번 HAL_ADC_Start를 다시 부르는 것은 단일 변환 모드였다면 필수인 구조이며, 연속 모드에서는 필수가 아니다. 채널을 바꾸기 전에 HAL_ADC_Stop으로 ADON을 끄기 때문에, 변환이 진행 중인 채로 SQR3를 바꾸는 상황은 생기지 않는다.

7. 코드 읽기

계층은 HAL이다. 사용자 코드는 /* USER CODE BEGIN ... */ 영역 안에 있다.

Core/Src/main.c — USER CODE BEGIN PD / 0
#define VREFINT_MV 1200UL   /* 전형값. 정밀도가 필요하면 개체별로 측정/보정 */
#define N_AVG      16U

static uint32_t adc_read_avg(uint32_t channel)
{
    ADC_ChannelConfTypeDef ch = {0};
    ch.Channel = channel;
    ch.Rank = ADC_REGULAR_RANK_1;
    ch.SamplingTime = ADC_SAMPLETIME_239CYCLES_5;
    if (HAL_ADC_ConfigChannel(&hadc1, &ch) != HAL_OK) Error_Handler();

    uint32_t sum = 0;
    for (uint32_t i = 0; i < N_AVG; i++)
    {
        HAL_ADC_Start(&hadc1);                      /* CR2.ADON / SWSTART */
        if (HAL_ADC_PollForConversion(&hadc1, 10) != HAL_OK) Error_Handler();   /* SR.EOC */
        sum += HAL_ADC_GetValue(&hadc1);            /* DR 읽기 */
    }
    HAL_ADC_Stop(&hadc1);
    return sum / N_AVG;
}
  1. VREFINT_MV는 데이터시트 전형값이다. F1에는 개체별 교정값이 없으므로 이 상수가 보정 정확도의 상한을 정한다.
  2. 두 채널 모두 239.5 사이클. Vrefint는 TS_vrefint 최대 17.1 µs를 만족해야 한다(22.45 µs).
  3. ADC_CHANNEL_VREFINT를 넘기면 HAL이 TSVREFE를 켠다.
  4. 마지막 나눗셈이 소수부를 버린다. 합(sum)에는 4비트만큼의 추가 정보가 있는데 여기서 사라진다(실험 C).
Core/Src/main.c — USER CODE BEGIN 2 / 3
HAL_ADCEx_Calibration_Start(&hadc1);            /* ADC1->CR2.CAL */

uint32_t raw_vref = adc_read_avg(ADC_CHANNEL_VREFINT);
uint32_t raw_a0   = adc_read_avg(ADC_CHANNEL_0);

uint32_t vdda_mv = (raw_vref != 0) ? VREFINT_MV * 4095UL / raw_vref : 0;
uint32_t a0_naive = raw_a0 * 3300UL / 4095UL;      /* VDDA=3.3V 가정 */
uint32_t a0_corr  = raw_a0 * vdda_mv / 4095UL;     /* 실측 VDDA 기준 */

int n = snprintf(msg, sizeof msg, "raw_vref=%4lu -> VDDA=%4lu mV | A0 raw=%4lu : assume3.3V=%4lu mV, corrected=%4lu mV\r\n", ...);
HAL_UART_Transmit(&huart2, (uint8_t *)msg, (uint16_t)n, 100);
HAL_Delay(1000);
  1. 교정은 첫 변환 전에 한 번. 오프셋 오차를 줄인다.
  2. Vrefint를 먼저, A0를 나중에 잰다. 두 측정 사이 약 0.4 ms 동안 VDDA가 같다고 가정한다.
  3. raw_vref != 0 검사로 0 나눗셈을 막는다.
  4. 곱셈은 1200 × 4095 = 4,914,000, 4095 × 3600 ≈ 1,474만 수준이라 uint32_t(약 42.9억) 안이다. raw_vref가 4 이하로 비정상이면 raw_a0 × vdda_mv가 넘칠 수 있다.
  5. a0_corr는 나눗셈을 두 번 거치므로 버림 오차가 최대 약 2 mV 쌓인다.
기대 출력 (USB 전원, VDDA ≈ 3.3 V, A0 = 가변저항 중간)
raw_vref=1489 -> VDDA=3300 mV | A0 raw=2048 : assume3.3V=1650 mV, corrected=1650 mV
raw_vref=1497 -> VDDA=3282 mV | A0 raw=2049 : assume3.3V=1651 mV, corrected=1642 mV

둘째 줄은 VDDA가 3.28 V로 내려갔거나, 이 칩의 Vrefint가 1.20 V보다 약간 커서 생기는 출력의 예이다. 펌웨어만으로는 둘을 구별할 수 없다. 멀티미터로 3V3(또는 AVDD) 전압을 재서 비교해야 한다. 예시 수치는 계산으로 만든 것이다.

8. 실험

배선: PA0(A0)에 가변저항 와이퍼(양 끝 3V3, GND). 멀티미터 또는 AD2 전압계로 Nucleo의 3V3 핀과 PA0를 함께 잰다. 터미널은 115200 8N1이다.

실험 A. 출력과 멀티미터 비교

출력의 VDDA와 멀티미터로 잰 3V3 값을 비교하고, A0의 assume3.3V, corrected를 PA0 실측값과 비교한다. 차이가 ±3% 안이면 Vrefint 편차 범위 안이다. USB 허브, 긴 케이블, 외부 전원 등으로 바꿔 VDDA를 흔들어 보고 두 값 중 어느 쪽이 실측을 더 잘 따라가는지 기록한다.

실험 B. 1점 교정

멀티미터로 잰 VDDA를 V_meas(mV)라 하면 이 칩의 Vrefint는 raw_vref × V_meas / 4095이다. 예: raw_vref = 1497, V_meas = 3300 → 1497 × 3300 / 4095 = 1206 mV. 이 값을 VREFINT_MV에 넣고 다시 빌드해 오차가 줄었는지 확인한다(실험용 사본에서 수정). 온도 변동은 데이터시트 기준 최대 10 mV(약 0.8%)이므로 교정 후 남는 오차의 상한이 크게 줄어든다.

실험 C. 평균 대신 합으로 계산

adc_read_avg()가 sum을 돌려주게 바꾸고 VDDA = 1200 × 4095 × 16 / sum으로 계산한다(분자 78,624,000은 uint32_t 안이다). raw_vref 1 LSB가 VDDA 약 2.2 mV에 해당하던 계단이, 잡음이 있으면 약 0.14 mV 단위로 촘촘해진다. 잡음이 전혀 없으면 합도 16의 배수뿐이라 이득이 없다는 점(디더링 효과)도 생각해 본다.

실험 D. Vrefint 샘플 시간 줄이기

ADC_SAMPLETIME_239CYCLES_5를 71CYCLES_5(6.70 µs), 7CYCLES_5(0.70 µs)로 바꿔 raw_vref를 비교한다. 샘플링 커패시터가 덜 충전되면 raw_vref가 작아져 VDDA가 크게 계산된다. A0 채널은 그대로 두어 Vrefint 쪽만 변하는지 확인한다.

10. 확인 문제

문제 1. raw_vref = 1638, A0 raw = 2000이면 예제가 출력하는 VDDA, assume3.3V, corrected는?

VDDA = 1200 × 4095 / 1638 = 4,914,000 / 1638 = 3000 mV. assume3.3V = 2000 × 3300 / 4095 = 1611 mV(정수 나눗셈). corrected = 2000 × 3000 / 4095 = 1465 mV. VDDA가 실제로 3.0 V라면 보정 없는 값은 약 10% 크게 나온다.

문제 2. 실제 VDDA는 정확히 3.3 V이고 이 칩의 Vrefint가 1.24 V이다. raw_vref와 출력 VDDA는? 오차는 몇 %인가?

raw_vref = 1240 / 3300 × 4095 ≈ 1538.7 → 1539. VDDA = 4,914,000 / 1539 = 3192 mV이다. −108 mV, 약 −3.3%로, 1.20 / 1.24 − 1 ≈ −3.2%에 양자화 버림이 더해진 값이다. 이 경우 3.3 V 가정 쪽이 정확하다.

문제 3. Vrefint 개체 편차가 1.16~1.24 V일 때, 보정이 최악의 경우에도 3.3 V 가정보다 낫다고 말할 수 있는 VDDA 범위는?

보정 후 최악 오차는 +3.45% 또는 −3.23%로 크기 약 3.4%이다. 3.3 V 가정 오차 |3.3 / VDDA − 1|이 이보다 크려면 VDDA < 3.3 / 1.0345 ≈ 3.19 V 또는 VDDA > 3.3 / 0.9677 ≈ 3.41 V이어야 한다. 그 사이에서는 교정하지 않은 Vrefint 보정이 오히려 손해일 수 있다. 1점 교정을 하면 이 구간이 거의 사라진다.

문제 4. Vrefint 샘플 시간으로 71.5 사이클이 아니라 239.5 사이클을 고른 이유를 데이터시트 수치로 설명하라.

TS_vrefint는 typ 5.1 µs, max 17.1 µs이다. ADCCLK 10.67 MHz에서 71.5 사이클은 6.70 µs로 최댓값을 만족하지 못하고, 239.5 사이클은 22.45 µs로 만족한다. F1의 샘플 시간 선택지는 71.5 다음이 239.5이므로 239.5를 쓴다. 대가로 변환 1회가 23.6 µs로 길어지지만 1초 주기 측정에서는 문제가 되지 않는다.
