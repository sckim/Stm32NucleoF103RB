가변저항으로 LED 밝기 조절: 이동평균과 감마 보정

센서 값을 읽어 그대로 액추에이터에 넘기면 두 가지 문제가 생긴다. 잡음 때문에 출력이 떨리고, 사람 눈이 밝기를 선형으로 느끼지 않아 손잡이의 앞쪽 조금만 돌려도 LED가 거의 다 밝아진다. 이 교안은 PA1(A1)의 가변저항 전압을 ADC 연속 변환 + DMA로 받아, 8샘플 이동평균과 감마(제곱) 보정을 거쳐 TIM2_CH1(PA0) PWM의 CCR1로 내보내는 07_ADC_Potentiometer_PWM_c 예제를 해석한다. ‘입력 → 처리 → 출력’이 한 루프에 모두 들어 있는 가장 작은 계측·제어 예제이다.

1. 문제: 떨리지 않고, 고르게 밝아지게

앞 예제들은 ADC 값을 UART로 보여 주는 데서 끝났다. 이 예제는 그 값으로 무언가를 움직인다. 그러려면 잡음을 줄이는 필터, 사람의 지각에 맞춘 변환, 미세한 떨림을 무시하는 불감대가 필요하다.

  • ADC 연속 변환 + DMA 원형 모드(1칸)로 ‘항상 최신값이 들어 있는 변수’를 만드는 방법을 이해한다.
  • 링 버퍼로 합계를 유지하는 N샘플 이동평균의 지연, 잡음 감소량(1/√N), 정수 연산 범위를 계산한다.
  • 감마 보정이 왜 필요한지, 정수식 duty = filtered² / 16765가 어떻게 0~1000을 만드는지 설명한다.
  • TIM2 PWM의 PSC/ARR/CCR1로 1 kHz, 0~100% 듀티를 만드는 계산을 05_TIM_PWM 교안과 연결한다.
이 예제의 동작

ADC1은 PA1(CH1)을 약 7.9 µs마다 쉬지 않고 변환하고, DMA1 채널1이 결과를 변수 adc_val 한 칸에 계속 덮어쓴다. main은 약 21 ms(HAL_Delay(20))마다 이 값을 하나 집어 8칸 이동평균을 내고, 제곱 곡선으로 듀티(0~1000)를 구한 뒤, 이전 출력과 3 이상 다를 때만 TIM2->CCR1에 쓴다. PA0에 연결한 외부 LED가 1 kHz PWM으로 밝기를 바꾸고, 0.5초마다 UART2(115200)로 adc=2048 duty= 25.0% 형식의 줄을 보낸다. 인터럽트는 쓰지 않는다.

이 예제는 검토 전(컴파일만 확인) 상태이다.

이동평균: 링 버퍼로 합계를 유지한다

매번 8개를 다시 더하지 않는다. 가장 오래된 값을 합계에서 빼고, 새 값을 더한 뒤, 그 자리에 새 값을 저장한다. 인덱스는 (idx + 1) & 7로 0~7을 돈다(N이 2의 거듭제곱이라 나머지 대신 AND, 나눗셈 대신 >> 3을 쓸 수 있다).

y[k] = (x[k] + x[k−1] + … + x[k−7]) / 8 sum ≤ 8 × 4095 = 32760 (uint16_t로도 충분, 코드는 uint32_t) 잡음 표준편차: σ_y = σ_x / √N = σ_x / √8 ≈ 0.354 σ_x (약 −9 dB, 표본 간 잡음이 서로 독립일 때) 군지연: (N−1)/2 × T = 3.5 × 21 ms ≈ 74 ms 계단 입력이 끝까지 반영되는 시간: N × T ≈ 168 ms

표본 주기 T는 ADC 변환 주기가 아니라 main 루프 주기이다. HAL_Delay(20)은 최소 대기를 보장하려고 1틱을 더 기다리므로 약 21 ms이고(05_TIM_PWM 교안의 HAL_Delay(1) ≈ 2 ms와 같은 이유), 0.5초마다 UART 송신 약 2 ms가 더해진다. 따라서 fs ≈ 47.6 Hz로 본다. 또 hist[]가 0으로 시작하므로 전원 직후 처음 8회(약 168 ms)는 평균이 0에서 올라오는 과도 구간이다.

그림 2. 이동평균의 주파수 응답. 사각 창의 푸리에 변환이므로 sinc 모양이며, fs/N의 정수배에서 정확히 0이 된다. 0.36 선은 백색 잡음 감소비 1/√8에 해당한다.

생체신호 계측 관점

이동평균은 가장 싼 저역통과 필터이자 빗살(comb) 노치 필터이다. 영점이 fs/N의 배수에 생기므로, 심전도처럼 전원 잡음이 문제인 신호는 fs/N = 60 Hz가 되도록 고르면(예: fs = 480 Hz, N = 8) 60 Hz와 그 고조파가 함께 사라진다. 반대로 부엽이 커서(약 −13 dB) 차단 특성은 좋지 않고, 창 길이만큼 파형이 뭉개진다(QRS 같은 날카로운 성분 손실). 또 이 예제는 127 kS/s로 변환한 값을 안티에일리어싱 없이 47.6 Hz로 솎아 읽으므로, 60 Hz 유도 잡음은 약 12 Hz 성분으로 접혀 들어온 뒤 이동평균에서 감쇠된다. 시뮬레이터에서 확인할 수 있다.

감마 보정: 눈은 밝기를 선형으로 느끼지 않는다

LED의 빛 세기(물리량)는 듀티에 비례한다. 그러나 사람이 느끼는 밝기는 빛 세기의 세제곱근에 가깝다(CIE L* ≈ 116·Y1/3 − 16). 그래서 듀티 25%가 이미 ‘반 이상 밝게’(L* ≈ 57) 보이고, 손잡이 뒤쪽 절반은 밝기 변화가 거의 느껴지지 않는다. 입력 비율 u를 uγ로 바꾸어 듀티로 쓰면 아래쪽을 눌러 펴서 지각 밝기가 고르게 늘어난다.

그림 3. 감마 2의 효과. 왼쪽은 입력에 대한 듀티, 오른쪽은 그 듀티가 만드는 지각 밝기이다. 선형 듀티는 손잡이 앞쪽 10%에서 이미 L* ≈ 38까지 치솟는다.

불감대(코드 주석의 ‘히스테리시스’)

코드는 duty > last_out + 2 또는 duty + 2 < last_out일 때, 즉 이전 출력과 3 이상 다를 때만 CCR1을 바꾼다. 0과 1000에는 예외로 바로 간다(끝까지 꺼지거나 켜지게). 엄밀히는 두 문턱을 가진 히스테리시스라기보다 이전 출력 둘레의 불감대(deadband)이다. 비교는 감마 뒤의 듀티 눈금(0~1000)에서 하므로, 저휘도에서는 3단계 계단(예: 1 → 4, 빛 세기 4배)이 눈에 띌 수 있다.

LED 전류는 적색 LED(Vf ≈ 2 V 가정)에서 (3.3 − 2.0) / 330 Ω ≈ 4 mA이고, 평균 전류는 듀티에 비례한다. 1 kHz는 눈의 깜빡임 융합 주파수(수십 Hz)보다 충분히 높아 깜빡임이 보이지 않는다.

4. 직접 만져 보기

아래 시뮬레이터는 main 루프 한 번(약 21 ms)을 한 틱으로 하여, ADC 값 → 이동평균 → 감마 → 불감대 → CCR1을 코드와 같은 정수 연산으로 계산한다.

  1. ▶ 재생을 누르고 가변저항 슬라이더를 움직인다. 주황(원 신호)보다 청록(이동평균)이 늦게 따라오는 것을 본다.
  2. 백색 잡음 σ를 20 LSB로 두고 N을 1, 8, 32로 바꾼다. σ 비율이 1/√N에 가까운지 확인한다.
  3. 계단 10% → 90%를 눌러 N = 8에서 8틱(약 168 ms) 뒤에 평균이 다 따라오는지 본다.
  4. 60 Hz 잡음을 넣는다. 21 ms 표본에서는 약 12 Hz의 느린 물결로 보이며, N = 8이 이를 크게 줄인다.
  5. 감마를 ‘선형’과 ‘γ 2 (예제)’로 바꾸며 아래 LED 띠의 밝기 간격을 비교한다.

    HAL_ADC_Start_DMA(…, 1) → 연속 변환 + DMAHWSWSTART 한 번으로 ADC가 7.875 µs마다 변환을 반복하고, 변환마다 DMA가 ADC1_DR → adc_val로 반워드 한 개를 옮긴다. CNDTR이 0이 되면 1로 다시 채워진다.
  8. 8
    main 루프: 약 21 ms마다SWHAL_Delay(20) → adc_val 읽기 → 링 버퍼 합계 갱신 → sum >> 3 → f²/16765 → 불감대 → CCR1.
  9. 9
    CCR1 프리로드 → 다음 주기에 반영HWOC1PE = 1이므로 새 CCR1은 다음 갱신 이벤트(최대 1 ms 뒤)에 그림자 레지스터로 옮겨져, 주기 중간 글리치 없이 PA0 듀티가 바뀐다.
  10. 10
    0.5초마다 UARTSWt_print += 500으로 누적 오차 없이 출력. 블로킹 송신 약 2 ms 동안에도 ADC/DMA/PWM은 하드웨어가 계속 돌린다.
인터럽트가 없는 이유와 주의점

HAL_ADC_Start_DMA()는 DMA의 TC/HT/TE 인터럽트 허용 비트를 켠다. 그러나 NVIC에서 DMA1_Channel1_IRQn이 꺼져 있고 stm32f1xx_it.c에도 핸들러가 없으므로 플래그만 서고 CPU는 방해받지 않는다. CubeMX의 기본값 NVIC.ForceEnableDMAVector=true이면 다시 생성할 때 DMA 인터럽트가 강제로 켜지므로, 이 예제의 .ioc는 이를 false로 꺼 두었다. 이 설정이 켜지면 길이 1 버퍼에서는 변환마다(초당 약 12만 7천 번) 인터럽트와 HAL 콜백이 돌아 CPU 시간 대부분을 빼앗긴다. 재생성 후에는 MX_DMA_Init()을 확인한다.

Core/Src/main.c — USER CODE BEGIN 3 (main 루프)
HAL_Delay(20);

/* 1) 이동 평균 (링 버퍼로 합계를 유지) */
sum -= hist[idx];
hist[idx] = adc_val;
sum += hist[idx];
idx = (idx + 1) & 7;
filtered = sum >> 3;

/* 2) 감마 보정 후 3) 히스테리시스: 새 값이 이전 출력과 2 이상 다를 때만 갱신 */
uint32_t duty = (filtered * filtered) / 16765U;
if (duty > 1000U) duty = 1000U;
if (last_out == 0xFFFF || (duty > last_out + 2U) || (duty + 2U < last_out) || duty == 0U || duty == 1000U)
{
  last_out = duty;
  __HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, duty);   /* TIM2->CCR1 */
}

if (HAL_GetTick() - t_print >= 500)
{
  t_print += 500;
  int n = snprintf(msg, sizeof msg, "adc=%4lu  duty=%3lu.%lu%%\r\n", (unsigned long)filtered,
                   (unsigned long)(last_out / 10), (unsigned long)(last_out % 10));
  HAL_UART_Transmit(&huart2, (uint8_t *)msg, (uint16_t)n, 100);
}
  1. HAL_Delay(20) ≈ 21 ms가 이동평균의 표본 주기이다
  2. 빼기 → 저장 → 더하기 순서로 합계를 O(1)에 갱신한다. & 7, >> 3은 N = 8일 때만 맞으므로 N을 바꾸면 둘 다 고친다
  3. adc_val을 한 번만 읽어 hist[idx]에 저장하고 그 값을 더한다. 두 번 읽으면 그 사이 DMA가 바꿔 합계가 어긋날 수 있다
  4. 감마는 곱셈 1회 + 나눗셈 1회. 1000 초과는 실제로 생기지 않지만 안전을 위해 제한한다
  5. 조건은 ‘2보다 크게’이므로 주석의 ‘2 이상’과 달리 3 이상 차이에서 갱신한다. 0과 1000은 항상 반영
  6. 듀티 0~1000을 /10, %10으로 나눠 소수 한 자리 %로 출력 (부동소수점 printf 불필요)
기대 출력 (가변저항을 가운데쯤에 둔 경우)
adc=2048  duty= 25.0%
adc=2050  duty= 25.0%
adc=4095  duty=100.0%
adc=   0  duty=  0.0%

가운데(약 1.65 V)에서 듀티가 50%가 아니라 25%인 것이 감마 보정의 결과이다. 실제 값은 가변저항 오차와 잡음에 따라 몇 LSB 다르다. 끝까지 돌려도 4095나 0이 정확히 나오지 않을 수 있다.

8. 실험

실험 A. 기본 동작과 감마 확인

터미널(115200 8N1)을 열고 가변저항을 0 → 100%로 천천히 돌린다. adc가 약 1024, 2048, 3072일 때 duty가 약 6.2%, 25.0%, 56.2%인지 기록해 adc² / 16765와 비교한다. LED가 손잡이 전체 구간에서 고르게 밝아지는지 눈으로 본다.

실험 B. 선형과 감마를 눈으로 비교한다

감마 줄을 uint32_t duty = (filtered * 1000U) / 4095U;로 바꾸어 다시 빌드한다. 손잡이의 앞쪽 20%에서 LED가 거의 다 밝아지고 나머지 구간은 변화가 작게 느껴지는지 확인한다. 시뮬레이터 LED 띠와 비교한다.

실험 C. 이동평균 길이를 바꾼다

hist[8], & 7, >> 3을 각각 hist[32], & 31, >> 5로 바꾼다. 가변저항을 빠르게 돌렸을 때 LED가 약 0.7초(32 × 21 ms) 늦게 따라오는 것을 관찰한다. 합계 최대는 32 × 4095 = 131040으로 uint16_t라면 넘치지만 uint32_t이므로 안전하다. 손을 뗐을 때 UART의 adc 떨림 폭이 N = 8보다 약 절반(√(8/32))인지 본다.

실험 D. PWM 파형을 AD2로 본다

AD2 오실로스코프 CH1을 PA0(A0)에 연결한다. 주기 1.000 ms(1 kHz)인지, UART의 duty와 High 폭(µs)이 같은지(25.0% → 250 µs) 측정한다. 손잡이를 아주 낮은 쪽에 두고 High 폭이 1 µs씩이 아니라 3 µs 이상씩 바뀌는 것(불감대)을 확인한다.

증상원인점검/조치
LED가 전혀 켜지지 않는다LED를 LD2/D13이나 다른 핀에 연결, LED 극성 반대, HAL_TIM_PWM_Start 실패PA0(A0) → 330 Ω → LED(+), (−) → GND. AD2로 PA0에 1 kHz가 나오는지 먼저 본다

10. 확인 문제

문제 1. ADCCLK 10.67 MHz, 샘플 시간 71.5 사이클일 때 변환 주기는? main이 21 ms마다 읽으면 몇 개 중 1개를 쓰는가?

(71.5 + 12.5) / 10.67 MHz = 84 / 10.67 MHz ≈ 7.875 µs, 약 127 kS/s이다. 21 ms / 7.875 µs ≈ 2667이므로 약 2667개 중 1개만 쓰고 나머지는 DMA가 덮어쓴다.

문제 2. filtered = 3000이면 CCR1과 듀티는? 선형 변환이었다면?

3000² = 9,000,000, 9,000,000 / 16765 = 536.8 → 정수 나눗셈으로 536, 듀티 53.6%이다. 선형이면 3000 × 1000 / 4095 = 732(73.2%)이다. 이전 출력과 3 이상 차이가 나야 CCR1에 실제로 반영된다.

문제 3. 이 예제의 이동평균(N = 8)에서 백색 잡음 σ = 16 LSB는 몇 LSB로 줄어드는가? N을 32로 늘리면 합계 변수의 최대값과 지연은?

16 / √8 ≈ 5.7 LSB이다. N = 32이면 합계 최대 32 × 4095 = 131040으로 16비트를 넘지만 uint32_t이므로 문제없다. 잡음은 16 / √32 ≈ 2.8 LSB, 군지연은 31/2 × 21 ms ≈ 326 ms, 계단 응답은 32 × 21 ms ≈ 672 ms로 늘어난다.

문제 4. fs ≈ 47.6 Hz, N = 8 이동평균의 첫 영점 주파수는? 60 Hz 전원 잡음을 이동평균 하나로 없애려면 fs와 N을 어떻게 고르는가?

첫 영점은 fs/N ≈ 47.6 / 8 ≈ 5.95 Hz이다. 영점이 fs/N의 정수배에 생기므로 fs/N = 60 Hz가 되게 한다. 예를 들어 타이머 트리거(04 예제 방식)로 fs = 480 Hz를 만들고 N = 8로 하면 60, 120, 180 Hz 성분이 모두 0이 된다. 이 예제처럼 HAL_Delay로 표본 주기를 정하면 fs가 정확하지 않아 영점이 어긋난다.
