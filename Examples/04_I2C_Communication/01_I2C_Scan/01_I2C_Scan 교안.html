I2C 버스 스캔: 주소마다 "있으면 ACK 하라"고 묻는다

I2C 장치가 응답하지 않을 때 가장 먼저 할 일은 버스에 누가 있는지 확인하는 것이다. 이 교안은 주소 바이트 하나와 ACK 비트 하나로 장치의 존재를 확인하는 원리를 다룬다. 그 원리로 I2C1(PB6/PB7)에서 7비트 주소 0x08~0x77을 차례로 호출하는 01_I2C_Scan 예제를 해석한다. HAL 주소 인자를 1비트 시프트해야 하는 이유와, 버스가 Low에 묶였을 때 나오는 HAL_BUSY도 함께 본다.

1. 문제: 장치가 대답하지 않는다

LCD 백팩, 가속도 센서, OLED처럼 I2C 모듈을 처음 연결하면 대개 아무것도 동작하지 않는다. 원인은 여러 가지일 수 있다. 배선이 틀렸을 수도 있고, 풀업이 없을 수도 있다. 주소를 잘못 알고 있거나 HAL 주소 인자를 시프트하지 않았을 수도 있다. 장치 레지스터를 읽는 코드부터 디버깅하면 이 원인들이 서로 섞인다.

스캐너는 문제를 둘로 나눈다. "버스와 장치가 살아 있는가"와 "장치와 대화하는 코드가 맞는가"이다. 스캔에서 주소가 보이면 배선, 풀업, 전원, 주소는 맞다. 그다음은 장치 레지스터 문제다.

  • I2C 프레임(START, 주소 7비트 + R/W, ACK, STOP)과 오픈 드레인 + 풀업 구조를 이해한다.
  • 주소 하나를 호출하는 동안 SR1.SB, SR1.ADDR, SR1.AF, SR2.BUSY가 어떻게 바뀌는지 따라간다.
  • HAL 주소 인자가 7비트 주소 << 1인 이유를 HAL 매크로 수준에서 확인한다.
  • HAL_I2C_IsDeviceReady()의 네 가지 반환값(HAL_OK, HAL_ERROR, HAL_BUSY, HAL_TIMEOUT)을 구별한다.
  • 100 kHz 표준 모드 타이밍 레지스터(CR2.FREQ, CCR, TRISE)의 값을 직접 계산한다.
예제 간 관계

04_I2C_Communication 그룹의 첫 예제이다. 장치를 붙이기 전에 버스에 무엇이 응답하는지부터 확인한다. 스캔을 2초마다 반복하고, 흔한 장치의 이름을 붙이고, 버스 오류를 따로 알린다. 핀이 다르다: 이 예제는 기본 핀 PB6/PB7을 쓰고, 다음 두 예제 02_PCF8574_Output·03_PCF8574_LCD는 I2C1을 리맵해 PB8(D15)/PB9(D14)를 쓴다. 핀을 옮기지 않으면 아무것도 보이지 않는다. 그 뒤의 04_I2C_MPU6050_c는 여기서 찾은 주소(0x68)로 레지스터를 읽는다.

2. I2C 프레임과 주소

두 선, 오픈 드레인, 풀업

I2C는 SCL(클럭)과 SDA(데이터) 두 선만 쓴다. 버스에 붙은 모든 장치는 선을 Low로 당기기만 할 수 있다(오픈 드레인). High는 외부 풀업 저항이 만든다. 그래서 한 장치라도 Low로 당기면 선은 Low가 된다(wired-AND). 마스터와 슬레이브가 같은 SDA를 번갈아 쓸 수 있는 것도, 슬레이브가 SCL을 잡아 마스터를 기다리게 할 수 있는 것(클럭 스트레칭)도 이 구조 덕분이다.

그림 1. I2C 버스. SCL·SDA에 풀업이 하나씩 있고, 모든 장치가 같은 두 선에 병렬로 붙는다. 대부분의 브레이크아웃 모듈에는 풀업이 이미 달려 있다.

STM32F1의 GPIO는 대체 기능(AF) 오픈 드레인 모드에서 내부 풀업을 켤 수 없다. 내부 풀업·풀다운은 입력 모드에서만 고를 수 있다. 그래서 이 예제는 외부 풀업이 반드시 필요하다. 풀업이 없으면 선이 High로 올라가지 못한다.

  • START: SCL이 High인 동안 SDA가 High → Low로 떨어진다. 데이터 비트는 SCL이 Low일 때만 바뀌므로, SCL High 구간의 SDA 변화는 START나 STOP을 뜻한다.
  • 주소 바이트: 7비트 주소를 MSB부터 보내고 8번째 비트에 R/W̄를 붙인다. 쓰기(0)이면 바이트 값은 addr << 1이다.
  • ACK: 9번째 클럭에서 마스터는 SDA를 놓는다. 주소가 일치한 슬레이브가 있으면 SDA를 Low로 당긴다(ACK). 없으면 풀업 때문에 High로 남는다(NACK).
  • STOP: SCL이 High인 동안 SDA가 Low → High로 올라간다. 버스가 비었음을 알린다.

스캔은 이 프레임에서 데이터 바이트를 하나도 보내지 않는다. 주소 + ACK만으로 존재를 확인한다. 쓰기 방향으로 부르므로 장치는 아무 데이터도 내보내지 않고 레지스터 값도 바뀌지 않는다.

3. 직접 만져 보기

시뮬레이터는 세 부분이다. 첫째는 주소 하나를 호출하는 파형과 플래그, 둘째는 112개 주소 전체 스캔, 셋째는 HAL 주소 인자 계산기다.

  1. 기본값(0x27, PCF8574 연결)에서 다음 단계를 눌러 SB → ADDR → STOP 순서로 플래그가 바뀌는 것을 본다.
  2. 주소를 0x28로 바꾸어 9번째 클럭이 NACK가 되고 SR1.AF가 서는 것을 본다.
  3. SDA/SCL이 Low에 묶임을 켜고 HAL_BUSY가 나오는 경로를 본다.
  4. 스캔에서 시프트 누락을 켜고 0x27 장치가 어디에 나타나는지, 0x68 장치는 왜 사라지는지 본다.
  5. 스캔에서 코드 버전을 "수정 전"으로 바꾸고 Low 고착 상태로 스캔해 출력과 소요 시간을 비교한다.

4. 레지스터 분석

타이밍: 100 kHz 표준 모드

SYSCLK 64 MHz(HSI/2 × 16), APB1 ÷2이므로 I2C1 클럭 PCLK1 = 32 MHz, TPCLK1 = 31.25 ns이다. HAL은 다음 매크로로 값을 정한다.

CR2.FREQ = PCLK1 / 1 MHz = 32 (0x20) CCR = (PCLK1 − 1) / (2 × 100 kHz) + 1 = 159 + 1 = 160 (0xA0) → T_high = T_low = 160 × 31.25 ns = 5 µs → 이론상 100 kHz TRISE = FREQ + 1 = 33 (0x21) (표준 모드 최대 상승 시간 1000 ns / 31.25 ns = 32, 여기에 +1)

RM0008의 CCR 설명은 Thigh = tr(SCL) + tw(SCLH)라고 적는다. 마스터는 SCL을 놓은 뒤 선이 실제로 High가 된 것을 보고 나서 High 시간을 센다. 그래서 상승이 느리면(풀업이 크거나 선이 길면) High 구간이 늘어나고, 실제 SCL 주파수는 100 kHz보다 조금 낮아진다. TRISE는 이 피드백 루프의 최대 지연을 알려 준다. RM0008에는 CCR을 PE = 0일 때만 설정하라는 조건도 있다. HAL은 이 순서를 지킨다.

BUSY의 정의

RM0008은 SR2.BUSY를 "SDA 또는 SCL의 Low를 검출하면 세트, STOP을 검출하면 해제"로 정의한다. 따라서 풀업이 없어 선이 Low로 읽히거나, 슬레이브가 SDA를 잡고 놓지 않거나, 선이 GND에 단락되면 BUSY가 풀리지 않는다. 그러면 마스터는 START를 낼 수 없다.

5. HAL이 대신 해 주는 일

초기화: HAL_I2C_Init → HAL_I2C_MspInit

  1. 1
    MspInit: GPIOB 클럭, PB6/PB7 = AF 오픈 드레인(고속), I2C1 클럭 허용 stm32f1xx_hal_msp.cGPIO_MODE_AF_OD. 내부 풀업 설정이 없다(F1에서는 불가). 리맵 없음.
  2. 2
    PE = 0, SWRST 1 → 0 CR1이전 상태를 지운다. 단, 정오표 2.8.7의 BUSY 고착은 SWRST만으로 풀리지 않는다(8절).
  3. 3
    PCLK1 확인과 타이밍 계산 HAL표준 모드는 PCLK1 ≥ 2 MHz여야 한다. FREQ = 32, TRISE = 33, CCR = 160을 쓴다.
  4. 4
    CR1(ENGC, NOSTRETCH), OAR1, OAR2 설정 후 PE = 1 CR1/OAR1/OAR2이 시점부터 I2C1이 버스를 감시하고 SR2.BUSY가 동작한다.

주소 하나: HAL_I2C_IsDeviceReady(hi2c, DevAddress, Trials = 1, Timeout = 10)

  1. 1
    SR2.BUSY = 0 대기 (최대 25 ms) HAL시간 안에 풀리지 않으면 HAL_BUSY를 반환한다. 이 타임아웃은 인자 Timeout이 아니라 고정값 I2C_TIMEOUT_BUSY_FLAG(25 ms)이다.
  2. 2
    잠금, PE 확인, CR1.POS = 0 HAL핸들 상태를 BUSY로 둔다.
  3. 3
    CR1.START = 1 → SR1.SB 대기 CR1/SR1Timeout(10 ms) 안에 SB가 서지 않으면 HAL_TIMEOUT을 반환한다.
  4. 4
    DR = DevAddress & 0xFE DRSR1 읽기 뒤 DR 쓰기로 SB가 지워지고 주소 8비트가 나간다.
  5. 5
    SR1.ADDR 또는 SR1.AF 대기 (최대 Timeout) SR19번째 클럭의 ACK/NACK가 둘 중 하나를 세운다.
  6. 6
    CR1.STOP = 1, 플래그 정리, BUSY = 0 대기 CR1/SR1/SR2ADDR이면 SR1→SR2 읽기로 지우고 HAL_OK를 반환한다. 아니면 AF에 0을 쓰고, Trials를 다 쓰면 HAL_ERROR를 반환한다.

Trials 인자와 ACK 폴링

Trials는 NACK를 받았을 때 다시 시도하는 횟수다. 스캔은 존재만 보면 되므로 1회로 충분하다. 같은 함수는 "준비될 때까지 기다리기"에도 쓴다. 쓰기 사이클 중인 EEPROM은 일정 시간 NACK를 내므로, ACK가 올 때까지 이 함수를 반복해 부른다(06 예제의 ACK 폴링).

main.c — 장치 이름 추정 (USER CODE 0)
static const char *guess_name(uint8_t a)
{
    switch (a)
    {
    case 0x20: ... case 0x26:
    case 0x27: return "PCF8574 (A=000..111) / LCD 백팩";
    case 0x38: case 0x39: case 0x3A: case 0x3B: return "PCF8574A";
    case 0x3C: case 0x3D: return "SSD1306 OLED";
    case 0x3F: return "PCF8574A LCD 백팩";
    case 0x48: return "ADS1115 / TMP102";
    case 0x50: case 0x57: return "AT24Cxx EEPROM";
    case 0x68: return "MPU6050 / DS1307 / DS3231";
    case 0x76: case 0x77: return "BMP280 / BME280";
    default: return "";
    }
}
  1. 이름은 추정일 뿐이다. 0x68은 MPU6050일 수도 DS3231일 수도 있다. 0x3C는 SSD1306일 수도, 주소 핀을 100으로 둔 PCF8574A일 수도 있다.
  2. 장치를 확정하려면 장치 고유 레지스터를 읽는다. 예를 들어 MPU6050은 WHO_AM_I(0x75)를 읽으면 0x68을 돌려준다(03 예제).
  3. 표에 없는 주소도 있다. 0x3E, MPU6050의 AD0 = 1 주소인 0x69, 0x51~0x56 같은 것이다. 이런 주소는 이름 없이 출력된다.
main.c — 스캔 루프 (USER CODE WHILE / 3, 검토 후 수정본)
const char *h = "\r\n--- I2C1 scan (0x08..0x77) ---\r\n";
HAL_UART_Transmit(&huart2, (uint8_t *)h, (uint16_t)strlen(h), 100);

int found = 0;
for (uint8_t addr = 0x08; addr <= 0x77; addr++)
{
    HAL_StatusTypeDef st =
        HAL_I2C_IsDeviceReady(&hi2c1, (uint16_t)(addr << 1), 1, 10);
    if (st == HAL_OK)
    {
        int n = snprintf(msg, sizeof msg, "found 0x%02X  %s\r\n",
                         addr, guess_name(addr));
        HAL_UART_Transmit(&huart2, (uint8_t *)msg, (uint16_t)n, 100);
        found++;
    }
    else if (st == HAL_BUSY || st == HAL_TIMEOUT)
    {
        /* 버스 자체가 비정상: 스캔 중단 + 진단 메시지 */
        int n = snprintf(msg, sizeof msg,
            "bus error at 0x%02X: %s (SDA/SCL low? check pull-ups)\r\n",
            addr, (st == HAL_BUSY) ? "BUSY" : "no START");
        HAL_UART_Transmit(&huart2, (uint8_t *)msg, (uint16_t)n, 100);
        break;
    }
}
int n = snprintf(msg, sizeof msg, "%d device(s)\r\n", found);
HAL_UART_Transmit(&huart2, (uint8_t *)msg, (uint16_t)n, 100);
HAL_Delay(2000);
  1. addr는 uint8_t이고 조건이 <= 0x77이다. 0x77 다음 0x78에서 끝나므로 오버플로 무한 루프가 없다.
  2. addr << 1이 HAL 주소 인자다. Trials 1회, Timeout 10 ms.
  3. HAL_ERROR(NACK)는 "빈 주소"라는 정상 결과다. 아무것도 출력하지 않는다.
  4. HAL_BUSY/HAL_TIMEOUT은 버스 이상이다. 남은 주소도 같은 결과를 낼 것이므로 바로 멈추고 알린다.
  5. 2초 쉬고 다시 스캔한다. 모듈을 꽂고 빼면서 결과를 볼 수 있다.
검토에서 고친 점

원래 루프는 == HAL_OK만 검사했다. 버스가 Low에 묶이면 112개 주소가 모두 25 ms씩 HAL_BUSY로 끝난다. 약 2.8초 뒤에는 "0 device(s)"가 찍혀, 장치가 없는 정상 버스와 구별되지 않았다. 원래 머리 주석은 이 경우 "결과가 나오지 않는다"고 적었지만 실제로는 늦게, 그리고 잘못된 결과가 나왔다. 수정본은 반환값을 넷으로 나누어 버스 오류를 따로 출력한다.

ISR과 HAL 콜백

구분이 예제설명
ISR (벡터 테이블의 함수)SysTick_Handler → HAL_IncTick()1 ms마다 틱을 올린다. HAL_Delay(2000)과 HAL I2C 함수의 타임아웃(25 ms, 10 ms)이 모두 이 틱으로 잰다. I2C1_EV_IRQHandler/I2C1_ER_IRQHandler는 없다(NVIC 미사용).
HAL 콜백 (HAL이 ISR 안에서 부르는 사용자 함수)없음HAL_I2C_IsDeviceReady는 블로킹 폴링 함수라 콜백이 없다. HAL_I2C_MasterTxCpltCallback, HAL_I2C_MemRxCpltCallback 같은 콜백은 _IT/_DMA 함수를 쓸 때만 불린다(04 예제).

주의: 폴링 함수라도 타임아웃은 SysTick 인터럽트에 의존한다. 인터럽트를 끈 구간(__disable_irq())이나 SysTick보다 우선순위가 높은 ISR 안에서 이 함수를 부르면 HAL_GetTick()이 멈춘다. 그러면 버스 고착 시 타임아웃 없이 영원히 기다린다.

7. 실험

실험 A. 기본 스캔

PCF8574 LCD 백팩(또는 아무 I2C 모듈)을 연결하고 터미널(115200)을 연다. 2초마다 found 0x27 PCF8574 (A=000..111) / LCD 백팩, 1 device(s)가 반복되면 정상이다. 0x3F가 나오면 PCF8574A 계열 백팩이다. 01 예제의 LCD 주소(0x4E)를 0x7E로 바꾸어야 한다.

실험 B. 핫플러그와 주소 핀

스캔 중에 모듈을 하나 더 꽂는다. MPU6050(GY-521)이면 다음 스캔에 0x68이 추가된다. GY-521의 AD0 핀을 3.3 V에 연결하면 0x69로 바뀐다. 이 주소는 guess_name 표에 없어 이름 없이 나온다. 기대 결과: 주소 핀 하나로 7비트 주소의 LSB가 바뀐다.

실험 C. 시프트를 빼먹는다

(uint16_t)(addr << 1)을 addr로 바꾸고 0x27, 0x68 장치를 연결한다. 기대 결과: found 0x4E, found 0x4F가 나온다. HAL이 bit 0을 지우므로 0x4E와 0x4F 모두 버스에 0x4E를 내보내고, 그 값은 7비트 0x27이다. 0x68 장치는 사라진다. 0x68을 부르려면 루프 변수가 0xD0이어야 하는데 범위(≤ 0x77) 밖이다. 3절 시뮬레이터 B에서 먼저 예측해 본다.

실험 D. 버스를 Low에 묶는다

점퍼선으로 SDA(PB7)를 GND에 잠깐 연결한다. 오픈 드레인 출력은 Low로 당기기만 하므로 핀이 상하지 않는다. 기대 결과(수정본): 약 25 ms 뒤 bus error at 0x08: BUSY (SDA/SCL low? check pull-ups), 0 device(s)가 나온다. 비교를 위해 루프를 원래 코드(== HAL_OK만 검사)로 되돌리면, 2초 대기 외에 약 2.8초가 더 걸린 뒤 0 device(s)만 나온다. 점퍼를 빼면 다음 스캔에서 정상으로 돌아오는지도 확인한다. 돌아오지 않으면 8절의 BUSY 고착 항목을 본다.

실험 E. 파형을 직접 본다

로직 분석기나 Analog Discovery 2(01_GPIO/10_AD2Test 참고)를 SCL·SDA에 연결하고 I2C 디코더를 켠다. 기대 결과: START, 주소 바이트(0x10, 0x12, ... 즉 addr << 1), NACK, STOP이 반복되다가 장치 주소에서만 ACK가 보인다. SCL 주기를 재어 100 kHz와 비교하고, 상승 에지 기울기와의 관계(4절)를 확인한다. 측정값은 풀업 값과 배선에 따라 다르다.

9. 확인 문제

문제 1. 데이터시트에 7비트 주소가 0x68로 적힌 장치를 HAL_I2C_Mem_Read로 읽을 때 DevAddress는?

0x68 << 1 = 0xD0이다. 읽기 방향 비트(1)는 HAL이 내부에서 붙인다.

문제 2. 스캔 결과가 found 0x4E, found 0x4F이고, 연결해 둔 MPU6050(0x68)은 보이지 않는다. 무엇이 잘못되었는가?

HAL 인자에서 시프트를 빠뜨렸다. 0x4E와 0x4F는 bit 0이 지워져 둘 다 버스 바이트 0x4E, 즉 7비트 0x27(PCF8574)을 부른다. 0x68을 부르려면 루프 변수가 0xD0이어야 하는데 스캔 범위 0x08~0x77 밖이라 보이지 않는다.

문제 3. APB1을 ÷8로 바꾸어 PCLK1 = 8 MHz가 되면 CR2.FREQ, CCR, TRISE는 얼마인가?

FREQ = 8, CCR = (8,000,000 − 1)/200,000 + 1 = 39 + 1 = 40 (0x28), TRISE = 8 + 1 = 9이다. RM0008이 CCR·TRISE 설명에서 드는 예와 같은 값이다(125 ns × 40 = 5 µs).

문제 4. HAL_ERROR와 HAL_BUSY는 스캔에서 왜 다르게 처리해야 하는가?

HAL_ERROR는 그 주소에 장치가 없다는 정상 결과(NACK, SR1.AF)다. HAL_BUSY는 START조차 낼 수 없는 버스 이상(SR2.BUSY 고착)이다. 다음 주소도 같은 결과가 나오고 주소마다 25 ms를 낭비한다. 둘을 섞으면 "장치 없음"과 "버스 고장"을 구별할 수 없다.

문제 5. 스캔에서 0x3C가 보였다. SSD1306 OLED라고 단정할 수 있는가?

없다. 스캔은 주소에 ACK 하는 장치가 있다는 것만 알려 준다. 0x3C는 주소 핀을 100으로 둔 PCF8574A일 수도 있다. 확정하려면 장치마다 다른 레지스터나 동작을 확인해야 한다(예: MPU6050은 WHO_AM_I 읽기).

문제 6. 스캔이 쓰기 방향(R/W̄ = 0)으로 주소만 보내고 끝내는 것이 장치에 안전한 이유는?

ACK 직후 STOP을 보내므로 데이터 바이트가 하나도 전달되지 않는다. 장치 레지스터 포인터나 내용이 바뀌지 않는다. 읽기 방향으로 부르면 장치가 SDA로 데이터를 내보내기 시작한다. 그러면 마스터가 NACK와 STOP을 제대로 처리해야 하므로 더 복잡하다.

정리

  • 주소 바이트 하나 + ACK 비트 하나로 장치의 존재를 확인한다. 데이터는 보내지 않는다.
  • 하드웨어 관점: CR1.START → SR1.SB → DR = addr<<1 → SR1.ADDR(ACK) 또는 SR1.AF(NACK) → CR1.STOP.
  • HAL 주소 인자는 버스 바이트 모양(7비트 << 1)이다. HAL은 bit 0만 지우고 시프트하지 않는다.
  • SR2.BUSY가 풀리지 않으면 START를 낼 수 없다. 원인은 풀업, 단락, 슬레이브의 SDA 고착, 정오표 2.8.7이다.
  • 100 kHz: FREQ = 32, CCR = 160, TRISE = 33 (PCLK1 = 32 MHz).
