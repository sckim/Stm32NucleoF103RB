SSD1306 OLED: 1 KB 프레임버퍼를 I2C로 밀어 넣는다

128×64 OLED 한 화면은 1024바이트이다. MCU RAM에 같은 크기의 프레임버퍼를 두고 그림을 그린 뒤, I2C 한 번의 쓰기로 통째로 보낸다. 이 예제설명은 SSD1306의 I2C 프레임(주소 → 제어 바이트 → 데이터), 페이지 단위 메모리 구조, 초기화 명령을 설명하고, HAL_I2C_Mem_Write의 "메모리 주소" 자리에 제어 바이트를 넣는 06_I2C_OLED_SSD1306_c 예제를 해석한다.

1. 문제: 점 하나하나를 그릴 수 있는 화면

03_PCF8574_LCD 예제의 문자 LCD는 글자 코드만 보내면 LCD 컨트롤러가 글꼴을 그려 준다. 대신 정해진 칸에 정해진 글자만 쓸 수 있다. SSD1306 OLED는 픽셀 하나하나를 켜고 끈다. 선, 도형, 큰 숫자, 애니메이션을 자유롭게 그릴 수 있지만, 무엇을 그릴지는 전부 MCU가 계산해야 한다.

문제는 두 가지이다.

  • 화면 램의 모양이 특이하다. 1바이트가 가로 8픽셀이 아니라 세로 8픽셀이다. 좌표 (x, y)를 바이트 번호와 비트 번호로 바꾸는 규칙을 알아야 한다.
  • I2C는 느리다. 400 kHz에서도 1024바이트를 보내는 데 약 24 ms가 걸린다. 픽셀을 하나 바꿀 때마다 보내면 화면이 엉망이 된다.

이 예제는 정석 해법을 쓴다. MCU RAM에 fb[1024]를 두고 그리기 함수는 fb만 고친다. 한 프레임을 다 그리면 oled_flush()가 1024바이트를 한 번에 보낸다.

  • SSD1306의 I2C 프레임: 주소 바이트 → 제어 바이트(0x00 명령 / 0x40 데이터) → 명령 또는 표시 데이터.
  • 이 프레임이 HAL_I2C_Mem_Write의 "장치 주소 → 메모리 주소 → 데이터" 모양과 같다는 점을 이용한다.
  • 페이지(8줄) × 열(128) 구조와 수평 주소 지정 모드를 이해한다.
  • I2C 속도로 최대 FPS를 계산하고, 측정값과 비교한다.

앞 예제 05_I2C_MPU6050_DMA_c는 DMA로 논블로킹 전송을 했다. 이 예제는 다시 블로킹 전송을 쓴다. 구조를 먼저 이해하고, 나중에 DMA로 바꾸는 것이 실험 과제이다.

회로 연결도

Nucleo와 OLED 모듈 사이에는 선 네 가닥(3.3V, GND, SCL, SDA)만 있다. SCL·SDA는 오픈 드레인 선이므로 3.3V로 가는 풀업 저항이 반드시 한 쌍 있어야 한다. SSD1306을 I2C 모드로 고정하는 BS 핀, 주소를 고르는 SA0(D/C#) 핀, 리셋 회로는 모듈 기판 안에서 이미 처리되어 있다.

2. I2C 프레임과 제어 바이트

I2C 버스는 SCL(클럭)과 SDA(데이터) 두 선이다. 둘 다 오픈 드레인이라서 장치는 선을 Low로 끌어내리기만 하고, High는 풀업 저항이 만든다. 마스터(STM32)가 START를 만들고, 7비트 주소와 R/W 비트를 보내고, 매 바이트 뒤 9번째 클럭에서 받는 쪽이 SDA를 Low로 당겨 ACK를 준다.

주소 바이트

SSD1306의 7비트 주소는 0b011110 SA0이다. 대부분의 모듈은 SA0 = 0으로 묶여 있어 0x3C이고, 일부는 0x3D이다. 버스에 실리는 첫 바이트는 7비트 주소를 왼쪽으로 1비트 밀고 R/W를 붙인 값이다.

3. GDDRAM 구조와 초기화 명령

페이지 × 열

SSD1306의 화면 램(GDDRAM)은 128열 × 8페이지이다. 한 페이지는 세로 8줄이고, 한 바이트는 한 열의 세로 8픽셀이다. LSB(bit 0)가 위쪽이다.

그림 1. GDDRAM. 수평 주소 지정 모드에서 바이트는 PAGE0의 열 0 → 127, PAGE1의 열 0 → 127 … 순서로 채워진다. 이 순서가 fb[]의 배열 순서와 같다.

페이지 = y >> 3 비트 = y & 7 fb 인덱스 = (y >> 3) × 128 + x 마스크 = 1 << (y & 7)

주소 지정 모드와 창

명령 0x20 뒤의 값이 주소 지정 모드를 고른다. 리셋 값은 페이지 모드(0x02)이다. 페이지 모드에서는 열 127 다음에 같은 페이지의 열 0으로 돌아가므로, 페이지마다 위치를 다시 지정해야 한다. 이 예제는 수평 모드(0x00)를 쓴다. 열 끝에 닿으면 다음 페이지로 넘어가므로 1024바이트를 한 번에 보낼 수 있다.

0x21(열 시작/끝)과 0x22(페이지 시작/끝)는 쓰기 창을 정한다. 이 명령은 내부 주소 포인터도 창의 시작점으로 되돌린다. oled_flush()가 매 프레임 창을 다시 설정하는 이유이다. 앞선 전송이 중간에 실패해도 다음 프레임은 (0, 0)부터 시작한다.

6. HAL이 대신 해 주는 일

HAL_I2C_Mem_Write(&hi2c1, 0x78, 0x40, I2C_MEMADD_SIZE_8BIT, fb, 1024, 200) 한 줄이 하는 일을 RM0008의 마스터 송신 이벤트(EV5, EV6, EV8, EV8_2)로 풀면 다음과 같다.

  1. 1
    버스가 비기를 기다린다SR2.BUSY = 0 대기. 최대 25 ms(I2C_TIMEOUT_BUSY_FLAG). 넘으면 HAL_BUSY.
  2. 2
    START CR1.START = 1SR1.SB = 1 대기 (EV5).
  3. 3
    주소 바이트 0x78 송신 DR = 0x78슬레이브가 ACK하면 SR1.ADDR = 1 (EV6). NACK이면 SR1.AF = 1 → HAL이 STOP을 내고 HAL_ERROR(ErrorCode = AF).
  4. 4
    ADDR 지우기SR1 읽기 → SR2 읽기 (__HAL_I2C_CLEAR_ADDRFLAG).
  5. 5
    "메모리 주소" = 제어 바이트 0x40 송신 TXE 대기 → DR = 0x40SSD1306은 이 바이트로 "이후는 데이터"임을 안다.
  6. 6
    데이터 1024바이트 TXE 대기 → DR = fb[i]바이트마다 SR1.TXE를 폴링한다(EV8). BTF도 서 있으면 한 바이트를 더 쓴다.
  7. 7
    마지막 바이트 완료 후 STOP BTF 대기 → CR1.STOP = 1EV8_2. 상태를 READY로 돌리고 HAL_OK.
타임아웃의 의미

F1 HAL은 함수 시작 시각(tickstart)을 한 번 잡고 모든 플래그 대기를 그 시각 기준으로 잰다. 그래서 Timeout = 200은 "바이트당 200 ms"가 아니라 트랜잭션 전체에 200 ms이다. 400 kHz에서 약 24 ms, 100 kHz에서도 약 93 ms라서 200 ms 안에 끝난다. 명령 전송(oled_cmds)은 가장 긴 초기화도 명령 25바이트라 100 ms면 충분하다.

  • HAL_I2C_MspInit()(stm32f1xx_hal_msp.c)은 PB6/PB7을 AF 오픈 드레인(GPIO_MODE_AF_OD)으로 설정하고 I2C1 클럭을 켠다. PB6/PB7은 I2C1의 기본 핀이라 리맵이 필요 없다.
  • 내부 풀업은 쓰지 않는다. 풀업은 모듈의 저항(보통 4.7 kΩ~10 kΩ)이나 외부 저항이 맡는다.
  • HAL 함수는 hi2c1.State와 __HAL_LOCK으로 동시 호출을 막는다. 블로킹 함수이므로 반환될 때 버스는 이미 STOP 상태이다.

main.c — SSD1306 저수준 (USER CODE BEGIN 0)
#define OLED_ADDR (0x3C << 1)
#define OLED_W 128
#define OLED_H 64
static uint8_t fb[OLED_W * OLED_H / 8];

static HAL_StatusTypeDef oled_cmds(const uint8_t *c, uint16_t n)
{
    return HAL_I2C_Mem_Write(&hi2c1, OLED_ADDR, 0x00,
             I2C_MEMADD_SIZE_8BIT, (uint8_t *)c, n, 100);
             /* 제어 바이트 0x00 = 명령 */
}

static HAL_StatusTypeDef oled_flush(void)
{
    static const uint8_t win[] =
        { 0x21, 0, OLED_W - 1, 0x22, 0, 7 };
    if (oled_cmds(win, sizeof win) != HAL_OK)
        return HAL_ERROR;
    return HAL_I2C_Mem_Write(&hi2c1, OLED_ADDR, 0x40,
             I2C_MEMADD_SIZE_8BIT, fb, sizeof fb, 200);
             /* 제어 바이트 0x40 = 데이터 */
}
  1. OLED_ADDR는 0x78이다. HAL은 시프트된 주소를 받는다.
  2. oled_cmds는 제어 바이트 0x00 뒤에 명령 n개를 한 트랜잭션으로 보낸다. 초기화 명령 25바이트도 한 번에 간다.
  3. oled_flush는 두 트랜잭션이다. ① 창을 열 0~127, 페이지 0~7로 다시 잡아 포인터를 (0, 0)으로 돌린다. ② 1024바이트를 보낸다.
  4. (uint8_t *)c는 HAL 원형이 const를 받지 않아서 넣은 캐스트이다. 블로킹 송신은 버퍼를 읽기만 한다.
main.c — 그리기 (프레임버퍼만 수정)
static void px(int x, int y, int on)
{
    if ((unsigned)x >= OLED_W || (unsigned)y >= OLED_H) return;
    uint8_t *b = &fb[(y >> 3) * OLED_W + x];
    if (on) *b |= (uint8_t)(1u << (y & 7));
    else    *b &= (uint8_t)~(1u << (y & 7));
}

static void line(int x0, int y0, int x1, int y1)   /* Bresenham */
{
    int dx = |x1-x0|, sx = x0 < x1 ? 1 : -1;
    int dy = -|y1-y0|, sy = y0 < y1 ? 1 : -1;  /* dy 는 음수 */
    int err = dx + dy;
    for (;;) {
        px(x0, y0, 1);
        if (x0 == x1 && y0 == y1) break;
        int e2 = 2 * err;
        if (e2 >= dy) { err += dy; x0 += sx; }
        if (e2 <= dx) { err += dx; y0 += sy; }
    }
}
  1. (unsigned)x >= OLED_W 한 번의 비교로 음수와 128 이상을 함께 거른다. 음수를 unsigned로 바꾸면 아주 큰 수가 되기 때문이다. 공이 화면 밖으로 나가도 메모리를 깨지 않는다.
  2. 인덱스와 마스크는 3절의 식 그대로이다. 픽셀 하나를 바꾸려면 같은 바이트의 다른 7비트를 지키는 읽기-수정-쓰기가 필요하다. 이것이 프레임버퍼가 필요한 진짜 이유이다. SSD1306은 I2C로 GDDRAM을 읽을 수 없다.
  3. Bresenham은 정수 덧셈만으로 직선을 그린다. (위 인용에서 |…|는 원본의 삼항 연산자를 줄여 쓴 것이다.)
main.c — 3×5 글꼴
/* 한 글자 = 5행, 각 행 3비트 (bit2 = 왼쪽 픽셀) */
{'0',{7,5,5,5,7}}, {'1',{2,6,2,2,7}}, ...
{'F',{7,4,6,4,4}}, {'P',{7,5,7,4,4}}, {'S',{7,4,7,1,7}},

static void text(int x, int y, int scale, const char *s)
{
  for (; *s; s++, x += 4 * scale)   /* 폭 3 + 간격 1 */
    ... if ((row[r] >> (2 - c)) & 1)
          fill_rect(x + c*scale, y + r*scale, scale, scale, 1);
}
  1. '0'의 첫 행 7 = 111, 둘째 행 5 = 101이다. 세로로 쌓으면 숫자 0 모양이 된다.
  2. scale배 확대는 픽셀 하나를 scale×scale 사각형으로 칠하는 것이다. 프레임 번호는 3배(12×15 픽셀), FPS 줄은 2배이다.
  3. 표에 없는 글자는 그리지 않고 자리만 넘긴다.
main.c — 초기화와 메인 루프 (USER CODE BEGIN 2, 3)
if (oled_init() != HAL_OK) {

int bx = 20, by = 20, vx = 2, vy = 1;
uint32_t frame = 0, fps = 0, frames_this_sec = 0,
         t_sec = HAL_GetTick();

while (1)
{
    memset(fb, 0, sizeof fb);
    rect(0, 0, OLED_W, OLED_H);
    line(0, 0, 127, 63);  line(0, 63, 127, 0);

    bx += vx; by += vy;            /* 공 4x4 */
    if (bx < 2 || bx > OLED_W - 6) { vx = -vx; bx += vx; }
    if (by < 2 || by > OLED_H - 6) { vy = -vy; by += vy; }
    fill_rect(bx, by, 4, 4, 1);

    snprintf(buf, sizeof buf, "%lu", frame);
    text(6, 6, 3, buf);
    snprintf(buf, sizeof buf, "FPS %lu", fps);
    text(6, 46, 2, buf);

    if (oled_flush() != HAL_OK) {
        HAL_UART_Transmit(&huart2, "flush error\r\n", 13, 100);
        HAL_Delay(100);
    }
    frame++; frames_this_sec++;
    if (HAL_GetTick() - t_sec >= 1000) {
        t_sec += 1000;
        fps = frames_this_sec; frames_this_sec = 0;
        /* "FPS = n\r\n" 을 UART 로 */
    }
}
  1. 초기화가 실패하면(대개 NACK) UART에 원인을 남기고 멈춘다. 문자열 길이 41, 13은 실제 길이와 맞다.
  2. 매 프레임 fb를 0으로 지우고 처음부터 다시 그린다. 지우기·다시 그리기가 단순하고 확실하다.
  3. 공은 x 2~122, y 2~58 안에서 튕긴다. 4×4 크기를 더해도 테두리(0, 127, 63)를 넘지 않는다.
  4. FPS는 1초 동안 보낸 프레임 수이다. t_sec += 1000으로 누적 오차 없이 1초 경계를 센다.
  5. 전송이 실패해도 멈추지 않는다. 다음 프레임의 창 설정이 포인터를 (0, 0)으로 되돌리므로 화면은 스스로 복구된다.

ISR과 HAL 콜백

구분이 예제설명
I2C ISR (I2C1_EV_IRQHandler, I2C1_ER_IRQHandler)없음블로킹 폴링 전송이라 I2C 인터럽트를 켜지 않는다. stm32f1xx_it.c에도 I2C 핸들러가 없다.
HAL 콜백 (HAL_I2C_MemTxCpltCallback 등)없음콜백은 _IT/_DMA 함수를 쓸 때 ISR 안에서 HAL이 부르는 사용자 함수이다.
ISR SysTick_Handler사용1 ms마다 HAL_IncTick()을 부른다. HAL의 타임아웃과 FPS 계산의 HAL_GetTick()이 이것에 의존한다.
DMA로 바꾸면

HAL_I2C_Mem_Write_DMA()를 쓰면 1024바이트를 DMA1 채널 6(I2C1_TX)이 옮긴다. 완료 시 DMA ISR(DMA1_Channel6_IRQHandler)과 I2C 이벤트 ISR을 거쳐 HAL이 콜백 HAL_I2C_MemTxCpltCallback()을 부른다. 콜백이 오기 전에는 fb를 고치면 안 되므로, 버퍼 두 개를 번갈아 쓰거나 콜백에서 플래그를 세운다. 오류 복구는 04 예제를 참고한다.

8. 실험

실험 A. FPS와 I2C 속도

CubeMX에서 I2C1 속도를 100 kHz로 바꾸어 다시 생성하고 UART의 FPS = n을 비교한다. 기대 결과: FPS가 약 1/4로 떨어진다. 이론 상한은 400 kHz에서 약 42, 100 kHz에서 약 10.7이다(시뮬레이터 참고). 측정값이 상한보다 조금 낮은 이유를 상승 시간, 바이트 사이 소프트웨어 지연, 그리기 시간으로 설명한다.

실험 B. 주소 실수 재현

OLED_ADDR를 0x3C로 바꾼다. 기대 결과: oled_init()이 HAL_ERROR를 반환하고 UART에 OLED not found at 0x3C가 찍힌다. 로직 분석기가 있으면 첫 바이트 0x3C 뒤 9번째 클럭에서 SDA가 High(NACK)인 것을 본다. hi2c1.ErrorCode는 HAL_I2C_ERROR_AF이다.

실험 C. 픽셀 좌표 확인

루프를 멈추고 px(0,0,1), px(0,7,1), px(0,8,1)만 그린 뒤 flush한다. 디버거로 fb[0] = 0x81, fb[128] = 0x01인지 확인한다. 화면에서 세 점의 위치를 시뮬레이터와 비교한다.

실험 D. 방향 명령 바꾸기

초기화 표의 0xA1을 0xA0으로, 다음에는 0xC8을 0xC0으로 바꾼다. 기대 결과: 숫자가 각각 좌우, 상하로 뒤집힌다. 대각선은 어느 쪽으로 뒤집어도 같은 X 모양이라 숫자로 판단한다.

실험 E. 부분 갱신

FPS 줄(y = 46~55)만 바꾸는 경우를 생각한다. 이 줄은 페이지 5~6에 걸친다. 창을 0x22, 5, 6으로 잡고 &fb[5*128]부터 256바이트만 보낸다. 기대 결과: 전송 바이트가 1/4로 줄어 갱신 시간이 약 6 ms가 된다. 프레임 번호처럼 다른 페이지에 있는 그림은 갱신되지 않는다는 점도 확인한다.

10. 확인 문제

문제 1. 픽셀 (x, y) = (10, 21)을 켜려면 fb의 몇 번째 바이트의 어느 비트를 1로 만드는가?

페이지 = 21 >> 3 = 2, 비트 = 21 & 7 = 5. 인덱스 = 2 × 128 + 10 = 266. fb[266] |= 0x20이다. 시뮬레이터의 기본 선택값으로 확인할 수 있다.

문제 2. OLED_ADDR를 0x3C로 정의하면 버스에는 어떤 주소가 실리고, HAL은 무엇을 반환하는가?

첫 바이트가 0x3C = 0011 1100이므로 7비트 주소 0x1E, 쓰기로 해석된다. 응답하는 장치가 없어 9번째 클럭에서 NACK, SR1.AF = 1이 된다. HAL은 STOP을 내고 HAL_ERROR를 반환하며 ErrorCode에 HAL_I2C_ERROR_AF를 남긴다.

문제 3. SSD1306에는 레지스터 주소가 없는데 왜 HAL_I2C_Mem_Write를 쓸 수 있는가?

Mem_Write는 [주소+W] [메모리 주소 1바이트] [데이터…]를 한 트랜잭션으로 보낸다. SSD1306 프레임은 [주소+W] [제어 바이트] [데이터…]이므로 바이트 순서가 같다. 메모리 주소 자리에 제어 바이트를 넣으면 된다.

문제 4. 100 kHz에서 이론상 최대 FPS는 얼마인가? (바이트당 9클럭, 명령 8바이트 + 데이터 1026바이트)

(8 + 1026) × 9 ≈ 9306클럭. 100 kHz에서 약 93 ms이므로 최대 약 10.7 FPS이다. 400 kHz(실제 약 395 kHz)에서는 약 23.6 ms, 약 42 FPS이다.

문제 5. 왜 픽셀을 바꿀 때마다 바로 OLED에 쓰지 않고 프레임버퍼를 두는가?

한 바이트가 세로 8픽셀이라 한 픽셀만 바꾸려 해도 나머지 7비트의 현재 값을 알아야 한다. SSD1306은 I2C로 GDDRAM을 읽을 수 없으므로 MCU가 사본을 가지고 있어야 한다. 또한 바이트마다 트랜잭션을 만들면 주소·제어 바이트 오버헤드가 커진다.

문제 6. 이 예제에서 HAL_GetTick()이 증가하는 곳은 어디이며, 왜 I2C 콜백은 없는가?

SysTick_Handler(ISR)가 1 ms마다 HAL_IncTick()을 부른다. I2C는 블로킹 폴링 함수만 쓰므로 I2C 인터럽트가 없고, ISR이 부르는 HAL 콜백도 없다.

문제 7. 제어 바이트로 0x80을 쓰면 무엇이 달라지는가?

Co = 1이므로 명령 한 바이트만 오고, 그 뒤에는 다시 제어 바이트가 와야 한다. 명령마다 제어 바이트를 붙이는 방식이다. 0x00(Co = 0)은 STOP까지 모두 명령이므로 이 예제처럼 명령을 한 번에 이어 보낼 수 있다.

정리

  • SSD1306 I2C 프레임은 주소(0x78) → 제어 바이트(0x00 명령 / 0x40 데이터) → 바이트들이다. HAL의 Mem_Write 모양과 같다.
  • GDDRAM은 8페이지 × 128열, 한 바이트 = 세로 8픽셀(LSB 위). 인덱스 = (y>>3)×128 + x.
  • 수평 모드와 창 명령(0x21, 0x22) 덕분에 1024바이트를 한 번에 보낼 수 있다.
  • 400 kHz에서 한 프레임 약 24 ms, 최대 약 40 FPS이다. 더 빠르게 하려면 SPI나 부분 갱신, CPU를 비우려면 DMA를 쓴다.

근거: 06_I2C_OLED_SSD1306_c 소스(main.c, stm32f1xx_hal_msp.c, .ioc)와 STM32CubeF1 HAL(stm32f1xx_hal_i2c.c/.h). 계층: HAL. 레지스터·비트 이름은 RM0008(STM32F101xx~F107xx 레퍼런스 매뉴얼), 명령 값은 SSD1306 데이터시트 기준이다. 클럭은 SYSCLK 64 MHz(HSI/2 × PLL16), APB1 ÷2 = 32 MHz 구성을 기준으로 한다. 코드는 해당 폴더의 소스에서 발췌한 것이며 일부 줄이 생략·축약되어 있다.
