DS3231 외장 RTC: 레지스터 7바이트로 시각을 읽는다

DS3231은 I2C로 연결하는 시계 칩이다. 시각은 BCD 형식으로 레지스터 0x00~0x06에 들어 있고, 마스터는 그 7바이트를 한 번에 읽는다. 이 예제설명은 HAL_I2C_Mem_Read가 버스에 내보내는 바이트 순서를 하나씩 따라가고, BCD 변환, 온도 레지스터의 2의 보수 형식, 전원이 끊겼음을 알리는 OSF 플래그를 08_I2C_DS3231_RTC_c 예제 코드로 확인한다.

1. 문제: 보드 전원이 꺼져도 시계는 가야 한다

데이터 로거는 "지금이 몇 시인가"를 알아야 한다. SysTick은 리셋하면 0부터 다시 센다. F103의 내부 RTC(06_Timers_RTC/13_RTC_Calendar_c)는 VBAT 핀에 전지를 달면 시각을 유지하지만, 정확도는 32.768 kHz 크리스털에 달려 있다. 크리스털 주파수는 온도에 따라 변한다.

DS3231은 크리스털과 온도 보상 회로(TCXO)를 칩 안에 넣었다. 데이터시트 기준으로 0~+40 °C에서 ±2 ppm이다. 하루 ±0.17초, 1년 약 ±1분이다. 모듈(ZS-042 등)에는 코인 셀 홀더가 있어서 보드 전원을 빼도 시각이 계속 간다.

이 예제설명의 목표
  • HAL_I2C_Mem_Read가 내보내는 S → 주소+W → 레지스터 → Sr → 주소+R → 데이터 → NACK → P를 바이트 단위로 읽는다.
  • HAL 주소 인자가 7비트 주소를 1비트 민 값(0x68 → 0xD0)인 이유를 안다.
  • BCD 형식과 마스크, 0.25 °C 단위 온도 형식, OSF 플래그 기반 부팅 로직을 이해한다.

앞 예제와의 관계. 01_I2C_Scan는 장치가 응답하는지(ACK)만 본다. 04_I2C_MPU6050_c는 같은 Mem_Read 시퀀스로 센서 레지스터를 읽는다. 07_I2C_EEPROM_AT24C_c의 EEPROM은 ZS-042 모듈에 DS3231과 함께 붙어 있다(주소 0x57). 이 예제는 그룹의 마지막 예제이며, 같은 버스에서 "레지스터 맵을 가진 장치"를 다루는 방법을 정리한다.

2. I2C 프레임: Mem_Read 한 번이 내보내는 것

I2C는 SCL(클럭)과 SDA(데이터) 두 선을 쓴다. 두 선 모두 오픈 드레인이다. 장치는 선을 Low로 당기기만 하고, High는 풀업 저항이 만든다. 그래서 여러 장치가 한 버스를 공유해도 충돌로 망가지지 않는다.

  • START(S): SCL이 High일 때 SDA가 High → Low. STOP(P): SCL이 High일 때 SDA가 Low → High. 데이터는 SCL이 Low일 때만 바뀐다.
  • 한 바이트는 MSB부터 8비트, 그 뒤 9번째 클럭에 수신 측이 ACK(SDA=Low) 또는 NACK(SDA=High)를 보낸다.
  • START 직후 첫 바이트는 7비트 주소 + R/W 비트이다. W=0, R=1.

DS3231의 7비트 주소는 1101000b = 0x68이다. 버스에 나가는 첫 바이트는 이것을 왼쪽으로 1비트 밀고 R/W를 붙인 값이다. 쓰기는 0xD0, 읽기는 0xD1이다. HAL은 주소 인자의 bit0을 R/W 자리로 쓰므로, 인자로 미리 민 값을 넘긴다. 그래서 코드는 #define RTC_ADDR (0x68 << 1)이다.

레지스터 읽기 프레임

그림 1. HAL_I2C_Mem_Read(&hi2c1, 0xD0, 0x00, 8BIT, r, 7, 100)의 버스 순서. 마스터는 마지막 바이트 뒤에 NACK을 보내 "더 읽지 않는다"고 알린 뒤 STOP을 낸다.

쓰기(HAL_I2C_Mem_Write)는 반복 START가 없다. S, 0xD0, A, 레지스터 번호, A, 데이터, A, 데이터, A, …, P 순서이고, 데이터 바이트마다 DS3231이 ACK를 보낸다.

한 바이트 = 9클럭 = 90 µs (100 kHz) 시각 읽기(7바이트): 주소 2 + 레지스터 1 + 데이터 7 = 10바이트 → 90클럭 ≈ 0.9 ms (+ START/Sr/STOP) 온도 읽기(2바이트): 5바이트 → 45클럭 ≈ 0.45 ms

짧지만 이 동안 CPU는 HAL 함수 안에서 플래그를 기다린다(블로킹). DMA 방식은 05_I2C_MPU6050_DMA_c에서 다룬다.

3. DS3231 레지스터 맵

DS3231 안에는 0x00~0x12까지 19개의 8비트 레지스터가 있다. 마스터가 레지스터 번호를 쓰면 내부 레지스터 포인터가 그 번호로 간다. 이후 한 바이트를 읽거나 쓸 때마다 포인터가 1씩 증가한다. 그래서 0x00부터 7바이트를 읽으면 초~년이 한 번에 온다.

BCD: 사람이 읽기 좋은 16진수

BCD(Binary-Coded Decimal)는 십진수 한 자리를 4비트에 넣는다. 59초는 이진수 0x3B가 아니라 0x59로 저장된다. 16진수로 찍으면 그대로 사람이 읽는 숫자가 된다.

0x59 = 0101 1001b → 상위 니블 5(십의 자리), 하위 니블 9(일의 자리) bcd2bin(x) = (x >> 4) × 10 + (x & 0x0F) bin2bcd(v) = ((v / 10) << 4) | (v % 10)

마스크는 BCD 숫자가 아닌 비트를 지운다. 시 레지스터의 bit6은 12/24 선택, 월 레지스터의 bit7은 세기(Century) 비트이다. 이 비트들이 남아 있으면 bcd2bin이 엉뚱한 값을 낸다. 예를 들어 연도가 99에서 00으로 넘어가면 Century 비트가 1이 되어 월이 0x81처럼 읽힌다. & 0x1F가 이것을 지운다.

시각을 한 번에 읽어야 하는 이유

데이터시트에 따르면 DS3231은 읽기 중 시각이 넘어가 생기는 오류를 막으려고 보조(사용자) 버퍼를 둔다. I2C START가 올 때 내부 시각이 이 버퍼로 복사되고, 마스터는 버퍼를 읽는다. 한 번의 START로 7바이트를 연속으로 읽으면 7바이트가 모두 같은 순간의 값이다.

반대로 1바이트씩 7번 읽으면 START가 7번 나가고 그때마다 새 값이 복사된다. 23:59:59.9998에 초를 읽고(59), 그 사이 자정이 지나 분·시를 읽으면(00, 00) 결과는 00:00:59가 된다. 4절 시뮬레이터에서 이 현상을 재현할 수 있다.

쓰기에도 규칙이 있다. 데이터시트 기준으로 초 레지스터를 쓰면 내부 1초 분주 체인이 리셋되고, 나머지 시각 레지스터는 1초 안에 써야 한다. 이 예제는 0x00~0x06을 한 번의 Mem_Write로 써서 두 조건을 모두 만족한다.

OSF: 시각을 믿어도 되는가

상태 레지스터의 bit7 OSF(Oscillator Stop Flag)는 발진기가 멈춘 적이 있으면 1이 된다. 데이터시트가 드는 원인은 처음 전원을 넣었을 때, VCC와 VBAT가 모두 부족했을 때, 배터리 구동 중 EOSC로 발진기를 껐을 때 등이다. OSF는 하드웨어가 지우지 않는다. 소프트웨어가 0을 써야 지워진다. 그래서 "OSF=1이면 시각을 다시 설정하고 OSF를 지운다"가 표준 부팅 로직이다.

온도: 0.25 °C 단위의 10비트 2의 보수

DS3231은 온도 보상을 위해 칩 온도를 잰다. 그 값을 0x11(MSB)과 0x12(LSB의 bit7:6)로 읽을 수 있다. 두 바이트를 이으면 0.25 °C 단위의 10비트 2의 보수이다.

4. 직접 만져 보기

아래 시뮬레이터는 DS3231 레지스터, 예제의 부팅 로직과 1초 루프, 그때 버스에 오가는 바이트를 함께 보여 준다. RTC는 실제 시간에 맞춰 흐른다.

  1. 루프마다 생기는 시각 7바이트와 온도 2바이트 읽기를 본다. 바이트를 누르면 SCL/SDA 파형이 그려진다.

  4. 롤오버 직전 읽기: 한 번에 읽기와 1바이트씩 읽기의 결과를 비교한다.
  5. 칩 온도 −0.25 °C → CONV=1 → 수정 전 출력식을 켜고 끈다.

5. I2C1 레지스터 분석

PB6(SCL), PB7(SDA)은 HAL_I2C_MspInit에서 대체 기능 오픈 드레인(GPIO_MODE_AF_OD)으로 설정된다. 푸시풀이면 ACK 때 STM32와 DS3231이 동시에 SDA를 구동해 충돌한다. I2C1은 APB1(PCLK1 = 32 MHz)에 연결된다.

6. HAL이 대신 해 주는 일

HAL_I2C_Init

HAL_I2C_MspInit(GPIOB 클럭, PB6/PB7 = AF_OD, RCC_APB1ENR.I2C1EN)을 부른 뒤 CR1.PE = 0, CR1.SWRST = 1 → 0으로 주변 장치를 리셋한다. 이어서 HAL_RCC_GetPCLK1Freq()로 PCLK1을 읽어 5절 표의 CR2.FREQ, TRISE, CCR, CR1(ENGC/NOSTRETCH), OAR1, OAR2를 쓰고 마지막에 CR1.PE = 1로 켠다.

HAL_I2C_Mem_Read: 앞부분 (공통)

  1. 1
    SR2.BUSY가 0이 될 때까지 대기최대 25 ms실패하면 HAL_BUSY. 버스가 걸려 있으면 여기서 막힌다
  2. 2
    CR1.POS = 0, CR1.ACK = 1, CR1.START = 1 → SB 대기 → DR = 0xD0EV5: SB는 SR1을 읽고 DR에 쓰면 지워진다
  3. 3
    ADDR 대기 (AF면 STOP 내고 HAL_ERROR)장치가 없거나 주소가 틀리면 여기서 끝난다. ErrorCode = AF
  4. 4
    ADDR 지움 → TXE 대기 → DR = 레지스터 번호 → TXE 대기8비트 레지스터 주소(I2C_MEMADD_SIZE_8BIT)이므로 한 바이트
  5. 5
    CR1.START = 1 (반복 START) → SB 대기 → DR = 0xD1 → ADDR 대기여기서부터 읽기 방향이다

HAL_I2C_Mem_Read: 뒷부분 (읽을 바이트 수에 따라 다르다)

F1의 I2C는 마지막 바이트 뒤에 NACK을 보내려면 그 바이트를 받기 전에 ACK=0을 써 두어야 한다. 그래서 HAL은 남은 바이트 수에 따라 다른 순서를 쓴다. 이 예제는 세 경우를 모두 쓴다.

Size = 1 (상태 0x0F)부팅 시 1회

ACK = 0 → 인터럽트 끔 → ADDR 지움 → STOP = 1 → 인터럽트 켬 → RXNE 대기 → DR 읽기.

Size = 2 (온도 0x11~0x12)매 루프

POS = 1 → 인터럽트 끔 → ADDR 지움 → ACK = 0 → 인터럽트 켬 → BTF 대기(두 바이트 도착) → STOP = 1 → DR 두 번 읽기.

Size = 7 (시각 0x00~0x06)매 루프

ACK = 1, ADDR 지움 → RXNE마다 읽기 → 3바이트 남으면 BTF 대기 → ACK = 0 → 읽기 → BTF 대기 → STOP = 1 → 마지막 두 바이트 읽기.

"인터럽트 끔"은 ADDR 지우기와 STOP 설정 사이에 다른 인터럽트가 끼어들지 않게 하려는 것이다(HAL 소스 주석).

HAL_I2C_Mem_Write

BUSY 대기 → START → 0xD0 → ADDR → 레지스터 번호 → 바이트마다 TXE 대기 후 DR 쓰기 → BTF 대기 → STOP. 데이터 바이트에 NACK이 오면(AF) STOP을 내고 HAL_ERROR를 돌려준다.

Timeout 인자

마지막 인자 100은 함수 전체에 대한 ms 제한이다(시작 때 HAL_GetTick()을 기억해 각 대기에서 비교). 첫 BUSY 대기만 25 ms 고정(I2C_TIMEOUT_BUSY_FLAG)이다.

7. 코드 읽기

ISR과 콜백

ISR: 주변 장치 인터럽트는 없다. 실행되는 ISR은 stm32f1xx_it.c의 SysTick_Handler 하나이며, 1 ms마다 HAL_IncTick()으로 HAL_Delay와 I2C 타임아웃의 시간 기준을 만든다.

HAL 콜백: HAL_I2C_MemRxCpltCallback 등은 _IT/_DMA 함수에서만 불린다. 이 예제의 호출은 모두 블로킹이라 콜백은 하나도 불리지 않는다(콜백 방식은 05_I2C_MPU6050_DMA_c).

main.c — 주소와 BCD 변환 (USER CODE PD, 0)
#define RTC_ADDR (0x68 << 1)

static uint8_t bin2bcd(uint8_t v)
{ return (uint8_t)(((v / 10) << 4) | (v % 10)); }
static uint8_t bcd2bin(uint8_t v)
{ return (uint8_t)((v >> 4) * 10 + (v & 0x0F)); }
  1. RTC_ADDR = 0xD0. HAL이 읽기 때 bit0을 1로 바꿔 0xD1을 보낸다.
  2. bin2bcd(59) = (5 << 4) | 9 = 0x59.
  3. bcd2bin(0x59) = 5 × 10 + 9 = 59.

실험 B. 전원을 끊었다 켠다

코인 셀을 둔 채 USB를 뺐다가 꽂는다. 다음에는 코인 셀을 빼고 같은 일을 한다.

실험 D. 칩을 손가락으로 데운다

10. 확인 문제

문제 1. 7비트 주소가 0x68인 장치에 HAL로 쓸 때 주소 인자는? 버스에 나가는 첫 바이트는 읽기와 쓰기에서 각각 무엇인가?

인자는 0x68 << 1 = 0xD0이다. 쓰기 때 첫 바이트는 0xD0, 읽기 때는 0xD1이다. Mem_Read는 쓰기 단계(0xD0)와 읽기 단계(0xD1)를 모두 내보낸다.

문제 2. 분 레지스터에서 0x47을 읽었다. 몇 분인가? 이진수 0x47(=71)과 무엇이 다른가?

BCD이므로 상위 니블 4, 하위 니블 7 → 47분이다. bcd2bin(0x47) = 4 × 10 + 7 = 47. 이진수로 해석한 71은 틀린 값이다.

문제 3. 0x11 = 0xFD, 0x12 = 0x80이다. 온도는? 원래 출력식은 무엇을 찍었는가?

(int8_t)0xFD = −3, 0x80 >> 6 = 2 → +0.50. 온도는 −3 + 0.5 = −2.50 °C이다. t100 = −250이고, 원래 식도 −250/100 = −2, 250 % 100 = 50 → -2.50으로 맞게 찍는다. 원래 식이 틀리는 것은 −1 < T < 0 구간뿐이다.

문제 4. 초·분·시를 각각 Mem_Read(..., 1바이트)로 세 번 읽으면 어떤 문제가 생길 수 있는가?

START마다 보조 버퍼가 새로 복사된다. 초를 읽은 뒤 분이 넘어가면 "59초 + 다음 분"처럼 섞인 값이 나와 최대 1분(자정이면 하루)이 틀린다. 한 번의 START로 7바이트를 연속으로 읽으면 같은 순간의 값이 보장된다.

문제 5. OSF를 지우는 코드를 시각 쓰기 결과와 상관없이 실행하면 어떤 일이 생기는가?

시각 쓰기가 실패해도 OSF가 0이 된다. 다음 부팅에서 코드는 OSF=0을 보고 "시각이 유효하다"고 판단해 다시 설정하지 않는다. 그 결과 2000-01-01 같은 잘못된 시각이 계속 쓰인다. 그래서 쓰기가 성공했을 때만 OSF를 지운다.
