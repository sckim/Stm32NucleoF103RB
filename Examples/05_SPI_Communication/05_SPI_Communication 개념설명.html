SPI: 두 시프트 레지스터가 클럭 한 가닥으로 원을 이루는 방식

SPI(Serial Peripheral Interface, 직렬 주변장치 인터페이스)는 디지털논리에서 배운 시프트 레지스터 두 개를 선 세 가닥으로 이어 원(ring)을 만들고, 한쪽(마스터)이 클럭을 공급해 두 레지스터의 내용을 한 비트씩 맞바꾸는 통신이다. 이 개념설명은 STM32F103RB를 기준으로, CPU가 데이터 레지스터에 쓴 값이 MOSI 핀의 비트열이 되고 같은 클럭에 MISO 핀으로 들어온 비트열이 다시 값이 되기까지의 경로를 RM0008의 원본 블록도 위에서 따라간다.

1. 문제 정의: SPI가 없으면 CPU가 무엇을 직접 해야 하는가

디스플레이, 플래시 메모리, SD 카드, LED 드라이버처럼 많은 데이터를 빠르게 주고받는 칩은 대개 클럭 선을 함께 주는 직렬 방식을 쓴다. 클럭이 있으므로 USART처럼 양쪽이 속도를 미리 약속하거나 비트 한가운데를 찾을 필요가 없다. 받는 쪽은 클럭 엣지에서 데이터 선을 읽기만 하면 된다. 그래도 SPI 하드웨어가 없다면 CPU가 GPIO 핀 서너 개로 이 일을 모두 해야 한다(비트뱅잉).

2. 일반 개념

동기식 직렬 통신, 마스터와 슬레이브

"동기식"은 데이터 선 옆에 클럭 선이 따로 있다는 뜻이다. 데이터는 클럭의 한쪽 엣지에서 바뀌고 반대쪽 엣지에서 읽힌다. 클럭을 만드는 쪽이 마스터, 클럭을 받는 쪽이 슬레이브이다. 통신은 언제나 마스터가 시작한다. 슬레이브는 보낼 것이 있어도 마스터가 클럭을 줄 때까지 기다려야 한다. 그래서 슬레이브는 정확한 발진기가 필요 없고, 속도는 마스터가 정한다.

  • SCK(Serial Clock): 마스터 출력, 슬레이브 입력.
  • MOSI(Master Out Slave In): 마스터 → 슬레이브 데이터.
  • MISO(Master In Slave Out): 슬레이브 → 마스터 데이터.
  • NSS / CS(Slave Select / Chip Select): 마스터가 Low로 내려 "지금 너와 통신한다"를 알린다. 선택되지 않은 슬레이브는 MISO를 놓아야 한다.

전이중 교환: 두 시프트 레지스터가 이루는 원

RM0008은 이 연결을 이렇게 설명한다. "When the master device transmits data to a slave device via the MOSI pin, the slave device responds via the MISO pin. This implies full-duplex communication with both data out and data in synchronized with the same clock signal"(25.3.1, p.703). 디지털논리로 보면 16단(8 + 8) 순환 시프트 레지스터이다. 클럭 8번이 지나면 두 레지스터의 내용이 정확히 맞바뀐다. 여기서 두 가지 결론이 나온다.

  • 읽으려면 써야 한다. 마스터가 슬레이브에게서 한 바이트를 받으려면 한 바이트를 내보내야 클럭 8개가 생긴다. 보낼 내용이 없으면 의미 없는 값(더미, 흔히 0xFF)을 보낸다.
  • 보내면 반드시 받는다. 송신만 하고 싶어도 MISO 쪽에서 무언가가 들어온다. 읽지 않고 두면 수신 버퍼가 넘친다(7장 시나리오 ③의 OVR).
원 시뮬레이터: 클럭 한 번에 한 비트씩 자리를 바꾼다

네 가지 모드: CPOL은 극성 반전, CPHA는 엣지 선택

장치마다 "유휴 때 클럭이 Low인가 High인가", "첫 엣지에서 읽는가 둘째 엣지에서 읽는가"가 다르다. 이 두 가지를 고르는 비트가 CPOL과 CPHA이다(RM0008 25.3.1, p.704).

  • CPOL(Clock Polarity): 0이면 유휴 SCK = Low, 1이면 High. 디지털논리로는 내부 클럭과 CPOL의 XOR이다. 극성만 뒤집을 뿐 엣지 개수와 간격은 같다.
  • CPHA(Clock Phase): 0이면 첫 번째 엣지가 첫 비트(MSB)를 잡는 샘플 엣지, 1이면 두 번째 엣지가 샘플 엣지이다. 샘플하지 않는 나머지 엣지에서 다음 비트로 바뀐다. CPHA = 0이면 첫 엣지 전에 이미 첫 비트가 선 위에 나와 있어야 하므로, 슬레이브는 NSS가 내려가는 순간 첫 비트를 내놓는다.

(CPOL, CPHA) = (0,0), (0,1), (1,0), (1,1)을 흔히 모드 0, 1, 2, 3이라고 부른다(모드 번호 = 2·CPOL + CPHA). 이 번호는 업계 관례이며 RM0008에는 나오지 않는다. 장치 데이터시트가 모드 번호로 적었으면 이 식으로 CPOL·CPHA를 정한다. 양쪽 설정이 다르면 비트가 한 칸씩 밀려 읽힌다. RM0008은 "Master and slave must be programmed with the same timing mode"라고 적고, CPOL/CPHA를 바꾸기 전에 SPE를 0으로 내리라고 한다(p.704).

3. 내부 구현 블록도

신호를 입력 → 클럭 → 처리 → 플래그/이벤트 → 출력 순서로 따라간다. F103이 마스터, 전이중(BIDIMODE = 0, RXONLY = 0)인 가장 흔한 경우이다.

  1. 1
    입력: MISO 핀 → 방향 선택 상자 → Shift register의 직렬 입력마스터에서 MOSI는 출력, MISO는 입력이다(25.3.3, p.707). 슬레이브이면 반대이다. MISO 핀은 GPIO에서 플로팅 또는 풀업 입력으로 둔다(Table 25, p.167).
  2. 2
    클럭: fPCLK → Baud rate generator(÷2BR+1) → SCK 핀마스터만 클럭을 만든다. 슬레이브에서는 SCK가 입력이고 BR[2:0]은 속도에 영향이 없다(25.3.2, p.706). 4장에서 계산한다.
  3. 3
    처리: DR 쓰기 → Tx buffer → (첫 비트 때) Shift register에 병렬 적재 → 비트마다 시프트"The data byte is parallel-loaded into the shift register (from the internal bus) during the first bit transmission and then shifted out serially to the MOSI pin MSB first or LSB first"(25.3.3). 같은 클럭에 MISO 비트가 반대쪽 끝으로 들어온다.
  4. 4
    플래그/이벤트: TXE, RXNE, BSY, 오류 플래그Tx buffer가 Shift register로 넘어가는 순간 TXE = 1이다. 마지막 샘플 엣지에서 Shift register 값이 Rx buffer로 복사되며 RXNE = 1이다(25.3.5, p.710). 허용된 플래그는 인터럽트나 DMA 요청이 된다(6장).
  5. 5
    출력: Shift register의 직렬 출력 → 방향 선택 상자 → MOSI 핀, 그리고 SCK 핀MOSI와 SCK는 대체 기능(AF, Alternate Function) 푸시풀 출력으로 둔다(Table 25). NSS 핀은 하드웨어 출력(SSOE = 1)으로 쓰지 않으면 GPIO로 쓸 수 있다.

4. 클럭 경로와 시간 계산

f_SCK = f_PCLK / 2^(BR+1) BR[2:0] = 000 … 111 → ÷2, ÷4, ÷8, ÷16, ÷32, ÷64, ÷128, ÷256 (RM0008 25.5.1, p.743) f_PCLK = PCLK2 (SPI1) 또는 PCLK1 (SPI2) 프레임 시간 = 비트 수(8 또는 16) / f_SCK = 비트 수 × 분주비 [PCLK 클럭]

USART의 BRR처럼 소수 분주가 없다. 고를 수 있는 속도가 여덟 개뿐이지만, 클럭을 마스터가 직접 보내므로 상대와 속도가 "조금 달라서" 생기는 오차 문제는 아예 없다. 슬레이브는 받은 클럭에 맞춰 움직일 뿐이다. 다만 슬레이브 칩마다 최대 클럭이 있으므로, 그 값을 넘지 않는 가장 빠른 분주비를 고른다.

  • 송신: TXE가 1이 될 때마다 DMA 요청 → DMA가 DR에 쓰고, 그 쓰기가 TXE를 지운다.
  • 수신: RXNE가 1이 될 때마다 DMA 요청 → DMA가 DR을 읽고, 그 읽기가 RXNE를 지운다.
  • 송신 DMA만 켜면 받은 값을 아무도 읽지 않으므로 OVR이 선다. 문서가 그렇게 명시한다.
  • 송신 DMA가 끝났다(DMA의 TCIF = 1)는 것은 "마지막 값을 DR에 넣었다"는 뜻일 뿐이다. SPI를 끄려면 TXE = 1, 이어서 BSY = 0을 기다린다.

③ CRC: 송신·수신 두 개의 LFSR

  • CPU로 전송할 때: 전이중·송신 전용이면 마지막 데이터를 DR에 쓴 직후 CRCNEXT = 1을 쓴다. 그러면 마지막 데이터 다음에 TXCRCR 값이 나간다. 수신 전용이면 끝에서 두 번째 데이터를 받은 뒤 CRCNEXT를 쓴다. 받은 CRC가 RXCRCR과 다르면 CRCERR이 서고, ERRIE = 1이면 인터럽트가 난다(25.3.6, p.716).
  • DMA로 전송할 때: CRC 송수신이 자동이고 CRCNEXT를 쓰지 않는다. 받은 CRC는 DR을 읽어 RXNE를 지워야 한다(p.721).
  • 정오표 ES096 2.10.1(p.22): 슬레이브에서 CRC를 켜 두면 NSS가 High(선택 안 됨)여도 CRC가 계속 계산된다. 회피책은 선택이 바뀔 때마다 양쪽에서 SPE = 0 → CRCEN = 0 → CRCEN = 1 → SPE = 1로 CRC를 지우는 것이다. RM0008 25.3.6에도 같은 내용이 주석으로 들어가 있다.
  • 정오표 ES096 2.10.2(p.22~23): CRC를 쓰면서 SPI 전송은 소프트웨어(폴링·인터럽트)로 하고, 같은 DMA 채널에 연결된 다른 주변장치가 DMA 전송 중이면 CRCNEXT를 쓰기 전에 CRC가 멈춰 CRC 오류가 날 수 있다. 회피책은 SPI 전송도 DMA로 하는 것이다. 위 채널 표에서 SPI1_RX와 USART3_TX가 같은 채널 2를 쓰는 식의 공유가 이 결함의 조건이다.

하드웨어 CRC는 데이터시트에서 "supports basic SD Card/MMC modes"라고 소개한다(DS5319 2.3.18, p.19). 다만 이 그룹의 예제는 모두 CRC 계산기를 끈 채(CRCEN = 0) 쓴다.

시나리오 ⑥ 마스터가 슬레이브로 밀려나는 경우: MODF

소프트웨어 NSS를 쓰면서 SSI를 0으로 두었거나, 하드웨어 NSS 입력(SSM = 0, SSOE = 0)인 마스터의 NSS 핀이 Low가 되면 다음이 한꺼번에 일어난다(25.3.10, p.721). MODF = 1(ERRIE = 1이면 인터럽트), SPE = 0(모든 출력 차단), MSTR = 0(슬레이브로 강제). 다중 마스터 버스에서 다른 마스터가 나를 선택했을 때 두 마스터가 동시에 SCK·MOSI를 구동하는 충돌을 막는 장치이다. 복구는 SR 읽기(또는 쓰기) → CR1 쓰기로 MODF를 지운 뒤 SPE와 MSTR을 다시 세운다. 이때 NSS 핀은 High여야 한다.

9. 이해 확인 문제

Q1. SPI1, PCLK2 = 64 MHz, BR = 010이다. fSCK는? 1024바이트를 빈틈없이 보내는 데 최소 얼마가 걸리는가?

BR = 010은 ÷8이므로 fSCK = 8 MHz이다. 바이트 하나는 8비트 × 125 ns = 1 µs, 1024바이트는 최소 1.024 ms이다. 소프트웨어가 늦어 프레임 사이에 틈이 생기면 이보다 길어진다(시나리오 ②).

Q2. PCLK2 = 72 MHz일 때 SPI1이 쓸 수 있는 가장 빠른 BR은? RM0008의 "fPCLK/2 max"와 어떻게 맞춰 읽는가?

÷2는 36 MHz로 DS5319 Table 43의 18 MHz를 넘는다. BR = 001(÷4) = 18 MHz가 가장 빠르다. RM0008의 fPCLK/2는 분주기 구조의 상한이고, 전기적으로 보장되는 한계는 데이터시트의 18 MHz이다. 둘 다 만족해야 한다.

Q3. 마스터가 0xA5를, 슬레이브가 0x3C를 시프트 레지스터에 넣고 클럭 8개를 주고받았다. 각 레지스터에는 무엇이 있는가? 슬레이브에게서 3바이트를 읽으려면 마스터는 몇 바이트를 써야 하는가?

두 값이 맞바뀌어 마스터에 0x3C, 슬레이브에 0xA5가 있다(2장 원 시뮬레이터). 클럭은 마스터가 DR에 쓸 때만 나오므로 3바이트를 읽으려면 3바이트(대개 더미)를 써야 한다. 명령 바이트를 먼저 보내는 장치라면 명령 길이만큼 더 쓴다.

Q4. 장치 데이터시트가 "모드 2"를 요구한다. CPOL, CPHA, 유휴 SCK 레벨, 첫 샘플 엣지는?

모드 번호 = 2·CPOL + CPHA라는 관례에 따라 CPOL = 1, CPHA = 0이다. 유휴 SCK는 High이고, 첫 번째 엣지(하강 엣지)가 샘플 엣지이다(RM0008 p.704: CPHA = 0이면 "falling edge if CPOL bit is set"). 모드 번호 자체는 RM0008에 없는 관례이므로 장치 문서의 파형과 Figure 240을 대조해 확인한다.

Q5. 2선 모드(BIDIMODE = 0)로 디스플레이에 100바이트를 보낸 뒤, 같은 SPI로 센서에서 1바이트를 읽었더니 엉뚱한 값이 나왔다. 왜이고, 어떻게 고치는가?

송신하는 동안에도 수신기가 MISO를 받아 두 번째 값부터 OVR이 섰다(p.712). OVR 상태에서는 Rx 버퍼가 새 값으로 갱신되지 않으므로, 읽은 값은 송신 중 첫 번째로 받아 둔 묵은 값이다(25.3.10). 수신을 시작하기 전에 DR 읽기 → SR 읽기로 OVR을 지운다. 송신만 하는 장치에는 단선 양방향 송신(BIDIMODE = 1, BIDIOE = 1)을 쓰면 수신이 일어나지 않는다.

Q6. 마스터로 설정하고 SSM = 1만 켠 채 SPE = 1을 썼더니 SPE와 MSTR이 저절로 0이 되었다. 원인과 복구 방법은?

SSI의 리셋값 0이 내부 NSS로 들어가 "마스터인데 NSS = 0"이 되었다. MODF가 서고 SPE·MSTR이 지워진다(25.3.10). SR을 읽어 MODF를 확인한 뒤 CR1에 쓰면(이때 SSI = 1을 함께 쓴다) MODF가 지워지고, 그다음 MSTR·SPE를 다시 세운다. MODF가 1인 동안에는 하드웨어가 SPE·MSTR 세우기를 막는다.

Q7. 송신 전용에서 마지막 값을 DR에 쓰자마자 BSY를 봤더니 0이라 SPE를 내렸다. 마지막 바이트가 잘렸다. 왜인가?

불연속 전송에서 BSY는 DR 쓰기 뒤 APB 클럭 2주기 늦게 선다(p.712). 쓰기 직후의 BSY = 0은 "끝났다"가 아니라 "아직 안 섰다"이다. 그래서 TXE = 1(마지막 값이 시프트 레지스터로 넘어감)을 먼저 기다린 뒤 BSY = 0을 기다린다(25.3.8).

Q8. PCLK2 = 64 MHz, ÷4로 전이중 연속 수신을 한다. RXNE가 선 뒤 CPU는 대략 몇 PCLK 클럭 안에 DR을 읽어야 OVR을 피하는가? 인터럽트로 처리하는 것이 현실적인가?

프레임 하나가 8비트 × 4 = 32 PCLK 클럭(0.5 µs)이다. 다음 프레임의 마지막 샘플 엣지 전에 읽어야 하므로 예산은 대략 32클럭이다. 인터럽트 진입·복귀만으로도 이 예산을 거의 다 쓰게 되므로 현실적이지 않다. 이 속도에서는 RXDMAEN으로 DMA에 맡긴다. (인터럽트 진입에 걸리는 정확한 클럭 수는 이 개념설명이 근거로 쓰는 문서들에서 확인하지 않았다.)

Q9. SPI1 수신에 DMA를 쓰면서 USART3 송신에도 DMA를 쓰고 싶다. 가능한가?

SPI1_RX와 USART3_TX는 둘 다 DMA1 채널 2이다(Table 78). 한 채널은 한 번에 한 요청만 처리하므로 동시에 쓸 수 없다. 둘 중 하나를 CPU 전송으로 돌리거나 다른 SPI·USART를 쓴다. SPI 쪽을 CPU 전송 + CRC로 돌린다면 ES096 2.10.2 결함 조건에도 걸린다.

Q10. CPU 폴링으로 CRC를 켜고 10바이트를 전이중으로 보낸다. CRCNEXT는 언제 쓰는가? DMA로 바꾸면 무엇이 달라지는가?

열 번째(마지막) 바이트를 DR에 쓴 직후 CRCNEXT = 1을 쓴다. 그러면 10바이트 뒤에 TXCRCR이 나가고, 받은 CRC가 RXCRCR과 비교된다(25.3.6). 빠른 클럭에서는 이 쓰기가 마지막 바이트 전송이 끝나기 전에 이뤄져야 한다. DMA로 보내면 CRC 송수신이 자동이라 CRCNEXT를 쓰지 않고(오히려 0으로 둔다), 받은 CRC는 DR을 읽어 RXNE를 지운다.

Q11. 레지스터 주소 1바이트 + 데이터 1바이트를 CS 한 번 안에 받는 장치가 있다. DFF = 0으로 두 번 보내는 것과 DFF = 1로 한 번 보내는 것은 선 위에서 무엇이 같고 무엇이 다른가?

MSB 먼저라면 선 위의 16비트 순서는 같다(DFF = 1이면 DR 값의 비트 15부터 나간다). CS가 두 프레임 내내 Low로 유지되면 장치는 차이를 모른다. 다른 점은 CPU가 DR에 쓰는 횟수(2번 / 1번)와, 8비트 두 번은 소프트웨어가 늦으면 두 바이트 사이에 클럭 틈이 생길 수 있다는 점이다. DFF는 SPE = 0일 때만 바꿀 수 있으므로 장치마다 프레임 길이가 다르면 바꿀 때마다 SPI를 꺼야 한다.

정리
  • SPI는 보레이트 분주기 + 송수신 겸용 시프트 레지스터 + 한 칸 버퍼(Tx/Rx) + 플래그 + 인터럽트 OR 트리이다. 마스터와 슬레이브의 두 시프트 레지스터가 원을 이루어 클럭 8(16)번에 내용을 맞바꾼다.
  • fSCK = fPCLK / 2BR+1. SPI1은 PCLK2, SPI2는 PCLK1을 쓴다. 전기적 상한은 18 MHz(DS5319)이므로 64·72 MHz PCLK2에서는 ÷4가 최고이다.
  • CPOL은 SCK 극성 반전, CPHA는 샘플 엣지 선택이다. 양쪽이 같아야 한다.
  • TXE는 "Tx 버퍼 빔", RXNE는 "마지막 샘플 엣지에 Rx 버퍼 채움", BSY는 "선 위에서 진행 중"이다. 끝 판단과 끄기는 TXE → BSY 순서이다. OVR은 DR 읽기 → SR 읽기, MODF는 SR 접근 → CR1 쓰기로 지운다.
  • 내부 NSS는 마스터에서도 High여야 한다(SSM = 1이면 SSI = 1). 프레임마다 CS가 필요한 장치는 GPIO로 CS를 토글한다.
  • 프레임 시간이 µs 이하이므로 연속 전송은 폴링 또는 DMA(SPI1: 채널 2·3, SPI2: 4·5)로 한다.
