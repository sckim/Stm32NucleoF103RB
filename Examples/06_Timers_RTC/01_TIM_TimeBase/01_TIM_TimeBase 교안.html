타이머 시간 기준: 1 ms 업데이트 인터럽트와 소프트웨어 분주

CPU가 반복문으로 시간을 재면 다른 일을 할 수 없고 정확하지도 않다. 타이머는 CPU와 무관하게 세고, 정해진 값에 도달하면 이벤트만 알려 준다. 이 교안은 TIM3를 PSC=63, ARR=999로 설정해 1 ms마다 업데이트 인터럽트를 만들고, 소프트웨어 분주로 1초를 얻는 01_TIM_TimeBase 예제를 레지스터 수준까지 해석한다.

1. 문제: 정확한 1 ms를 CPU 없이 만든다

HAL_Delay()나 빈 반복문은 CPU를 붙잡는다. 타이머는 카운터가 하드웨어로 증가하므로 CPU는 이벤트가 올 때만 일하면 된다. 학습 목표는 다음과 같다.

  • 주기 공식 f_update = f_TIM / ((PSC+1)(ARR+1))로 PSC·ARR을 계산한다.
  • APB1 타이머 클럭이 버스 클럭의 2배가 되는 규칙을 설명한다.
  • 진짜 ISR(TIM3_IRQHandler)과 HAL 콜백의 차이를 구분한다.
  • ISR에서는 플래그만 세우고 출력은 main 루프에서 하는 패턴을 익힌다.
이 예제의 동작

1 ms마다 업데이트 인터럽트 → 콜백이 카운트 1000회마다 gSecondFlag를 세운다 → main이 LD2를 토글하고 printf로 초를 출력한다.

2. 타임베이스의 세 요소

요소레지스터역할
프리스케일러TIMx_PSC입력 클럭을 (PSC+1)로 나누어 카운터 클럭을 만든다.
카운터TIMx_CNT카운터 클럭마다 1씩 증가한다 (업카운트 기준).
자동 재장전값TIMx_ARRCNT가 ARR을 넘어 0으로 돌아가는 상한이다. 카운트 수는 ARR+1이다.
업데이트 이벤트SR.UIF오버플로 시 하드웨어가 1로 세운다. DIER.UIE = 1이면 인터럽트로 이어진다.

그림 1. CNT는 0에서 ARR까지 증가한 뒤 0으로 돌아가며, 이 순간 업데이트 이벤트(UEV)가 발생한다. 1카운트 = (PSC+1)/f_TIM = 64/64 MHz = 1 µs이다.

f_update = f_TIM / ((PSC + 1) × (ARR + 1)) = 64 MHz / (64 × 1000) = 1 kHz (주기 1 ms)

시간 기준으로 쓸 때는 비교 채널이 필요 없다. 짧은 틱을 하나 만들고 소프트웨어 카운터로 긴 주기를 얻는 것이 RTOS 틱·스케줄러·타임아웃 처리의 기본 구조이다.

3. 타이머 클럭이 64 MHz인 이유

단계설정클럭
시스템 클럭HSI(8 MHz) ÷2 → PLL ×16 → SYSCLK64 MHz
AHB (HCLK)÷164 MHz
APB1÷232 MHz (TIM2~4 버스)
TIM3 입력 클럭APB1 분주비 ≠ 1이므로 타이머 클럭은 ×264 MHz
APB2÷164 MHz → TIM1은 ×1 = 64 MHz
규칙

APB 분주비가 1이 아니면 해당 버스의 타이머 클럭은 버스 클럭의 2배이다. 클럭 트리를 바꾸면 PSC와 ARR도 다시 계산해야 한다.

4. 직접 만져 보기

  1. PSC=63, ARR=999에서 주파수가 1 kHz인지 확인한다. ARR을 9999로 바꾸면 100 Hz가 된다.
  2. PSC=6399, ARR=9999로 바꾸면 하드웨어만으로 1 Hz(1초)가 된다. 이때 소프트웨어 분주가 필요한가?

7. 코드 읽기

외부 부품은 필요 없다. LD2(PA5)가 1초마다 토글되고, USART2 가상 COM(115200 8N1)으로 출력한다.

main.c — 타이머 초기화 (CubeMX 생성)
static void MX_TIM3_Init(void)
{

  TIM_ClockConfigTypeDef sClockSourceConfig = {0};
  TIM_MasterConfigTypeDef sMasterConfig = {0};

  htim3.Instance = TIM3;
  htim3.Init.Prescaler = 63;
  htim3.Init.CounterMode = TIM_COUNTERMODE_UP;
  htim3.Init.Period = 999;
  htim3.Init.ClockDivision = TIM_CLOCKDIVISION_DIV1;
  htim3.Init.AutoReloadPreload = TIM_AUTORELOAD_PRELOAD_ENABLE;
  if (HAL_TIM_Base_Init(&htim3) != HAL_OK)
  {
    Error_Handler();
  }
  sClockSourceConfig.ClockSource = TIM_CLOCKSOURCE_INTERNAL;
  if (HAL_TIM_ConfigClockSource(&htim3, &sClockSourceConfig) != HAL_OK)
  {
    Error_Handler();
  }
  sMasterConfig.MasterOutputTrigger = TIM_TRGO_RESET;
  sMasterConfig.MasterSlaveMode = TIM_MASTERSLAVEMODE_DISABLE;
  if (HAL_TIMEx_MasterConfigSynchronization(&htim3, &sMasterConfig) != HAL_OK)
  {
    Error_Handler();
  }

}
  1. Prescaler 63과 Period 999가 1 kHz를 만든다.
  2. AutoReloadPreload가 켜져 있어 ARR 변경이 다음 UEV에서 반영된다.
  3. ClockSource는 내부 클럭이다.
main.c — 시작과 main 루프
printf("TIM3 TimeBase start (1ms update IRQ, print every 1s)\n");

/* TIM3_DIER.UIE = 1 (업데이트 인터럽트 허용), TIM3_CR1.CEN = 1 (카운터 시작) */
if (HAL_TIM_Base_Start_IT(&htim3) != HAL_OK) {
    Error_Handler();
}

if (gSecondFlag) {
    gSecondFlag = 0;
    printf("[%lu s] LD2 toggle\n", (unsigned long) gSeconds);
}
  1. Start_IT가 UIE와 CEN을 켠다.
  2. main은 플래그를 확인하면 즉시 지우고 LD2를 토글한 뒤 출력한다.
  3. printf는 main 루프에서만 호출한다.
main.c — 콜백 (ISR 문맥)
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    if (htim->Instance != TIM3) {
        return;
    }
    gTimerCnt++;
    if (gTimerCnt == 1000) {
        gTimerCnt = 0;
        HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
        gSeconds++;
        gSecondFlag = 1;
    }
}
  1. htim->Instance를 검사하여 TIM3만 처리한다.
  2. gSecondFlag는 콜백이 세우고 main이 지우므로 volatile이 필수이다.
  3. UART 블로킹 송신이 ISR을 점유하지 않도록 콜백은 플래그만 세운다.
기대 출력
TIM3 TimeBase start (1ms update IRQ, print every 1s)
[1 s] LD2 toggle
[2 s] LD2 toggle

115200 bps에서 1바이트는 약 86.8 µs이다. 한 줄(약 18바이트)은 약 1.6 ms가 걸리지만 ISR이 인터럽트로 동작하므로 이 시간 동안에도 1 ms 틱은 누락되지 않는다. (02 예제와 비교)

8. 실험

실험 A. 1초 주기를 하드웨어만으로

PSC=6399, ARR=9999로 바꾸고 콜백에서 분주 없이 바로 플래그를 세운다. 주파수가 1 Hz가 되는지 시뮬레이터와 비교한다.

실험 B. 10 ms 주기

PSC=63을 유지하고 ARR을 9999로 바꾼다. LD2 토글 주기가 어떻게 달라지는지 예측한 뒤 확인한다.

실험 C. 콜백에서 printf

콜백 안에서 직접 printf를 호출해 본다. 1 ms 틱 처리가 밀리는 현상을 gTimerCnt와 SysTick(HAL_GetTick()) 차이로 측정한다.

실험 D. ARPE 끄기

AutoReloadPreload를 끄고 동작 중 ARR을 줄여 본다. CNT가 새 ARR보다 클 때 어떤 현상이 생기는지 관찰한다.

10. 확인 문제

문제 1. PSC=6399, ARR=9999로 바꾸면 업데이트 주파수는?

64 MHz / (6400 × 10000) = 1 Hz이다. 하드웨어만으로 1초 주기가 된다.

문제 2. PSC=63을 유지하고 10 ms 주기를 만들려면 ARR은?

카운터 클럭이 1 MHz이므로 10 ms = 10000 카운트, ARR = 9999이다.

문제 3. HSI 대신 수정 발진기(HSE)를 쓰면 1초 주기의 무엇이 달라지는가?

주기의 정확도가 좋아진다. 분주비 계산은 같고 입력 클럭의 오차만 줄어든다. 정확도는 데이터시트의 HSI 정확도 표를 참조한다.

문제 4. ARPE를 끄고 동작 중 ARR을 줄이면 어떤 현상이 생길 수 있는가?

현재 CNT가 새 ARR보다 크면 한 바퀴를 더 돌아야 UEV가 발생한다. ARPE=1이면 변경이 다음 UEV에서 반영되어 이를 피한다.
