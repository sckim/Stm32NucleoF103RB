자유 계수 카운터: 32비트 µs 시계와 경쟁 조건

01·02 예제는 오버플로를 '주기 신호'로만 썼다. 이 교안은 카운터가 멈추지 않고 계속 도는 자유 계수(free-running) 상태에서 CNT 값 자체를 시간으로 읽는다. 16비트 CNT와 오버플로 횟수를 결합해 32비트 µs 시계를 만들고, 두 번의 읽기 사이에서 생기는 경쟁 조건을 관찰하는 03_TIM_Overflow_Counter 예제를 해석한다.

1. 문제: 16비트 CNT는 65.536 ms뿐이다

TIM2를 PSC=63(1 MHz), ARR=0xFFFF로 설정하면 CNT는 1 µs마다 증가하여 65.536 ms마다 오버플로한다. 타이머를 멈추거나 되돌리지 않고 계속 돌려 두면 임의 시점에 CNT를 읽는 것만으로 시각을 얻는다. 다만 표현 범위가 65.536 ms이다.

f_update = 64 MHz / ((63+1) × (65535+1)) = 15.26 Hz (주기 65.536 ms)
  • 16비트 카운터와 오버플로 횟수를 결합하여 32비트 µs 시계로 확장한다.
  • 두 번의 읽기(gOvf, CNT) 사이의 경쟁 조건을 관찰하고 안전한 읽기를 구현한다.
  • 래핑에 안전한 비교 (int32_t)(a − b) < 0를 이해한다.
  • µs 시계로 printf 한 줄, HAL_Delay의 실행 시간을 실측한다.

2. 카운터 확장

업데이트 인터럽트에서 오버플로 횟수 gOvf를 증가시켜 상위 16비트로 쓰면 32비트 시간이 된다.

3. 래핑에 안전한 비교

32비트 값이 한 바퀴 돌아도 두 시각의 차이는 올바르다. 부호 있는 정수로 해석하면 선후를 판정할 수 있다.

(int32_t)(a − b) < 0 ⇔ a가 b보다 이전 (두 시각의 차이가 2³¹ µs ≈ 35.8분 이내일 때)

5. 경쟁 조건

gOvf와 CNT는 서로 다른 두 번의 읽기이다. 그 사이에 오버플로가 발생하면 ISR이 gOvf를 올려도 이미 읽은 hi는 옛 값이고, lo는 0 근처의 새 값이 된다.

그림 2. ①과 ② 사이에 오버플로가 끼어들면 상위값은 옛 값, 하위값은 새 값이 된다.

Micros_Safe의 논리

  1. PRIMASK을 저장하고 __disable_irq()로 인터럽트를 막는다. 이제 gOvf는 바뀌지 않는다.
  2. gOvf와 CNT를 읽는다.
  3. SR.UIF = 1이고 CNT < 0x8000이면, 오버플로가 났지만 ISR이 아직 세지 못한 것이므로 hi에 1을 더한다. CNT가 큰 값이면 오버플로 이전에 읽은 값이므로 더하지 않는다.
  4. PRIMASK을 복원한다 (이미 인터럽트가 막힌 문맥이나 ISR 안에서 호출해도 안전하다).
전제

ISR이 32.768 ms(= 0x8000 µs) 이상 지연되지 않아야 3단계의 판정이 맞다.

7. 코드 읽기

배선이 필요 없다. LD2(PA5)가 1초마다 토글되고, USART2 가상 COM(115200 8N1)으로 결과를 출력한다.

main.c — 읽기 함수 두 가지
static uint32_t Micros_Naive(void)
{
    uint32_t hi = gOvf;          /* ① 상위 16비트 */
    for (int i = 0; i < NAIVE_GAP_NOPS; i++) __NOP();   /* 실험용: ①과 ② 사이 간격 늘리기 */
    uint32_t lo = TIM2->CNT;     /* ② 하위 16비트 (TIM2->CNT 직접 읽기) */
    return (hi << 16) | lo;
}

static uint32_t Micros_Safe(void)
{
    uint32_t primask = __get_PRIMASK();
    __disable_irq();
    uint32_t hi = gOvf;
    uint32_t lo = TIM2->CNT;
    if ((TIM2->SR & TIM_SR_UIF) && (lo < 0x8000UL))
    {
        hi++;                    /* 아직 ISR 이 반영하지 못한 오버플로 */
    }
    __set_PRIMASK(primask);
    return (hi << 16) | lo;
}
  1. naive는 gOvf와 CNT를 차례로 읽을 뿐이다.
  2. safe는 PRIMASK으로 인터럽트를 막은 상태에서 읽고 UIF로 보정한다.
  3. NAIVE_GAP_NOPS는 두 읽기 사이 창을 일부러 넓히는 장치이다.

  2. 콜백은 gOvf++ 한 줄로 끝낸다. 출력은 모두 main 루프에서 한다.
main.c — 측정 루프
uint32_t naiveBack = 0, safeBack = 0;
uint32_t prevN = Micros_Naive();
uint32_t prevS = Micros_Safe();
uint32_t tEnd  = prevS + TEST_WINDOW_US;

/* (int32_t)(a - b) < 0 : 32비트 래핑(71.6분)을 넘어도 올바른 비교 */
while ((int32_t)(Micros_Safe() - tEnd) < 0)
{
  uint32_t n = Micros_Naive();
  if ((int32_t)(n - prevN) < 0) naiveBack++;
  prevN = n;

  uint32_t s = Micros_Safe();
  if ((int32_t)(s - prevS) < 0) safeBack++;
  prevS = s;
}

10. 확인 문제

문제 1. lo < 0x8000 조건이 없으면 어떤 경우에 오류가 생기는가?

CNT를 읽은 직후 SR을 읽기 전에 오버플로가 나면, lo는 오버플로 이전의 큰 값인데 UIF=1이므로 hi가 잘못 1 증가한다.

문제 2. 이 확장 기법을 입력 캡처에 적용하면 측정 하한(15.3 Hz)보다 느린 신호를 어떻게 잴 수 있는가?

캡처 시점의 CNT에 오버플로 횟수를 결합해 32비트 시각으로 만들고 두 시각의 차이를 구한다. (06 예제)

문제 3. 32비트 µs 시계가 한 바퀴 도는 데 걸리는 시간은?

2³² µs ≈ 4294.97 s ≈ 71.6분이다.

문제 4. HAL_Delay(10)이 10~11 ms가 걸리는 이유는?

HAL은 최소 대기를 보장하려고 1틱(1 ms)을 더 기다린다. 따라서 HAL_Delay(1)도 약 2 ms이다.
