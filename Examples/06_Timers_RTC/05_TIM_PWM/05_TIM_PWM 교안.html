PWM 출력: 듀티로 평균 전압을 만든다

MCU 핀은 High와 Low만 낼 수 있다. 일정 주기 안에서 High 구간의 비율(듀티)을 바꾸면 평균 전압을 조절할 수 있다. 이것이 PWM이다. 이 교안은 PWM이 출력 비교의 한 모드(OCxM = 110)임을 04 예제와 연결하고, TIM1의 두 채널(PA8, PA10)로 1 kHz PWM을 만들어 LED 밝기를 바꾸는 05_TIM_PWM 예제를 해석한다.

1. 문제: 디지털 핀으로 밝기를 바꾼다

04 예제는 일치 시마다 ISR이 개입해야 했다. PWM은 CPU가 CCRx만 바꾸면 하드웨어가 파형을 계속 만든다. 인터럽트가 필요 없다.

  • PWM이 출력 비교의 한 모드(OCxM = 110)임을 04 예제와 연결한다.
  • 주파수 f = f_TIM / ((PSC+1)(ARR+1))와 듀티 D = CCR / (ARR+1)를 계산한다.
  • 한 타이머의 두 채널(CH1, CH3)이 같은 주파수, 독립된 듀티를 가짐을 확인한다.
  • 고급 타이머(TIM1)의 BDTR.MOE 조건과 HAL의 처리를 이해한다.

2. PWM 모드 1과 2

모드OCxMCNT < CCRCNT ≥ CCR
PWM 모드 1110High (활성)Low
PWM 모드 2111LowHigh

그림 1. PWM 모드 1: CNT < CCR이면 High. 주기는 ARR이, High 구간 길이(듀티)는 CCR이 정한다. 위 그림은 듀티 25%이다.

f_PWM = 64 MHz / ((63+1) × (999+1)) = 1 kHz 듀티 D = CCR / (ARR+1) × 100 [%]

99999.9%한 카운트 Low가 남는다 (이 예제의 상한)
1000 이상100%CCR ≥ ARR+1이면 항상 High (PWM 모드 1)

분해능은 ARR+1 = 1000단계(약 10비트)이다. 주파수를 낮추거나 PSC를 줄이면 분해능을 늘릴 수 있다.

3. 클럭

TIM1은 APB2에 연결된다. APB2 분주비가 1이므로 타이머 클럭은 ×1 = 64 MHz이다. APB1의 TIM2~4는 분주비 2라서 ×2로 64 MHz가 된다. 결과는 같지만 도출 과정이 다르다.

타이머버스분주비타이머 클럭
TIM1APB2÷164 MHz (×1)
TIM2~4APB1÷232 MHz × 2 = 64 MHz

6. HAL이 대신 해 주는 일

레지스터기대 값근거
TIM1->CCMR10x0068OC1M = 110 (0x60) + OC1PE = 1 (0x08)
TIM1->CCMR20x0068OC3M = 110 + OC3PE = 1
TIM1->CCER0x0101CC1E(bit 0), CC3E(bit 8)
TIM1->BDTR.MOE1 (bit 15)HAL_TIM_PWM_Start()의 __HAL_TIM_MOE_ENABLE()
확인

위 값은 HAL의 동작에서 유도한 기대값이다. 디버거의 Peripheral/SFR 뷰에서 실제 값을 확인한다.

  • PWM 채널 설정(HAL_TIM_PWM_ConfigChannel)은 OCxPE(CCR 프리로드)를 켠다. CCR을 바꿔도 다음 주기부터 반영되어 주기 중간의 글리치가 없다. (04의 OC 설정은 프리로드가 꺼져 있었다.)
  • HAL_TIM_PWM_Init()은 타이머 클럭 허용을, HAL_TIM_MspPostInit()은 핀을 AF 푸시풀로 설정한다 (PA8 = TIM1_CH1, PA10 = TIM1_CH3, 리맵 불필요).
  • 온보드 LD2(PA5)는 타이머 채널이 아니므로 PWM이 불가하다. 외부 LED가 필요하다.

7. 코드 읽기

PA8  (D7) ── 330 Ω ── 외부 LED 1 ── GND
PA10 (D2) ── 330 Ω ── 외부 LED 2 ── GND

적색 LED(Vf ≈ 2 V 가정)의 순방향 전류는 (3.3 − 2.0) / 330 ≈ 4 mA이다. 평균 전류는 듀티에 비례한다.

main.c — 타이머·채널 초기화
static void MX_TIM1_Init(void)
{

  TIM_MasterConfigTypeDef sMasterConfig = {0};
  TIM_OC_InitTypeDef sConfigOC = {0};
  TIM_BreakDeadTimeConfigTypeDef sBreakDeadTimeConfig = {0};

  htim1.Instance = TIM1;
  htim1.Init.Prescaler = 63;
  htim1.Init.CounterMode = TIM_COUNTERMODE_UP;
  htim1.Init.Period = 999;
  htim1.Init.ClockDivision = TIM_CLOCKDIVISION_DIV1;
  htim1.Init.RepetitionCounter = 0;
  htim1.Init.AutoReloadPreload = TIM_AUTORELOAD_PRELOAD_ENABLE;
  if (HAL_TIM_PWM_Init(&htim1) != HAL_OK)
  {
    Error_Handler();
  }
  sMasterConfig.MasterOutputTrigger = TIM_TRGO_RESET;
  sMasterConfig.MasterSlaveMode = TIM_MASTERSLAVEMODE_DISABLE;
  if (HAL_TIMEx_MasterConfigSynchronization(&htim1, &sMasterConfig) != HAL_OK)
  {
    Error_Handler();
  }
  sConfigOC.OCMode = TIM_OCMODE_PWM1;
  sConfigOC.Pulse = 0;
  sConfigOC.OCPolarity = TIM_OCPOLARITY_HIGH;
  sConfigOC.OCNPolarity = TIM_OCNPOLARITY_HIGH;
  sConfigOC.OCFastMode = TIM_OCFAST_DISABLE;
  sConfigOC.OCIdleState = TIM_OCIDLESTATE_RESET;
  sConfigOC.OCNIdleState = TIM_OCNIDLESTATE_RESET;
  if (HAL_TIM_PWM_ConfigChannel(&htim1, &sConfigOC, TIM_CHANNEL_1) != HAL_OK)
  {
    Error_Handler();
  }
  if (HAL_TIM_PWM_ConfigChannel(&htim1, &sConfigOC, TIM_CHANNEL_3) != HAL_OK)
  {
    Error_Handler();
  }
  sBreakDeadTimeConfig.OffStateRunMode = TIM_OSSR_DISABLE;
  sBreakDeadTimeConfig.OffStateIDLEMode = TIM_OSSI_DISABLE;
  sBreakDeadTimeConfig.LockLevel = TIM_LOCKLEVEL_OFF;
  sBreakDeadTimeConfig.DeadTime = 0;
  sBreakDeadTimeConfig.BreakState = TIM_BREAK_DISABLE;
  sBreakDeadTimeConfig.BreakPolarity = TIM_BREAKPOLARITY_HIGH;
  sBreakDeadTimeConfig.AutomaticOutput = TIM_AUTOMATICOUTPUT_DISABLE;
  if (HAL_TIMEx_ConfigBreakDeadTime(&htim1, &sBreakDeadTimeConfig) != HAL_OK)
  {
    Error_Handler();
  }
  /* PSC=64-1 -> 1MHz, ARR=1000-1 -> 1kHz, CCR1/CCR3 초기값 0 (OC1M/OC3M=110 PWM1, CR1.ARPE=1)
     BDTR: DTG=0, BKE=0, AOE=0 -> MOE 는 HAL_TIM_PWM_Start() 에서 세트 */
  HAL_TIM_MspPostInit(&htim1);

}
  1. Prescaler 63, Period 999가 1 kHz를 만든다.
  2. OCMode가 PWM1이고 초기 Pulse는 0이다.
  3. AutoReloadPreload가 켜져 있다.
main.c — 시작과 듀티 스윕
if (HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_1) != HAL_OK) Error_Handler();
if (HAL_TIM_PWM_Start(&htim1, TIM_CHANNEL_3) != HAL_OK) Error_Handler();

/* Infinite loop */
while (1)
{

  __HAL_TIM_SET_COMPARE(&htim1, TIM_CHANNEL_1, (uint32_t)duty);   /* TIM1->CCR1 = duty */
  __HAL_TIM_SET_COMPARE(&htim1, TIM_CHANNEL_3, (uint32_t)duty);   /* TIM1->CCR3 = duty */

  duty += step;
  if (duty >= 999) step = -1;
  if (duty <= 0)   step = 1;
  HAL_Delay(1);                                                    /* 1ms x 1000 = 1초에 0->100% */
}
  1. 채널마다 HAL_TIM_PWM_Start를 호출한다 (TIM1은 MOE도 함께 켜진다).
  2. 두 채널에 같은 duty를 쓰므로 두 LED가 함께 변한다. 채널별로 다른 값을 쓰면 독립 제어된다.
  3. duty가 0~999 사이를 ±1씩 왕복한다.
소요 시간

소스 주석은 '1 ms × 1000 = 1초'라고 되어 있으나, HAL_Delay(1)은 최소 대기를 보장하려고 1틱을 더 기다리므로 실제로는 약 2 ms이다 (03 예제에서 실측). 따라서 0 → 100% 스윕에 약 2초가 걸린다.

8. 실험

실험 A. 채널별 듀티

CH1은 25%, CH3은 75%로 고정되도록 코드를 바꾼다. 같은 주파수에서 듀티만 독립적인지 확인한다.

실험 B. PWM 모드 2

OCMode를 PWM2로 바꾸면 같은 CCR에서 High/Low가 반전되는지 시뮬레이터와 비교한다.

실험 C. 20 kHz

PSC=0, ARR=3199로 바꾸면 64 MHz/3200 = 20 kHz, 3200단계이다. LED 밝기 변화와 가청 소음을 비교한다.

실험 D. 스윕 시간 측정

03 예제의 µs 시계로 스윕 한 번의 시간을 재어 약 2초인지 확인한다.

실험 E. 감마 보정

듀티를 제곱한 표로 스윕하여 밝기 변화가 더 선형으로 보이는지 비교한다.

10. 확인 문제

문제 1. PWM 모드 2(OCxM = 111)로 바꾸면 같은 CCR에서 파형이 어떻게 달라지는가?

High와 Low가 반전된다. CNT < CCR이면 Low, CNT ≥ CCR이면 High이다.

문제 2. PWM 주파수를 20 kHz로 올리려면 PSC·ARR은? 분해능은?

PSC=0, ARR=3199이면 64 MHz/3200 = 20 kHz이고 3200단계이다.

문제 3. 04 예제의 Toggle 방식으로 1 kHz, 25% 듀티 파형을 만들 수 있는가? 필요한 ISR 횟수는?

High 간격과 Low 간격을 번갈아 더하면 가능하다. 주기마다 에지가 두 번이므로 ISR이 초당 2000회 필요하다. PWM은 ISR이 필요 없다.

문제 4. CH1은 25%, CH3은 75%로 고정하려면 코드를 어떻게 바꾸는가?

스윕 대신 시작 후 한 번 __HAL_TIM_SET_COMPARE(&htim1, TIM_CHANNEL_1, 250), (…, TIM_CHANNEL_3, 750)을 쓴다. ARR을 공유하므로 주파수는 같다.
