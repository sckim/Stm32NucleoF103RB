타이머와 RTC: 카운터와 비교기로 시간을 만들고 재기

타이머(TIM, Timer)는 디지털논리에서 배운 분주 카운터, 업/다운 카운터, 크기·일치 비교기, 래치(이중 버퍼), 엣지 검출기, 디바운서, 멀티플렉서를 한 블록에 묶은 주변장치이다. 같은 카운터 하나로 "정해진 시각에 사건을 만드는 일(출력 비교·PWM)"과 "사건이 일어난 시각을 기록하는 일(입력 캡처)"을 모두 한다. RTC(Real-Time Clock, 실시간 시계)는 32.768 kHz 시계 수정에서 1초를 만들어 전원이 꺼져도 세는 32비트 카운터이다. 이 개념설명은 STM32F103RB를 기준으로, 클럭이 분주기와 카운터를 지나 비교기·캡처 래치에 닿고 다시 핀·플래그·인터럽트·다른 타이머로 나가는 경로를 원본 블록도 위에서 따라간다.

1. 문제 정의: 타이머가 없으면 CPU가 무엇을 직접 해야 하는가

마이크로컨트롤러는 "1 ms마다 무엇을 한다", "LED 밝기를 30 %로", "이 펄스가 몇 µs 동안 High였나", "모터 축이 몇 칸 돌았나", "지금 몇 시인가"를 끊임없이 묻는다. 타이머가 없다면 CPU가 명령어 실행 시간을 세어서 이 모든 일을 직접 한다.

풀어야 할 문제타이머가 없다면 CPU가 하는 일타이머가 대신하는 소자
일정한 주기 만들기빈 루프를 정해진 횟수만큼 돈다. 그동안 다른 일을 못 하고, 인터럽트가 끼면 주기가 늘어난다분주 카운터(PSC) + 모듈로 카운터(CNT, ARR) → 갱신 사건(UEV)
정해진 시각에 핀 바꾸기시각을 계속 확인하다가 핀을 쓴다. 확인 간격만큼 오차가 생긴다일치 비교기(CNT = CCRx) + 출력 세트/리셋 논리
PWM으로 평균 전압 조절주기마다 두 번 핀을 바꾼다. 20 kHz면 초당 4만 번 끼어든다크기 비교기(CNT < CCRx)가 매 클럭 핀 값을 정한다
펄스 폭·주기 재기핀을 폴링하며 엣지가 오는 순간의 시각을 읽는다. 폴링 간격만큼 오차가 생긴다엣지 검출기 + 디지털 필터 + 캡처 래치(CNT → CCRx)
엔코더의 방향과 이동량A·B 두 핀의 모든 엣지에 인터럽트를 받아 상태표로 판정한다직교 신호 디코더가 CNT를 직접 올리고 내린다
정확한 펄스 하나핀을 켜고 바쁜 대기 후 끈다. 인터럽트가 끼면 폭이 늘어난다원 펄스 모드: 카운터가 한 바퀴 돌고 스스로 멈춘다
전원이 꺼져도 흐르는 시계불가능하다. CPU가 멈추면 셈도 멈춘다배터리 도메인의 RTC: 32.768 kHz ÷ 32768 = 1 Hz 카운터

64 MHz CPU에서 1 µs는 64 클럭이다. 소프트웨어로 1 µs 분해능의 펄스 폭을 재려면 64 클럭마다 핀을 확인해야 하므로 사실상 다른 일을 할 수 없다. 타이머는 이 셈을 하드웨어 카운터가 매 클럭 하게 하고, CPU에는 "사건이 일어났다"는 플래그와 "그때의 카운터 값"만 남긴다. 이것이 이 그룹 예제들이 시간 기준 → 출력(OC → PWM) → 입력(IC → PWM 입력) → 응용 순서로 나아가는 이유이다.

2. 일반 개념

시간 기준: 분주기와 모듈로 카운터

타이머의 심장은 클럭 엣지마다 1씩 늘어나는 카운터이다. 카운터가 0부터 N−1까지 세고 다시 0으로 돌아가면(모듈로 N 카운터), 넘어가는 순간마다 펄스가 하나 나온다. 그 펄스의 주파수는 f/N이다. 이것이 주기 인터럽트의 원리이다.

16비트 카운터 하나로는 N이 최대 65 536이다. 64 MHz를 65 536으로 나누면 약 977 Hz이므로 1초 주기를 못 만든다. 그래서 카운터 앞에 또 하나의 카운터(분주기, prescaler)를 둔다. 분주기가 M개를 세면 주 카운터가 1 증가한다. 전체 분주비는 M × N이 되어 최대 232까지 늘어난다. 디지털논리의 직렬 연결된 카운터(캐스케이드 카운터)와 같다.

비교: "그 시각이 되면"

카운터 값과 미리 정한 수를 일치 비교기(CNT = CCR)에 넣으면, 같아지는 순간에 사건이 생긴다. 이 사건으로 핀을 세우거나(set), 내리거나(reset), 뒤집을(toggle) 수 있다. 이것이 출력 비교(OC, Output Compare)이다. 카운터가 시계라면 비교 레지스터는 알람 시각이다.

크기 비교기(CNT < CCR)를 쓰면 카운터 한 바퀴 동안 앞부분은 1, 뒷부분은 0인 파형이 나온다. 이것이 PWM(Pulse Width Modulation, 펄스 폭 변조)이다. 주기는 카운터 길이(ARR+1)가 정하고, High 구간은 비교값(CCR)이 정한다.

PWM 주기 = (ARR + 1) / f_CNT 듀티 = CCR / (ARR + 1) (가장자리 정렬, PWM 모드 1)
계산 예

타이머 클럭 64 MHz, PSC = 63이면 f_CNT = 64 MHz / (63 + 1) = 1 MHz이고, 카운트 하나가 1 µs이다.

ARR = 999 → PWM 주기 = (999 + 1) / 1 MHz = 1 000 µs = 1 ms (PWM 주파수 1 kHz) CCR = 250 → 듀티 = 250 / 1 000 = 25 % → 한 주기 1 ms 중 High 250 µs, Low 750 µs CCR = 750 → 듀티 75 %, CCR = 0 → 항상 Low(0 %), CCR ≥ 1 000(= ARR + 1) → 항상 High(100 %)

카운터가 0, 1, …, 249인 250카운트 동안 CNT < CCR이 참이라 High이고, 250부터 999까지 750카운트 동안 Low이다. 이렇게 CCR이 곧 High 구간의 카운트 수이므로, 듀티를 바꾸려면 CCR만 바꾸면 된다. CCR이 0이면 출력은 항상 0이고, CCR이 ARR보다 크면 항상 1이다(RM0008 15.3.9, p.388). 같은 f_CNT에서 ARR을 99로 줄이면 주기는 100 µs(10 kHz)가 되고, CCR = 25가 25 %이다. 주파수는 10배가 되었지만 듀티를 1 % 단위로밖에 조절할 수 없다. 바로 아래 "분해능과 주파수의 맞바꿈"이 이 관계이다.

캡처: "그 일이 언제 일어났나"

반대 방향도 가능하다. 입력 핀에 엣지가 오는 순간 카운터 값을 레지스터에 래치하면, 그 사건의 타임스탬프가 남는다. 이것이 입력 캡처(IC, Input Capture)이다. 두 캡처값의 차가 주기이고, 상승·하강 엣지 캡처값의 차가 펄스 폭이다. 카운터가 한 바퀴 돌아 0으로 넘어가도, 차이를 16비트 부호 없는 뺄셈으로 구하면 한 번의 넘어감은 저절로 보정된다(모듈로 216 산술). 같은 레지스터가 출력에서는 "이 시각에 이 일을 하라", 입력에서는 "그 일이 이 시각에 일어났다"는 뜻이 된다.

캡처 래치는 한 칸이다. 소프트웨어가 값을 꺼내기 전에 다음 엣지가 오면 이전 값은 덮어써진다. 이것을 오버캡처라고 하며, USART의 오버런과 같은 구조이다.

분해능과 주파수의 맞바꿈

카운터 클럭 f_CNT가 정해지면 PWM 주파수와 듀티 분해능은 서로 묶인다. 한 주기 안의 카운트 수가 곧 듀티의 단계 수이기 때문이다.

듀티 단계 수 = ARR + 1 = f_CNT / f_PWM 분해능(비트) = log2(ARR + 1) 예) f_CNT = 64 MHz: 1 kHz → 64 000단계(약 16비트), 20 kHz → 3 200단계(약 11.6비트), 1 MHz → 64단계(6비트)

여기서 f_PWM은 만들려는 PWM의 주파수, 즉 1 / PWM 주기이다(최대 주기가 아니다). 위 식 "PWM 주기 = (ARR + 1) / f_CNT"를 뒤집은 것이다. 한 주기가 ARR + 1카운트로 이루어지므로 듀티는 0/(ARR+1), 1/(ARR+1), …, (ARR+1)/(ARR+1)처럼 1/(ARR+1) 단위로만 바꿀 수 있다. 예를 들어 f_CNT = 64 MHz에서 20 kHz PWM을 내려면 ARR + 1 = 64 000 000 / 20 000 = 3 200이므로, 듀티의 최소 변화 폭은 1/3 200 ≈ 0.03 %이다. 같은 f_CNT에서 PWM 주파수를 높일수록 한 주기 안의 카운트 수가 줄어 듀티를 거칠게만 조절할 수 있다.

입력 캡처도 같은 맞바꿈이 있다. f_CNT가 높으면 타임스탬프가 세밀하다(분해능 1/f_CNT). 그러나 16비트 카운터는 65 536카운트마다 한 바퀴 돌기 때문에, 넘어감을 따로 세지 않고 두 캡처값의 뺄셈만으로 잴 수 있는 가장 긴 간격은 65 536/f_CNT보다 짧아야 한다. 이보다 긴 간격은 카운터가 두 바퀴 이상 돌아 차이값이 모호해진다. 즉 캡처할 수 있는 최대 시간이 짧아진다.

f_CNT = 64 MHz → 분해능 15.6 ns, 최대 간격 65 536 / 64 MHz ≈ 1.02 ms f_CNT = 1 MHz → 분해능 1 µs, 최대 간격 65 536 / 1 MHz ≈ 65.5 ms

더 긴 간격을 재려면 분주기(PSC)를 키워 f_CNT를 낮추거나, 갱신 인터럽트로 넘어감 횟수를 따로 세어 216배씩 더한다. 하부 예제 03_TIM_Overflow_Counter가 이렇게 16비트 카운터를 32비트 µs 시계로 늘린다.

RTC와 32.768 kHz

시계용 수정 진동자는 32 768 Hz = 215 Hz이다. 15비트 이진 카운터를 거치면 정확히 1 Hz가 나온다. 주파수가 낮아 소비 전력이 아주 작으므로 배터리로 몇 년씩 돌릴 수 있다. RTC는 이 1 Hz로 초 카운터를 올리고, 날짜·시각은 그 초 수에서 계산한다. 수정의 오차는 보통 ppm(백만분율) 단위로 말한다. 20 ppm이면 하루에 약 1.7초가 어긋난다.

4. 클럭 경로와 시간 계산

타이머 클럭이 APB 클럭의 두 배가 되는 규칙은 RM0008 7.2(p.94)에 있다. "if the APB prescaler is 1, the timer clock frequencies are set to the same frequency as that of the APB domain ... otherwise, they are set to twice (×2) the frequency of the APB domain." 그래서 SYSCLK 64 MHz, APB1 ÷2(PCLK1 32 MHz)로 두면 APB1에 붙은 TIM2~4도 64 MHz를 받는다. APB2 ÷1이면 TIM1도 64 MHz이다. 이 저장소 예제들이 쓰는 설정이다. PCLK1은 최대 36 MHz이므로 SYSCLK 72 MHz에서는 APB1을 ÷2로 둘 수밖에 없고, 타이머는 72 MHz를 받는다.

계산식

f_CK_CNT = f_CK_PSC / (PSC + 1) (RM0008 15.4.11, p.418) 갱신률 (가장자리 정렬) = f_CK_CNT / (ARR + 1) 갱신률 (중앙 정렬) = f_CK_CNT / (2 × ARR) (0 → ARR−1 업, ARR → 1 다운, 15.3.2) TIM1 갱신률 = 위 값 / (RCR + 1) (반복 카운터, 14.3.3) PWM 듀티 (모드 1, 가장자리) = CCR / (ARR + 1) CCR > ARR이면 100 %, CCR = 0이면 0 % (15.3.9) 캡처 분해능 = 1 / f_CK_CNT 16비트로 잴 수 있는 가장 긴 간격 = 65 536 / f_CK_CNT RTC: f_TR_CLK = f_RTCCLK / (PRL + 1) (RM0008 18.4.3, p.489)

ARR = 0이면 카운터가 멈춘다("The counter is blocked while the auto-reload value is null", RM0008 15.4.12, p.419). PSC의 새 값은 다음 UEV 때(UG로 카운터를 지울 때 포함) 실제 분주기에 들어간다(p.418). 그래서 초기화 끝에 UG를 한 번 써서 섀도 레지스터를 채운다. 이 UG가 UIF를 세우는 문제는 5장에서 다룬다.

이중 버퍼: 프리로드와 섀도

왜 두 겹인가? 카운터가 도는 중에 비교값을 바꾸면, 바꾸는 순간이 주기의 어디냐에 따라 그 주기의 파형이 깨진다(7장 시나리오 ①). 프리로드에 미리 써 두고 UEV, 즉 주기의 경계에서 한꺼번에 옮기면 모든 주기가 "옛 값으로 온전히" 또는 "새 값으로 온전히" 나온다. 디지털논리의 이중 버퍼(double buffering) 래치이다. PSC는 늘 이 방식이고, ARR은 ARPE, CCRx는 OCxPE로 고른다.

UG와 URS: 초기화가 인터럽트를 부르는 문제

프리로드가 켜져 있으면 처음 쓴 PSC·ARR·CCR은 UEV가 오기 전까지 섀도에 들어가지 않는다. 그래서 RM0008은 PWM을 시작하기 전에 "initialize all the registers by setting the UG bit"라고 한다(15.3.9, p.387). 그런데 URS = 0이면 이 UG도 UIF를 세운다. UIE를 먼저 켜 두었다면 카운터를 시작하기도 전에 갱신 인터럽트가 한 번 들어온다. URS = 1이면 넘침만 UIF를 세우므로 이 문제가 없다. URS의 원래 목적은 "to avoid generating both update and capture interrupts when clearing the counter on the capture event"이다(15.3.2, p.370).

RTC 쪽 스위치: 동기화와 설정 모드

RTC 코어는 RTCCLK(예: 32.768 kHz)로, 레지스터 창구(APB1 interface)는 PCLK1로 돈다. 두 클럭 영역 사이에 값이 오가므로 손 맞잡기(handshake)가 필요하다.

  • 읽기 쪽 RSF: CPU가 읽는 RTC 레지스터는 RTC 클럭의 상승 엣지마다 갱신된다. 리셋이나 정지·대기 모드 뒤에는 APB1 쪽 사본이 아직 갱신되지 않아 첫 읽기가 틀릴 수 있다(보통 0). 그래서 RSF를 0으로 지우고 하드웨어가 다시 1로 세울 때까지 기다린 뒤 읽는다(RM0008 18.3.3, p.485).
  • 쓰기 쪽 RTOFF·CNF: RTOFF가 1(이전 쓰기 끝)인지 확인 → CNF = 1(설정 모드) → PRL·CNT·ALR 쓰기 → CNF = 0 → RTOFF가 1이 될 때까지 기다림. 실제 쓰기는 CNF를 내릴 때 시작되며 RTCCLK로 최소 3클럭 걸린다(18.3.4, p.485). 32.768 kHz에서 약 92 µs이다. 본문은 RTOFF가 "RTC_CR register"에 있다고 적지만 레지스터 설명(18.4.2)에서 RTOFF는 RTC_CRL의 비트 5이다.
  • 백업 도메인 쓰기 보호: 리셋 뒤에는 RTC와 백업 레지스터가 쓰기 보호된다. PWR·BKP 인터페이스 클럭을 켜고 PWR_CR의 DBP를 1로 해야 쓸 수 있다(18.1, p.482). RM0008 7.2.8(p.98)의 "DPB bit"는 DBP의 오기이다.
  • 클럭 선택은 한 번만: RTCSEL은 백업 도메인을 리셋하지 않고는 바꿀 수 없다(7.2.8).

확장: TIM1의 상보 출력, 데드타임, 브레이크

  • MOE(Main Output Enable): TIM1 출력 전체의 주 스위치이다. 리셋 직후 0이므로 TIM1은 CCxE를 켜도 MOE를 1로 해야 핀에 나온다. 범용 타이머에는 없는 단계이다.
  • 브레이크: BKE = 1이면 BKIN 핀(BKP로 극성 선택)이나 CSS 클럭 고장이 오는 순간 MOE가 비동기로 0이 된다. 타이머 클럭이 없어도 동작한다. 출력은 OISx/OISxN으로 정한 안전 레벨로 가고, BIF가 선다. AOE = 1이면 다음 UEV에 MOE가 저절로 돌아오고, 0이면 소프트웨어가 다시 켤 때까지 꺼져 있다. 브레이크 입력은 레벨로 동작하므로 입력이 살아 있는 동안 MOE를 다시 켤 수 없다(14.3.12, p.323~324). EGR.BG로 소프트웨어 브레이크도 낼 수 있다.
  • LOCK: BDTR의 LOCK을 한 번 쓰면 리셋 전까지 데드타임, 극성, 출력 모드 등을 단계별로 잠근다. LOCK 비트 자체도 리셋 뒤 한 번만 쓸 수 있다(14.4.18, p.360).

7. 동작 시나리오 추적

시나리오 ① 도는 중에 주기·듀티를 바꾼다: 프리로드의 효과

ARPE = 0에서 위험한 경우는 끝값을 현재 CNT보다 작게 줄일 때이다. 비교기는 CNT = ARR인 순간만 보므로, 이미 새 ARR을 지나친 카운터는 16비트 끝까지 갔다가 0으로 돌아와 새 ARR에 닿을 때까지 넘치지 않는다. 1 MHz 카운터에서 한 주기가 약 65 ms로 늘어난다(예제 14에서 측정). CNT가 ARR보다 클 때 0xFFFF 다음 동작은 문서에 직접 적혀 있지 않으며, 이 설명은 "일치할 때만 넘친다"는 15.3.2의 서술에서 나온 추론이다. ARPE = 1이면 새 값이 주기 경계에서만 들어가므로 이 일이 없다. CCR과 OCxPE도 같은 관계이다.

시나리오 ② 펄스의 주기를 캡처하는데 CPU가 늦는다: 오버캡처

정오표 두 건이 이 경로에 걸린다. ES096 2.6.5(p.15): CCRx를 읽는 바로 그 순간 캡처가 일어나면 CCxIF가 지워진 채 CCxOF는 서지 않을 수 있다. 새 데이터는 레지스터에 들어가 있지만 소프트웨어는 새 캡처를 모른다. 회피책은 캡처 핀에 EXTI를 잠깐 켜서 놓친 엣지를 따로 잡는 것이다. ES096 2.6.6(p.16): 반대로 데이터를 잃지 않았는데 CCxOF가 설 수 있다. 회피책은 없다. 따라서 CCxOF는 "잃었을 수 있다"는 경고로 다루고, 측정값의 타당성은 주기 범위 같은 응용 지식으로도 확인한다.

9. 이해 확인 문제

Q1. SYSCLK 72 MHz, APB1 ÷2일 때 TIM3의 클럭은? APB1 ÷1로 바꿀 수 있는가?

PCLK1 = 36 MHz이고 APB1 분주비가 1이 아니므로 TIM3는 ×2인 72 MHz를 받는다(RM0008 p.94). APB1 ÷1이면 PCLK1이 72 MHz가 되어 최대 36 MHz를 넘으므로 이 SYSCLK에서는 쓸 수 없다.

Q2. 타이머 클럭 64 MHz에서 1 µs 분해능으로 50 Hz 서보 PWM을 내려면 PSC와 ARR은? 1 µs는 몇 도인가(1~2 ms = 0~180°)?

PSC = 63이면 f_CNT = 1 MHz, 20 ms = 20 000카운트이므로 ARR = 19 999이다. 1 ms 폭에 180°가 담기므로 1 µs ≈ 0.18°이다. 0.09° 분해능이 필요하면 f_CNT를 2 MHz로 올려야 하는데 그러면 ARR = 39 999로 16비트 안에 들어간다. 8 MHz로 올리면 ARR = 159 999가 16비트를 넘는다.

Q3. 64 MHz 카운터 클럭에서 20 kHz PWM의 듀티 단계 수와 비트 수는? 중앙 정렬로 같은 20 kHz를 내면?

가장자리 정렬: ARR + 1 = 64 000 000 / 20 000 = 3 200단계, log2 3200 ≈ 11.6비트. 중앙 정렬: 주기가 2 × ARR이므로 ARR = 1 600, 듀티 = CCR/ARR로 1 600단계(약 10.6비트). 같은 주파수에서 중앙 정렬은 분해능이 절반이다. 대신 펄스가 주기 중앙에 대칭으로 놓인다.

Q4. f_CNT = 1 MHz, ARR = 999, ARPE = 0으로 돌다가 CNT = 700일 때 ARR에 499를 썼다. 그 주기는 얼마나 걸리는가? ARPE = 1이면?

ARPE = 0이면 새 끝값 499가 즉시 비교에 쓰이는데 CNT는 이미 700이다. 일치는 CNT가 0xFFFF를 지나 0으로 돌아온 뒤 499가 될 때 일어나므로 그 주기는 약 65.5 ms 이상으로 늘어난다(예제 14의 측정: 65~66 ms). ARPE = 1이면 현재 주기는 1 000 µs로 끝나고 그 UEV부터 500 µs 주기가 된다(Figure 108).

Q5. 초기화 끝에 UG를 쓰고, UIE를 켜고, CEN을 켰더니 시작하자마자 갱신 인터럽트가 한 번 들어왔다. 왜인가? 두 가지 고치는 방법은?

URS = 0이면 UG로 만든 UEV도 UIF를 세운다(RM0008 15.4.1, 15.4.5). 그 UIF가 남은 채로 UIE를 켜면 즉시 인터럽트가 걸린다. URS = 1로 두고 UG를 쓰거나, UG 뒤 UIE를 켜기 전에 UIF에 0을 써서 지운다.

Q6. f_CNT = 1 MHz, ARR = 0xFFFF에서 연속한 두 상승 엣지의 캡처값이 0xFF00, 0x0100이었다. 주기는? 이 방법이 틀리는 경우는?

16비트 부호 없는 뺄셈 0x0100 − 0xFF00 = 0x0200 = 512이므로 512 µs이다. 카운터가 그 사이 한 번 넘어간 것이 저절로 보정된다. 실제 주기가 65 536 µs보다 길면 넘침이 두 번 이상이라 구분할 수 없다. 이때는 넘침을 함께 세거나 PSC를 키운다.

Q7. 타이머 클럭 64 MHz, CKD = 00에서 ICxF = 0011과 0101은 각각 대략 몇 ns보다 짧은 펄스를 거르는가? 187.5 ns 폭 펄스는 각각 통과하는가?

0011은 f_SAMPLING = f_CK_INT = 64 MHz, N = 8이므로 약 125 ns, 0101은 f_DTS/2 = 32 MHz, N = 8이므로 약 250 ns이다(RM0008 15.4.7). CKD를 01(×2)로 바꾸면 f_DTS가 32 MHz로 낮아지므로 0101은 f_DTS/2 = 16 MHz, 약 500 ns로 넓어진다. 0011은 f_CK_INT로 표본화하므로 CKD와 무관하게 125 ns 그대로이다. 187.5 ns는 첫째는 통과하고 둘째에서는 걸린다. 예제 16의 측정이 이 계산과 같다. 경계 가까운 폭에서는 표본 위상에 따라 결과가 달라질 수 있다.

Q8. f_CNT = 1 MHz, PWM 모드 2 + 원 펄스, CCR1 = 2, ARR = 12이다. 지연과 펄스 폭은?

지연은 CNT 0, 1 동안이므로 2 µs이다. 활성 구간은 CNT = 2~12(양 끝 포함) 11카운트이므로 RM0008 15.3.10의 식(ARR − CCR1 + 1)으로 11 µs이다. 14장의 식(ARR − CCR1)을 따르면 10 µs가 되므로, 정확한 폭이 중요하면 측정으로 확인한다. 하부 예제 10_TIM_OnePulse_HCSR04_c는 이 계산에 따라 ARR을 11로 고쳐 (11 − 2 + 1) = 10 µs 펄스를 낸다.

Q9. LSE로 RTC를 돌리는데 PRL을 리셋값 그대로 두었다. 하루에 얼마나 어긋나는가? LSI(실제 30 kHz)에 PRL = 39 999를 쓰면 RTC의 1초는 실제 몇 초인가?

리셋값 0x8000이면 분주비가 32 769이므로 1/32 769 ≈ 30.5 ppm 느리고, 하루 86 400 s × 30.5 ppm ≈ 2.6 s 늦다. LSI 30 kHz에 분주비 40 000이면 TR_CLK = 0.75 Hz이므로 RTC의 1초는 실제 약 1.33초이다. LSI는 정밀 시계에 쓸 수 없다.

Q10. 회전당 100주기를 내는 직교 엔코더를 SMS = 011로 읽는다. 회전당 카운트와, ARR = 0xFFFF일 때 몇 바퀴마다 CNT가 한 바퀴 도는가?

두 입력의 모든 엣지를 세므로 주기당 4카운트, 회전당 400카운트이다. 65 536 / 400 = 163.84바퀴마다 CNT가 한 바퀴 돈다. 이동량은 이전 값과의 16비트 부호 있는 차로 구하면 그 사이 한 번의 래핑은 보정된다.

Q11. TIM1으로 64 MHz, CKD = 00, DTG = 64를 쓰면 데드타임은? 20 kHz, 50 % PWM의 High 구간은 얼마나 짧아지는가?

DTG[7:5] = 010(0xx)이므로 DT = 64 × tDTS = 64 × 15.625 ns = 1.0 µs이다(RM0008 14.4.18). 20 kHz 50 %의 High 구간 25 µs는 OCx와 OCxN 모두 상승 엣지가 1 µs 늦어져 약 24 µs가 된다.

Q12. TIM2·TIM3을 동시에 출발시키려 한다. 어떤 MMS, TS, SMS 조합이 필요한가? TS 값은 Table 86의 어디서 나오는가?

TIM2(마스터) MMS = 001(Enable → TRGO), TIM3(슬레이브) SMS = 110(트리거 모드)이다. TIM3에서 TIM2는 ITR1이므로 TS = 001이다(Table 86). TIM2의 CEN이 켜지면 TRGO가 High가 되고 TIM3의 CEN을 하드웨어가 세운다. 슬레이브 클럭은 미리 켜 두어야 한다(ES096 2.6.2).

정리 — 반드시 알아야 할 5가지
  1. 타이머는 "클럭을 세는 카운터"이다. 먼저 PSC(분주기)가 클럭을 느리게 만들고, 카운터가 0부터 ARR까지 센 뒤 다시 0으로 돌아간다.
    카운터 클럭 f_CNT = f_CK / (PSC + 1) 한 바퀴 시간 = (ARR + 1) / f_CNT
    예: 64 MHz, PSC = 63, ARR = 999 → f_CNT = 1 MHz(1카운트 = 1 µs), 한 바퀴 = 1000 µs = 1 ms. 이 1 ms마다 인터럽트를 받는 것이 주기 타이머이다.
  2. 같은 카운터로 세 가지 일을 한다. 카운터 값을 비교값 CCR과 견주어 출력을 만들거나, 입력 핀의 엣지가 온 순간의 카운터 값을 기록한다.
    • 출력 비교(OC): 카운터가 CCR과 같아지는 순간에 핀을 켜거나 끄거나 뒤집는다.
    • PWM: 카운터가 CCR보다 작은 동안 High이다. 듀티 = CCR / (ARR + 1). 예: ARR = 999, CCR = 250이면 25 %이다.
    • 입력 캡처(IC): 엣지가 온 순간의 카운터 값을 CCR에 저장한다. 두 값의 차가 두 엣지 사이의 시간(주기, 펄스 폭)이다.
  3. 주파수를 높이면 듀티를 세밀하게 조절할 수 없다. 한 주기의 카운트 수(ARR + 1)가 듀티의 단계 수이기 때문이다. 같은 f_CNT = 64 MHz에서 1 kHz PWM은 64 000단계, 20 kHz PWM은 3 200단계, 1 MHz PWM은 64단계이다. 입력 캡처는 반대로, f_CNT가 높으면 시간을 세밀하게 재지만 16비트 카운터가 한 바퀴 도는 시간(65 536 / f_CNT) 안의 간격만 잴 수 있다.
  4. 새 설정은 한 주기가 끝날 때 적용된다. ARR과 CCR은 "대기 칸"에 먼저 쓰이고, 카운터가 한 바퀴를 마치는 순간(갱신 이벤트, UEV)에 실제 레지스터로 옮겨진다. 그래서 PWM 주기 도중에 값을 바꿔도 파형이 중간에 깨지지 않는다. 이 방식을 켜는 스위치가 ARPE(ARR용)와 OCxPE(CCR용)이다.
  5. RTC는 1초를 세는 32비트 카운터이다. 32.768 kHz 시계 수정(LSE)을 32768로 나누어 1초마다 1씩 센다. 분주값 PRL에 0x7FFF(= 32767)를 써야 정확히 1 Hz가 된다. 주 전원이 꺼져도 백업 전원(VBAT)이 있으면 계속 센다.
한 걸음 더 — 필요할 때 해당 장에서 찾아본다
  • 타이머 클럭 계산 주의(4장): APB 분주비가 1이 아니면 타이머 클럭은 APB 클럭의 2배이다. TIM1은 APB2에, TIM2~TIM4는 APB1에 있다.
  • 입력 필터(5장): 핀 신호가 N번 연속 같은 값이어야 변화로 인정한다. 마이크로초 이하의 짧은 잡음 스파이크를 거르는 용도이다(버튼의 ms 단위 튐은 못 거른다).
  • 캡처값을 늦게 읽으면(7장): 저장 칸이 하나라 다음 엣지가 값을 덮어쓴다. 이때 CCxOF 플래그가 선다.
  • 타이머끼리, 타이머와 ADC 연결(6장): 한 타이머의 TRGO 신호로 다른 타이머나 ADC를 시작시킬 수 있다.
  • RTC 레지스터 읽고 쓰기(5장): 읽기 전에는 RSF가 1이 될 때까지, 쓰기 전후에는 RTOFF와 CNF 절차를 지킨다.
