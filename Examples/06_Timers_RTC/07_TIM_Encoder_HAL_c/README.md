# 07_TIM_Encoder_HAL_c

> 계층: **HAL** + TIM — Claude 작성, 검토 전 (컴파일만 확인)

**엔코더 인터페이스 모드**: 직교(quadrature) 엔코더의 A/B 신호를 타이머가 직접 카운트한다.

## 핵심 학습 내용

- **직교 엔코더**: 90° 위상 차이가 나는 A/B 신호에서 어느 쪽이 먼저 바뀌는지로 **방향**, 에지 수로 **이동량**을 안다. 타이머가 두 입력을 직접 보고 `CNT`를 증감(방향은 `CR1.DIR`)시키므로 CPU 부하가 0이고, 인터럽트 없이도 고속 회전을 놓치지 않는다.
- **설정** (RM0008 15.3.12, TIM3, A = PA6(TI1), B = PA7(TI2)): `SMCR.SMS = 011` → TI1과 TI2의 모든 에지에서 카운트(**x4 모드**, 1 주기 = 4 카운트). `CCER.CC1P/CC2P` 극성, `CCMR1.IC1F/IC2F` 입력 필터(기계식 접점 튐 제거).
- **오버플로 안전한 이동량**: 16비트 카운터가 오버플로하므로 "이전 값과의 16비트 **부호 있는** 차"로 계산하면 래핑에 안전하다.
- **소프트웨어 시뮬레이션**: 실제 엔코더 없이도 PB0/PB1로 직교 신호를 만들어 시험하는 기법.

## 시험 방법

- (A) 실제 엔코더: A/B를 PA6/PA7에 연결(풀업 필요), 공통 GND. `SIMULATE_ENCODER`를 0으로 바꿔 빌드.
- (B) 시뮬레이션(기본): `PB0 → PA6`, `PB1 → PA7` 점퍼. B1(PC13)을 누를 때마다 회전 방향이 바뀐다.

## 출력

200ms마다 `count=… delta=… (+정방향/-역방향) rate=… counts/s` (UART 115200).

## 인터럽트

사용하지 않는다 (폴링). 필요하면 오버플로/CC 인터럽트를 추가.
