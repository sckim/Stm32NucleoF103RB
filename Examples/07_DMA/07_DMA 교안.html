DMA: CPU 대신 버스를 잡고 데이터를 옮기는 두 번째 버스 마스터

DMA(Direct Memory Access, 직접 메모리 접근) 제어기는 디지털논리에서 배운 레지스터, 증가기(덧셈기), 다운 카운터, 비교기, 우선순위 인코더, 세트·리셋 플립플롭을 묶어 "주소 A에서 읽어 주소 B에 쓰기"를 CPU 없이 반복하는 장치이다. 이 교안은 STM32F103RB의 DMA1을 기준으로, 주변장치가 낸 요청 신호가 중재기를 거쳐 버스 읽기·쓰기 한 쌍이 되고, 개수 카운터가 줄어 절반·완료 플래그가 서기까지의 경로를 원본 블록도 위에서 따라간다. 레지스터 비트는 그 경로 위의 스위치·선택기·플래그로만 등장한다. 코드와 라이브러리는 하부 예제 교안에서 다룬다.

1. 문제 정의: DMA가 없으면 CPU가 무엇을 직접 해야 하는가

데이터를 한 곳에서 다른 곳으로 옮기는 일은 단순하다. 원본 주소에서 읽고, 목적지 주소에 쓰고, 두 주소를 다음 칸으로 옮기고, 남은 개수를 하나 줄이고, 0이 아니면 반복한다. 문제는 이 단순한 일을 CPU(Central Processing Unit, 중앙 처리 장치)가 하면 그동안 CPU가 다른 일을 못 한다는 점이다. 주변장치에서 데이터가 띄엄띄엄 들어오는 경우는 더 나쁘다. 데이터 하나마다 CPU가 불려 나와야 한다.

2. 칩과 무관한 일반 개념

버스 마스터와 슬레이브

버스에서 "읽기/쓰기를 시작할 수 있는" 장치를 마스터, 주소를 받고 응답만 하는 장치를 슬레이브라고 한다. 메모리와 주변장치 레지스터는 슬레이브이다. 보통 마스터는 CPU 하나뿐이다. DMA 제어기는 두 번째 마스터이다. 주소와 읽기/쓰기 신호를 스스로 내므로, CPU처럼 메모리와 주변장치 레지스터에 접근할 수 있다. 마스터가 둘 이상이면 같은 슬레이브를 동시에 원할 때 누가 먼저 쓸지 정하는 버스 중재가 필요하다.

사이클 훔치기(cycle stealing)

DMA는 CPU를 멈추고 버스를 통째로 빼앗지 않는다. 필요한 버스 사이클만 잠깐 빌린다. 두 마스터가 서로 다른 슬레이브를 쓰면(예: CPU는 Flash에서 명령을 읽고 DMA는 SRAM에 쓴다) 다층 버스에서는 동시에 진행된다. 같은 슬레이브를 원할 때만 중재기가 한쪽을 기다리게 한다. 이렇게 CPU 입장에서 "가끔 한두 사이클을 도둑맞는" 방식을 사이클 훔치기라고 한다.

핸드셰이크: 요청과 응답

주변장치가 "데이터 하나 준비됨"을 알리는 선을 요청(REQ, Request), DMA가 "처리하고 있다"를 돌려주는 선을 응답(ACK, Acknowledge)이라고 한다. 두 선을 아래 순서로 주고받는 것을 4단계 핸드셰이크라고 한다. RM0008 13.3.1은 F103의 DMA가 정확히 이 순서를 따른다고 적는다.

  1. 주변장치에 사건이 생기면 REQ를 1로 올린다.
  2. DMA가 우선순위에 따라 이 요청을 골라 주변장치에 접근하는 순간 ACK를 1로 올린다.
  3. 주변장치는 ACK를 보면 REQ를 0으로 내린다.
  4. DMA는 REQ가 내려간 것을 보고 ACK를 0으로 내린다. 이제 다음 요청을 받을 수 있다.

우선순위 중재

요청이 여러 개 동시에 와 있으면 하나만 골라야 한다. 디지털논리의 우선순위 인코더가 이 일을 한다. 입력 중 가장 높은 순위의 1을 찾아 그 번호를 낸다. 순위를 정하는 방법에는 고정 순서(번호가 작을수록 먼저)와 프로그램 가능한 등급이 있다. F103은 두 가지를 섞는다. 먼저 소프트웨어가 정한 4단계 등급을 비교하고, 등급이 같으면 채널 번호로 가린다(6장).

원형 버퍼와 이중 버퍼링

소리, 센서 값, 통신 바이트처럼 끝없이 이어지는 흐름은 버퍼 끝에 닿으면 처음으로 돌아가 다시 써야 한다. 이것이 원형 버퍼이다. 하드웨어로는 "카운터가 0이 되면 처음 값을 다시 적재하는" 재적재 카운터 하나로 된다. 그런데 DMA가 쉬지 않고 버퍼를 돌면 CPU는 언제 데이터를 읽거나 채워야 할까? 버퍼를 반으로 나누어, DMA가 앞 절반을 다 쓴 순간(절반 사건)과 뒤 절반을 다 쓴 순간(완료 사건)에 CPU를 부른다. DMA가 한쪽 절반을 쓰는 동안 CPU는 다른 절반을 처리한다. 이것을 이중 버퍼링 또는 핑퐁 버퍼라고 한다.

3. F103 내부 구현 블록도

칩 전체에서 DMA의 자리: 버스 행렬

RM0008 3.1(p.49)은 버스 행렬이 "the access arbitration between the core system bus and the DMA master bus"를 맡고 중재는 라운드 로빈(Round Robin)이라고 적는다. 본문은 마스터 넷(CPU DCode, System 버스, DMA1, DMA2)과 슬레이브 넷(FLITF, SRAM, FSMC, AHB-APB 다리)을 세지만, F103RB에는 DMA2와 FSMC가 없으므로 실제로는 마스터 셋, 슬레이브 셋이다(DMA2 부재는 아래 표의 근거). 디지털논리로 보면 버스 행렬은 슬레이브마다 하나씩 있는 멀티플렉서 + 중재기이다. 슬레이브마다 "이번 사이클에 어느 마스터의 주소·데이터를 통과시킬지" 고른다. 그래서 서로 다른 슬레이브를 쓰는 두 마스터는 동시에 진행할 수 있다. 등가 모델

요청 속도 f_req [회/s], 버퍼 N개, 원형 모드 HT 간격 = TC 간격 = N / f_req (HT와 TC는 N/(2·f_req)만큼 어긋나 번갈아 온다) DMA 인터럽트 = 2·f_req / N [회/s] (HTIE와 TCIE를 모두 켤 때) CPU 처리 마감 = N / (2·f_req) (절반 하나를 옮기는 시간) 샘플마다 인터럽트 방식 = f_req [회/s]

예: 하부 예제 02는 타이머 갱신 10 kHz로 64개 버퍼를 돈다. HT와 TC는 각각 초당 10 000 / 64 = 156.25번, 합쳐 312.5번이고, CPU는 3.2 ms 안에 절반 32개를 채우면 된다. 샘플마다 인터럽트를 쓰면 초당 10 000번이다.

폭이 다를 때: 늘이기와 자르기

디지털논리로 보면 폭 변환은 0 확장(상위 비트에 0 붙이기)과 절단(하위 비트만 배선)이다. 둘 다 배선만으로 되는 일이라 별도 연산이 필요 없다. 메모리는 리틀 엔디언이므로(RM0008 3.2, p.49) 32비트 값 B3B2B1B0의 "하위"는 가장 낮은 주소의 B0이다.

APB 주변장치에 좁게 쓸 때는 한 가지가 더 있다. DMA가 AHB에 바이트·하프워드를 쓰면 쓰지 않는 바이트 자리에 같은 값을 복제해 HWDATA(AHB write data bus) 32비트를 채운다. AHB-APB 다리는 폭 신호 HSIZE를 보지 않으므로 이것을 32비트 쓰기로 바꾼다. 그래서 바이트 0xB0을 쓰면 레지스터에는 0xB0B0B0B0이 들어간다(13.3.4, p.280; 3.1 주석 p.49도 같은 말을 한다). 16비트 레지스터가 32비트 간격으로 놓인 백업 레지스터에 쓰려면 MSIZE = 16, PSIZE = 32로 두라고 문서가 예를 든다.

플래그는 어떻게 지워지는가

DMA_ISR(DMA Interrupt Status Register)의 플래그는 모두 읽기 전용이다. 하드웨어가 세우고, 소프트웨어가 DMA_IFCR(DMA Interrupt Flag Clear Register)의 짝 비트에 1을 써서 지운다. 0을 쓰면 아무 일도 없다. 그래서 한 플래그를 지우는 쓰기가 다른 플래그를 건드리지 않는다. 이름의 ISR은 레지스터 이름이다. 인터럽트 처리 함수(ISR, Interrupt Service Routine)와 헷갈리지 말아야 한다.

6. 이벤트 생성 기전: 요청 → 중재 → 전송 → 플래그 → 인터럽트 → 다른 장치

① 요청은 채널마다 OR로 모인다

RM0008 13.3.7은 이 OR를 두고 "this means that only one request must be enabled at a time"라고 적는다. OR 게이트는 어느 입력이 1인지 구별하지 못한다. 같은 채널의 두 주변장치가 동시에 요청을 켜면 DMA는 누구의 데이터인지 모른 채 같은 주소 쌍으로 옮긴다. 그래서 채널 하나에는 요청 하나만 켠다. 요청을 켜고 끄는 스위치는 DMA가 아니라 각 주변장치 쪽에 있다. USART의 CR3.DMAT·DMAR, ADC의 CR2.DMA, SPI의 CR2.TXDMAEN·RXDMAEN, I2C의 CR2.DMAEN, 타이머의 DIER.UDE·CCxDE·TDE·COMDE가 그것이다. 각 주변장치가 언제 요청을 올리는지는 해당 그룹 상위 교안의 6장에 있다: USART, ADC, I2C, SPI.

② 중재: 등급이 먼저, 번호가 다음

RM0008 13.3.2(p.277)는 우선순위를 두 단계로 정한다. 먼저 CCR.PL의 소프트웨어 등급(매우 높음 > 높음 > 중간 > 낮음)을 비교하고, 등급이 같으면 "the channel with the lowest number will get priority"이다. 디지털논리로는 {PL[1:0], 7 − 채널 번호}를 이어 붙인 5비트 값이 가장 큰 채널을 고르는 비교기 트리이다. 등가 모델 중재가 전송 한 번마다 다시 이루어진다는 직접 문장은 없지만, 13.3.1이 요청 하나를 전송 하나로 처리한다고 적으므로 아래 도구는 "요청 하나 처리 후 다시 중재"로 모델링했다.

고정 순서에는 대가가 있다. 높은 등급 채널이 요청을 쉬지 않고 내면, 낮은 채널은 그동안 한 번도 버스를 받지 못한다. 문서는 이 경우의 최대 대기 시간을 밝히지 않는다. 그래서 등급은 "늦으면 데이터를 잃는 쪽"(예: 수신 바이트를 덮어쓰기 전에 꺼내야 하는 통신 수신)에 높게 준다. 채널 간 중재를 실험하는 예제는 12_Advanced_Topics/06_DMA_Priority_c이다.

③ 플래그 세 개, 채널마다 벡터 하나

채널 하나의 세 사건은 벡터 하나를 공유하므로, 인터럽트 처리 함수는 DMA_ISR을 읽어 어떤 사건인지 가려야 한다. 대신 채널끼리는 벡터를 나누지 않는다. DMA1 채널 1~7은 IRQ 11~17, 벡터 주소 0x6C~0x84이다(RM0008 Table 63, p.204~205). 그래서 등가 모델의 IRQ 번호는 10 + x이다. NVIC에서 해당 번호의 허용 비트(NVIC_ISERx)를 켜야 CPU까지 간다(PM0056 4.3.2, p.120). 플래그를 폴링만 하고 인터럽트를 쓰지 않는 것도 가능하다. 하부 예제 03이 그렇게 한다.

④ 주변장치 → DMA → 주변장치: CPU 없는 연쇄

DMA의 목적지가 메모리가 아니라 다른 주변장치 레지스터일 수 있다. 그러면 "어떤 주변장치의 사건이 다른 주변장치의 레지스터를 바꾸는" 연쇄가 CPU 없이 만들어진다. 하부 예제 02가 이 구조이다.

같은 모양의 연쇄가 다른 그룹에도 있다. ADC 변환 끝 → DMA → SRAM(03_ADC 6장), USART 수신 → DMA → 원형 버퍼(02_USART 6장), SPI 송신과 수신 두 채널 동시 사용(05_SPI 6장)이다. 이 교안은 DMA 쪽만 설명하고 각 주변장치의 요청 조건은 그쪽에 맡긴다.

파랑 = 방금 읽은 바이트, 주황 = 방금 쓴 바이트. 원본 쪽은 00, 01, 02 …로, 목적지 쪽은 EE로 채워 두었다. 폭 변환은 Table 76 규칙(0 확장, 하위 절단), 주소 증가는 13.3.3을 따른다. HTIF는 "남은 개수 ≤ N/2가 된 전송"에서 세운다. N이 홀수일 때의 정확한 시점은 문서에 없으므로 이 부분은 등가 모델이다. 하부 예제 03의 실험 A가 같은 아홉 조합을 실제 칩에서 덤프한다.

시나리오 ③ 예약 주소에 접근하면

RM0008 13.3.5(p.280)에 따르면 전송 오류는 "reading from or writing to a reserved address space"에서 생긴다. 그 순간 하드웨어가 해당 채널 CCR의 EN을 0으로 지우고 TEIF를 세운다. TEIE = 1이면 인터럽트가 된다. CNDTR은 남은 개수에서 멈춘다. 다시 쓰려면 원인을 고친 뒤 CNDTR을 다시 쓰고 EN을 켠다. 이 오류 검출은 "주소가 예약 영역인가"만 본다. 엉뚱하지만 존재하는 주소(예: 다른 변수의 SRAM 영역)에 쓰는 실수는 잡지 못한다. 원문은 TEIF가 "DMA_IFR register"에 있다고 적었지만 그런 레지스터는 없고 DMA_ISR이 맞다.

9. 이해 확인 문제

Q1. 요청 속도 8 kHz, 원형 버퍼 N = 160, HTIE·TCIE를 켰다. HT와 TC는 각각 몇 ms마다 오고, CPU의 처리 마감은 얼마인가?

한 바퀴는 160 / 8000 = 20 ms이므로 HT와 TC는 각각 20 ms마다 오고, 둘이 10 ms씩 어긋나 번갈아 온다. CPU는 절반 80개를 옮기는 시간, 즉 10 ms 안에 자기 몫을 끝내야 한다. 인터럽트는 초당 100번이다. 샘플마다 인터럽트라면 초당 8000번이다.

Q2. 채널 2(PL = 높음)와 채널 5(PL = 매우 높음)가 동시에 요청 중이다. 누가 먼저인가? 채널 5도 PL = 높음이면?

등급을 먼저 비교하므로 채널 5가 먼저이다. 둘 다 높음이면 등급이 같으므로 번호가 작은 채널 2가 먼저이다(RM0008 13.3.2). 위 중재기 체험에서 확인할 수 있다.

Q3. USART1 송신과 SPI2 수신을 둘 다 DMA로 하려 한다. 가능한가?

Table 78에서 USART1_TX와 SPI2/I2S2_RX는 둘 다 채널 4이다. 채널 입력은 OR이므로 동시에 켜면 안 된다("only one request must be enabled at a time"). 둘 중 하나는 인터럽트나 폴링으로 처리해야 한다.

Q4. PSIZE = 32, MSIZE = 8, DIR = 0, PINC = MINC = 1, CNDTR = 2이다. CPAR 쪽 메모리에 바이트 00 01 02 03 04 05 06 07이 있다. CMAR 쪽에는 무엇이 쓰이는가?

첫 전송은 0x03020100을 읽어 하위 바이트 00을 CMAR+0에 쓴다. 두 번째는 0x07060504를 읽어 04를 CMAR+1에 쓴다. 결과는 00 04이다(Table 76의 32→8 행). 시뮬레이터에서 PSIZE 32비트, MSIZE 8비트로 확인할 수 있다.

Q5. 일반 모드 전송이 끝나 TCIF가 섰다. 같은 버퍼로 한 번 더 받으려고 CNDTR에 다시 64를 썼는데 아무 일도 없다. 왜인가?

EN이 여전히 1이기 때문이다. EN = 1인 동안 CNDTR은 읽기 전용이라 쓰기가 무시되고, 값이 0이므로 요청도 받지 않는다. EN = 0 → CNDTR = 64 → EN = 1 순서로 해야 한다. CPAR·CMAR·CCR은 꺼도 지워지지 않으므로 다시 쓸 필요가 없다(13.3.3).

Q6. 16비트 원형 수신 버퍼(N = 256, 시작 주소 0x2000 0100)에서 CNDTR을 읽었더니 200이었다. DMA가 다음에 쓸 주소는?

이미 256 − 200 = 56개를 썼다. 다음 주소는 0x2000 0100 + 56 × 2 = 0x2000 0170이다. 내부 현재 주소는 읽을 수 없으므로 이렇게 CNDTR로 계산한다. 원형 수신에서 "지금까지 몇 바이트 왔나"를 알아내는 방법이 이것이다(02_USART의 IDLE 처리).

Q7. DMA로 어떤 APB 주변장치의 32비트 레지스터 하위 바이트에만 0x5A를 쓰려고 PSIZE = 8로 설정했다. 레지스터에는 무엇이 들어가는가?

DMA는 HWDATA에 0x5A5A5A5A를 싣고, AHB-APB 다리는 이를 32비트 쓰기로 바꾼다. 레지스터 전체에 0x5A5A5A5A가 들어가 상위 필드까지 바뀐다(RM0008 13.3.4, 3.1). 하위 바이트만 바꾸는 쓰기는 이 경로로는 안 된다.

Q8. CPAR에 실수로 예약 주소를 넣고 EN을 켰다. 채널에는 무슨 일이 생기는가? TEIE = 0이면 어떻게 알 수 있는가?

첫 읽기에서 전송 오류가 난다. 하드웨어가 EN을 0으로 지우고 TEIF와 GIF를 세운다(13.3.5). TEIE = 0이면 인터럽트는 없지만 DMA_ISR의 TEIF와 CCR의 EN = 0, 줄지 않은 CNDTR로 알 수 있다.

Q9. 채널이 동작 중일 때 처리 함수에서 "편하게" CGIFx 하나로 플래그를 모두 지웠다. 어떤 위험이 있는가?

ES096 2.4.1에 따르면 전송 오류와 같은 클럭에 CGIF를 쓰면 자동 비활성화가 실패하고 TEIF도 서지 않는다. 오류가 났는데 채널은 계속 돌고, 소프트웨어는 오류를 모른다. 동작 중에는 CHTIF·CTCIF·CTEIF만 쓴다.

Q10. DMA가 SRAM에서 SRAM으로 1 KB를 복사하는 동안 CPU는 Flash에서 명령을 실행하며 레지스터끼리만 계산한다. CPU는 느려지는가? CPU가 SRAM 배열을 읽는 계산이면?

명령 인출은 ICode로 Flash에 직접 가고(그림 1), 레지스터 계산은 버스를 쓰지 않으므로 DMA와 다툴 일이 거의 없다. SRAM 배열을 읽으면 CPU와 DMA가 같은 슬레이브(SRAM)를 원하므로 버스 행렬이 번갈아 준다. CPU는 느려지지만 대역폭의 절반 이상은 보장된다(13.3). 얼마나 느려지는지는 문서에 없고, 하부 예제 03의 실험 E가 잰다.

Q11. 메모리→메모리 복사를 원형 모드로 끝없이 반복해 "하드웨어 메모리 갱신기"를 만들려 한다. 가능한가?

안 된다. MEM2MEM과 CIRC는 함께 쓸 수 없다(13.3.3, p.279). 반복하려면 TC 때마다 소프트웨어가 채널을 껐다 다시 켜야 한다. 다른 방법으로, 타이머 요청이 박자를 주는 원형 채널의 CPAR에 메모리 주소를 넣는 구성도 생각할 수 있다. 13.2가 원본·목적지로 SRAM을 허용하므로 가능해 보이지만, 문서가 이 구성을 예로 들지는 않으므로 실측으로 확인해야 한다.

정리
  • DMA는 CPU 옆의 두 번째 버스 마스터이다. 요청 하나마다 "읽기 1번 + 쓰기 1번 + CNDTR 1 감소"를 한다.
  • 채널 하나 = 요청 OR + MEM2MEM 선택기 + EN 게이트 + 주소 레지스터 두 개와 증가기 + 재적재 다운 카운터 + 플래그 플립플롭 세 개이다.
  • F103RB에는 DMA1 하나, 7채널뿐이다. 요청과 채널의 연결은 고정이고(Table 78), 한 채널에는 요청 하나만 켠다.
  • 중재는 PL 등급이 먼저, 같으면 번호가 작은 채널이 먼저이다. 버스 행렬은 CPU에게 대역폭 절반 이상을 보장한다. 전송당 클럭 수는 문서에 없다.
  • 원형 모드 + HT·TC로 핑퐁 버퍼를 만든다. CPU 마감은 절반 하나를 옮기는 시간 N/(2·f_req)이다.
  • 폭이 다르면 0 확장·하위 절단(Table 76, 원본 오타 주의), APB에 좁게 쓰면 32비트로 복제된다. 레지스터는 32비트로만 접근하고, 동작 중에는 CGIF를 쓰지 않는다(ES096 2.4).
