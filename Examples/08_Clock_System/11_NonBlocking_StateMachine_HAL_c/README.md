# 11_NonBlocking_StateMachine_HAL_c

> 계층: **HAL** — Claude 작성, 검토 전 (컴파일만 확인)

`HAL_Delay` 없이 **상태 머신(FSM)** 으로 만든 보행자 신호등. 버튼 디바운스와 이벤트 처리 포함.

## 핵심 학습 내용

- **왜 상태 머신인가**: `HAL_Delay()`로 순서대로 쓰면 그 시간 동안 버튼 입력·통신 등 다른 일을 못 한다. "지금 상태"와 "상태가 시작된 시각"만 기억하고 루프를 돌며 (a) 시간 경과 (b) 버튼 이벤트로 상태를 바꾸면 여러 일이 겹쳐도 반응성이 유지된다 (delay 탈출).
- **구현 요점**
  - 상태 = `enum`, 전환 조건 = 시간(`HAL_GetTick` 차이, 오버플로 안전) 또는 이벤트
  - **진입 동작(entry action)은 전환 함수 한 곳에서만** 수행 → 상태가 바뀔 때 LED/로그가 항상 일관됨
  - 버튼은 5ms마다 샘플링하는 **"연속 N회 일치" 디바운스**, 눌림 **에지**에서만 이벤트 발생
  - 상태 전환 로그를 UART로 출력하되 짧은 문자열만 써서 폴링 주기가 흔들리지 않게 한다

## 시나리오

G(녹색) 5초 → Y(황색) 1초 → R(적색) 3초 → G … 보행자 버튼(B1): 녹색에서 최소 2초가 지난 뒤 누르면 남은 녹색을 건너뛰고 황색으로. 황색/적색 중 누르면 요청만 기억했다가 다음 녹색이 최소 시간을 채운 뒤 즉시 황색.

## 핀

녹색 = LD2(PA5), 황색 = PB0(A3), 적색 = PB1(Morpho CN10). 외부 LED는 330Ω과 직렬로 GND에 연결.

## 인터럽트

사용하지 않는다 (SysTick은 `HAL_GetTick`을 위해 돌고 있을 뿐).

## 관련 예제

`05_SysTick_Reg_c`(같은 사상의 레지스터 버전), `01_GPIO/06_ExtInt`(디바운스 없는 버튼 입력과 비교).
