# 02_WWDG_HAL_c

> 계층: **HAL** + WWDG — Claude 작성, 검토 전 (컴파일만 확인)

**윈도우 워치독**: "너무 늦게"뿐 아니라 "**너무 빨리**" 리프레시해도 리셋한다. 프로그램이 정해진 타이밍에 실행되는지까지 감시한다.

## 핵심 학습 내용

- **IWDG와의 차이**: IWDG는 독립 저속 클럭(LSI 40kHz), 타임아웃 전에만 리프레시하면 됨(늦는 것만 감시). WWDG는 APB1 클럭 기반 7비트 다운카운터(T[6:0])로 카운터가 **윈도우 값 이하일 때만** 리프레시를 허용하고, 윈도우 밖(너무 이름)이거나 `0x3F` 아래(너무 늦음)이면 리셋한다.
- **타이밍 계산 (PCLK1 = 32MHz)**: `t_tick = 4096 × prescaler(8) / 32MHz = 1.024ms`. 카운터 시작 0x7F, 윈도우 0x50, 리셋 임계 0x3F.
  - 리프레시 허용: 카운터 ≤ 0x50 → (0x7F−0x50) × 1.024 ≈ **48ms 이후**
  - 리셋(타임아웃): 카운터 < 0x40 → (0x7F−0x3F) × 1.024 ≈ **65.5ms**
  - ⇒ 리프레시는 약 **48~65ms 사이에만**. 이 예제는 55ms 주기로 리프레시.
- **하드웨어 대응**: `WWDG->CR`(`WDGA`(bit7)=1 활성화, **한 번 켜면 끌 수 없음**, `T[6:0]`), `WWDG->CFR`(`W[6:0]` 윈도우, `WDGTB[8:7]` 프리스케일러, `EWI`(bit9) 조기 경고 인터럽트), `WWDG->SR.EWIF`.
- **리셋 원인 확인**: `RCC->CSR.WWDGRSTF`(bit30), `RMVF`(bit24)로 플래그 지움 → 부팅 메시지에 WWDG 리셋 표시.
- **조기 경고 인터럽트(EWI)**: 카운터가 0x40이 되는 순간 리셋 직전 "마지막 기회"를 준다 (로그 저장 등).

## 시험 방법

- 기본: 55ms 주기 리프레시로 LD2가 정상 점멸.
- **B1(PC13) 누름**: 프로그램 "멈춤"을 흉내(리프레시 중단) → 약 65ms 뒤 리셋 → 부팅 메시지에 WWDG 리셋 표시.
- `EARLY_REFRESH_TEST`를 1로 바꾸면 20ms 주기(너무 이름)로 리프레시 → 계속 리셋되는 것을 확인.

## ISR vs 콜백

`WWDG_IRQHandler`(진짜 ISR) → `HAL_WWDG_IRQHandler()` → `HAL_WWDG_EarlyWakeupCallback()`(이 파일).
