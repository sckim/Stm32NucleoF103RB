# 90_Flash_Write_HAL_c

> 계층: **HAL** + FLASH — Claude 작성, 검토 전 (컴파일만 확인)

"부팅 횟수"를 전원이 꺼져도 유지되도록 내부 Flash의 마지막 페이지에 저장한다 (EEPROM 에뮬레이션 맛보기).

## 핵심 학습 내용

- **Flash의 제약**: 지우면 모든 비트가 1, 이후 필요한 비트만 0으로 쓸 수 있다. 지우기는 **페이지(1KB) 단위**.
- **웨어 레벨링**: 값이 바뀔 때마다 지우지 않고 페이지 안의 **다음 빈 칸(0xFFFFFFFF)** 에 새 값을 덧붙인다. 256칸 = 256번 부팅까지 한 번도 지우지 않아 Flash 수명(약 10,000회 쓰기/지우기)을 아낀다. 현재 값 = 마지막으로 쓰인 칸. 페이지가 다 차면 지우고 처음부터 다시.
- **메모리 맵** (128KB Flash): `0x08000000 ~ 0x0801FFFF`, 페이지 크기 1KB, 마지막 페이지(127) = `0x0801FC00 ~ 0x0801FFFF`. 링커 스크립트의 Flash 크기를 줄여 이 페이지를 데이터 전용으로 예약하는 것이 정석이다 (이 예제는 프로그램이 작아 생략).
- **하드웨어 대응** (RM0008 3장, PM0075): `FLASH->KEYR`에 KEY1/KEY2를 써서 잠금 해제(`HAL_FLASH_Unlock`), `FLASH->CR.LOCK`으로 재잠금. 소거: `CR.PER=1`, `AR`=페이지 주소, `CR.STRT=1`, `SR.BSY` 대기. 쓰기: `CR.PG=1` 후 **반워드(16비트)** 단위(HAL의 WORD 프로그램은 반워드 2번).

## 동작

B1(PC13)을 누른 채 리셋하면 페이지를 지워 카운터를 초기화한다. 그 외에는 부팅 횟수를 읽고 +1 해서 덧붙여 쓴다.

## 주의

- 소거/쓰기 중에는 Flash 접근이 막혀 코드 실행이 멈춘다 (소거 약 20~40ms). 인터럽트 응답이 그만큼 지연된다.
- 쓰기 도중 전원이 끊기면 값이 깨질 수 있다. 실제 제품은 CRC/유효 표시, 2벌 저장으로 보호한다 → `91_CRC_Unit_HAL_c`.
- ST-Link로 새 프로그램을 올릴 때 이 페이지가 덮어써지면 카운터가 초기화된다.

## 인터럽트

사용하지 않는다.
