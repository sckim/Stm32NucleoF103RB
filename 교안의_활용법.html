교안의 활용법

이 저장소의 교안은 두 종류이다. 그룹 폴더의 개념설명은 주변장치의 개념을 설명하고, 예제 폴더의 예제설명은 코드를 설명한다. 이 설명서는 교안 전체를 어떤 순서로, 어떻게 보면 좋은지 정리한 설명서이다. 어디서 시작하는지, 어떤 문서가 있는지, 그룹 하나를 공부하는 순서, 개념설명을 읽는 법과 모든 교안에 공통인 약속을 한 곳에 모았다. 각 교안에는 그 교안만의 내용을 쓰고, 공통 내용은 반복하지 않는다.

한 줄 요약

저장소를 받고 최신으로 유지한 다음(실습자료_최신화), 그룹마다 개념설명으로 개념과 신호의 흐름을 잡고, 예제를 실행하며 확인한다. 막히면 개념설명의 한계·정오표 장, 그다음 원본 PDF(Docs/)를 본다.

2. 시작 전: 저장소 받기와 최신화

  1. 처음 한 번: 실습자료_최신화.pdf의 1절을 따라 VS Code에서 저장소를 클론한다.
  2. 매 수업 시작 전: 같은 문서의 2절과 5절 체크리스트로 Pull을 실행해 최신 자료를 받는다. 오류나 충돌이 나오면 파일을 지우지 말고 담당자에게 문의한다(4절 상황표).
  3. 용어가 낯설면 Git_개념과_기본사용법.pdf를 본다. Clone, Pull, 커밋, 브랜치의 뜻과 수업에서 지킬 습관이 있다.
  4. 저장소 전체가 궁금하면 루트 README를 본다.

학생은 자료를 내려받기만 한다. 수업에서 지시하지 않았다면 Push나 Sync Changes는 누르지 않는다.

3. 전체 교안 한눈에

그룹은 번호 순서대로 한다. 앞 그룹의 개념(GPIO, 인터럽트, 클럭 게이트 등)이 뒤 그룹의 개념설명에서 다시 쓰인다.

02_USART시리얼 통신
03_ADC아날로그 입력
04_I2C_CommunicationI2C
05_SPI_CommunicationSPI
06_Timers_RTC타이머·RTC
07_DMADMA
08_Clock_System코어·클럭 시스템

4. 그룹 하나를 공부하는 순서 (권장)

  1. 그룹 README.md: 예제 목록과 필요한 배선을 확인한다.
  2. 개념설명 1~3장: 문제 정의, 일반 개념, 내부 구현 블록도를 먼저 읽는다. 개념과 신호의 흐름을 먼저 잡는다.
  3. 예제설명과 코드: 예제를 번호 순서대로 빌드하고 실행한다. 예제설명이 없는 예제는 예제 README와 main.c 주석을 본다.
  4. 개념설명 4~7장: 클럭·시간 계산, 제어 요소, 이벤트, 동작 시나리오를 실습한 예제와 연결해 다시 읽는다.
  5. 개념설명 9장 확인 문제로 점검한다. 정답이 문제 바로 아래에 접혀 있으므로 먼저 풀어 본 뒤 연다.
  6. 막히면 개념설명 8장(설계상 한계와 정오표)을 보고, 그래도 모르면 Docs/의 원본 PDF로 간다.

개념설명 10장의 표는 "각 예제가 개념설명의 어느 장을 쓰는지"를 보여 준다. 예제를 하다가 개념이 막히면 이 표에서 해당 장으로 돌아간다.

5. 개념설명 읽는 법: 10장 틀

개념설명은 모든 그룹이 같은 10장 틀이다. 입력에서 클럭, 처리, 플래그와 이벤트, 출력 순서로 신호를 따라간다.

장제목내용이럴 때 본다
1문제 정의이 주변장치가 없으면 CPU가 무엇을 직접 해야 하는가왜 이 주변장치가 필요한지 알고 싶을 때
2일반 개념칩과 무관한 기본 원리. 디지털논리와 연결한다기본 개념이 낯설 때
3내부 구현 블록도입력 → 클럭 → 처리 → 플래그·이벤트 → 출력 순서로 원본 블록도 위에서 신호를 따라간다신호가 핀에서 CPU까지 어떤 경로로 흐르는지 볼 때
4클럭 경로와 시간 계산버스 소속, 분주, 결과 주파수와 시간 분해능을 계산 예로 보인다주파수·시간을 계산할 때(계산기 포함)
5제어 요소의 역할블록도 위의 스위치·선택기에 레지스터 비트를 대응시킨다레지스터 비트가 블록도의 어느 스위치인지 볼 때
6이벤트 생성 기전플래그 → 인터럽트 요청 → DMA 요청 → 다른 주변장치 트리거인터럽트와 DMA 연결을 볼 때
7동작 시나리오 추적한 번의 동작을 시간 순서로 타이밍도와 함께 따라간다실제 동작 순서를 눈으로 따라갈 때
8설계상 한계와 이유왜 이렇게 만들었는지, 무엇을 감수했는지, 정오표의 결함예상과 다르게 동작할 때
9이해 확인 문제계산형·추론형 문제이해를 점검할 때
10하부 예제 연결각 예제가 이 교안의 어느 경로를 쓰는지, 마지막 "정리" 상자예제와 개념을 연결할 때, 핵심만 복습할 때

마지막 "정리" 상자는 반드시 알아야 할 핵심 5가지를 중요한 순서로 적고, 그 아래 "한 걸음 더"에 나머지를 해당 장 표시와 함께 둔다. 시간이 없으면 정리 상자부터 읽는다.

6. 근거 문서와 표기 약속

기준 칩은 STM32F103RB 하나이다. 개념설명의 사실은 아래 문서(저장소 Docs/ 폴더)에서만 가져왔다. 교안마다 어느 장과 표를 썼는지는 각 교안 맨 앞의 "이 교안이 쓰는 근거" 상자에 적었다.

문서종류이 저장소에서 쓰는 용도
RM0008 Rev 21참조 매뉴얼(Reference Manual)주변장치의 블록도, 기능 설명, 레지스터와 비트. 모든 개념설명의 중심 근거이다
DS5319 Rev 19STM32F103x8/xB 데이터시트이 칩의 블록도, 메모리 맵, 핀, 전기적 특성(전압·전류·타이밍·전력)
PM0056 Rev 7Cortex-M3 프로그래밍 매뉴얼(Programming Manual)코어 쪽 내용: 예외와 NVIC, 비트 밴딩, SysTick, 폴트
ES096 Rev 15정오표(Errata sheet)칩이 매뉴얼과 다르게 동작하는 알려진 결함과 회피 방법
PM0075 Rev 2Flash 메모리 프로그래밍 매뉴얼(Doc ID 17863)Flash 읽기·쓰기·소거 절차. 08_Clock_System과 10_Flash_CRC에서만 쓴다

위 문서들 사이에도 서로 어긋나는 곳과 원본의 오기가 있다(그림 라벨, 절 번호, 비트 이름 등). 발견한 것은 해당 그림의 캡션이나 각 교안 8장에 표시했다. 교안에 쓰인 표기 약속은 다음과 같다.

  • 인용: 인용마다 문서, 쪽, Figure·Table 번호를 붙였다. 링크를 누르면 해당 PDF의 그 쪽이 열린다(#page=N).
  • 등가 모델 표시: 문서에 내부 구현이 나오지 않아 디지털논리 소자(카운터, 비교기, 시프트 레지스터, 동기화기, 엣지 검출기, 상태기계 등)로 바꿔 그린 부분이나 문서의 숫자로 직접 유도한 계산에 붙인다. 동작을 설명하기 위한 그림이며 실제 회로도가 아니다. 문서에 있는 사실과 구분하기 위한 표시이다.
  • "문서에 없다": 위 문서가 말하지 않는 내용은 사실처럼 쓰지 않고 이렇게 밝힌다. 약어의 풀네임도 문서가 풀어 쓰지 않으면 지어내지 않는다.
  • 레지스터 비트는 블록도 위의 스위치·선택기·플래그로만 등장시킨다. 비트표를 통째로 옮기지 않는다. 신호가 하드웨어 안에서 어떻게 흐르는지가 설명의 중심이다.
  • 약어는 본문에 처음 나올 때 풀네임과 우리말을 적고, 앞쪽의 "약어 모음"에도 모아 두었다.
  • 코드와 라이브러리 함수, 보드 배선, 추상화 계층(HAL·LL·레지스터) 비교는 개념설명에 없다. 이것은 각 예제의 예제설명과 README, main.c 주석에서 다룬다. 센서·메모리 같은 외부 장치의 레지스터 의미와 배선도 예제 쪽에서 다룬다.

7. 그림 출처

그림은 STMicroelectronics의 위 문서에서 가져왔다. 원본이 있는 그림은 SVG로 다시 그리지 않고 PDF의 해당 쪽을 잘라 실었으며, 캡션에 문서, Rev, 쪽, Figure·Table 번호를 적었다. 등가 모델 그림과 타이밍도는 각 교안에서 새로 그렸다. 일부 그림을 부분만 잘랐거나 표를 줄여 옮긴 경우는 그 교안의 맨 아래에 따로 적었다.

8. 교안 여는 법

  • 브라우저로 연다. 교안은 HTML이다. 파일을 더블클릭하면 계산기와 시뮬레이터가 동작하고, 정답은 접혀 있다. PDF로 바꾸면 이 기능이 사라지므로 교안은 HTML 그대로 둔다.
  • 폴더 구조를 그대로 둔다. 그림은 같은 그룹 폴더의 img/에 있고, 원본 PDF 링크는 Docs/를 가리키는 상대 경로이다.
  • 안내서 두 개는 PDF이다. 실습자료_최신화와 Git_개념과_기본사용법은 동적 요소가 없는 안내서라 PDF로 올렸다.
